# 经验收尾流程

按 [AGENTS.md](../../AGENTS.md#经验沉淀闭环codex-任务收尾) 在验证后筛选经验。只有出现现有代码、测试或文档不能直接解释的教训，或需要纠正旧经验时，才读取并执行本页；没有新发现就结束，不为走流程创建文档。

## 核对与记录

1. 定点查 [经验索引](index.md)、相关 pattern 和历史提案，避免重复记录或重提已拒绝建议。只用本任务的实际操作、完整错误、验证结果和用户反馈核对；旧总结只作线索，不自动扫描历史会话。
2. 写入或局部更新 `patterns/`，说明现象、原因、方法、适用条件、验证与来源。区分事实、推断和未验证部分；证据链接到项目验收记录，不复制敏感轨迹，不把局部成功推广成整体成功。
3. 更新索引，在 [演化日志](logs.md) 记一行。纠正已有经验时保留修订依据与反例；任务当前进度只在 [STATUS](../../docs/STATUS.md) 维护。

## 提案与交付

- 值得推广且现有规则或 skill 尚未覆盖时，按 [提案与裁决](proposal-workflow.md) 至多形成一条原子提案；没有合适建议时不创建。
- 提案不等于获准修改规则或安装 skill。用户已明确授权的修改按原授权执行，不再变成待审提案；原有提案的采纳或拒绝仍需对应的用户裁决。
- 最终交付简述本轮新增或修订的经验，并链接本轮新增或修订的待审提案。既有待审项不阻塞工作，也不每轮催审。

## 执行入口

本流程由当前主代理执行，沿用 `.kimi-code/wiki/` 唯一经验库。目录名是历史遗留，不启动 Kimi、不新增代理、不等待退出事件，也不保证应用关闭后继续运行。历史 Kimi 接线独立保留，其可用性不决定本流程能否执行。
