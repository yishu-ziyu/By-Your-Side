# 经验：旧入口验收通过，仍可能没有解决用户当前的问题

## 现象

用户在 Codex 中希望本仓库持续沉淀开发经验。前轮工作修复了旧 Kimi 复盘脚本，并验证交互会话退出后能生成经验和提案；用户随后指出，当前工作发生在 Codex，目标并未因此得到解决。

## 原因与证据

- **事实**：[前轮验收](../../../docs/evals/20260909-wiki-consolidation-repair.md)把范围限定为 Kimi SessionEnd，并明确没有保证其他宿主。它能证明旧 Kimi 接线可用，不能证明当前 Codex 收尾流程可用。
- **事实**：用户在当前 Codex 会话纠正了使用环境，并要求改动前先对齐目的。本轮经确认的目的与范围记录在 [Codex 收尾验收](../../../docs/evals/20260909-codex-experience-closeout.md#已确认的目的与范围)。
- **判断**：前轮把容易定位的旧实现当成了任务入口，验收只覆盖了该实现。缺少实际使用入口的约束，使局部工程成功被当成用户目标已完成。

## 本次处理

先明确“当前 Codex 开发任务收尾”这个入口，再与用户确认目的和改动范围。把当前主代理的提炼、核对、记录、待审写入项目规范，直接维护已有经验库。

这项处理改变了任务的完成路径：无需退出应用或启动另一宿主，当前主代理在验证后、最终交付前即可形成可审阅的经验与提案。

## 适用条件与限制

适用于仓库同时保留多个宿主、运行模式、旧脚本或历史接线的工作。方案选择前先明确用户实际通过哪个入口得到结果；旧入口只能作为参考和已有证据。

本轮验证的是当前任务确实完成了对齐及经验收尾，不是对后续所有会话自动执行的技术保证，也没有验证未来偏离率是否降低。日常执行仍依赖主代理遵循项目规范。

## 验证与来源

- 前轮完整的 Kimi 路径及边界保留在上述验收文件，未删除或改写成 Codex 验收。
- 本轮用户先确认目的，再批准具体范围；当前主代理据此更新规范，并在交付前写出本页及 [待审模板提案](../proposals/20260909-acceptance-entry-field.md)。
- 证据来源：2026-09-09 本次 Codex 开发会话、两个项目验收文件。未额外扫描历史轨迹，未启动其他代理。

避免重犯的行为要求已按用户授权写入 AGENTS.md。进一步把“使用入口”做成验收模板固定字段，仍由用户裁决，不把本页当成该模板变更已获准的证明。
