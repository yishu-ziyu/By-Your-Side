# Pattern: 收盘顺序错了，跨进程会话的尾巴必丢

## 现象

2026-09-11 示范录制真机验收（隔离 Chrome + CDP 可信输入）。页面侧自检说出真相：

```
页面侧自检（停止后）：{"recording":false,"count":12,"truncated":false,"lastKind":"submit"}
面板步骤列表：……「点击输入框「密码」」      ← 只有 10 步，尾巴没了
```

丢掉的是最后两条：填密码、点「保存」/提交表单。用户手动点「做完了」时，录下来的那一步就没了。

同一轮还暴露两个同族问题：

- **点完「做完了」，面板把刚录的东西收走了**（立刻查 DOM：`#demo-strip` 的 `hidden` 为 `true`、高度 0）。
- **示范页没有任务绑定时，步骤全被丢掉**：页面侧上行只带 `sender.tab`，而落库用的是「标签页 → 会话」绑定，
  用户自己打开的新页面天然没有这个绑定。

## 根因

三个问题都是「一段跨进程会话怎么收尾」没想清楚：

1. **先删状态，再让对端补发。** `stopDemo` 先 `sessions.delete(...)`，之后才调用页面侧 `record.stop()`；
   而最后一批正是 `stop()` 才发出的 → 到后台时已经没有归属，被当成无主消息丢弃。
2. **收盘后下发了空状态。** 会话删了，`demoStatus()` 自然返回空步骤，面板按「空 = 不显示」收起 —— 用户刚录完的东西
   在**收工这类最该显示结果的时刻**消失。
3. **归属绑在任务模型上。** 录制对象是「用户亲手操作的一页」，它不需要、也经常没有任务绑定；
   用任务态的绑定关系去找归属，等于要求用户先让 Agent 碰过那一页。

## 方法

- **收盘顺序**：先让对端收尾（并拿到它自报的真实规模，如页面返回 `count`），**等到齐**（本例上限 800ms，到齐即走），
  最后才清状态。别用固定 sleep 猜同步点，用对端给出的数字做判据。
- **结果留到用户显式收起**：收工只标 `stopped`，记录继续下发；「收起」才删。再开始一次会替换上一份。
- **归属用会话自己的身份**：录制时就把 `tabId → conversationId` 记在自己的会话表里（`conversationForRecordingTab`），
  不查任务绑定。晚到的批次也只认「还在录的那一个」。
- **抓得到的自检入口**：页面侧暴露只读 `selfCheck()`（沿用 overlay 自检惯例），验收脚本才能区分
  「页面没记下」和「记下了但没送到」——这正是本轮定位问题的关键证据。

## 同一族的第四个实例：关服务前先断开还连着的客户端

示范编译的验收脚本起了一个协议桩（`WebSocketServer`）冒充伴随进程。收尾调 `server.close()` 时**脚本自己挂死**：
扩展的 WebSocket 客户端还连着，Node 的 `server.close()` 会等所有连接结束，而它永远不会主动断。
`lsof` 一看就明白：`127.0.0.1:7758` 两端都是 ESTABLISHED。

方法：关闭服务前先 `for (const socket of server.clients) socket.terminate()`，再给关闭加一个上限
（`Promise.race([close, timeout])`）。服务端"优雅关闭"的语义是**等对端**，而在验收/测试里对端往往不会配合。

## 适用条件

任何「一端产生、另一端持有、由用户显式结束」的跨进程会话都适用：录制、语音会话、验收驱动、长任务结算。
判据是存在两个必须对齐的动作：**清状态** 和 **对端补发**。

不适用：单进程内的一次性调用；或对端结束时不产生任何数据。

## 验证

- 修前真机 13/14：`页面自检 count=12`，面板 10 步，缺「提交表单」。
- 修后同一脚本连续三次 16/16；断言里新增「收工后步骤条仍可见、步骤没有消失」与「点收起后不再显示」。
- 单测锁住三条回归：示范页无绑定时仍收步骤、收盘等到齐、页面报的步数永远收不到时 800ms 后照常收盘。
- 命令：`node scripts/acceptance/demo-record-run.mjs`（无头，见 [headless pattern](gui-test-window-steals-focus.md)）。

证据：[skill-from-demo 验收](../../../docs/evals/20260911-skill-from-demo.md)。
