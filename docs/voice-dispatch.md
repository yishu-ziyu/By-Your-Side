# 任务调度与回执

文字与语音共用任务调度。语音接入和播放见[语音架构](voice-architecture.md)，实现状态见 [STATUS](STATUS.md)。旧 2.5 的说明见[历史](history/20260920-voice-dispatch-snapshot.md)。

## 身份与入口

- 程序按请求、任务和控制版本识别任务请求，不用当前可见会话替换原请求归属。
- 上一个任务没做完、用户正在回答助手的问题时，文字新消息按插话续接原任务。见[记忆、过往任务与任务跨轮](memory-and-tasks.md)。
- 语音模型的任务工具是语音适配接口，不是共享协议里的同名类型。
- 「终止任务」直接中止的机制见[语音架构](voice-architecture.md#提示词和程序分别保证什么)。其他中止说法仍由模型转达。
- 语音的各项后台判断走[后台判断入口](model-effort.md#后台判断)。
- 读页不启动网页写任务，也不切换标签页。用户要切换标签页时，选没选对工具取决于语音模型，工具名或提示词不能保证。

## 回执

本节是回执语义的唯一说明。回执的取值见 [`shared/task-actions.ts`](../shared/task-actions.ts)。

- 回执只说明请求的去向：排队、已接收、已应用、被拒、失败或结果未知。
- 已接收不证明网页结果成立。失败可能已部分完成，要读回执内容。
- 程序不自动重做结果未知的一步；助手重读页面后可以重做，见[去掉重试锁](evals/20261010-drop-retry-locks.md)。
- 执行前，程序先登记持久记录；出现异常时，记录保留不确定性。
- 结果交付和播放另有生命周期。不能从「已接收」或空闲推出「完成」。

## 页面、排队与恢复

- 网页操作经扩展执行和控制闸门检查。接管见[协议](protocol.md#任务与页面控制)。
- 恢复需要新的页面观察和原任务身份。断连或超时不代表已停手，也不代表已完成。
- 多个独立要求的准入与结果关联见[多要求设计](voice-multi-request-design.md)。容量是策略配置，不是服务承载量实测。
- 重启保留会话和任务资料。未通过项在 STATUS 维护。
