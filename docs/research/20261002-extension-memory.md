# 浏览器助手记忆：当前缺口与扩展实施方案

研究日期：2026-10-02。[当前状态](../STATUS.md) · [现有记忆契约](../memory-and-tasks.md)

## 给产品负责人的结论

本项目已经有长期用户资料、网站方法、过往任务、版本和纠正机制。最急的缺口是重启后的连续性：用户能看见旧对话，模型却未必知道这段对话、未完成任务及旧文件。先补这一层，再提升检索；现在引入记忆云服务或向量库不能解决丢失的上下文。

用户可见的目标应是：第二天回到同一任务，助手能说清昨天做到哪里、沿用用户已确认的要求、读回之前生成的文件；进入另一个网站时不误用原网站的操作规则；用户纠正或删除后不再用旧值。

本报告是当前代码审计与外部研究。没有把拟议行为当成已实现功能；后续验收必须在真实扩展中重启并继续任务。

## 当前已有能力与缺口

| 用户期待 | 当前代码事实 | 影响 |
|---|---|---|
| 重开侧栏继续聊 | 侧栏历史在storage.local，每会话256KiB，最多保留8个会话历史键；模型 messages 初始化为空 | 回放与模型理解脱节 |
| 重启后继续未完成任务 | 会话目录与阅读交接在IndexedDB；PiAgentLoop的任务自定义条目仍为内存MemoryEntries | 当前任务恢复不能依靠长期偏好代替 |
| 昨天的文件仍可用 | artifacts内容在会话Map；查看页副本在storage.session | 模型读取、打开与下载缺少同一份持久文件 |
| 记得偏好与网站规则 | profile、past、method存IndexedDB，带范围、来源原话、版本、状态和有效期 | 可复用底座，不必重建另一份“记忆系统” |
| 找到“上次选的那款” | 代码按网站、时间和预算注入；显式查询主要依赖词匹配，问过去带最近5条任务 | 更早或同义表达可能找不到 |
| 忘记之后不再引用 | 存储删除与版本复核已有；旧聊天和模型消息中的副本仍可能存在 | 删除存储与消除旧对话影响需分别验收 |

代码依据：[`PiAgentLoop`](../../agent/src/pi-agent-loop.ts)、[`conversation-store`](../../extension/src/inproc/conversation-store.ts)、[`panel-history`](../../extension/src/background/panel-history.ts)、[`artifacts-tool`](../../agent/src/artifacts-tool.ts)、[`memory-context`](../../agent/src/memory-context.ts)、[`memory-runtime`](../../agent/src/memory-runtime.ts)。

#31 的机制已在代码中确认：截图base64整体进入artifact历史事件；历史从末尾向前取，至少保留最新一条。单条大图可能挤掉前面的文字，并超过历史预算。扩大Chrome存储权限不能解决这条截取规则。

另一个边界：memory-decision缺失about时回退为长期事实。来源和版本校验不能证明模型把网站操作做法分对了；历史MiniMax试用出现过这个误判，本次研究没有重新复现该模型行为。依据：[`memory-decision`](../../agent/src/memory-decision.ts)及[原验收](../evals/20261001-remember-corrections.md)。

## 外部机制中值得采用的部分

| 来源 | 资料支持什么 | 在本项目如何采用 |
|---|---|---|
| [Letta memory blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks) | 少量稳定信息常驻上下文，其他资料按需查询 | 复用现有预算；稳定偏好与历史材料分开，不每轮塞全部聊天 |
| [Mem0论文](https://arxiv.org/html/2504.19413v1)与[抽取代码](https://raw.githubusercontent.com/mem0ai/mem0/main/mem0/configs/prompts.py) | 论文把抽取和更新分开；研究时main已出现ADD-only linking，不能当作论文流程的同一版本 | 模型提出候选，宿主检查范围、来源、版本；沿用已有替换历史，不给模型自由合并不同网站事实 |
| [Generative Agents](https://arxiv.org/html/2304.03442v2) | 事件、检索与反思分开；推断链接底层事件 | 真实任务结果是经验的来源，模型总结单独标为推断；模拟人物实验不等于浏览器任务验收 |
| [Reflexion](https://arxiv.org/html/2303.11366v4) | 把评价反馈保存给后续尝试，记忆有容量边界 | 保存条件、失败与经验证的修法；不能把一次错误日志直接变成所有网站的规则 |
| [LongMemEval](https://arxiv.org/html/2410.10813v2) | 分别测事实提取、跨会话推理、时间推理、知识更新与不知道时拒答；检索到不等于用对 | 增加“上次”“后来改了”“哪个时间有效”等真实多会话测试，不只测存储API返回成功 |

上述研究支持机制与测试维度，不证明本扩展已经获得相同收益。优先复用现有模型接口、IndexedDB与MemoryEntry类型。结构化过滤和关键词先作为基线；若同义表达反例持续失败，再用同一批题比较向量检索。没有证据要求现在增加数据库服务。

## Pi原生能力核对：更新实施选择

用户要求优先核对原生能力。当前锁定的`@earendil-works/pi-agent-core` **0.84.4** 已公开导出并实际实现`Session`、异步`SessionStorage`、`InMemorySessionRepo`、`buildSessionContext`和压缩函数。原生Session能记录用户/助手/工具消息、自定义检查点、分支和操作记录。存储接口不要求Node文件系统，适合由IndexedDB实现。

一次只在内存运行的探针已成功创建原生会话、追加消息与检查点、重建用户消息；压缩阈值函数也可运行。浏览器打包探针不依赖本机文件系统。它们验证组件可用，正式扩展的IndexedDB恢复尚未接入。

两个层次要分开：完整`pi-coding-agent.AgentSession/SessionManager`仍带Node文件系统等依赖；核心包内的新Session/Storage可独立复用。当前安装版的`AgentHarness`虽有导出，`prompt/resume/compact`等运行方法实际上抛`HarnessNotImplemented`，不能据类型声明整套替换当前执行循环。

**修订建议：优先采用原生Session、上下文重建与压缩规则，Chrome只补IndexedDB存储适配；保留当前已可运行的Pi执行循环。** 原计划“给我们自己的MemoryEntries加快照”退为备选，不再作为首选。避免继续维护第二套会话语义。

接入要处理真实契约：现有任务检查点按同步接口写入，原生Session是异步的；接受任务与保存完成的回执要等事务提交。条目、递增序号与分支指针应原子写入。恢复采用显式`oldestFirst`顺序，原生摘要也必须实际进入模型请求。旧执行证据恢复不授予自动重做权限。

依据为当前安装源码：`pi-agent-core/dist/harness/session/{types,session,context,memory}`、`dist/harness/compaction/compaction`、`dist/harness/agent-harness.js`。上游[会话代码](https://github.com/earendil-works/pi/tree/main/packages/agent/src/harness/session)只作导航；不能用main中的新名称代替0.84.4实际导出。项目当前适配见[`PiAgentLoop`](../../agent/src/pi-agent-loop.ts)。

## 在扩展中按三步实施

### 1. 持久保存文件与任务恢复材料

先处理#31。把图片和文件内容独立保存，聊天事件只保留产物编号、名称、类型和摘要。模型读取、侧栏下载和查看页访问同一份产物。不能只修侧栏历史、让模型的文件Map重启后仍为空。

通过原生Session持久化同一会话的恢复材料：用户原要求与改口、最近交付、任务账本、未完成项、结果未知的写入证据和必要消息。复用会话编号，不把这些内容写成全局用户偏好。存储提交失败时不能回报已可靠保存。

恢复后，先展示上次状态，再读取当前页面核对。浏览器重启不会自动重放点击或提交；结果未知的写入必须先核查。持久化应按小批事务提交，不能依赖长期常驻整理进程。Chrome官方说明worker通常在空闲30秒后被终止，内存变量会丢失：[生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。

### 2. 把事实、网站方法和单次要求分清

沿用已有profile/past/method及all/site范围。三个反例必须可区分：“我每次坐飞机靠过道”是稳定偏好；“这次靠过道”留在任务；“这个网站导出全部”是网站方法，不自动成为全局个人资料。

候选分类缺失或畸形时不按长期事实兜底。用户明确纠正时，新版本生效，旧版本只作历史；网页说明不能覆盖用户偏好，也不能自行授权永久规则。自动判断失败保留待处理状态，不把失败伪装为没有记忆。

检索先执行状态、来源、任务/网站范围过滤，再按内容与时间选择。进入网站、用户问“上次”、继续任务、同类失败是明确检索时机。普通导航不用每次调用模型。全局共享只限用户已明确设为全局的资料。当前范围只区分all与精确hostname，没有账号维度；同站切换公司/个人账号必须作为额外反例，不能用语义相似度代替账号归属。

### 3. 提高召回与可见纠正

用任务轮次、来源页和时间给历史建可查询索引。摘要帮助找到原记录，原证据保留供核对；不能只留摘要而丢掉用户原话。常驻记忆继续有总预算，相关历史按需读。

用户需要看到记忆内容、来源、范围与本轮引用原因，并能改正、停止引用或删除。引用计数不能冒充行为已经遵守。删除还要阻止迟到补判重建，并检查旧会话里的副本；“清掉存储”和“本轮不再受影响”是两个标准。

网站暂停采集可作为后续产品选择；本轮不增加后台浏览监控。扩展本地保存不等于本地推理，模型抽取继续走用户已有服务。

## 最小验收：先证明用户真的记得住

用同一主模型、快速模型、页面和输入比较当前版本与补丁版本，不把关闭已有长期记忆作为当前基线。先做以下8条真实路径，再扩成20–30条轨迹：

1. 用户给当前任务一个随机代号，重启后在同一会话问代号、要求与当前进度，答案对得上原话。
2. 大截图与CSV生成后重启，旧文字、图片、下载和模型读文件都成功，文件字节hash不变。
3. 结果未知的写入后重启并继续，站点计数证明没有重复提交。
4. 网站A确认导出方法，网站B不采用；同站另一个任务只采用适用方法。
5. 永久偏好、这次要求、网站做法按预先人工标注的范围落盘，并在下一次实际操作中生效。
6. 纠正偏好后采用新值；问“之前”时还能辨认旧值及生效时间。记录时间、实际生效时间和保存多久是不同含义；昨天购买的事实不因日期过了就等于无用，而“明天去成都”的临时计划也不应永久主导回答。
7. 删除后，新会话、重启、迟到补判都不能重新引用或写回；原会话旧副本单独核查。
8. 同义表达能找回正确旧选择；证据不足时说不知道，网页注入不能升级为用户规则。

证据应同时包括输入、落盘版本与来源、检索条目、实际模型请求、最终页面行为、重启阶段和额外调用耗时。存储成功或检索命中只是辅助证据。

## 当前决定与待验证项

研究建议：#31之后优先做会话和任务恢复，再修范围兜底，然后评估语义检索。所有状态留在本项目，不写全局配置。本报告不改变已有默认自动记忆策略、不授权后台收集所有网页。实现时按上述反例验证，成本与体验有实际数据后再扩大范围。
