# 记住走过的路、Jev 与浏览器路径代码检查

日期：2026-10-07。三份只读调研的结论，供重构时设计用。用户决定：“记住走过的路”等重构后再实现；Jev 先调研，再做对照实验。本文不代表已实现。上游代码只读，未运行。

## 记住走过的路：三家怎么做

读的版本：Stagehand main `fdd1795` 与 v3.7.3，Skyvern `44de8cd`，Browser Use `914c59b`（0.13.11），workflow-use `5d2d19f`。

| | Stagehand | Skyvern | Browser Use |
|---|---|---|---|
| 存什么 | xpath、动作描述、方法、`%变量%` 占位 | 每个动作存选择器 + 原意图文字 + 目标状态；整段生成 Python 脚本 | 元素指纹（hash、xpath、无障碍名称） |
| 用什么找回 | v3：指令 + 网址 + 变量名；v4：服务端黑盒 | 工作流 + 域名 | 无，调用方自己管文件 |
| 动手前核对 | v3 等不到选择器也继续；v4 同一结果见过 N 次才用 | 只看选择器在不在 | 5 级元素匹配，取第一个，不查唯一 |
| 对不上时 | 当作没缓存，交给模型；v3 按描述重找 | 单步按意图重找 → 整段交给 Agent 从当前页接着做 → 成功后改写脚本 | 重试 3 次后失败或跳过，不交回模型 |
| 提交/付款类闸门 | 无 | 无；但已发出的点击不重试，开关类按目标状态跳过 | 无 |

结论：

- Skyvern 最完整。值得学：存意图、单步重找、整段交回 Agent、已发出的点击不重试。
- 三家都没有“回放前核对页面签名”，也没有不可逆动作闸门。这两样要我们自建。
- Browser Use 的自愈代码被注释掉（workflow-use #146）。Skyvern 自述的 279→120 秒在仓库里找不到出处。

### 对本项目的含义（推断）

可以学：

- 每个点击、填写存“意图 + 角色/名称/容器路径”，回放时重新定位；不存 `@N`（换一次加载就失效）。
- 定位必须唯一，否则算没命中。宁可没命中，也不能点错。
- 变量只绑到填写的位置，缺值就不回放。
- 一条路线成功几次后才允许回放（Stagehand 的“见过 N 次”）。
- 对不上时，带着已完成步骤交回模型，从当前页接着做。

不学：域名级的键、等不到也继续、沿用旧参数的自愈、跳过失败、按值全局替换变量、失败就整步重跑。

要自建：

- 找回用的键：任务类型 + 页面类型 + 意图 + 页面特征。
- 提交、付款、发送、删除前，强制核对页面和参数，或请用户确认。

### 在我们代码里的落点与卡点

- 录制：`session.ts` 的 `observeProgramStep` 拿得到每个子步骤；`browser_run` 的程序本身就是可回放的单元。
- 执行：复用 `runBrowserProgram` 注入的 `call`，保留控制闸门、接管与执行身份。
- 不能存在诊断记录里：诊断记录脱敏、限长、只留 20 个会话、满了会丢。
- 卡点：
  - 没有“任务成功”的权威信号（产品有意不声明业务成功），要先定义什么算成功。
  - 记忆里现有规则写着“不要重放旧工作流”（`memory-runtime.ts`），要先对齐。
  - 程序遇错即停，中途失败会留下做了一半的副作用，交回时要带上已完成步骤。
  - 程序子步骤目前不写进诊断记录；每个动作有约 1 秒的光标动画和等待，回放 10 步会多出约 10 秒。

## Jev

- 是什么：TypeSafe 的小模型（`jev-1.13.0`），只做“从选项里挑一个”，不写字。Browser Use 用它做了开源演示库 jev-ultrafast（MIT，0.1.0，最后提交 09-18）。不是 Browser Use 主库的模式。
- 机制：DOM 脚本列出可见控件表；一次请求同时选动作和目标；只有要打字时才调另一个小模型写字；没有升级到大模型的机制；连续 3 步没变化就判卡住。
- 证据：只支持“每步更快”，不支持“更准”。
  - 厂商自测：一个任务 6 次，中位 9.45→7.09 秒；比较的是旧版对新版，不是对大模型。
  - 社区自测：每组 3 次，快 1.6–3.0 倍。
  - 没有找到独立的浏览器任务成功率测试。
- 限制：
  - 必须调用 TypeSafe 线上接口，需要它的密钥。
  - 不支持 iframe、上传、弹出标签页、shadow DOM。
  - 中日韩语言自注“不太可靠”。
  - 已知缺陷：同名字段的文字缓存不分（#191、#198），过期编号可能选中别的控件（#132）。
- 本项目历史：在扩展里一次都没跑通，一直报凭据不可用（[退役验收](../evals/20261001-retire-native-and-dead-code.md)）。

### 对照实验（待做，需要 TypeSafe 密钥）

- 做法：不接入产品。取多页、表单、中文页面任务的真实决策点，用我们现有的候选表，分别问 Jev 和当前主模型“下一步做什么”，比较一致率、单次耗时。
- 判负：在长页面、中文、同名控件、多步规划这类决策点上，与主模型一致率低于约 90%；或者算上必须保留的大模型兜底后，总轮数没有明显减少。
- 对照组：用我们已接入的小模型做同样的“选编号”，可能不必引入第三方接口。

## 浏览器路径代码检查：剩余项

已在本 PR 修：`browser_run` 返回不加不可信标记、截断不明说、说明自相矛盾、程序里的 `navigate` 不带页面内容。

剩下的，按价值排：

| 问题 | 后果 | 工作量 |
|---|---|---|
| 程序里被 try/catch 接住的只读失败也会终止整个程序（`browser-program.ts`） | 模型为可选元素写的容错白跑一轮 | 小 |
| 读过的页面快照一直留在上下文里 | 多页任务越往后输入越长 | 中（改历史会让缓存失效一次，先实验） |
| 页面 interactive 时就补读，前端渲染的页面可能只有骨架（推测） | 模型以为页面是空的 | 小 |
| 程序子步骤不写诊断记录 | 看不到子步骤耗时，回放也取不到数据 | 小 |
| 每个动作有约 1 秒的光标动画和等待 | 回放会被拖慢 | 小（给回放加跳过开关） |
| 工具清单约 2.9 万字，前四个工具占 36%；第 3 轮才命中缓存的原因未知 | 每次请求多读一万 token | 先查原因 |
| `createBrowserTools` 两处接线不一致，回退路径缺工具开关 | 走回退的会话没有开关闸门 | 中 |

速度上不值得改：每次重建工具定义只花 0.36 ms；程序每步宿主开销约 11 ms。
