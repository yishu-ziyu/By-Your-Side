# 开源对照：动作之后怎么确认、谁来说「完成」（2026-10-09）

来由：[复制后先核对](../evals/20261009-claim-after-check.md)。用户要求读源码、看懂结构，不只看介绍。六个项目各自浅克隆后只读不跑，逐个读主循环、动作结果、完成判定。版本：browser-use `c75e847`、Skyvern `94c7ee1`、Stagehand `2d605b0`、Playwright（MCP 实现在主仓库）、BrowserGym `e71419a` 与 AgentLab `8488c56`、axstream `0fa3e30`。

## 一句话结论

六个项目里，只有 Skyvern 的新版循环在产品里同时做到「填写后读回」和「没确认就不让宣布完成」。其余项目要么不读回，要么读回了却不拦住完成声明。我们这次要做的三件事（读回、扣住完成声明、只数适用的检查）都有现成的参照。

## 对照

| 项目 | 填写后读回 | 谁说「完成」 | 完成声明会不会先给用户 | 值得借 |
|---|---|---|---|---|
| browser-use | 有：输入后约 50 毫秒读回，不一致时在结果里写一句，但不算失败 | 模型自己（done 动作带 success），只有提示词里的检查清单 | 会：裁判模型在 done 之后才跑，而且不推翻模型的结论 | 在动作层读回；对上时也回报实际值 |
| Skyvern 旧版 | 只对卡号、电话、密码类读回，普通文本不读 | 模型说完成后，另一次模型调用拿新截图和网页核对，不通过就判这一步失败 | 不会：核对通过才标完成 | 完成之前单独核对 |
| Skyvern 新版 | 每次填写都读回，分五种：一样、格式不同、没留住、不一样、读不到 | 读回不一样或读不到时打「未确认」标记，排在后面的「完成」和「提交」不执行 | 不会 | 五种读回结果；未确认就扣住完成；核对模型只在有相反证据、并能逐字引出证据时才否决 |
| Stagehand | 产品不读回；它自己的测试在填写后读回 | 动作不报错就算成功 | 没有任务循环 | 测试框架里：程序检查只能把「通过」改成「不通过」；不适用的检查不进分母，查不了的算没通过 |
| Playwright MCP | 默认不读回；另有一个需要单独开启的核对工具，模型得自己想起来调用 | 没有完成判定 | 不涉及 | 元素引用失效时直接报错，不猜 |
| axstream | 不读回（输入只回「成功、耗时」） | 最后一个动作之后必须有一次检查且通过，才给「已验证」标记 | 拦不住模型说完成 | 「最后一个动作之后没检查过，就不算完成」 |
| BrowserGym / AgentLab | 不涉及（测试框架） | 每个任务有判分程序，看网页、后台数据或网络请求，不看助手怎么说 | 不涉及 | 测「假装成功」：能做成的任务上说做不到必须得 0 分；分数写成 k/n 加标准误差；结束、做对、出错分开记 |

## 用到了哪里

- 读回分五种、对不上时扣住完成声明、程序检查只能把通过改成不通过：并进[复制后先核对](../evals/20261009-claim-after-check.md)的 R1、R2。
- 不适用的检查不进分母、查不了的算没通过：并进同一文件的 R4。
- 成绩表（[底子](../evals/20261009-scoreboard-baseline.md)）以后可借：一个永远说「已完成」的假助手必须得 0 分，证明判分不被说法骗过；分数带误差；单独数「说做到了却没做到」。还没排期。

## 不借

- 每次完成都多调一次模型（Skyvern 旧版）：我们已有目标核对，只改它的位置。
- browser-use 那种跑在完成之后、又不改结论的裁判。
- 用识字（OCR）当判据（axstream）：我们能直接读网页里的值。
- Stagehand 的自动修复：它只在动作报错时重找元素，不核对结果。

## 没看到的

- Skyvern 的前端与流式显示没读，哪一版是默认引擎是推断。
- Stagehand 旧版的任务循环在没装的 npm 包里，没读。
- WorkArena 的判分程序不在克隆里。
