# 路线与决定

本页保留产品方向和放弃的方案。实际状态和当前任务只看 [STATUS](STATUS.md)。本页不构成自动开工的授权。

条目编号被其他文档引用（如“路线图第 9 条”），所以新决定只追加，旧条目不重新编号。

## 现在的形态与放弃的方案

- 产品只有扩展一种形态，用户自己安装扩展、自己连接模型（第 6、9 条）。
- 放弃了本机助手模式和 Jev，因为它们要另装本机程序。
- 放弃了 EverOS，因为它要另装 Python 服务，与“只装扩展”冲突（第 10 条）。
- 删除了技能复用（看演示学会做法、下次照做）和多会话协作（并行助手）的代码。接管和接手保留。技能复用以后是否重做，尚无新裁决。

## 方向决定

1. 产品目标是自然交流、可靠执行、越用越熟练。先解决反馈不足，再解决慢和理解错误。票组和局部指标不应遮住用户结果。
2. 日常语音用 Realtime 模型。网页操作复用现有的任务、页面控制和结果账本。
3. 先开放日常试用，由用户自己尝试陌生任务。这没有降低正式的质量与速度标准。
4. 文档不能误导开发。体验失败仍沿真实路径解决，不因文档整理结项而消失。
5. 产品要分发给他人，长期支持 macOS、Linux、Windows，先专攻 macOS。验收标准：在没有 Node、Pi CLI 和开发者代理的干净电脑上，用户能安装产品，在界面里连接模型，并完成第一次真实任务。
6. 产品形态只做扩展，任务核心搬进扩展。原因是“扩展＋配套应用”的安装、代码量和模型配置都偏重。
   - 界面分工为「侧栏是家，页面是现场」：结果先在原文旁指向；完整任务卡、中止与确认留在侧栏。
   - 密钥、记忆和其他标签页的内容不进入页面层；语音只在扩展里采集。
7. 目标用户是陌生人。**即时交互排第一位**：用户说一句，回应当场出现在用户当前看的页面上（圈画、原地翻译、划词追问）。替用户操作网页排在即时交互之后，可以先慢一些。语音是核心入口，不是可选附加。
   - 主路径：安装 → 连接模型 → 开口或选中 → 页面当场变化 → 看清做成没有 → 中途插话、改口、中止。排期看改动是否改善这条路径。
   - 先做错误分析，再定测什么：用户逐条看真实记录，写出第一处错误，归类计数，按频次决定下一步修什么。测什么不由开发者设想。
   - 语音稳定性是发布阻断项。换不换语音服务，由同一批用例的对比实验决定，不只修症状。
8. 记忆、主动性、任务感一起做。
   - 记忆记用户亲口说的个人资料（自动记、给撤销，网页内容一律不记）和过往任务。
   - 助手为了达成目标，直接去别的已登录网站操作；遇到登录、验证码、付款、发送、删除时，仍停下等用户。
   - 任务不随一轮结束；任务没做完时，用户随口补一句，算同一任务。
   - 同一条路径应在用户用的每家模型上都有像样的效果。
9. 本机助手模式退役，产品只剩扩展；只在本机模式可用的 Jev 和多会话协作随之退役。
10. 记忆与「越用越好用」是产品留住用户的核心，不再作为暂停项。
    - 错误分析时，专门标出「它要是记得就不会错」的地方，先做最痛的一处。
    - 「用户纠正 → 助手提出规则 → 用户确认 → 以后照做」做进扩展。
    - 「从经历里学习」在扩展自己的记忆上做，不靠 EverOS。
11. **能做的范围不设限，承诺的可靠程度分三档。** 每步都可能出错，多步时各步的成功率相乘；所以可靠程度由步数和结果能否当场核对决定。
    - **第一档 必须稳**：只读或一步、结果在当前页一眼可核对。例如读懂页面、划词提问、圈画、单步操作。
    - **第二档 应该做好**：多步但都在可见页面上、结果有明确对错，做完交给用户核对。例如提取成表格、填表不提交。
    - **第三档 陪着做**：步数多、结果难当场核对或撤不回。例如多页调研、整页翻译、提交、付款、发送、删除。这一档分段交付、在关键处停下给用户看，不承诺无人值守一次完成。
    - 判档看任务本身，不看类别名：一步点开属第一档，十步填完并提交属第三档。
    - 评测按档报通过率，不只报总分；排期先补第一档缺口。一般模型在各档都达标，才算产品本身合格。
12. **两条主线并列**（10-14）：即时交互，和“在用户登录的网站上替用户做完多步的事”。原因是用户一周的真实使用里（41 件），这一类等得最久：8 件，中位 116 秒，每件约 12 次来回；一半是第一个回答不完整，靠核对补齐。所以第 7 条“替用户操作网页可以先慢一些”不再适用于这一类。
    - 评测跟着主线：公开网站上的 24 个任务（[爬坡评测](evals/20261014-hillclimb.md)）当护栏，改动不能让它们变慢、变差；新增“补一句、改口”任务，量多久转过来、旧的有没有停下；已登录网站的任务不拿用户的账号自动跑，先用真实记录做错误分析，要不要测试账号以后再问用户。
    - 改法不限于提示词，也可以改工具和循环（爬坡评测 R4），因为目前测到的最大一次提速来自工具本身。

## 保留的产品主线

长期方向是四项：可靠执行与恢复、运行中纠正与接管、记忆、可核对的成果交付。这四项不是串行阶段：部分已有实现，部分缺验证。

首次使用、主动提醒、持续观察等未完成方向，不由本页自动启动。
