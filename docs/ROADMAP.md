# 路线与决定

本页保留产品方向及其修订依据；实际状态与当前任务只看 [STATUS](STATUS.md)。历史阶段不作为自动开工授权。

## 最近的方向决定

1. 自然交流、可靠执行、越用越熟练是产品目标。09-20 的讨论强调先解决反馈不足，再看慢和理解错误；不能让票组和局部指标遮住用户结果。
2. 日常语音使用 Realtime 3；浏览器操作复用现有任务、页面控制、授权与结果账本。Jev 作结构化判断，主模型处理开放式内容和核验；分工必须由实际任务验证。[方案与标准](evals/20260920-general-browser-contract.md)
3. 用户后来要求先开放日常试用，由自己尝试陌生任务；这修订了“完整评测通过后才开放试用”的先后顺序，没有降低正式质量与速度标准。[试用修订](evals/20260920-general-browser-trial.md)
4. 用户最新要求先整顿文档系统，避免过时材料误导开发；当前体验失败仍需沿真实路径解决，不因文档整理结项而消失。[当前状态](STATUS.md)
5. 09-23：产品要分发给他人，长期支持 macOS、Linux、Windows，先专攻 macOS。验收：在没有 Node、Pi CLI 和开发者代理的干净电脑上，用户能安装产品、在界面里配置模型并完成第一次真实任务。用户曾选"扩展＋配套应用、运行时随产品打包"，随后又对照 Sitegeist（只装扩展，开发者模式加载）提出质疑：安装、代码量和模型配置都偏重。形态和模型配置方式正在重新评估，未裁决前不迁移 Node/Pi 核心。
6. 09-24 裁决：产品形态只做扩展，把任务核心搬进扩展（先花一天试搬，并用双入口行为契约验收）。界面分工为「侧栏是家，页面是现场」：结果先在原文旁以小卡指向，完整任务卡、停止与确认留在侧栏；侧栏关闭时只在正在操作的标签页显示小胶囊，其他网页不出现。密钥、记忆和其他标签页的内容不进入页面层；语音只在扩展里采集。侧栏以任务卡为主还是以对话为主暂不决定，做出第一版后在真实使用中再定。

## 保留的产品主线

可靠执行与恢复、运行中纠正与接管、显式记忆与技能复用、可核对的成果交付仍是长期方向。这些不是严格串行的未开工阶段：部分已有实现，部分缺验证，不能继续把 09-17 的“P0 唯一核心开发”写成今天的全部安排。

首次使用、主动提醒、持续观察等未完成方向不由本页自动启动。旧提案、候选参数、被推翻方案见[整理前路线图](history/20260920-roadmap-snapshot.md)，具体历史证据仍保留原链接。
