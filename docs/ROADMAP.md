# By-Your-Side 路线图

更新：2026-09-07。当前集成分支：`fix/takeover-handoff-closure`。

## 方向与本轮决定

目标不是功能齐全的侧栏工具箱，而是在同一个真实浏览器里长期共处、可纠正、可接管、能接续工作的伙伴。

用户已提出的方向：自然且长周期的交互；会话管理；单次示范学习与多次行为学习；长期记忆；语音输入/输出；更可靠自然的点击与圈画；截图直接进入会话和拖拽图片。**本轮已明确的执行顺序：先排查并修复现有 bug，提高已有能力的可靠性，再开发新能力。**

下面的产品扩展是 ChatGPT 提出的待讨论建议，不代表用户已逐项批准，也不是让 Coding Agent 全量实现的任务单。技术选型、阈值与具体界面须经实验/评审后再定。

## 产品判断：怎样才算越来越像一个伙伴

少要求用户重新交代，但不要自作主张。衡量“记得住”不是记录条数，而是同类工作里重复解释、重复操作和接管纠正是否减少，同时误操作与打扰是否没有增加。

- **连续，而非无限聊天。** 离开后保留目标与进度；回来只交代变化、阻塞和下一步，不要求重读全部聊天。会话、任务、记忆、技能分别管理，模型上下文可压缩，但任务事实不能跟着消失。
- **共同注意，而非同时播放。** 文字、声音、截图、选区、圈画和真正点击共享一个目标。用户说“不是这个，下面那个”时，系统能定位并修正，而不只是识别文字。
- **学习纠正，而非只统计频率。** 用户接管改正一次，是理解偏差的线索；先区分“这次例外”和“以后如此”，不把偶然行为变成永久偏好。
- **主动有分寸。** 值得提醒时提醒，专注时安静；沉默也可以是合适的产品行为。学习建议、主动建议与自动执行的权限分开，不能因为学会了就默认获准执行。
- **可信、可检查、可遗忘。** 状态来自真实执行；记忆能追溯来源、纠正、设定范围并删除；操作有结果收据。只有确实可逆的动作才能提供撤销，不能假承诺“任何操作都能回滚”。

## 1. 连续工作的底座（方向已提出，方案待定）

### 会话与任务分开

会话保存交流；任务保存目标、进度、产物、待确认项和 Lead/worker 关联。新建、最近、重命名、搜索、归档是会话入口，不应演化成沉重的项目管理面板。

优先核对仓库锁定版本的 Pi 持久会话能力，复用已有运行时；产品只补自己的任务、附件和权限语义。恢复记录不等于自动恢复执行：重新核对页面/账号/目标、已发生外部操作与权限，防止重复发送、重复写入。

**新增建议：回来时的接续摘要。** 显示“已做什么、离开后变了什么、卡在哪、下一步是什么”，按需展开历史。成功体验是用户无需重讲背景，而不是 UI 多出聊天历史。

### 多模态上下文入口

扩展内框选截图完成后直接成为附件；外部文件拖入即预览，可撤销、删除、重试。必须把图送到支持视觉的模型并持久关联消息，不止做到前端缩略图。

扩展截图可携带来源页/时间/选区；外部图没有来源就不猜。旧图中的按钮不直接当成当前页可点击目标。系统截图浮动缩略图是否可直接拖入属于目标操作系统/Chrome 的兼容性实验，尚不承诺。

**新增建议：上下文收件区。** 文字、截图、链接和网页选区形成一次请求的材料组，用户可以看见 Agent 将使用哪些材料，并在发送前移除错页或敏感内容；先验证简单附件托盘，不默认建庞大知识库。

## 2. 学得会：从明确示范与纠正开始（待实验）

### 单次示范

“看我做”→明确录制范围→用户示范→Agent 复述目标与规则→用户修正→换材料验证→保存技能候选/发布版本。

技能表达目标、可变输入、前置条件、步骤、完成验证、权限与失败退出，而不只保存坐标。看过一次不等于普遍掌握；首个试点至少包含不同材料的迁移验证。流程稳定的部分再逐步确定性执行，不承诺一录制就能零模型重放。

### 接管纠正学习（新增建议）

比较 Agent 原意图与用户接管后的结果；只在值得确认时问“这次例外，还是以后如此”。一次性指令、任务约束、站点习惯和长期偏好分别存放。不得把 Agent 自己的行为误学成用户习惯。

### 技能草稿、试用与回退（新增建议）

自动提炼先进入草稿；解释来自哪次示范。范围内验证后启用，失败可退回上一版本或请求协助。学到的做法与获准执行的权限分开；涉及外部写入时重新核对当下授权。

候选里程碑：教会一次→关闭并重新进入会话→换一份材料调用→中途纠正→正确区分例外与规则。通过后才扩大采集规模。

## 3. 记得准：长期记忆与选择性观察（待讨论、后于治理）

记忆需要来源、适用项目/站点/账号、时间、置信程度与修订记录。明确表达与系统推断分开；用户可查看、纠正、关闭和删除，派生记忆应关联证据，删除时处理关联影响。站点内容视为不可信资料，不能自行升级为用户偏好或系统权限。

长周期学习从用户明确允许的范围开始：事件记录→工作片段摘要→规律候选→用户/任务验证→可使用记忆。采集本地与发往模型的数据边界分别说明；私密区域与未授权站点不采集，保留期限和暂停入口先于持续捕获。

**新增建议：承诺记忆。** 比“你经常访问什么”更重要的是“上次约定了什么、哪些事情还没做完”。跨日保留未完成目标与待用户决策项；主动提醒是另行授权的能力，不凭一次对话悄悄启动。

**新增建议：情境切换与遗忘。** 工作项目/账号切换时避免串用记忆；临时规则按任务到期；证据冲突时询问或保守降级，不为拟人化而假装一直记得、一直确定。

## 4. 说得自然、指得准确（共享上下文之后可与学习试点并行）

语音输入与流式输出、中文指代、打断和工具执行共享现有任务与控制权，不新增一套与 Pi 竞争的执行大脑。比较语音识别→现有 Agent→语音合成，与实时语音前端→现有执行系统两条路线，再选型。

停嘴与停手分开。一般插话先停止播报；“我来/停手”走真实接管闸门。系统确认后才宣告停手；危险操作仍需当下明确授权。麦克风状态可见，默认不做永久监听。

现有点击/圈画的 bug 在阶段 0 修；体验升级再分别评估：定位是否准确、框/按钮是否跟随目标、动作节奏是否拖沓。点击、标注和语音指代复用目标引用；失效就重定位，不在旧坐标继续动作。可复用定位/浮层/动画组件须先验证与当前 CDP、页面注入和控制权的兼容性。

**新增建议：低打扰的协作反馈。** 普通动作安静执行；关键步骤短句解释并指向目标；不确定时停在具体对象上提问。语音不逐字朗读工具日志，小精灵/光标不以持续运动制造“活着”的错觉。

## 5. 有分寸的主动性（后置探索）

主动建议必须回答“为何此刻、依据是什么、能节省什么、现在打断是否值得”。建议可以延后收进摘要，不连续弹窗。频率上限、静默时段和关闭入口需要产品验证，不能只优化建议点击率。

**新增建议：操作预览与结果收据。** 批量写入前展示对象与差异；完成后保留实际改变与核验结果。失败后说明哪些已发生、哪些没发生，而不让用户凭聊天猜测。可逆操作才考虑撤销/补偿。

页面哨兵、触发器和自动执行，必须先有可解释授权、失败处理、可停止的任务生命周期与稳定性证据。轨迹回放继续低优先级；“视觉回放”不等于撤销或技能学习。

## 选型与评估约束

先复用本仓库 Pi、协议与验收工具；外部技能格式、录制工具、实时语音和定位库只作为候选，不因流行就引入。每次选型记录具体版本、许可证、与扩展/本地进程的边界、成本与一条真实路径的对照结果；未经验证不写“已接入”。

优先观测：真实任务完成率、误写/重复操作、接管后写入次数、恢复失败、重复解释/纠正次数、示范迁移成功率、记忆误用与建议打扰。先采基线再定改进阈值；不以消息数、token 数或录制时长当产品价值。
