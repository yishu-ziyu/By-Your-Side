# 当前状态

自用的 Chrome 扩展开发预览版。只写能力现状、仍需解决和下一步；装了什么看提交记录。

## 现在能用什么、还差什么

| 能力 | 现在 | 还差 |
|---|---|---|
| 侧栏对话与卡片 | 保留上下文；材料可批量移出、撤销；比价重算与回页、追问表单、结构图出处、拖短回答、章节条、另开任务带回回答；小程序默认关 | 当前页自动带入；真网页选区、部分卡片待试用 |
| 读页与阅读卡 | 大页面与屏幕上的 PDF（含文字、目录页码与 `#page=N` 翻页）能直接读出；表单包裹正文的页面（如对话网站）自动回退提取完整正文；划词解释写到一半可改口；阅读卡可拖、可缩放，尺寸记住 | 阅读卡不查证、不用记忆；PDF 偶发未翻页就列作者或主要引用找不准 |
| 网页操作 | 点击、填写、回车直接执行（见[网页操作](web-actions.md)）；新开页与跳转直接带回内容，结果页留在后台并提供「切过去看」；自动站点笔记已暂停，旧记录可管理；富文本编辑器支持子块定向修改与 `ClipboardEvent('paste')` 粘贴回退，掩码输入框同值重填不再重复触发重试；跨页原样搬文字不经模型重打，可只搬指定的句或段；发送前在网页与侧栏双重确认（覆盖点击和多行回车；页面脚本只读），拒绝后保留草稿并提供重试入口；付款按钮永远由用户自己点；填写结果按字段列出并支持一键还原未改动的标准控件 | 画板（Canvas）无 DOM/无障碍节点，感知与核验受限；跨域 iframe 圈选、无发送语义的控件仍有边界；真实网站批准后实际发送待真人验；超 1 MB 的网页请求无法核对会停发（用户已接受） |
| 跑完后的核对与持久化 | 回答先显示，过程行写「核对中…」后更新为「已核对页面」或「有 N 步没做成」；常规核对只调 1 次模型，多目标补读并行执行，续做上限收敛为 3 轮，同一证据不重复续做（见[目标核对](goal-check.md)）；核心循环基于 `pi-durable` + OPFS Worker 原地追加，宿主重启后等用户手动继续，重新读原页后做剩余步骤 | 语音念结果不等核对；回答中文名字未读到原文的核对尚未覆盖 |
| 圈画与教学 | 能把每一处词单独圈出，被标签拆开的词也圈得到；教学一次一步指给用户看，等用户自己点 | 圈过后刷新再点旧名称仍会发操作指令；真人未试教学 |
| 记忆与浏览习惯 | 个人资料原话直记可撤销；明确的网站操作纠正自动记、可删除；默认从用户自己的浏览记录里发现连续 2 天重复的操作并询问是否记为做法（见[记忆模型](memory-model.md)）；教过「说 X 就开这些网址」后说 X 约 0.3 秒并行开好 | 真人长期试用待验；删除规则不清除对话、过往任务或站点笔记 |
| 整页翻译 | ⌥T、侧栏「文A」、右边缘入口不经助手直接翻；一屏先译，由近及远译完；风格可选；同页再翻不用等 | 译文只记到浏览器关掉；说出来的那条路离 2 秒首屏还差；中途插话改网页会让译文写不进 |

| 模型与备用切换 | 模型菜单用离散滑块选档位并显示自动升档后的实际档位；设了备用模型时主模型首次出错换它接着做（日常还没设）；同一批 11 个真实网站任务上 `gpt-6-luna`、`MiniMax`、`Kimi` 均 11/11 通过 | 30 条日常错误分析中排第一的是模型服务卡住未触发备用切换（4 条中 2 条）；跨页搬运时 `gpt-6-luna` 仍偶发重打 |
| 语音 | 读文章时按住右 ⌥ 问选中的段落，光标停在这段末尾听，回答在同一处的阅读卡里边写边念，念到一半可改口，换段问时同一张卡里各轮保留各自的出处；语音发起的任务等核对完再念；语音模型没交给助手的话由宿主再判一次；长任务念过程；「记下来」写 flomo 和记忆；去别的网站查时原文留着；插话即停声；按住右 `⌥` 说话，松开先应一句短确认，做完在胶囊上方显示精简卡片；GPT-Live 切页同步窗口标题与站点、带最近话题指代、长回答只读开头、后台忙时换连接不挂断通话（见[语音架构](voice-architecture.md)） | 10-28 播报连接提前准备已装日常，加载代码已核对；固定正文五组对照，播报启动中位 1.13→0.48 秒，整轮 P95 与真人外放未验。旧版、新版完整用例均 19/20，flomo 识别错误未修；[验证范围](evals/20261028-speech-connection.md)。「去别的网站查」常只去英文维基；阶跃边生成边念的部分不等核对；阶跃实时语音傍晚常挂住；MiniMax 意图判断约一成调用 15 秒内不回；连续改口与外放回声未完整验收 |
| 实验功能 | 「持续关注网页」默认关闭；做成的只读任务可存成 / 菜单里的直接运行技能（仅原网站） | 持续关注受控页通过、实站仍失败（[验收](evals/20261029-continuous-delegation.md)）；技能提速未测（[验收](evals/20261027-learned-operations.md)） |

## 速度与启动表现

| 情况 | 当前实测 | 目标 |
|---|---|---|
| 点进输入框预热后，按下回车到发出首个模型请求前的页面采集（`pre_observation`） | 约 24 ms（未预热日常中位 370 ms） | 越低越好 |
| 问当前网页一个简单问题，到第一个字 | `gpt-6-luna` 命中会话前缀缓存后中位 2.6 秒，超 4 秒占 6/50 | 3 秒 |
| 做一个单步网页动作，到做完 | 单次键盘填表含读回中位 115 ms；端到端受模型单轮耗时影响 | 10 秒 |

- 给模型的网页内容里带元素清单会让阶跃答错。

## 能用的模型

日常主模型 `MiniMax-M3.1-Flash-Preview`，快速模型 `openai-codex/gpt-6-luna`。设置页「模型」可点「测一下」。

- 不再用：OpenCode Go（订阅到期）、小米 MiMo 自家套餐、DeepSeek（密钥失效）、智谱 GLM（余额用完）。
- Kimi 编程套餐同一时间只收 1 个请求，扩展已排队；评测用的 Kimi 登录每次有效约 15 分钟，由 `npm run kimi:keep` 后台续期。

## 仍需解决

- 去掉批准卡后，网页里的恶意内容可能让助手在已登录的网站上动手（见[网页操作不再逐次确认](web-actions.md#网页操作不再逐次确认)）。近期仅自用，分发给他人前必须先做防护。
- 页面脚本仍能读到卡号、密码这类敏感栏的值。

0. 语音入口合并（用户 10-30 定）：一个入口，设置里选「按住说 / 一直听」，听和念用同一家服务，登录和密钥都能连。第 1 步按键跨平台已完成，正在做第 2 步：按住说话改用所选语音服务。
