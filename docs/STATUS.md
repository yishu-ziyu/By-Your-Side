## 现在能用什么、还差什么

| 能力 | 现在 | 还差 |
|---|---|---|
| 侧栏对话 | 回答逐字淡入；输入 @ 带上别的标签页；比价、选择、步骤、清单画成卡片，数由侧栏算，按钮能接着说或切页；回答先显示，目标核对在后面运行；核对判没做完时屏幕上仍只有一份回答；写完后能拖短成要点或一句，不再问模型 | 交给你、中止时任务栏、续做卡、团队卡仍各说一遍 |
| 读页与阅读卡 | 大页面能读完；划词解释，写到一半可以改口 | 阅读卡不能查证、不用记忆 |
| 网页操作 | 点击、填写、回车直接执行；新开页、跳转后直接带回页面内容，结果页留在后台，回答下给「切过去看」（见[真实网站对比](evals/20261013-real-sites-vs-ego.md)）；同一网站第二次带上上次做成的做法（[站点笔记](evals/20261013-site-notes.md)）；发送先问用户，付款由用户自己点；填表后、提交前能还原助手填过的格子，用户后来改过的不动 | iframe 里的按钮、页面脚本直接点击都不拦 |
| 跑完后的核对 | 回答先显示，过程行写「核对中…」，出结论后改成「已核对页面」或「有 N 步没做成」，判做完时不再出「继续原任务」；做错时说“核对发现：…正在改” | 语音念结果不等核对 |
| 圈画与教学 | 能把每一处词单独圈出；能一步一步指给用户看，等用户自己点 | 被标签断开的词圈不到；真人没试过教学 |
| 记忆 | 纠正后点“记住”，在该网站照做，可撤销；过往任务只记做成的事 | 待真人试用 |
| 整页翻译 | 一屏先译出第一段，再译完整屏 | 离 2 秒目标还差 |
| 下载 | 点击引起的下载会告诉助手，所以不再重复导出 | 助手读不到已下载文件的内容；要产品决定 |
| 备用模型 | 主模型卡住或暂时出错时换备用模型接着做 | 换模型后的完整交付没测过 |
| 语音 | 插话即停声；按住说话，松开后先应一句，做完把回答里的卡片显示在胶囊上方；免按键可选 GPT-Live | 阶跃实时语音傍晚常挂住；外放回声没验 |

## 能用的模型

日常配置：主模型 Kimi kimi-for-coding，快速模型 gpt-6-luna，没有备用模型。设置页「模型」一栏点「测一下」就能重测。

- 不再用：OpenCode Go（订阅到期）、小米 MiMo、DeepSeek（账号的密钥失效）、智谱 GLM（余额用完）。OpenCode Go 和智谱还连在日常扩展里，建议删掉。
- 同一个模型每次快慢差好几秒，所以单次数字只看大概。

## 仍需解决

- 去掉批准卡后，网页里的恶意内容可以让助手在已登录的网站上动手（[说明](browser-confirmation.md)）。用户决定近期只自用，给别人用之前必须先做防护。
- 页面脚本仍能读到卡号、密码这类栏的值。

## 下一步

10-13 起，产品好不好用以真模型、真网站、有窗口的浏览器为准；用户的日常使用记录用 `npm run logs` 读。


1. 减少模型来回的次数：插话评测（eval/duplex-v0 分支）量出改口的时间几乎全花在模型来回上；真实必应搜索里模型找搜索框也来回了好几轮。
2. 核对 Kimi 的同时请求上限：任务里主请求和后台判断同时发给 Kimi 时，会不会被拒（测速时几个 Kimi 模型同时发，后面的被拒过）。
3. 决定助手要不要读已下载文件的内容。
4. 做“快捷指令”（[路线图](ROADMAP.md)第 14 条）：存法、用法用户已定，侧栏预览给用户看过；先用这两天的新记录挑最先学的几件事，再写验收文件。
