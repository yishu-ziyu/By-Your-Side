## 现在能用什么、还差什么

| 能力 | 现在 | 还差 |
|---|---|---|
| 侧栏对话 | 回答逐字出现；回答先显示，目标核对在后面运行 | 同一对话多轮后侧栏变乱，原因待查 |
| 读页与阅读卡 | 大页面能读完；划词解释，写到一半可以改口 | 阅读卡不能查证、不用记忆 |
| 网页操作 | 点击、填写、回车直接执行；助手自己新开的后台页也能一次点中（10-13 修，以前点了没反应）；网页脚本等到内容出来就往下走，不等图片；发送先问用户，付款由用户自己点 | iframe 里的按钮、页面脚本直接点击都不拦；真实网站上模型找元素要来回好几轮 |
| 跑完后的核对 | 会动网页的一轮，等核对出结论再显示回答；做错时说“核对发现：…正在改” | 语音念结果不等核对 |
| 圈画与教学 | 能把每一处词单独圈出；能一步一步指给用户看，等用户自己点 | 被标签断开的词圈不到；真人没试过教学 |
| 记忆 | 纠正后点“记住”，在该网站照做，可撤销；过往任务只记做成的事 | 待真人试用 |
| 整页翻译 | 一屏第一段约 4.5 秒变中文，一屏译完约 12 秒 | 离 2 秒目标还差 |
| 下载 | 点击引起的下载会告诉助手，所以不再重复导出 | 助手读不到已下载文件的内容；要产品决定 |
| 备用模型 | 主模型卡住或暂时出错时换备用模型接着做 | 换模型后的完整交付没测过 |
| 语音 | 插话约 0.25 秒停声；按住说话；免按键可选 GPT-Live | 阶跃实时语音傍晚常挂住；外放回声没验 |

## 速度基线（10-12）

| 情况 | 现在 | 目标 |
|---|---|---|
| 问当前网页一个简单问题，到第一个字 | 约 6.7 秒（step-5-preview） | 3 秒 |
| 做一个单步网页动作，到做完 | 约 11.6 秒 | 10 秒 |

这两项是用阶跃测的，不是日常的 Kimi。把同一份网页问题直接发给模型（不经过侧栏）也要 6–8 秒，去掉元素清单或只发相关几行都没有稳定变快，所以第一个问题慢主要在模型；但元素清单会让阶跃答错。

## 下一步

10-13 起，产品好不好用以真模型、真网站、有窗口的浏览器为准；用户的日常使用记录用 `npm run logs` 读。


1. 减少模型来回的次数：插话评测（eval/duplex-v0 分支）量出改口中位 7 秒，几乎全花在模型来回 2–3 轮；真实必应搜索里模型找搜索框也来回了 4 轮。
