## 当前工作

已修复语音问候重复回应与文字先到时丢音：正式答案只播一次，闲聊不自动读页，空白候选不会吞掉等待中的答案。已重载日常扩展，合成问候经真实 native host 验证一次回答、有音频、无读页/任务确认/页面介绍；1,662 单测、类型与依赖检查通过。真人麦克风待用户验收，监控继续暂停。延迟及测试中出现的服务/工具失败见[修复验收](evals/20260913-voice-greeting-fix.md)。

已量清语音首声等待：说一句话到听见第一声实测 4.9–7.7 秒，其中**两段串行的模型往返占 5.2 秒**（意图分类 1.7–2.7s、主 Agent 首字 2.5s）。三条本地优化路径都用真实调用验过并被数据否决：分类耗时≈供应商下限（削提示词、加 reasoning 都无效）、池内更快的模型不是更慢就是判断出错、TTS 提前建连只值 270ms。见[首声验收](evals/20260913-voice-first-audio-latency.md)。

首声已改善并提交推送：**闲聊、寒暄、算数改走一条独立的最小请求直接出正文**，其余（控制、页面问答、依赖事实的问询、动手委托）走与改前逐字同形的分类请求加既有派发。实测问候 6.8→3.8 秒、7.0→2.8 秒，算数 5.4→3.4 秒，reply 分支 9 个样本中位 **3432ms**（该口径不含脚本先送的 500ms 静音与真人停句时间，≤4 秒须以真人路径实测为准，不能引用合成口径宣布）；控制句首次实测 3.3 秒。**页面问答与基线持平（5.2–6.4 秒），未达成 ≤5 秒线**，按不达成记录，待裁决。防编事实改为失败关闭：由程序判定整句是否属于无事实类别，不依赖模型自律。首声目标由 ≤2 秒修订为 ≤4 秒（2.8 秒是链路地板，用户已同意）。外部复核指出的两点代码事实（`sendUserMessage()` 提前改状态、未执行的交付参数会被提前发成交付流）已核对属实，并行方案据此降级为备选。见[合并验收](evals/20260914-voice-single-proposal.md)。

用户已认可宋体、回答层次及设置方案。已实现阅读外观并重载本地扩展，原生验证保存、重开、恢复默认及实际长短回答。普通单测通过，规模检查复跑仍超时，原因未定位；不宣称全套检查通过。见[阅读外观验收](evals/20260913-reading-settings.md)及[使用说明](reading-appearance.md)。

仓库可维护性整理已完成并重载验证：模型选择器、无工具语音模型调用独立成模块；Node授权账本归回Agent；生产依赖方向加入自动检查。统一check通过（1598普通+2规模）；最后绝对路径反例补充后13项边界与类型检查通过。模型菜单和正常消息原生通过。检查与原生验证见[本轮验收](evals/20260913-repository-maintainability.md)。开发入口见[架构与维护](architecture.md)。
