# 记忆模型

2026-10-01 用户定稿（[路线图](ROADMAP.md)第 10 条）。本页定义记什么、记成哪种、用到哪里、到什么时候；已实现的接口与存储以[记忆与任务跨轮](memory-and-tasks.md)为准。每条标注现状：**已有** / **待做（第 N 块）**，块的进度见[当前状态](STATUS.md)。调研依据与方案页见 [10-01 记忆方案](previews/20261001-memory-model.html)。

## 每条记忆回答两个问题

| | 长期有效 | 有时间或条件 |
|---|---|---|
| 到处适用 | 邮箱、生日、爱吃辣、「回复我用中文」 | 「10 月 3 日飞成都」：行程结束前订酒店、叫车都用得上，结束后不再主动带 |
| 只在某处适用 | 「这个客户系统导出要选全部」 | 「这次报销要附发票」：只对这一件事 |

现状：只有「到处 / 某网站」范围（**已有**）；没有有效期（**待做（第一块）**）。

## 四种记忆

| 种类 | 例子 | 谁记 | 存哪 | 怎么带给助手 | 到什么时候 | 现状 |
|---|---|---|---|---|---|---|
| ① 这件事的要求 | 「不对，我要的是 3 号的航班」「只看京东自营」 | 自动 | 这次对话 | 这次任务每一步都在 | 任务结束；内容转进 ② | 已有（对话上下文与任务账本） |
| ② 做过的事 | 「10/3 在携程订了北京→成都，东航」 | 自动，任务结束时 | 本机扩展数据库 | 有效期内主动带（当前网站最近几条 + 有效期内的行程类）；过期后只在用户问起或助手查时出现 | 带日期与有效期，过期改为过去时，仍可查 | 摘要已有（最多 200 条，当前网站最近 3 条）；日期与有效期待做（第一块） |
| ③ 关于你 | 邮箱、生日、「坐飞机要靠过道」 | 用户原话说出 → 直接记，给「撤销」；助手推断的 → 先问用户 | 本机扩展数据库 | 每次都带（有上限） | 长期；被新值替换时旧的标为「被替换」留历史 | 原话自动记已有；「被替换」与「推断先问」待做 |
| ④ 做事的方法 | 「这个客户系统导出要选全部」「别每次下单前都让我确认」 | 用户纠正后助手总结 → 出卡片，用户点「记住」才生效 | 本机扩展数据库 | 网站操作类在该网站带；关于助手做事方式的到处带 | 长期；在该网站反复失败时提示可能过时 | 待做（第二块），总结部件已有但只在已退役的本机模式里接过 |

## 一句话记成哪种（按顺序，先命中先停）

1. 来自网页、附件、工具输出的文字 → 不记。
2. 密码、验证码、证件号、银行卡 → 不记，原话也不进任何记录。
3. 用户明说「记住 / 以后都 / 忘掉」→ 照办，并告诉用户记在哪个范围。
4. 改这次任务的参数 → 只改 ①；任务结束后进 ②，带日期。
5. 用户原话说出的长期事实或偏好 → ③，直接记，给「撤销」。
6. 助手从行为里推断的规律（如连续几次选靠过道）→ 先问用户一次再记 ③。
7. 用户纠正助手的做法 → 助手总结成一条 ④，出卡片，用户确认。
8. 其余 → 只进 ②。

原则：**记下的内容就是用户原话 → 直接记并可撤销；需要助手归纳或推断 → 先问用户。** 这解释了已有两个决定为何不同：资料自动记（原话），纠正规则要确认（归纳）。

## 默认范围

| 种类 | 默认 | 例子 |
|---|---|---|
| ③ 关于你 | 到处 | 邮箱、生日 |
| ④ 关于助手做事方式的纠正 | 到处 | 「回复我用中文」 |
| ④ 关于某网站操作的纠正 | 该网站 | 「这个客户系统导出要选全部」 |
| ② 做过的事 | 按有效期 | 「10/3 飞成都」行程结束前主动带 |

卡片上都可改。网站相关默认收窄，因为模型容易把某处的偏好当成到处都要照做（BenchPreS，2026-03）。

## 每次干活前带哪些

1. **总是带**：③、到处适用的 ④、有效期内的 ②；各设上限。
2. **按网站带**：当前网址精确匹配的 ④ 与该网站最近几条 ②。
3. **需要才查**：更早的 ② 与其他网站的 ④，由助手用「查记忆」查，侧栏显示「查了记忆」（待做）。

暂不用语义向量检索：几百条规模下网址精确匹配更准、说得清为什么带。

## 每条记忆存什么

种类、内容、范围、有效期（开始、结束或「随这件事」）、来源原话、创建与修改时间、用过几次与上次用上、状态（生效 / 被替换 / 失效）、格式版本号。现状：内容、范围、来源对话、时间、版本已有；其余待做（第一块）。扩展申请「不限存储」权限（待做）；导出 / 导入在纠正卡片之后紧接着做。

## 怎么检查

| 看什么 | 检查 |
|---|---|
| 记成哪种判得对不对 | 从用户真实记录抽样，人工标「该记成哪种 / 不记」，数判对多少；重点数「一次性的事被记成长期」 |
| 用得对不对 | 该用时用上、不该用时不用；过了有效期不再主动出现；每次多带多少字 |
| 用户感受 | 同一句纠正要说几遍；用户删掉记忆的次数 |

具体场景：纠正卡片见 [20261001 记住我的纠正](evals/20261001-remember-corrections.md)；底座场景随第一块验收文件补充。
