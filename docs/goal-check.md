## 规则

Lead 会话的一轮正常结束时，如果本任务用过工具，或最后在问用户，任务宿主先交付回答并回到空闲。然后，任务宿主用快速模型核对结果是否满足用户要求。目标核对不拖住回答：此前交付要等目标核对，中位多等 2.2 秒、最长 12 秒。目标核对期间，用户中止、接管、插话或另发任务时，这次目标核对作废。读页问答也做目标核对，纯聊天不做。

目标核对同时检查回答与文本文件：数字、日期、合计、计数口径、来源与数据日期，以及用户明确要求的数量、格式和逐项来源。文件存在不单独作为完成依据。

完整 CSV 的合计行能无歧义相加时，由程序直接检查；有小计、平均、比例或非整数时不推断加法关系。程序发现的明确合计差异不能被模型的 `done` 覆盖。

目标核对的输入有容量上限。容量不足时，优先取最新内容，并标明裁断；看不到必要部分时不能凭文件名断言正确。图片不送原图；工具结果与文件文本先遮掉凭据信息。

目标核对发现具体错误时，任务宿主把诊断作为数据交回主模型。任务宿主要求主模型对照来源修正回答及已有文件，并向用户说明纠正。诊断不新增动作授权。续做次数有上限；超过上限后，未解决项留给用户。流式显示不变；纠正后有新回答，不代表错误草稿未曾出现。

结论分「完成 / 等用户 / 继续 / 受阻」：

- 继续：任务宿主等会话空闲后，发一轮看得见的后续，带上用户原话和本任务已失败的做法。这一轮要求换做法，并保留用户设的条件和安全规则。
- 受阻：做不成的原因在助手和用户之外（网站连不上、页面或数据不存在、服务端拒绝），且回答已说明。任务宿主不催续做、不升思考档，按部分完成结束任务，并把原因写成人话。
- 最后一轮回答在问用户时，「继续」改按「等用户」处理；「受阻」不改判。
- 其余结论只更新「还差…」那一行。

任务条据结论写「等你：…」「还差：…」或「没做成：<原因>」，做完不留。目标核对失败时，只留诊断记录。侧栏停下/结束那行按「核对的还差 → 模型列的未完成 → 计划目标」取，没经过目标核对的计划目标写「还没确认完成」。验收见[回答自检](evals/20261002-answer-selfcheck.md)。
