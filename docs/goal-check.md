# 目标核对

本页是目标核对的唯一说明：为什么这样做、用户看到什么、还差什么。

## 什么时候做

- 一轮正常结束时，任务宿主先交付回答，再做目标核对。因为交付等目标核对时，用户要多等几秒。
- 侧栏马上显示回答，过程行写「核对中…」，核对出结论后改成「已核对页面」或「有 N 步没做成」。完成情况只在过程行说一次（#334）：
  以前回答末尾补「还有没做完」、下面再出「继续原任务」卡片，事情做对了也这样显示，用户分不清到底做没做完。
- 核对判做完时，结果未知或受阻的那一步只在展开的过程里标「没做成」，不再出卡片；发送类动作另有发送前确认把关。
  核对判「没做完」时出「继续原任务」卡片。核对没有结论时，只有宿主账本认为没做完，过程行才写「有 N 步没做成」。
- 读回的内容和要写的对不上时，核对判「完成」也只按「结果还没确认」显示，因为代码看到的事实只能把通过改成不通过。
- 例外：用户这次说了不止一件事（任务进行中插过话，或原话是编号列表）时，回答扣到核对之后才出，最多等 6 秒。
  没做完就不出这份回答，过程行写「还在做第 N 件（共 M 件）」，接着做。因为用户多次遇到先出一个像做完的回答再更正（[验收](evals/20261014-goal-gate.md)）。
- 纯聊天不做目标核对。
- 目标核对期间，用户中止、接管、插话或另发任务时，这次目标核对作废。

## 查什么

- 文件存在本身不算完成。
- 回答说「没找到」时，看助手是怎么找的。只按用户的原话找过，就判「继续」，提示换同义词、换语言或用网站自己的搜索。因为网站上常有词条换个字就查得到。
- 用户要「每处」「每个」「全部」时，更粗的结果不算完成，比如整段圈起来代替逐词圈。
- 程序能算出的合计差异，模型的结论不能推翻。程序不猜小计、平均或比例的加法关系。
- 看不到必要部分时，目标核对不凭文件名断言正确。
- 回答列出的西文名字过半在这次读到的全文里找不到时，宿主把这些名字交给核对。用户问的是页面或文件里写了什么时，判「继续」，要助手读到名字所在那部分再答；产品名、地名、用户要的推荐不受影响，所以由核对模型判断，宿主不直接拦。
  因为核对只看得到截断后的读数：PDF 只读了前几页，作者在第 87 页，助手照样列出 25 个名字，核对判了做完。中文名字还查不到。

## 发现错误后

- 诊断不新增动作授权。
- 任务宿主催过一次续做以后，助手又说做不成，而且网页和催之前一样，任务宿主就不再催，未解决项留给用户。
  网页一样不一样由任务宿主比较，不听模型的说法。因为空白画板上助手曾被连催多次，侧栏留下几段几乎一样的「没能完成…」。
- 改过网页的一轮判「继续」时，回答位置写「核对发现：…。正在改…」。
  「核对发现」后面是目标核对单独写给用户的一句诊断，不带指令。因为写给主模型的诊断带「请改为…」这类指令，从里面挑句子给用户看会漏出指令。
- 已显示的文字不会撤回。

## 四种结论

用户在任务条上看到：

- 完成：不留任务条。
- 等用户：「等你：…」。
- 继续：「还差：…」。会话空闲后，任务宿主发一轮看得见的后续，要求换做法，并保留用户设的条件和安全规则。
- 受阻：「没做成：<原因>」，原因写成人话。原因在助手和用户之外（网站连不上、页面不存在、服务端拒绝，或者换过做法后按钮仍没反应），所以任务宿主不催续做、不升思考档。

没经过目标核对的计划目标，侧栏写「还没确认完成」。
