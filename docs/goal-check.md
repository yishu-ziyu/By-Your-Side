# 目标核对

本页只写代码里看不出的理由和还差什么。

- 先交付回答再核对：交付等核对时，用户要多等几秒。
- 完成情况只在过程行说一次：回答末尾补「还有没做完」、下面再出「继续原任务」卡片时，事情做对了也这样显示，用户分不清到底做没做完。
- 读回的内容和要写的对不上时，核对判「完成」也只当「结果还没确认」：代码看到的事实只能把通过改成不通过。
- 用户一次说了不止一件事时，回答扣到核对之后才出：用户多次遇到先出一个像做完的回答再更正。
- 回答说「没找到」而助手只按原话找过时判「继续」：网站上常有词条换个字就查得到。
- 回答列出的西文名字过半在读到的全文里找不到时交给核对：核对只看得到截断后的读数，PDF 只读了前几页、作者在第 87 页时，助手照样列出 25 个名字，核对判了做完。中文名字还查不到。
- 催过一次续做后，助手仍说做不成且网页没变，就不再催；网页变没变由宿主比较，不听模型：空白画板上助手曾被连催多次，侧栏留下几段几乎一样的「没能完成…」。
- 「核对发现」后面是核对单独写给用户的一句诊断：写给主模型的诊断带「请改为…」这类指令，从里面挑句子给用户看会漏出指令。
- 受阻不催续做、不升思考档：原因在助手和用户之外（网站连不上、页面不存在、服务端拒绝，或换过做法后按钮仍没反应）。
