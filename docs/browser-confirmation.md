# 网页操作不再逐次确认

2026-10-04 起，助手在网页上的操作直接执行，不再弹批准卡（产品负责人决定，见[验收](evals/20261004-remove-approvals.md)）。已删除的部分：

- 每一步的“允许一次”卡片、受信任网站名单及设置页“信任的网站”。
- 网络请求（fetch POST）授权票据。
- 删除、发送、支付、提交类按钮的“拿住等确认”，以及重启后低风险填写的恢复确认卡。
- 记忆里“必填字段”的提交前核对。
- 对 Enter/空格、拖放和底层按住/松开输入的硬拦截。

仍然保留：

- 结果未知锁：写入结果不确定时，不重复执行，助手停下来如实告诉用户，用户在对话里决定是否继续（见[结果未知](unknown-results.md)）。
- 用户接管、交还与停止；派发前仍核对任务身份与控制轮次。
- 无进展、重复失败自动停下，以及完成核对。
- raw CDP 只读白名单、凭据脱敏、隔离环境读取页面。
- 记忆照常作为上下文交给模型，纠正后的“要我记住吗”照常询问。

已知后果：网页里注入的恶意指令可能让助手在已登录的网站上点击、发送或提交，不再有逐步确认来拦。

原生弹窗：点击或按键弹出 alert/confirm/prompt 时，回执说明弹窗内容；助手用 `dialog_info` 查询，再按用户意思 `accept_dialog` 或 `dismiss_dialog`。
