# 网页操作不再逐次确认

本页是“网页操作不弹批准卡”这一决定的权威位置。

产品负责人决定：助手在网页上的操作直接执行，不弹批准卡。删除、提交类按钮也不拿住等用户确认。产品没有受信任网站名单。

两个例外：

- **发送。** 助手点名字以「发送 / Send」开头的按钮前，程序先停下，在网页上和侧栏里同时问用户（[侧栏确认卡](evals/20261015-panel-send-confirm.md)）。因为发出去的消息收不回来，而网页里注入的指令可以让助手在用户已登录的网站上发消息。用户只点「发送」才发；点「先不发」、按 Esc、关掉侧栏、停下、接管、离开网页或久不理会，都不发。确认框写明发多少字、发给谁（读网页上的收件人栏或标题）、在哪个网站，同时在网页上圈出要点的按钮。
- **付款。** 助手永远不点付款按钮，用户在聊天里同意也不点。程序在网页上圈出这个按钮，由用户自己点。

结果未知时，助手重读页面后可以重做（见[结果未知](unknown-results.md)）。「连续失败就停」也已去掉。

仍然保留的保护：

- 用户的接管、交还与中止。派发动作前，程序仍检查任务身份与控制轮次。
- 原地打转时，任务自动停下；[目标核对](goal-check.md)照常运行。
- 凭据脱敏；页面内容在隔离环境里读取。

## 已知后果与缺口

已知后果：网页里注入的恶意指令可能让助手在已登录的网站上点击、提交，或在聊天框里按回车发出消息，因为没有逐步确认来拦截这些动作。

发送前确认的已知缺口。下面这些情况，消息可能不经用户确认就发出去，或者确认的范围比用户以为的大：

- 按回车（press_key）：焦点在有字的多行输入框、可编辑区，或焦点所在表单里有发送按钮时，按回车前走同一个确认（#290）。焦点在单行输入框、附近又没有发送按钮时不问。
- 页面脚本路径（#290，验收 `scripts/acceptance/real-path/program-send-confirm.mts`）：脚本运行期间，脚本里的 element.click()/dispatchEvent 点发送按钮、提交带发送按钮的表单（requestSubmit、form.submit）、合成回车、路径像发送接口的 fetch/XHR/sendBeacon 先拦下，走和点击同一个确认，用户点「发送」才原样重做。仍有缺口：脚本用定时器在返回之后才发；网络请求只按路径里的词（send、message、comment、reply、post 等）猜，名字不像的发送接口拦不到；页面自己的代码在脚本结束后异步再发。
- 「发送」按钮在 iframe 里：程序读不到按钮名字，不问。
- 网页在最后一刻把指针下的按钮换掉：程序读按钮和真正点下去之间有空隙。
- 按钮名字读不到（例如只有图标、没有文字和标签）：程序认不出是发送，不问。
- 「不发」只记在这一轮里（到用户再说话为止），而且只按网页和按钮名记：同一轮里改发另一条、点同一个「发送」，也不再问，直接不点。
- 等确认的状态只在扩展后台的内存里：后台重启时等待丢失，确认框收起，按钮不点。
- 「发送验证码」这类名字以发送开头的按钮，也会停下问一次。
