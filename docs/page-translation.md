# 整页翻译

[返回协议](protocol.md) · [使用说明](guides/usage.md)

用户说「把这页翻译成中文」时，主模型调用整页翻译工具。`agent/` 包负责分批和调用模型，页面一侧只取段落、写译文。
批次大小、批次顺序、并发、时限和重试次数以 [`agent/src/page-translation.ts`](../agent/src/page-translation.ts) 为准。

## 用户看到什么

- 用户先看到当前一屏的译文，再由近及远看到其他译文。
- 多批同时在途，哪一批先译完就先写入页面，所以译文一批一批出现。
- 翻译优先用快速模型；没设快速模型时，用会话的主模型。
- 程序只写入原文没变的段落。翻译期间被网站换掉的段落，留给下一次取段。

## 待翻占位

- 还没有译文的段落末尾显示淡蓝色流光占位。系统设置减弱动态效果时，占位静止。
- 占位是产品自己的独立元素，不改网站元素的样式。
- 翻译生成失败、可以继续时，占位延迟撤除；模型再次调用翻译会取消撤除。这样两次调用之间，占位不会成片消失又出现，页面不跳动。
- 用户中止任务后，控制闸门会拒绝后续页面动作，所以撤占位不做任务身份检查；撤占位只删产品自己的占位。
- 页面一侧另有兜底：长时间没有翻译动作时，页面自行撤掉占位，因为流程意外中断后占位不能一直留着。
- 实测见[验收记录](evals/20260927-translate-marks.md)：改后约 5–8 秒出现占位，中止后 0.25 秒收掉。

## 失败与限流

- 一批最终失败后，程序不再开新批，但在途批次照常写入页面，然后如实报告已完成和剩余的段数。
- 页面一直在变、译文写不进去时，程序停止并说明原因。
- 服务商以「同时请求太多」拒绝时，这一批不写页面，程序降低并发、退避后再发。额度、余额和账单类错误不算限流。
- 一直被限流、没有一批写入时，程序按失败报告。
- 加限流处理的起因：Kimi 编程套餐的并发上限低，4 路并发时每次调用有 3 批被 403 拒绝，长文只译出几十段（[验收](evals/20260927-translate-marks.md)「日常试用」）。

## 时限

- 整页翻译不设固定的工具总时限。只有长时间没有一批写入页面时，程序才停止并报告「长时间没有进展」。
- 用户中止任务时，在途请求立即取消，晚到的译文不写入页面。
- 输出写满上限多半是思考失控，所以程序把这一批拆小再翻，不原样重试。
- 每次翻译请求写一行诊断记录，用户可从设置页「诊断记录」导出。长文翻译的耗时实测见[验收记录](evals/20260926-translate-fast.md)。

## 可掀开的仅译文

- 仅译文模式不改写原文。译文覆盖在原节点上；用户按住时，译文偏移旋转，松开、移出、取消或失焦后复位。
- 用户普通点击原链接时，点击仍交给原节点；掀开手势不触发网页点击。
- 双语模式仍在原文后追加译文，不覆盖原文。
- 父级文字和独立子段落同时存在时，父级译文不挡住子段落。
- 恢复原文或网页更新时，程序不用旧快照覆盖网站的新内容。
- 用户设置了减少动态效果时，按住只显露原文，不旋转。
- 页面显示核验检查实际的译文层和对应的原节点，不把「原文已经变成中文」当作成功判据。注入和观察入口见[协议](protocol.md)。
