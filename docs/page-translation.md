# 整页翻译

[返回协议](protocol.md) · [使用说明](guides/usage.md)

## 用户看到什么

- 用户先看到当前一屏的译文，再由近及远看到其他译文。哪一批先译完就先写入页面，所以译文一批一批出现。
- 程序只写入原文没变的段落。翻译期间被网站换掉的段落，留给下一次取段。

## 待翻占位

- 还没有译文的段落末尾显示流光占位。占位是产品自己的独立元素，不改网站元素的样式。
- 翻译失败、可以继续时，占位延迟撤除；模型再次调用翻译会取消撤除。这样两次调用之间，占位不会成片消失又出现，页面不跳动。
- 用户中止任务后，控制闸门会拒绝后续页面动作，所以撤占位不做任务身份检查。撤占位只删产品自己的占位。
- 流程意外中断后，占位不能一直留着，所以页面一侧另有兜底：长时间没有翻译动作时，页面自行撤掉占位。

## 失败与限流

- 一批最终失败后，程序不再开新批，但在途批次照常写入页面，然后如实报告已完成和剩余的段数。
- 页面一直在变、译文写不进去时，程序停止并说明原因。
- 一些编程套餐的并发上限很低。所以服务商以「同时请求太多」拒绝时，程序降低并发、退避后再发。额度、余额和账单类错误不算限流。

## 时限

- 整页翻译不设固定的总时限。只有长时间没有一批写入页面时，程序才停止并报告。
- 用户中止任务时，在途请求立即取消，晚到的译文不写入页面。
- 输出写满上限多半是思考失控，所以程序把这一批拆小再翻，不原样重试。

## 可掀开的仅译文

- 仅译文模式不改写原文。译文覆盖在原节点上；用户按住时，译文掀开露出原文，松开后复位。
- 用户普通点击原链接时，点击仍交给原节点；掀开手势不触发网页点击。
- 恢复原文或网页更新时，程序不用旧快照覆盖网站的新内容。
- 判断翻译是否显示成功时，要检查实际的译文层，不能把「原文已经变成中文」当作判据，因为仅译文模式根本不改原文。
