# 整页翻译

[返回协议](protocol.md) · [使用说明](guides/usage.md)

用户说「把这页翻译成中文」时，主模型调用 `page_translation`。`agent/` 包负责分批和调用模型（[`agent/src/page-translation.ts`](../agent/src/page-translation.ts)）；页面一侧只取段落、写译文（[`extension/src/shared/page-translation.ts`](../extension/src/shared/page-translation.ts)）。批次大小、并发、时限和重试次数以代码为准。

## 分批与顺序

- 先译当前一屏，再由近及远。最先几批取得很小，当前一屏分几路先落页，不等一整批。
- 翻译批次优先用快速模型，没配时用会话主模型。
- 只写入原文未变的段落。页面在翻译期间换掉的段落留给下一次取段。

## 待翻占位

- 还没有译文的段落末尾显示淡蓝色流光占位；系统设置减弱动态效果时静止。占位是独立元素，不改网站元素自身的样式。
- 译文写入、恢复原文或翻译结束时撤掉占位。
- 「翻译生成失败，可继续」时延迟撤除；模型再次调用翻译会取消撤除。这样两次调用之间占位不会成片消失又出现，页面不跳动。
- 用户中止任务后，控制闸门拒绝后续页面动作，所以撤占位豁免任务身份检查。撤占位只删产品自己的占位。
- 页面自带兜底：长时间没有翻译动作就自行撤掉占位，防止流程意外中断后占位常驻。
- 实测见[验收记录](evals/20260927-translate-marks.md)：改后约 5–8 秒出现占位，中止后 0.25 秒收掉。

## 请求池

- 多批同时在途。哪一批先译完就先落页；用户会看到译文一批一批出现。
- 一批最终失败后不再开新批，在途批次照常落页，然后如实报告已完成和剩余段数。页面一直在变、译文写不进时停止并说明。

## 服务商限流

- 服务商以「同时请求太多」拒绝时，这批不写页面，降低并发并退避后再发。额度、余额、账单类错误不算限流。
- 一直被限流、没有一批写入时按失败报告。
- 起因：Kimi 编程套餐并发上限低，4 路并发时每次调用 3 批 403，长文只译出几十段（[验收](evals/20260927-translate-marks.md)「日常试用」）。

## 时限与失败

- 不设固定的工具总时限。长时间没有一批落页才停止，并报告「长时间没有进展」。
- 用户中止任务时，在途请求立即取消，晚到的译文不写入页面。
- 输出写满上限多半是思考失控，所以把这批拆小再翻，不原样重试。

每次翻译请求写一行诊断记录，只装扩展时随设置页「诊断记录」导出。长文翻译的耗时实测见[验收记录](evals/20260926-translate-fast.md)。

## 可掀开的仅译文

仅译文模式不改写原文。译文覆盖在原节点上，按住后偏移旋转，松开、移出、取消或失焦后复位。原链接普通点击仍交给原节点；掀开手势不触发网页点击。双语模式仍追加译文，不覆盖原文。

同时有父级文字和独立子段落时，父级译文不挡住子段落。恢复或网页更新时不用旧快照覆盖网站新内容。减少动态效果时只显露原文，不旋转。

页面显示核验检查实际译文层和对应原节点，不用「原文已经被改成中文」作为成功判据。注入和观察入口见[协议](protocol.md)。
