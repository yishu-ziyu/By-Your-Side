# 语音首声延迟：交接说明

## 产品是什么

浏览器里的语音 Agent。用户对着 Chrome 说话，它读页面、操作网页、回答问题，用语音回话。

## 现象

用户说完一句话，要等 **5–7 秒**才听到第一声。等待期间完全静默（界面上只有文字状态）。

实测（合成语音走真实识别→真实分类→真实模型→真实合成→生产播放器，4 轮）：
第一帧音频到达时间 **4.9 / 5.4 / 6.8 / 7.0 秒**。

## 这 5–7 秒的构成

| 步骤 | 耗时 |
|---|---|
| 说完 → 识别出终稿文字 | 0.5–0.7s |
| **用一次 LLM 调用判断这句话要干什么** | **1.7–2.7s** |
| **主 Agent 生成回答 → 出第一个字** | **2.5s** |
| 回答上屏 → TTS 出第一帧音频 | 0.6–0.7s |

两段加粗的是两次模型往返，**串行**，合计 5.2s，占 76%。

## 现有链路

1. 音频 → Step 实时语音会话（stepaudio-2.5-realtime）→ 终稿文字。
2. **分类调用**：把整句分类成一个计划。动作域：`chat`（闲聊/知识问答）、`start`（新任务）、`steer`（修改正在执行的任务条件）、`status`（查任务进度）、`observe`（看当前页面并回答）、`silence`、`clarify`（需要用户确认，例如只说了"停"）。用当前会话模型（opencode-go/deepseek-flash），temperature 0，maxTokens 1400，带 6s/9s 两档重试预算。**这是第 2 步 1.7–2.7s 的来源。**
3. 按分类结果派发给主 Agent（Pi 会话，同一模型）。主 Agent 生成回答，通过一个正式交付工具把文本交给语音层。**这是第 3 步 2.5s 的来源。**
4. 交付文本流式送 Step TTS（stepaudio-2.5-tts），第一帧音频到达生产播放器。
5. 播放器出声。

## 必须保住的约束（这些是踩过坑之后定下的）

- **一轮只能有一份回答。** 之前的做法是"语音层在判定完成前抢先开口"，结果一句话被答了三遍（抢答 + 任务确认 + 正式回答），而且抢答时它还没有任何事实依据，会编内容（实测编出过"这是 Chrome 的扩展管理页"，后台从没说过这句话）。现在改成：只要是内容请求，语音层等主 Agent 的正式交付，不抢答。
- **分类不能砍。** 它决定这句话是闲聊、新任务、修改正在跑的任务、查询、看页面，还是"停"。不能把"停"当普通内容发给主 Agent。
- 判定为控制类（停/改条件）时，必须走原有的控制闸门（授权、任务身份、页面归属校验）。

## 已经排除的做法（都有实测）

| 做法 | 结果 |
|---|---|
| 削分类提示词 / 加 `reasoning:"minimal"` | 无效。分类调用耗时≈同一供应商跑极小提示的下限（进程内首次 4.7s，热了之后 1.4s）。提示词只有 2625 字符。 |
| 换更快的模型跑分类（本地池 4 个候选） | 更差。`gemini-3.1-flash-lite` 4.36s 且把"把姓名改成李明"判成闲聊（该动手的没动手）；`gemini-3-flash` 4.21s 且把"暂停"判错；`kimi-k2.5` 0.6s 但 8 句全返回空文本；`gpt-5.4-mini` 不可用。现用的 `deepseek-flash` 中位 1.73s。 |
| TTS 提前建连 | 只值 270ms。建连+握手约 270ms，其余约 540ms 是 TTS 服务端从收到文字到出声的固有时间。 |

结论：本地代码可削减的固定开销只剩约 270ms。**只要还是两次串行模型往返，说一句话就是 5 秒起步。**

## 想请教的问题

1. 有没有办法让**一次**模型往返同时完成"判断这句话的性质"和"回答这句话"？（即把路由判定和回答合并成一次调用，或者让主 Agent 自己判断该不该动手）
2. 语音助手类产品一般怎么处理"路由判定 + 回答"的串行？有没有成熟的第三种解法（不是"抢答"也不是"等"）？
3. 如果没有更好的办法：**并行化**——收到终稿时立刻把原话派给主 Agent 开始生成，同时并行跑分类，但在分类结论落地前扣住主 Agent 的工具调用和正式交付；结论是内容类就放行，是控制类就丢弃这次生成并走控制路径。这个方案的问题：按 8 句样本，8 句里有 3 句（停、查进度、需确认）会白跑一次生成；代价是花费和面板上短暂出现一次被取消的运行。这个代价你们认为可接受吗？有没有更好的取消/接管协议？
4. 供应商单次往返下限约 1.4s，这个数本身能不能降？（换供应商不算答案，我们希望保留现有模型生态）

## 目标

- 一句招呼：说完 **≤2 秒**听到第一声。
- 不牺牲：一轮一份回答、说停能停、不编事实。

## 已知缺口

以上数字全部来自合成语音（隔离浏览器 + 验收桥接传输）。真人麦克风路径的实测数字还没有，不能拿合成数字替代。
