# 从一次原地探查补齐浏览器恢复能力

## 1. 先看实际缺什么

BOSS 项目经历任务调用了 45 次工具，其中 30 次是 JS。截图反复提到悬停，产品却没有真实 hover 工具。

对照 ego lite 的执行层，第一步确定为补真实鼠标悬停。没有先给 Agent 加固定次数停止。

## 2. 让错误能指向下一步

新增 hover，并接入原有标签归属、光标和接管闸门。

无效定位、失效引用、多个匹配都明确拒绝，返回可操作的恢复指引。修正了 ref 的说明：编号稳定不代表旧快照里的引用一直可用。

同时补齐本地运行轨迹。此前只能看到工具名称和 ok；现在可以看实际参数、返回、错误和耗时。输入值和图片按规则隐藏，日志有大小预算。

## 3. 真实路径推翻了什么

本地隐藏入口和三类错误恢复都通过，不能据此认定真实网站已经可靠。

BOSS 验收先遇到旧接管约束污染新任务。新会话中，Agent 通过真实 hover 显示添加按钮，打开项目表单。这个结果证明工具能力有用，也留下了明确的跨任务上下文问题。

验收脚本两次因事件收集方式不对误判超时。持久化轨迹和页面截图证明实际动作已完成。报告分别记录产品结果和脚本结果，没有把命令失败改写成命令通过。

## 4. 数字与下一步

422 项测试通过，类型检查和构建通过。

本地四条自主路径通过。原生接管后续填通过，记一次自动化模拟人工介入。

BOSS 新会话用 69.2 秒、16 次工具调用打开新增项目表单，零人工介入，零填写，零提交。

下一步修接管约束对新任务的影响，再减少真实网站上的重复探查。当前没有总体成功率对照数据。
