# 语音听错之后怎么办：接话少说、控制句复述、纠正时补当前页

方向：用户贴面板截图说"这个语音太蠢了"。查日志后确认是三个独立问题叠在一起——转写听错（BOSS直聘→
boss直拼、否定词丢失）、接话抢答（后台还没判定就先编了一句页面描述）、文本模型拿旧前提继续推理。
用户选了"接话只说安全的话"，并批准"控制句先复述确认"。

转写这一层我们改不了。StepFun 的实时链路负责听和说，换文本模型不影响它。能改的是听错之后的三个动作：

接话不许替后台描述世界。接话发生在用户话音落下 1–2ms，而后台判定要 1.5–3s 才回来——这段时间里模型没有
任何事实。原来只靠提示词"不回答尚未查到的内容"，实测拦不住。现在接话的音频先攒着，整句转写一到就过安全
校验（长度、数字、拉丁专名、具体对象、结果宣称），通过才播，不通过就改播固定台词"我看一下"。固定台词走
已有的"原样朗读 + 校验"通道，第一次生成后进音频缓存，之后不再多花一次生成。

控制句先复述。转写听错时，改任务和终止任务是最贵的错误，而这两类恰好是"做了就收不回"的。所以运行中、
当前会话、单步的修改/终止句先复述用户原话（"你是说'…'，对吗？"），下一轮"对/是/确认"才落，"不/算了"
撤销，90s 没回应作废。复述用原话而不是"确认要修改吗"——转写错了，只有原话才看得出来。复用文件里已有的
跨轮确认写法（原本用于"要另开会话吗"），不新造协议。

纠正时补一次当前页。用户说"不是 chrome 的扩展管理页了"这种句子，是在纠正"我在看哪一页"。插话里出现
页面指代或纠正信号时，先做一次只读 snapshot 附在消息尾部（trace 记 `phase:"steer"`）；纯参数修改不附，
不为此给每次插话加页面 token。

踩到的两个坑（都由回归测试挡下）。第一版闸门把"修改""切换"这类动作词一律拉黑，结果模型说"我来处理这个
修改。"也被拦——那是打算做什么，不是报事实；黑名单收成只拦"已经发生"的措辞。第一版也不分开场确认，
把有回执的开场确认一起拦了；现在只在"后台还没有回执"时校验。

结果。154 文件 1352 项测试通过（新增 11 项），typecheck、build 通过。真机语音端到端没跑——需要真实
麦克风与实时链路，属人裁决项。

边界。没动实时链路与文本模型选择；pause/resume 不加确认（可逆，加了反而吵）；常见词偏置与空响应重试
本轮未做。
