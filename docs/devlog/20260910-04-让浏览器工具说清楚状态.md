# 让浏览器工具说清楚状态

## 1. 先改善环境

用户强调先向ego-lite学习有效的浏览器工具，再决定是否削减推理和上下文。对照固定源码后，本轮保留同一模型，补直接读状态与有界条件等待。没有把减少轮次设成硬限制。

## 2. 能执行还要接得对

真实模型开始用新状态接口。但一次正确的组合操作被目标登记闸门拒绝。原因是子步骤记录走Pi异步进度队列，权限检查先到了。

生产装配改为先同步记录子步骤，再进入原权限检查。新回归用例先红后绿。布尔属性的条件也采用明确类型，拒绝字符串true造成的无效等待。

## 3. 工具修复不等于整体提速

1024项测试、类型检查、构建通过；真实Chrome7项边界通过。最后自主样本暂停并读对三条评论，用了新状态检查，0次JS探查，9轮29.6秒。旧环境部分基线为10轮21.8秒，不能据此说速度提高。

本轮已重载。下一步仍是任务登记带来的往返和改口接续；没有用模型调参掩盖。详细失败与成功证据见[验收](../evals/20260910-browser-environment-state.md)。
