# 能做成优先于保守：去掉让助手放弃重试的规则

- 日期：2026-10-10。验收见[去掉重试锁](../evals/20261010-drop-retry-locks.md)。
- 方向：用户决定，自用产品的能力优先于「安全正确性」。用户原话：「因为这是我的一个自用产品，我宁愿它的功能性强过它所谓的'安全正确性'。」「安全限制太多太傻逼了。」
- 原因：一步超时或结果不明后，程序暂停写入、拒绝重做、只许核查一次，然后替助手结束本轮，告诉用户「没有重复执行」。已经做成的一步不许再做。同样的错连续三次就停。用户看到的结果是助手经常半路放弃，而页面其实只要重读一下再点一次就能做完。
- 现在：结果未知只表示「先重读页面再决定」。助手可以重做同一步、换方法，然后交付。已做成的一步可以再做。同样的错不再三次就停。原地打转仍会自停，但门槛放宽。
- 放弃了什么：
  - 助手可能把同一个按钮点两次。例如浏览器在提交时崩溃，用户说「继续」后，助手重做提交，网站收到两次（`session-durability` 现在按这个判）。
  - 结果不明时，助手可能没核实就说做完了。程序不再替它拦着；提示词只要求它以页面现状为准。
  - 「每项只核查一次」的核查工具删掉了，所以不再有宿主替助手说「查不清」那段话。
- 留下的：付款永远由用户自己点；点「发送」前先在网页上问；用户接管或插话后，在途写入被拒；做不到的事照实拒绝；重启后用户说继续前不执行写入；原地打转停下后同一轮不再写入。
- 没动的：语音实时通道在原任务缺执行记录时仍拒绝语音写入，另行决定。核对与交付一侧的同类规则由另一项任务处理。
