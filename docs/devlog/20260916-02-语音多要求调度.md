# 语音从单任务插话扩展到多要求调度

用户实测途中新增任务导致原回答无声，进一步要求检查多个要求持续进入时的承载能力。基线确认：请求串行接收不是任务等待队列，跨会话运行也不自动意味着结果能回到当前语音。

决定同时建立独立要求登记、有限执行准入和交付归属，保留现有执行器、控制通道与页面保护。初始限额为2个根任务与8个待办，不代表已测出供应商并发极限。普通补充仍送原任务，不能按“新标签页”几个字直接另开任务。

真实三任务验证暴露两类额外问题：分类把背景条件拆成动作；声音还未到达客户端时的插话把结果永久静音。已分别修正任务关系/分段规则和未听结果保留。类型、回归、真实模型/浏览器/TTS及侧栏排队显示通过；证据和范围见[验收](../evals/20260916-voice-multi-request.md)。

后续按已听片段精确续播、任务整体控制与重启恢复体验继续完善，不用增加确认台词代替任务协调。
