# 让改口和暂停接住剩下的步骤

## 1. 用户会在执行中改变要求

任务还在做，用户说“改成Y”。暂停后补一句要求，再交还页面。这些动作不应该让用户重新讲一遍任务。

先前的任务记录没有完整接住文字补充。旧任务的迟到状态也会改写新任务。独立测试先复现，再修入口和回执归属。

## 2. 页面变了，旧目标也要失效

真实测试发现，页面换了之后，旧选择器仍圈到了另一个对象。模型随后看图发现错误，把圈清掉。

最终没有圈，不代表过程中没做错。现在把观察与当时的文档关联。文档替换后，旧目标在操作前被拒，必须重新核对。

## 3. 记录也可能拖住执行

为了解决“读到了不等于圈好了”，新增了结果登记。登记只声明意图，完成由匹配的执行回执推进。

第一版把这件事做复杂了。模型改对象时另建编号，留下旧待办；预检和真正执行之间的先后顺序也没有对齐。有的页面已经圈好，登记仍在等，模型反复补记录。

修复让纠正更新原结果位置，登记目标必须与执行目标相同。状态只作为数据传给模型。已满足就交付结束，无法完成也可以保留欠项、报告原因后结束。

## 4. 暂停恢复不能为补账重做动作

交还时，扩展已经读取了当前页面。这次真实观察此前没有进入结果记录，恢复后仍被当作未读。

现在接回这份已有快照。恢复只读记录与结果未知的写操作分开处理。未知写不重放，匹配的晚到回执可以确认原操作。

## 5. 验证方式也需要收敛

用户指出工作持续了一小时，却难以知道完成了什么。这次验证切片没有控制好。单测全量约10秒，主要时间耗在真实模型场景和扩修，不能把慢归咎于全量测试。

后续小改动先定点验证，稳定后一次全量。每完成一个功能，先展示用户可见的变化。行为HTML已经提供，但用户认为抽象；下一步应在实际扩展里判断，不继续打磨示意图。

## 6. 停在真实试用之前

最后989项测试、类型检查、构建和diff检查通过。文字纠正11项、暂停恢复16项定点通过。原整组3/5及后续失败全部保留，未把分阶段结果写成最终源码一次全绿。

没有重载用户扩展，没有提交推送，没有进入TTS。下一步由用户检查自然改口和暂停恢复。结果登记增加了内部步骤，是否顺手、是否等得住，由真实试用决定。
