# 20260907-02 Composer 附件瓷贴与多模态图片闭环落地

对应标准 `docs/evals/20260907-composer-attachments-v1.md`。

## 1. 背景与转向

用户看到 Mertcan（@sitenley 为 @boardui 制作）的 Composer Attachments 动效后，提出引入 SideAgent 项目。
在并排 HTML 方案评审（`docs/evals/20260907-composer-attachments.html`）中，用户选定方案 A（复合上下文分层流 Context Ribbon），并指出核心问题：
**SideAgent 原有架构只有 Agent 单向给用户截图，缺少用户主动截图与向 Agent 投喂材料的管道。只做 UI 瓷贴是空花架子，必须连通底层多模态输入。**

## 2. 判断：动效与管道并重，首期聚焦图片多模态

多模态能力边界要克制：
- 首期不引入重型 PDF 文本提取与复杂服务端解析，聚焦最高频的图片场景（截图、本地图片、粘贴板）。
- 动效必须毫厘不差还原参考样张的灵魂：56px Squircle、顺时针 SVG 进度描边（周长 194px）、右上角 9px 百分比与关闭 ✕ 的原位 Blur Cross-Fade（Zero Layout Shift）。

## 3. 做法

1. **协议层契约升级（`shared/protocol.ts`）**：
   - 增加 `ImageAttachment` 与 `Attachment` 定义，包含 `id`, `name`, `dataBase64`, `mimeType`。
   - `ClientMessage` 的 `user_message` 与 `steer` 扩展可选 `attachments?: Attachment[]`。
   - `isAttachment` 与 `parseClientMessage` 完备校验。
   - `relay.ts` 扩展 `PanelHistoryItem`，支持侧栏重开与多面板同步时完整保留附件。

2. **伴随进程打通 Pi SDK 多模态（`agent/src/session.ts` & `main.ts`）**：
   - 编写 `extractImages` 转换器，提取消息中的图像附件转化为 Pi SDK 原生 `ImageContent[]`。
   - 传入 `session.prompt(text, { images })` 与 `session.steer(text, images)`。
   - 补齐单元测试覆盖非法类型过滤、合法图像解析与纯文本向后兼容。

3. **后台服务截屏（`extension/src/background/index.ts`）**：
   - 监听 `sidepanel_capture_tab` 消息，基于 `chrome.tabs.captureVisibleTab` 截取当前激活页。
   - 用户发送消息时将 `attachments` 完整写入回放历史。

4. **侧栏界面与动效引擎（`extension/src/sidepanel/`）**：
   - 实现 `AttachmentsManager` 模块，管理 56px 瓷贴与顺时针 SVG Accent Ring 描边。
   - 右上角 9px 百分比数字与关闭 ✕ 原位 Blur Cross-Fade，零布局偏移。
   - 交互源：左下角 `+` 呼出动作菜单（📸 网页截屏、📁 本地选图）、输入框 `Cmd+V` / `Ctrl+V` 粘贴图片、拖拽到 Composer。
   - 用户消息气泡渲染附件缩略图，点击可在新标签页查看原图。

## 4. 成果与数字

- 测试：42 个测试文件、403 项测试全绿（通过率 100%）。
- 机器检查：`npm run typecheck` 零错误，`npm run build` 产物正常构建（`dist/sidepanel.js` 287.5KB）。
- 评估卡：`docs/evals/20260907-composer-attachments-v1.md` 全部 6 项标准检查通过。

## 5. 下一步

- 用户真机验收：在 Chrome 中加载更新后的扩展，测试网页截屏、粘贴图片、观察 56px 瓷贴顺时针描边动效，发送给 Agent 并观察分析响应。
