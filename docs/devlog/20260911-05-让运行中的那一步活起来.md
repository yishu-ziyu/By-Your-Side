# 让运行中的那一步活起来，让结束变成收束

方向：用户看实时截图后说"那个光球目前没看到它在跑"，并希望这一屏"更活一点"。用户指定临时使用
`oil-frontend`、`oil-motion` 两个 skill 一起检查（临时 clone 到 `/tmp`，用完删除，不长期安装）。

先测再改，别按直觉重做。第一反应是"这里没有动效，得加"，实测否掉了这个前提：同一批 6 个 canvas 隔
400ms 取像素指纹，运行中有 3 个发生变化——光球机制一直在跑。真正的两个问题是：① 只有球体内部纹理在
变，整体尺寸与位置不动，肉眼几乎看不出；② 已结束那一屏完全没有运动线索，从"在跑"到"跑完"是硬切换。
所以本轮不是补动效，而是把已有运动做得可察觉，并给结束一个收束。

按 A+B 落地（用户在这两个方案里选定）。A 运行中：光球整体呼吸 18→20px（0.9s），思考行的竖线先长出来
再轻微呼吸、名字转强调色，跑着的工具 chip 亮蓝边。B 完成：工具结束那一帧 chip 退出运行态、光球一次性
收束回原位、状态点与文案各落定一次，不反向播放。

为什么这样做而不是别的。依据 oil-frontend 的动效与性能规则：一个动效只承担一个职责（A 说"还在跑"、
B 说"这一步结束了"），复用项目已有的 `--m-move`/`--m-morph`/`--e-swift`/`--e-spring` token，连续动画
只动 `transform`/`opacity`，不用 `transition: all`，不为一个效果引入第二套动画系统；已有
`prefers-reduced-motion` 机制，新动效在减少动态时退化为只剩状态色。选择"呼吸 + 收束"而不是加载条或
更多运动线条，是因为这一屏的任务是让人知道 Agent 在做什么，不是演出。

踩到的坑。收束结束时不能用 `animationend` 摘 class——折叠的 `details` 里 CSS 动画不会启动，事件永远不
会来，class 会永久残留。改成定时器到点摘除。这条已单独记为经验
[collapsed-details-animation-end](../../.kimi-code/wiki/patterns/collapsed-details-animation-end.md)。

结果。真构建面板 + 隔离 headless Chrome 21/21 PASS（新增 11 项），其中"运行中的光球真的在动"用像素
指纹证明；结束时 `orb-live`/`orb-settle`/`.chip.running` 计数归零，无动画残留。`panel-open-session` 13/13、
153 文件 1341 项测试、typecheck、build 全过。

边界。历史回放不进入运行态（读旧记录不等于正在发生），光球引擎仍是 MIT vendor 原样，没动状态行文案、
执行块结构、会话切换与任务执行。

未定。呼吸幅度与收束节奏是否合适由用户在真实侧边栏里裁决。
