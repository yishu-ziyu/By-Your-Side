# 让规范约束结果而非重复流程

用户审阅当前开发规范后，批准收紧确认条件、允许有依据地修正验收方法，并减少重复文档和强制工具步骤。

此前五秒收尾指标没有准确对应原问题，人声检测样本也没有覆盖真实语音识别结果。这些记录说明检查方法本身需要核对；不能因此降低用户要求，也不能把所有失败归因于规范。原证据分别保留在[收尾任务](../evals/20260910-task-completion-tail.md)和[语音交接](../tasks/20260910-voice-review/handoff-gpt6-pro.md)。

本次保留真实路径验收、授权边界和有证据的经验沉淀。明确目标与范围时连续推进，测量错误保留依据后修正；收尾细节改为按需读取，记录按关键节点触发，设计预览按实际判断需要选择。状态首页同步去掉已被真人负反馈取代的“待试用”描述。

仅调整项目规范与必要文档。验收及检查结果见[本轮记录](../evals/20260910-working-rules-simplification.md)；后续任务再观察是否减少重复确认和状态误读，不把本次文档修改当作产品体验改善。
