# SideAgent 开发日志（一）：教学模式为什么做错了

2026-09-03

## 1、这一天的起点

SideAgent 是一个 Chrome 侧边栏 Agent。它在网页上有一只虚拟鼠标，点击前先圈出目标元素，还能在页面上画标注。

这一天本来只是例行推进路线图。上午做了操作前高亮，下午做了标注工具。傍晚，路线图轮到了"教学模式"：Agent 不直接操作页面，而是画箭头、画圈，一步步教用户自己点。

## 2、第一版的设计

第一版的思路很直接：既然叫"模式"，就把能力切开。

教学模式打开后，执行层直接拦截 click、fill 等五个动作工具，系统提示词里写明禁令。Agent 只剩观察（截图、读页面结构）和标注（mark）两类能力。设计意图是安全：教学时绝不误触页面。

代码当天就上线了，88 项测试全绿。

## 3、实测

用户拿到后，给了一个很重的测试任务：在 GitHub 仓库里新建一个 Issue，填标题、填正文、勾选 label，但不许点提交。

这个任务选得好。它包含跨页跳转、表单、下拉面板，第一步的"Issues"标签还正好贴在屏幕顶边——这直接暴露了标注 pill 画在元素上方会出屏的问题。

但真正有价值的发现是两个设计错误。

## 4、错误一：Agent 不知道用户做完了

教学过程是：Agent 画一个标注，等用户回复"好了"，再教下一步。

实测中，用户点了 Issues 标签，页面已经进入列表页，但没有回话。Agent 就一直在原地等。它没有任何手段知道这一步已经完成了。

原因值得记录。GitHub 是单页应用，点击后走的是 pushState 软跳转，不触发整页导航。我们原有的"页面导航即清标注"机制完全没有激活。Agent 收不到 URL 变化的任何信号。

这提醒我们：现代网页里，"页面变了"不等于"导航发生了"。

## 5、错误二：模式不应该是二分的

第二个问题更根本。用户让 Agent 打开 X 网站，讲解页面上值得探索的区域。Agent 拒绝了，回复说"教学模式下我不能替你打开页面，请关闭教学模式"。

用户的反馈是：打开标签页是基础能力，不该被模式砍掉。学位帽应该意味着"教学性更强"——解释更细、步步标注、关键动作前等确认——而不是能力变少。反过来说，通用模式下也不排斥教学行为。

我认为这个批评是对的。第一版把"教学"理解成一种受限状态，但用户要的是一种表达倾向。模式二分是简单，可惜是错的简单。

## 6、重设计

当天就重做了。改动有三处。

第一，拆除全部闸门。教学模式下工具能力全集保留，提示词改为倾向式：默认引导用户亲手操作，但任务需要或用户要求时，直接动手并解释。

第二，补上感知。教学模式下如果还有待完成的标注，后台监听标签页 URL 变化（包括 SPA 软跳转），一变就清掉旧标注，并通知 Agent"用户可能已完成上一步"。Agent 自行确认页面状态，主动推进，不再干等"好了"。

第三，修掉出屏。标注文字在元素上方空间不足 34 像素时，自动翻到元素下方。

还有一个顺带的设计收敛：真正该设防的不是"教学时的点击"，而是"危险动作"（提交、删除、支付）。这条防线按动作的危险性划分，与模式无关。它和路线图上"危险操作确认"就此合并成一件事。

## 7、侧边栏的信息流

同一天还重做了侧边栏的运行过程展示，参考了 ChatGPT 和 Kimi 的侧边栏。

它们有两个共同做法值得学。一是人性化：不说"snapshot（参数略）"，而是说"读取页面结构"。二是聚合：一次任务的思考和工具调用收进一个可折叠的"执行步骤"块，运行时显示步骤链，完成后一个对勾加总耗时。

我们照这个思路实现了。每张工具卡带中文动作描述和耗时，思考块也标注耗时。正文回答保持全文宽排版，不被步骤块稀释。

## 8、设计取向

借这次重做，把设计原则写下来，免得以后再摇摆。

参考对象优先选优质开源项目和一线产品，但要消化，不照搬。美学上追求克制、简约，同时给人安全和可依赖的感觉。克制的意思是：信息有层次，默认只露摘要，细节收进折叠；可依赖的意思是：每个动作有名字、有耗时、有结果状态，让用户始终知道 Agent 在做什么。

这两点其实是一回事：少即是信任。
