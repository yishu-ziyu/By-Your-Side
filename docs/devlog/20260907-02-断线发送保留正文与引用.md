# 断线发送不能静默丢正文（issue #4）

日期：2026-09-07。分支 `fix/stability-issue4-send-delivery`，base `2cd23a1`。

## 1. 问题

用户在断线窗口里发送消息，正文和划词引用被无条件清空。函数级早就复现过：`send()` 吞掉所有失败，`sendInput()` 发完就清输入框和引用存储。这一轮校验方（issue #4）预写了 C1–C7 标准，要求先用实际生产入口复现，再做最小修复。

## 2. 复现方式的选择

上一轮的隔离复现是抄三段函数体做替身，issue 明确说不接受替身。这次分了两层：

- 生产 UI 层：Playwright 加载真实构建扩展，普通标签页打开生产 sidepanel.html，只在 chrome.runtime.connect 这一个边界注入故障（connect 抛错 / client 信封抛错）。先正常连接种入引用，再断 Port 进入故障——和真实断线时序一致。
- 生产模块层：vitest 直接 import 真实 background/index.ts，驱动它注册的真实 onConnect 路由；测试环境天然没有 native host，上行确定失败。

旧代码上，UI 层 4 场景各丢正文/引用/存储且无提示；模块层 4 例失败，其中 1 例还暴露了新缺陷——畸形 `{kind:"client"}` 信封会让 SW 监听器直接抛 TypeError。这是审阅没写到、复现捎带发现的真实 bug。

## 3. 修复的边界划分

把"发送成功"拆成两层，各自只认账到自己的边界：

- panel→background：Port 接受（postMessage 未抛错）即 true。失败=确定未送达，正文、引用 UI、storage 引用全部保留，提示「没有发出去」且可重发。
- background→agent：`uplink.sendClientMessage` 返回 false（传输不可用）时，广播新增的最小回执 `{kind:"delivery", seq, ok:false, original}`，面板把对应气泡标「未送达」并给原文重试按钮。回执只按 seq 操作自己的气泡，永远不碰输入框——迟到回执清不掉用户后来编辑的新正文。

没有回执=background 层已接受并交给传输层，不表示 agent 已处理。不做自动重放，所有重发都是用户显式动作。

## 4. 真实扩展端到端

隔离 profile 加载真实扩展，CDP `Target.closeTarget` 终止 service worker 制造真实断连：断线窗口发送→正文/引用保留→面板自动重连唤醒真实 SW→用户重试→真实 background 接受并回显。该环境上行如实不可用，真实回执把气泡标了未送达——两层语义都在真实运行时走通了。全程 headless，不抢用户前台。

## 5. 结果与边界

- 修复前后同一批断言：4+4 失败 → 8 场景 46 断言 + 路由 5 例全绿。
- `npm run typecheck / test / build` 全绿；test 390（基线 385 + 净增 5）。
- overlay-check、accept:browser、accept:team 各复跑，`reload:ext` 换新构建后再各一轮，均 PASS。
- 剩余边界如实保留：瞬死毫秒竞态、native 接受后 agent 崩溃属"已接受未知处理"、idle 态 steer 重试语义未验证、真实 side panel 容器观感待人评。
