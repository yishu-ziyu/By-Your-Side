# 两个杠杆都生效：省掉观察轮与收尾轮

方向：用户追问"为什么改动之后总耗时反而增加了"后确认中位数基本不动，接受更正，并要求把两个真杠杆
（预注入当前页观察、交付后运行时收尾）真的改掉，做对照。

做了什么。① 新任务发出前，运行时先对用户当前页做一次只读 `snapshot`（4s 超时，读不到就静默降级），
把观察按不可信页面内容包裹后附在消息尾部；运行中插话不预注入。② `send_user_message(kind="finding")`
的工具结果带 `terminate:true`，命中 SDK 的批次早停规则，round 在交付轮结束；`ack` 不带，被拒绝的交付
也不带（异常路径）。

结果。同一条单动作 case（暂停视频，真模型 + 隔离浏览器）：轮数中位 4 → 2，总耗时中位
13.47s → 5.33s，首个页面动作中位 7.47s → 2.72s，改后 5/5 恰好交付一次且页面真的暂停。
trace 里能直接看到两处结构变化：模型的 `snapshot` 轮被 5–31ms 的运行时读取替代；
交付轮 `turn_end` 之后 1–4ms 就是 `agent_end`，改前 986–1740ms 的纯文本收尾轮消失。

为什么不是提示词能解决的。上一轮已经证明：提示词写"用 browser_run 把观察+动作折成一轮"，
模型在明确单动作下仍分两次调用；收尾轮由 SDK 循环决定，工具层无法取消。两处都必须在运行时改，
这次改在 `agent/src/session.ts`（预观察）与 `agent/src/user-delivery.ts`（`terminate`）。

代价与遗留。每条新任务多一次只读快照 + 最多 12k 字符上下文；多步任务探针 3 次里有 1 次
完成后没有任何交付就结束——改前基线同样出现过 1/3 无交付，属既有缺口，需单独查。

人裁决（2026-09-11）：用户看过对照后确认提升有效（"这个提升很好"），并决定提交、推送。
