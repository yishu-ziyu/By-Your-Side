# 先让语音恢复有据可查

## 1. 空识别不能抹掉上一句

原来的打断会立即丢掉上一轮状态。新输入后来被识别为空，上一句也找不回来了。

现在先停声音，保留原请求。确认新输入为空后，闲聊继续回答，页面观察重新读证据。写操作只补已有回执；没发送的指令不自动恢复。新的有效输入会取消旧恢复。

## 2. 连接恢复不重置责任

原请求的等待期限保留下来。断线不能无限续期，生成结束但播放尚未完成的结果也不再被清掉。

如果操作可能已经发出，错误提示只说明结果未知。不会再用“未执行”让人误以为可以安全重发。

## 3. 看的是用户当前页面

原来的观察借用了任务工具，可能取到任务工作页。

现在由当前语音连接发放短期观察授权。只读可见区域，不认领标签，不切换前台。文字和截图核对文档身份；同网址重载也会使本次结果失效。

## 4. 一句话可以分步，但不能丢步

分类校验增加全文覆盖和明确控制语义检查。先复现的七个错误候选已被拦下。真实分类仍发现一次把整理选区判成观察，正在按原48句标准重跑。

复合计划在分类前落盘。每一步记录待执行、待确认或已有回执。重放读取原结果。用户再次接管后，旧计划不能继续交还页面。

另开任务的确认绑定固定提案和固定会话身份，避免重试产生多份空会话。

## 5. 验证还差真实入口

本地全量曾通过721项；后续新增测试分组通过，最终全量待复跑。生产采音脚本已准备，经过VoiceClient、AudioWorklet、检测器和播放器，不再把直接发送PCM等同于生产采音。

尚未重载用户扩展，浏览器操作仍在等待交接。真实页面、真人控制闭环和20轮时延标准没有改，也没有宣称通过。

## 6. 实测推翻与后续结果

强化控制第一次恢复失败。协作者在独占页误用共享页工具。补上页面类型后，17项完整控制检查通过一轮。

生产空轮恢复、画布独有信息读取、捕获期间同网址重载拒绝、真实断线以及本地进程重启均已有通过记录。连续三轮仍在跑。

分类关闭推理的首轮没有通过。补齐歧义、目标和未来条件校验及有界重试后，完整144次通过，中位约1.1秒，95分位约3.4秒。正式采用后仍保留原15秒总期限。

停播最初被后台轮询定时器误测为约1秒。改用音频线程时间，计入一个渲染周期后，20轮图内停播95分位上界约5.33毫秒。这不代表真人耳机端延迟。

固定回执开始复用已核对对应转写的音频，缓存只在取得本轮实际回执后使用。动态内容不缓存，本地片段不伪装成供应商音频身份。整体语音4秒门槛仍需端到端验收。
