# 接管交还真机验收

## 1. 第一次失败

机器检查先绿了。

真机却暴露了三个问题：交还入口被侧栏挡住，旧控制条不消失，侧栏重开后原任务和对话丢失。

所以第一次结论是未完成。

## 2. 修到同一条路径通过

交还改成两阶段确认。

系统先读取用户当前活动标签和新 snapshot，再把控制权交还给原 Pi 会话。

侧栏历史由后台保存，重开后会恢复。

真机从 Radius 开始任务。用户接管后切到 Wikipedia。交还后，原会话识别到了 Wikipedia 当前页，没有回到、重载或重开 Radius。

## 3. 验收又抓到两个尾巴

第一次点中止后，侧栏出现红色 `Request aborted`。

原因是用户主动停止后到达的 `agent_end` 被误判成模型失败。现在会话只吞掉这次预期停止的尾声。

随后检查发现，扩展重载会让旧 isolated world 的「现在归你」重新出现。

现在后台恢复控制状态时，如果页面不归用户，会主动在当前页清扫旧控制条。

中止还增加了二次清理：控制权立即释放，已进入执行器的旧动作退出后，再清一次光标、回放和控制条。

## 4. 结果

真实路径是 Radius → 接管 → Wikipedia → 交还 → 原会话继续。

接管、当前页交还、同一会话继续和中止清理都出现了预期可见结果。

证据是四张 PNG 和一张 GIF，位于 `docs/evidence/20260905-takeover-handoff/`。

v1 仍不处理完整关闭并重启 Chrome 后恢复原 Pi 会话。
