# 模型面收窄了，单动作轮数没降

方向：按用户批准的三件事①快而果断 ②砍模型面 ③砍用户面推进。

做了什么。标签页五个工具合成 `tabs`，标注两个合成 `mark`；协作工具（post / await_message /
list_workers / stop_worker / take_tab）只在有 worker 时挂载；系统提示词 17,418 → 14,993 字符；
提示词新增单动作 2 轮预算，并删掉代码已守住的重复规则。

结果与反证。模型面确实小了（Lead 无 worker 时 32 → 22 个工具，工具描述+参数 schema 少 26%），
但同一条真实单动作 case（暂停视频，真模型 + 隔离浏览器，各 3 次）的模型调用次数是 4/4/5 → 4/4/4：
没有下降。实测结构是「观察 1 + 动作 1 + 交付 1 + SDK 收尾 1」；改前的多出轮次来自多余的
read_element 复核，这次改后稳定没有复核轮，但观察轮与收尾轮都还在。

原因。① 提示词要求用 `browser_run` 把观察和动作折成一轮，模型（MiniMax-M3）在明确单动作下
仍然分两次调用；② 交付本身是工具调用，SDK 在最后一个工具结果后必然再问一次模型，收尾轮
在工具层取消不了。

下一步的两个真实杠杆（都动架构，需用户裁决）。A：把当前页观察预注入用户消息，模型第一轮
即可动手（少一轮，代价是每条消息多一点上下文）；B：运行时在 finding 交付后判定收尾
（少一次模型调用，代价是要改运行结束语义）。

证据：[本轮标准与结果](../evals/20260911-fast-and-lean.md)。
