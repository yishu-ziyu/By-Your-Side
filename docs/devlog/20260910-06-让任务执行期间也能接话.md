# 让任务执行期间也能接话

## 1. 用户等的是声音

用户指出主要问题是任务结束前一直不出声。页面进度不是本轮重点。范围确定为接话、执行中闲聊和改口，以及一致的说话语气。

## 2. 只解除静音还不够

接收分支原先主动省略回应，后台结果又可能抢占当前回答。先修接话和排队后，真实测试仍出现一次11.93秒等待。分类服务的等待仍挡在声音之前。

因此改为先接话与任务分类并行。先接话只能表达理解和意图，确认修改和完成必须等实际回执。闲聊也不能取消尚待接收的原委托。

## 3. 用户必须能看到测试

此前隔离Chrome静音跑真实服务，保留了录音，但用户看不到过程。用户明确指出这种方式让他痛苦。已打开实际录音回放，并将新版加载到日常Chrome。侧栏重载后被收起，程序打开被用户手势限制拒绝，真实验收待继续。

## 4. 当前结果

最新1044项测试、类型检查和构建通过。较早四轮样本流程通过；最新并行样本2.324秒出声，随后任务模型529过载，整条任务未完成。未判真人体验通过。下一步在日常侧栏可见、可听地完成验证。
