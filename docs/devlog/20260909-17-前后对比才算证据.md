# 前后对比才算证据

## 1. 新读到的文字不证明是这次写入造成的

R3 的恢复工具允许模型在失败后自由给 target 和 expect。只要这段文字出现在新读数里，未知就解除。隔离浏览器用写入前就存在的标题“隔离记录页”就解除了新增动作的未知状态，随后换等价选择器再点一次，服务端和 DOM 都变成 2 条。

问题不在读数不真，在证据和这次写入没有因果关系。

## 2. 证据要绑在写入前的页面上

每次成功的 snapshot / read_element 现在都作为一条页面读数进入结果账本，只留在内存。写入开始时，把该次写入之前最近一条工作页读数冻结成这一项的基线。核查必须同时满足：

- 基线存在，而且没有截断；
- 基线和核查读数是同一个标签页；
- 基线是 read_element 时，核查目标必须和基线相同；基线是 snapshot 时按整页对比；
- expect 出现在核查读数里，并且不在写入前基线里出现。

少任何一条都保留未知。模型不能在失败后换一个更容易满足的范围或文字。

## 3. 页面变了，基线就作废

navigate、open_tab、switch_tab、close_tab、worker_tabs、page_operation、js 一开始，之前的读数和基线全部清掉。跨文档的前后对比没有意义。恢复不了就保留未知，这是正确结果，不是失败。

## 4. 结果

验收者的反例 7/7 通过：无关标题不再解除未知，重试被拦，计数保持 1。新增充分证据正例通过：写入前 snapshot、写入后读到“记录 1”，解除未知并继续剩余步骤，计数仍 1。固定入口 15/15、unknown 反例 6/6、独立边界 10/10、定点 98 项、全量 1014 项、typecheck / build / diff 通过。冻结 4 文件未动。
