# 把语音接回完整的执行能力

## 1. 真实试用推翻了交付判断

用户要求找到页面对象并圈出来。产品只解释页面，还说自己不能圈。随后文字已经出现，语音又等了近18秒，最后没有播出。

此前的测试验证了回答一致，没有验证这条已有能力，也没有把及时开口列为不能退让的结果。测试通过没有代表产品通过。

## 2. 工具没有消失，入口分裂了

主Agent仍有圈画工具。语音入口却先做分类，分类成观察或闲聊就进入没有工具的回答分支。它没有完成剩余动作的出口。

独立探测重建了三句话。明确的“找到然后圈出来”被归为观察；纠正“你可以圈出来的”被归为闲聊；更强的纠正才归为修改任务。最后一种在没有运行任务时也不能自然接续。

此外，旧回答会被当作补答事实。“我不能圈”这句错误话因此可能影响下一次回答。

## 3. 调研后的方向

官方工程资料和Pi现有能力都支持先简化入口，而不是继续增加分支。我们已有工具循环、任务回执、会话恢复和执行闸门，当前没有替换整个框架的理由。

建议让正常文字和语音共享执行会话。能力来自真实工具注册；对话、观察和回执分清来源；尚未满足的用户要求有记录。播放单独消费正式正文，不再依靠整段复述校验后才开口。

## 4. 改动先有标准，再有结果

冻结标准时只完成研究，没有改产品代码。首步只覆盖空闲会话的页面委托和纠正。机器验证后由用户在原页面检查，通过才继续。

冻结12个首步场景，前6个各做2次独立试验。先建立能复现失败的评估器，再实现第一步。语音延迟另做可独立听验的切片。

## 5. 第一轮绿灯里藏着一次假阳性

正常委托已接回主任务。旧的“我不能圈”留在历史里，不再充当能力事实。真实圈画复用已有手绘轮廓和轻微抖动。

但禁用mark的测试仍给了绿灯。模型改用JS画了红框，评估器只检查正式mark的覆盖层，因此漏掉了它。原19次试验只有14个有效通过，另有4个失败和1个假阳性。

修复不能只写“请勿绕过”。任意页面JS无法可靠区分读取与写入意图。写能力不完整时，通用JS通道必须在执行之前关闭，受限读取仍可用。

## 6. 实现者通过，不等于可以交付

新会话按用户指定的DeepSeek路由实现这处补口，主代理负责标准与独立验收。

第一版通过了单测，却误封了正常JS。原因是把内部通道名当成了模型注册的工具名。真实浏览器检查发现了这点。另一条测试又发现，组合执行里的纯读取也被误封。两处都修正后才继续验收。

最终禁用场景中，模型尝试JS时被拒绝。页面没有新增覆盖层、样式或内容写入，答复明确无法画圈。正常JS仍能读写页面；正常圈画仍有手绘抖动，并能跟随滚动和清除。

## 7. 停在用户检查之前

本轮独立终检为938项测试，类型检查和构建通过。最新三个真实场景分别通过9、11、11项检查。所有失败保留，历史证据没有改写成最终源码的全量通过。

证据来自隔离Chrome、生产侧栏与执行器、真实模型和合成麦克风。没有重载用户扩展，没有提交推送。下一步由用户检查S1的语音、文字圈画与纠正；S2和语音及时开口仍未开始。
