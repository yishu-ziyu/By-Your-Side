# 回答不再被核验扣下

## 方向

模型写出的回答直接交给用户。核验只能给回答加标注（部分完成、未确认项），不能扣下回答。写入外部之前的原文核对保留。提问、闲聊、读页和简单页面操作不再先列目标计划；只有把页面原文复制进输入框或文档的任务才走目标账本。

## 原因

2026-09-24 18:42，用户发"你好"，19 秒、4 轮模型调用后没有任何回答，侧栏却出现 3 条内部提示、任务卡、"剩余 1 项"和"继续原任务"。trace（`~/.sideagent/traces/1790246541972-*.jsonl`）显示：模型已经写好问候，但写成了普通正文而不是 `send_user_message`，宿主丢弃正文；补交付又被两级模型复核否决。

翻查 `~/.sideagent/conversations`（268 个会话、409 次请求）：

| 事实 | 数据 |
|---|---|
| 同一句"你好" | 9/07 1 轮 3 秒 → 9/22 11 轮 72 秒未交付 → 9/24 4 轮 18 秒未交付 |
| 每次请求中位耗时 / 输入 token | 9/07–08 约 13 秒 / 1.4–2.2 万 → 9/22 75 秒 / 约 32 万 |
| 9/21 引入目标核验后的 `send_user_message` | 24 次调用，13 次被拒 |
| 目标核验调用 | 188 次，92 次被驳回或挂起；计划复核在概率 0.52–0.6 之间反复驳回同一份计划 |
| 被扣下的正确答案 | "1+1 等于 2"；9/24"找出处"7 次交付全被拒（460 秒、约 100 万 token） |
| 被拒原因里的故障 | "目标核验未完成"是复核模型自身出错/超时；"Unexpected token '你'"是复核模型没返回 JSON |
| 真正拦住的错误 | 1 次：9/22 flomo 复制取了整个 Note 框而非第一句（写入前核对） |

根因：这套核验照搬了无人值守 Agent 的"独立结果验证"（9/20 方向文档引用 Browser Use / Cua），但侧栏里用户本人就在看页面。核验对有人值守的对话几乎没有保护，却让每一次请求付出延迟和"没有回答"的代价。同一套规则还分散在系统提示、工具说明、请求前缀、应用状态快照和"下一步"提示五处。

## 做了什么

- `send_user_message` 与"最后一段正文"共用 `deliverUserMessage`：只拒绝格式无效；账本仍有未完成项时照常交付，标为 partial 并附宿主说明。浏览器调用还在执行时交付但不结束本轮。
- 删除回答复核、部分交付复核、计划的模型复核；计划只保留确定性覆盖检查。写入前原文核对、目标位置核对、来源范围核对不变。
- 未规划的占位计划不再展示给模型，也不再让每个回答被标"未完成"（`nextStepIgnoringPlaceholder`，交付与模型上下文共用）。
- 五处注入规则统一为同一套说法。第一次只改了部分规则，模型为调和矛盾在第一轮推理约 3700 token（glm 上 80 秒以上），"你好"反而变成 104–139 秒；统一后恢复。
- 交付正文上限 2000 → 12000 字，避免长回答因超长被丢弃。

## 持续跟踪

以后每次改交付、提示词、核验或换默认模型，都重跑上面这条命令，把 10 条的通过数、每条耗时、回答以外元素数追加到本表下方。硬线：10/10 有回答；问答类不慢于本次改后数据的 2 倍。单次运行受模型响应波动影响大，看趋势，不拿单次数字下结论。
