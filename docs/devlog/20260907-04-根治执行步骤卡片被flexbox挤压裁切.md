# 根治执行步骤卡片被 Flexbox 挤压裁切

长对话中执行步骤被压成一条缝，图标和文字只露出一半。

今天排查并根治了这个 bug。

## 1. 现象与排查

用户发来截图，反馈侧边栏在对话展开后，“执行步骤”折叠卡片被异常压缩：
- 绿色打勾圆圈被上下削掉一半；
- “执行步骤”中文字符被削去下半截；
- 卡片高度被挤压到不足 20px。

我们通过 CDP 连接到正在运行的 Chrome 侧边栏，读取真实 DOM 的计算样式：
- `details.run-steps` 的 `offsetHeight` 在长会话中甚至直接降到了 `2px`（仅剩上下边框）；
- 但其内部的 `summary` 高度为 `42px`。

## 2. 根因分析

问题出在 CSS 弹性盒规范的隐式默认行为。

1. `#messages` 是一个垂直 Flexbox 容器（`display: flex; flex-direction: column`），当内部消息总高度超过视口高度时，Flexbox 会在子元素间分配负空间（negative space）以尝试塞下所有元素。
2. 普通气泡 `.msg` 为 `overflow: visible`，在弹性盒中拥有隐式 `min-height: auto`（等价于内容最小尺寸），浏览器绝不压缩它的高度。
3. 但 `details.run-steps` 声明了 `overflow: hidden;`。按 CSS Flexbox 规范，一旦声明了非 `visible` 的 overflow，其隐式最小尺寸会直接回退为 0（`min-height: 0`）。
4. 由于未显式声明 `flex-shrink: 0`，Flexbox 计算时把所有多出来的负空间全部扣减在 `details.run-steps` 身上，将其硬生生压成了 20px 乃至 2px 的切片，并在 `overflow: hidden` 的裁剪下露出了被切碎的文字。

## 3. 解决办法

在侧栏样式表建立完整防线：

1. **容器级别**：为 `#messages > *` 声明 `flex-shrink: 0;`。聊天消息流只允许由内向外自然舒展并依托 `overflow-y: auto` 滚动，任何元素均不得被垂直压缩；
2. **卡片级别**：在 `details.run-steps` 显式设置 `flex-shrink: 0; min-height: min-content;`；
3. **Summary 级别**：为 `details.run-steps summary` 显式设置 `min-height: 38px; line-height: 1.5; box-sizing: border-box;`，确保内边距和文字对齐有严格的下限保证；
4. **子级抽屉级别**：为 `.run-body > *`、`details.thinking`、`.chip-group` 全面补充 `flex-shrink: 0;` 防护。

## 4. 验证与数字

1. **测试**：在 `extension/test/steps.test.ts` 新增针对防压缩契约的测试，全量 42 个测试套件、404 个用例全部通过；
2. **真机回测**：在 Chrome 环境注入超高长消息流，`details.run-steps` 在收起状态下高度稳定保持 40px（未展开），展开状态按需伸展到 3400px+，上下边框与内边距舒展，文字图标垂直居中且零裁切。
