# 三轮 live 才过表单门槛：失败分类比重跑更有用

方向：Codex 执行包 PR-06 要求 30 模板 × 5 次 = 150 次隔离真模型，总体 ≥95%、每类 ≥90%。这不是作者旧记录，是本轮用 MiniMax-M3 + 隔离无头扩展自己跑的。用户授权了 USD 200 / 2500 次 / 120 音频分钟，明确不连日常 Chrome。

第一轮以为是关键字太严。拆开后「交付有字但对不上」= 0。真正的 19 次是页面已经对、交付是空的：`agent_end` 后补交付是 fire-and-forget，评测在补完前采样。评测侧加了最多 12 秒等待；产品上补交付仍不许调写工具。

第二轮空交付清零，读取 100%，总通过 93%，表单仍 84%。剩下 11 次全是页面没做成。样本显示单人页去调协作专用 `page_operation`，被拒却记成未知写入，闸门连 snapshot 也拦住，同错三次停手。原生 `<select>` 去 click 系统选择器，headless 没有那层菜单。翻三页是同一颗「下一页」第二次被当成重复点击。

第三轮对着这些改产品，不覆盖前两轮样本：没有协作者时模型看不到 `page_operation`；未知写入只停后续写入；读过页之后同一按钮允许再点。结果 145/150 = 96.7%，读取 100%，表单 96%，多步 94%。门槛过了。累计约 $56.6 / 1414 次。还剩 5 次锁在该 run：过期或格式错误的 ref 仍被记成 unknown、一条十二栏超时、一条 browser_run 没 await。过期 ref 已补结构化 `not_executed`，live 桥回传 executionFact，没有为此再开一轮 150。

结果。机器门槛这一项从 BLOCKED 变成有分母的 PASS。正式版仍不能打：执行包是 AND，真人验收、留出集保管人、声学打断、20k 回执事件循环、侧栏人裁都还缺。

边界。没洗第一、二轮失败。没把 live 过了写成正式发布。没跑 V05 / H01 / H02。

证据：[live 教训](../evals/20260911-live-lessons.md)、[表单死路](../evals/20260911-form-deadlock.md)、run `08-34-18` / `09-14-42` / `10-11-47`。
