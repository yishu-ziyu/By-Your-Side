# 让观察到的对象一直可操作

## 1. 真人失败推翻了什么

用户要求执行中从一个对象改成另一个对象。旧动作被挡住了，新对象却没有圈出来。

此前我过多围绕改口、暂停和结果记录做检查，把局部控制正确当作交付可用。真人失败说明这个判断不成立。检查数量增长，用户承担的试错成本没有相应下降。

这次失败推翻的假设是：模型能读懂页面，就有足够信息操作页面。默认快照给按钮编号，却不给标题和正文编号。定位失败后让模型再看一次，仍然缺少可操作对象。模型只能猜选择器。

## 2. 修复连接，而不是业务案例

内容现在也有来自真实 DOM 节点的引用。它不依赖模型名称、页面布局和 CSS 层级猜测。

跨内容检查随后发现第二次信息丢失：正文圈画最初正确，滚动后却贴到整段容器上。绘制层此前只拿到坐标，然后重新找锚点。

现在同一个节点进入绘制环境。文字用 Range，元素用自身边界。滚动后继续跟随该节点，失效后不换成另一个同名对象。

工具失败也不再解释为用户撤销授权。明确未执行的定位失败可以重新观察后恢复。结果未知、取消和接管仍然禁止自动重放。

## 3. 验收要能反驳实现

新验收更换内容和结构，加入同名标题、普通正文、图片和 Shadow DOM，并检查滚动后的实际圈画范围。恢复检查故意制造一次未命中，观察模型是否自行完成原目标。

测试图片一度没有加载，截图暴露了这个问题。修正夹具并检查图片实际解码，才接受图片结果。中途失败全部保留，没有用最后一次成功覆盖它们。

本轮最终 991 项测试通过，真实模型的并排改口及不同内容恢复有逐项证据，扩展已重载。完整证据见[验收记录](../evals/20260909-observation-action-recovery.md)。下一步是日常使用中的体验验证，不能从这些样本推出所有网页都可靠。
