# 明确状态分工与需求修订

## 1. 取舍

用户认可从 Project Working Loop 吸收四项规则：状态分工、需求修订、连续推进、阶段收尾。逐步审批没有纳入默认流程，已授权的开发无需每一步重新等待。

## 2. 边界

用户修改需求后，记录应跟着更新。实现方为了让代码通过而降低验收要求，仍被禁止。

当前状态可以压缩，原始标准、实测证据和重要失败原因必须保留。文档记录也不能替代真实授权。

## 3. 结果

四项规则写入 AGENTS.md，并协调原有校验与记录要求。验收见 [完成标准](../evals/20260909-working-rules.md)。产品代码改动 0 处；后续任务按新分工维护记录，历史记录本次不迁移。
