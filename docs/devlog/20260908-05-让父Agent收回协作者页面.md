# 让父 Agent 收回协作者页面

## 1. 问题

协作者开了页面，任务结束后，父 Agent 仍可能无法关闭它。

原来的授权只检查页面属于哪个会话、当前成员是否在名单里。父 Agent 没有管理同会话成员页面的能力。停止协作者时，也只清理了显式共享页。

## 2. 改动

父 Agent 切换或关闭协作者页面时，先停止相关成员，再接手页面。

协作者完成、失败或取消后，它打开过的页面都交回父 Agent。页面和结果保留，由父 Agent 根据用户要求继续操作或关闭。

不同会话仍然隔离。用户接管页面时，父 Agent 的管理动作也不能越过接管限制。

## 3. 为什么需要等待

停止模型不等于已发出的浏览器操作结束。

扩展先拒绝后续调用，再等待已经开始的操作结束。还在排队的共享页写入取消。确认移交后，父 Agent 才继续操作。

## 4. 验证

真实 Chrome 已验证两个历史页面移交、内容保留、父 Agent 切换与关闭，以及跨会话拒绝和迟到操作拒绝。

真实模型首轮多开了一个空白页，没有满足两页条件。后续自主派工又遇到模型超时。最终通过生产派工接口固定初始条件，让真实 worker 完成读取，再由父 Agent 模型处理清理请求。两个页面实际关闭。

最终机器检查通过。真实页面权限检查 10 项、真实模型清理检查 4 项通过，现有会话与用户接管浏览器回归通过。扩展已重载，下一步由用户在原会话体验清理操作。
