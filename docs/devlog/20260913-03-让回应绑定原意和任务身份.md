# 让回应绑定原意和任务身份

真人连续三次确认后仍收到复述，说明词表通过不能代表对话接得住。扩大实测又发现跨页误操作、交还按钮无响应，以及旧“已中止”状态盖住新任务。

本轮保留原架构，修正三个状态边界：

- 待确认绑定的是用户要求，不是必须紧邻的语音采集轮次。问进度、系统只读恢复和空白轮不消耗待办；确认、取消、新指令或新话题才消费，原任务身份、有效期和原资料仍校验。
- 发送任务时的页面成为缺省执行目标。固定目标必须传到真实点击、填写、截图等执行器；只给预观察加页面编号不够。原页关闭后失败，不替用户选另一页。
- 页面控制条绑定其来源会话，任务状态绑定runId。活动页可能不是任务所属页；新任务也不能沿用上一轮中止状态。同一任务的交还续跑则保留原状态。

这些决定来自失败路径，而不是源码审查的抽象建议。机器检查、原生操作和未跑的真人声学验收分别留证，见[本轮验收](../evals/20260913-interaction-loop-audit.md)。
