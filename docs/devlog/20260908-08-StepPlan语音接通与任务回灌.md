# Step Plan 语音接通与任务回灌

## 1. 连接方式确定

用户确认使用阶跃星辰 Step Plan。随后提供了测试 Key。

真实连接确认模型为 StepAudio 2.5 Realtime。专用套餐端点和“我的音色 03”均可用。输入音频、服务端断句、转写与语音返回也取得了成功样本。

## 2. 长任务可以和交流并行

我们让一个本地任务等待 30 秒，立即向模型返回“已接收”。等待期间模型回答了另一个问题。任务完成后，再把随机生成的结果补充给它，它准确读了出来。

这说明可以让现有 Pi 执行网页任务，让阶跃继续交流。

一次失败改变了消息接法。服务端拒绝 system 角色的任务更新，只接受 user 或 assistant。改用带明确应用数据标记的 user 消息后，结果回灌通过。产品自己的历史仍要保留真实来源。

## 3. 工具存在，触发仍不稳定

模型有时会真正调用工具，有时只读工具名称或声称无法查询。随机结果回读证明工具能力存在，失败样本说明不能只凭模型说“开始了”来改变产品状态。

自然语音的自动断句和手动提交都出现过成功与失败。换提交方式还不能被认定为根治方法。

我建议下一步先接语音查询真实任务进度，做好调用、接收和结果回执，再扩大操作范围。

## 4. 数字与边界

保留 6 轮探针记录。30 秒后台等待期间的独立问题在接收任务后约 3.1 秒完成回答。两次短文本到首音频到达约为 0.9 秒，这不是用户听感或完整往返延迟。

产品代码改动 0。未打开麦克风、播放声音或操作网页。Key 只在探针进程内使用，进程已退出。下一步验证自然工具触发和真实耳麦体验。
