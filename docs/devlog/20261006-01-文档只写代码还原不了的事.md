# 文档只写代码还原不了的事

- 日期：2026-10-06。规则见 [AGENTS.md](../../AGENTS.md#文档每次功能修改应执行)和[文档维护](../development/documentation.md)。
- 原来：项目规定改功能应在同一变更里改对应文档，`check:docs --base` 按代码路径强制检查。结果每次改代码都把常量、字段和流程抄进文档；文档和代码各存一份，代码一变文档就过时。
- 现在：核心原则是“代码能还原的别写进文档”。文档只写为什么、放弃了什么、用户看到什么、现状和踩过的坑。强制同步检查已删除。来源：[The Death of Documentation](https://prefactor.tech/blog/the-death-of-documentation)、[Docs in the Coding Agent Era](https://nyosegawa.com/en/posts/docs-in-agent-era/)。
- 写法：按 ASD-STE100 精简技术写作，用词以[术语表](../glossary.md)为准。规则和检查脚本来自 hai-simplified-technical，用时临时下载，不安装。
- 结果：长期文档约 31 万字符降到约 24 万字符；删掉 2 篇只剩链接或已实现的提案。清理时发现几处文档与代码矛盾（已删的下载工具、已删的确认卡、退役的 Jev），已按代码改正。
- 不变的：验收记录、开发日志和历史快照保留原文，不按新规则改写。
