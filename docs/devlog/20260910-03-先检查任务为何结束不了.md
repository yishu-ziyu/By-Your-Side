# 先检查任务为何结束不了

## 1. 声音正常不等于任务顺畅

用户确认新的语音可以工作，但暂停视频迟迟不汇报，随后读评论的要求也被阻塞。用户要求先研究整个项目与优质做法，再讨论改法。

## 2. 慢发生在执行前后

真实轨迹里，暂停任务经历7轮模型，记录6429个推理token，工具累计185毫秒。49秒后视频才暂停，确认成功后又等73秒才出声。新要求接受后等待63秒才进入模型消息流。

当前记录要求工具方式与登记相同，却没有同等严格地检查用户结果。已安装Pi的改口是轮次边界投递；播报又只看同run，无法区分其中已经变化的要求。这些比音频延迟更接近本次断点。

## 3. 先明确边界，再选提速方法

对照Pi、LiveKit、Stagehand、Browser Use、Anthropic和Will's S资料后，暂不建议替换整套框架。先明确完成、改口和播报资格，再比较轮次、上下文与推理配置。保留权限与unknown副作用保护。

本轮仅研究与模块探针，未改产品。候选数字不是达成承诺；完整证据、取舍及实验在[调研报告](../research/20260910-agent-responsiveness/report.md)。本轮原因已在报告与探针说明，不重复新增wiki经验或规则提案。
