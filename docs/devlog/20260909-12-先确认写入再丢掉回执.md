# 先确认写入，再丢掉回执

## 1. 为什么先复现

代码显示，超时可能进入普通失败。但这还不能证明网页真的会被写两次。

本次先冻结验收标准，再用隔离页面记录实际新增次数。第一次写入确认后，测试丢弃回执，随后再次请求同一动作。页面计数与服务端记录分别核对。

## 2. 发现了什么

正常路径新增一条。超时和断连两种故障都先新增一条，再被记为blocked。重新登记后，第二次点击通过生产执行检查，最终新增两条。

问题不只在提示词。执行结果不明被压成普通失败，使现有unknown保护没有发挥作用。

## 3. 交付边界

本轮交付工程任务书、冻结标准、可重跑验收器与修复前证据。没有改产品。固定驱动替代了模型调度，CDP桥替代完整生产传输，不能称完整用户路径已复现。
