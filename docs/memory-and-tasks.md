# 记忆、过往任务与任务跨轮

本页写记忆、过往任务和任务跨轮的边界与取舍。记什么、记成哪种、用在哪里，见[记忆模型](memory-model.md)。

## 个人记忆

- 操作失败时，侧栏不显示成功结果。
- 网站范围只限制助手在哪里使用记忆。记忆面板仍列出全部条目。
- 程序读不懂的数据，或比当前版本更新的格式，只读不写，不当作空记忆覆盖。
- 网页、附件和工具输出都不能自行授予修改记忆的权限。
- 判断一句话要不要记的期间，如果新消息、中止或接管让这句话作废，判断结果不写入。
- 诊断记录不写用户原话和记忆原文。

**纠正后学成做法。** 关于网站怎么操作的，直接记下，回答下面一行「记下了：……」给撤销；关于你个人或助手说话方式的，仍问「要我记住吗」（10-16 用户定：纠正就是为了让它学会，每次再问是让用户多点一下）。见[纠正闭环](evals/20261016-correction-loop.md)。

- 助手只看用户直接发的话，包括任务运行期间的插话；网页、附件、工具结果里的话不算。插话在后台会开新的一轮，连插几句时前面的会被盖掉，所以插话先单独留下，一轮结束后逐条判断。
- 两种判断：一种找以后都照做的工作方式（「导出先选全部」）；另一种找「你这样说时指的是什么」（「在 YouTube 说右边第二个，是右侧列表从上往下第二个」）。只用第一种时，使用记录里的真实纠正一条都学不到，因为它们多半是「没理解你指的是哪一个」。
- 回答先显示，然后程序才问快速模型。
- 做法的文字应出自用户原话。如果做法里有原话中没有的邮箱、网址或长数字，助手这次不问。
- 做法所属的网站，取用户说这句话时所在的网页，不从原话里解析网址。
- 询问期间，如果用户又发话、中止或接管，程序丢掉这次询问，不发过时的询问。

**判断失败后补判。** 补判前，如果用户已改动这次补判涉及的记忆，程序作废这次补判。代价是可能少记一条，但记忆不会被改回旧值，也不会新旧并存。

用户忘记一条记忆后，原来的会话记录仍保留。记忆没有按 Chrome 配置分开存储，所以不应宣称已实现浏览器配置隔离。

## 过往任务

- 只记做成了事的任务（会留下后果的），以及没做完的任务。只读的查询不记。
- 平时带给助手的只有「做成了什么」，不带当时的回答。因为回答里有当时页面上的价格、重量这类信息，助手会不看页面就照抄。用户问起过往时，查过往的工具才附上当时的回答，并标明可能过期。
- 旧条目没有「做成了什么」，平时只带原话目标。
- 写入前，程序只隐去密码、验证码、卡号等具体值，不删整段。
- 过了有效期的过往任务，助手仍能查到。
- 程序读不懂的过往任务只读不写。只有「全部清空」会连读不懂的条目一起清掉。

## 任务跨轮

上一个任务部分完成时，程序按简单规则判断用户的下一句是否算接着做，不调用模型，因为调用模型会让回应变慢。
接着做时，任务和目标不变；恢复提示写明这是用户的补充，不是重启。

## 扩展会话恢复

- 会话恢复复用 Pi 原生的会话与存储规则，不另写一套。记录存在扩展里，不访问本机文件系统。
- 恢复旧消息时，程序不自动执行旧的工具调用。中断的任务先读取当前页面；用户说继续之前不执行写入。
- 个人记忆不替代当前会话记录。旧版本从未保存的消息，不能凭侧栏回放还原成完整的执行证据。

文件正文独立保存，见[文件卡片与截图](artifacts.md)。
