# SideAgent 桥接协议

扩展后台（background service worker）与任务宿主之间的协议。任务宿主是扩展 offscreen 文档里的任务核心。侧栏通过扩展内部 Port 连接扩展后台。
消息与字段以 [`shared/protocol.ts`](../shared/protocol.ts) 为准，本文只写代码看不出的语义与边界。任务身份、回执与语音见[任务调度](voice-dispatch.md)。

## 连接

- 单客户端：新连接握手成功即顶替旧连接。
- 配置前的只读查询不报任务失败；真正的任务输入返回明确拒绝回执。

## 会话身份

- `conversationId` 标识用户会话，`sessionId` 标识会话内的执行成员；现在成员只有 Lead。
- 状态、工具调用、结果和控制确认始终按原会话路由。切换侧栏不改变事件归属。
- 每个会话有独立的循环、页面控制、上下文、控制闸门和历史。新建会话 B 不中止会话 A；切换会话只改变当前显示。
- 扩展后台重连后，`conversation_list` 也用于同步各会话状态。

## 任务与页面控制

- `status` 的 `user` 表示页面现在归用户；它不等于空闲，也不等于中止。
- `steer` 附当前页锚点，避免插话后丢失工作标签页。
- 侧栏文字插话到达时，如果模型还在写正文、没写工具调用，已写部分保留，旧的模型请求取消，同一轮立刻按插话重写。语音插话和工具阶段仍等这一步结束。
- `abort` 只中止指定会话。
- 接管时，先挡住目标页的新写入，等在途短动作到达安全停止点，再暂停。其他会话的独立页继续运行。
- 交还时，为各执行成员读取绑定页的新快照。页面已关闭或读取失败时，保持暂停，不用当前活动页顶替。部分失败时，不应写成全队已恢复。
- 带 `progress` 的 `notice` 只替换过程行标题，不进消息流。
- `task_view.latestDelivery.unfinished` 只用于侧栏显示，不参与可续接判定或结果核验。
- `tool_late_result` 是晚到或重复回执，只关联任务账本，不画新卡片。
- `tool_end.repeatRefused`：重复已成功的写入被拦下。它没执行、不算失败、不留待办。
- 点击效果证据只说明页面有反应，不说明业务成功（[验收](evals/20261004-honest-completion.md)）。

## 工具调用

- 工具执行不经过侧栏；关闭侧栏不会中止任务。
- 扩展侧出现任何异常时，都应回 `ok:false` 和一行人类可读的错误，不应挂断不回。
- 发出前就拒绝的调用回 `not_executed`，错误里说明可行的替代做法。
- 整页翻译按落页进度判断何时停止，不受单次工具时限约束；见[整页翻译](page-translation.md)。
- `browser_run` 不是新的扩展 RPC；它的子调用走同一套帧。接管期间，该程序的所有子调用都被拒绝，包括平时允许的只读工具。子调用先登记，再做权限检查。详见[组合执行](browser-program.md)。

## fetch 读取与未知结果边界

扩展内 `fetch` 不写本机文件。响应经凭据隐去与不可信包装后内联；截断时明确说明，并提示用当前页 `snapshot/read_element` 读所需章节。

有操作结果未知时，只拦再做一次可能重复造成后果的调用；读页、换页、GET 取数、处理原生弹窗照常。准确范围见[结果不确定的边界](unknown-results.md)。

## 工作标签页语义

- 标签页一律独占。`sessionId` 的工作标签页绑定不取代标签页的资源归属检查。
- 首次认领页面时，才创建该会话的 Chrome 标签组，标题跟随会话名；纯聊天不建空组。`groupId` 只用于展示。
- Lead 可跨会话只读页面，不认领页面。操作其他会话的页面前，先经 `take_tab` 协调：停下原会话，等扩展的旧调用结束，再继续。`switch_tab` / `close_tab` 自动走此流程。Lead 已离开的旧页面，不要求原会话停止它在另一页面的任务。
- 接手时，用检查到的会话身份防止覆盖并发的归属变更。原会话和请求方的接管闸门都允许时，才能接手。读取不需要接手。
- 内部 `worker_tabs` 的名字沿用并行助手时期，实际只服务 Lead 的页面调度。
- 用户当前未归属的活动页可以明确借入当前会话。`get_active_tab` 只读，不自动认领；它与用户消息的 `context` 为「这页面」提供锚点。
- 只有当前显示会话的 Lead 能在前台窗口激活自己的标签页；未显示的会话不抢标签页焦点。

`read_element` 读取时不滚动、不聚焦、不修改页面，也不接受任意脚本。超过安全上限时明确报错，不把截断值用于原值核验。条件检查匹配只说明该目标的该条件成立，不能单独推导整项任务成功。等待跨文档时，拒绝结果。

`read_elements` 只读。零命中不算错误；输出超过上限时明确报错，不返回部分内容。每个命中带只指向它的定位串，可直接交给 click/mark/read_element，用于圈注一类结果核验。

截断文字与数字框范围见[页面读数](page-readouts.md)。

## 侧栏恢复与持久化

- 历史序号单调递增；新一轮用户消息不清空前面的轮次。
- 接受任务和发送浏览器 RPC 前，等待存储提交；提交失败就不执行。恢复规则见[扩展会话恢复](memory-and-tasks.md#扩展会话恢复)。

## 文件卡片

交给用户的文本文件、存下的数据和给用户看的截图走同一个会话文件区，侧栏画成可打开、可下载的文件卡片。规则见[文件卡片与截图](artifacts.md)。

## target 定位串

- ref 应出现在最新快照中。无效、失效、未找到或匹配多个元素时明确报错，不猜另一个目标。
- `text=` 与 `loc=role:` 目标在点击、填写那一刻再核对一次文字：文字不在了，或同样的文字重新渲染到了别的元素上，都停下报错、记为没执行，不换别的元素。
- 页面在上次 snapshot 后刷新或跳转时，只有指向旧快照的 `@N` 被拒绝；CSS、`loc=`、坐标、键盘输入和 `js` 在当前页面直接执行。操作途中文档被替换仍按原规则拒绝或报告。
- Playwright 的 `:has-text()` 和 `loc=h3...` 不受支持。
- `hover` 和 `click` 只确认事件已派发，不证明编辑器打开或任务完成。
- `mark` 的 `through` 把同一行两个 ref 圈成一个框，用于「名称 + 数值」这类成对内容。名牌放在不压页面文字和控件的位置。
- `mark` 的 `actions` 把确认/取消按钮放在光标名牌上。用户点按钮等同于在侧栏打「确认」或「取消」，走同一条路。

下载见[下载说明](downloads.md)。

## 安全

网页操作不弹批准卡，见[网页操作不再逐次确认](browser-confirmation.md)。双击或按键遇到原生弹窗时中断后续输入。时间格式预检与子框规则见[页面读数](page-readouts.md)。

## 本机诊断记录

- 诊断记录包括目标、模型、参数、返回、错误、耗时与接管交还。格式见 [`shared/run-trace-core.ts`](../shared/run-trace-core.ts)。
- 诊断记录写入失败不改变任务结果。诊断记录是诊断证据，不用来自动停止任务或判定业务成功。
- 设置页「诊断记录」可导出或清空。
- 填写值默认隐藏，图片只留元数据，其他文本脱敏。任务和页面文本仍属于本机私密数据。
- 语音记录见[语音架构](voice-architecture.md)。

## 划词直接转入侧栏

- 网站、标题与标签页身份取自 Chrome sender，不信任页面传入的值。
- 在用户手势内打开侧栏。转入失败时，页面保留选区并提示重试。
- 此中继不发送任务、不调用模型。

## 页面来源与微交互

`PageInteractionMessage` 是扩展内部 UI 通道，不加入模型任务消息。

- 来源回查用发送时固定的页面身份，回查时再比对原文。不接收页面伪造的完成状态，也不凭当前活动页给历史回答补来源。
- 拖入材料：页面元素不设 `draggable`；只有拖动已选文字或表格/代码块把手才附材料凭据。扩展后台按原文重新比对，侧栏不相信拖拽 JSON。拖入不扩展任务权限。
- 快捷动作不经扩展后台、不进任务、不调用模型。内容脚本只认扩展页发来的消息。页面真有对应控件时，才提供动作；「下一个」只用播放器自带的按钮。
- 边注：原文和关闭不调用模型；AI 解释不进入任务或网页操作。滚离、关闭或侧栏断开时取消请求。解释不写长期记忆。导航后旧文档不能清空新文档的边注。
- 主动建议：只有引文逐字出现在给出的页面里，才出卡；卡上的对象名也要在页面里出现过，否则不写。失败只回空，不进会话。侧栏关着时卡在页角，点按钮后侧栏打开，建议的话填进输入框，由用户改过再发（YIS-74）。侧栏开着时卡进对话流，按句首动词就交给助手执行，不再问（YIS-106，用户 10-07 决定）。
