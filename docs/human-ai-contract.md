# By Your Side 的人机协作约定

来源：

- [Taras Bakusevych，39 Principles for Designing Human–AI Interaction](https://syntaxstream.substack.com/p/42-principles-for-designing-humanai)，
  由 [Adham Dannaway 转发](https://x.com/AdhamDannaway/status/2097328604128374967)。
- [Will's S Design Note / AI产品设计指南](https://app.notion.com/p/1f8886bc60ff81f8ba2bdf6c65d28bef)。

本页是本产品对这些原则的应用判断，不是原文翻译，也不是要自动新增的功能清单。

设计目标：用户知道如何开始，能核对助手的结果，能在出错时带着原任务继续。新增功能不应用更多提示、确认或诊断信息代替解决问题。

## 每条使用路径都要检查的事

每个使用时刻写两件事：本产品的约定，以及检查方式。

**打开新会话**

- 约定：打开侧栏时恢复上次的会话，点「＋」才明确新建。空会话应让人看出这是浏览器 AI 助手，并给出少量真实可做的起点。
- 约定：建议只填草稿，由用户决定发送。例外是侧栏里的主动卡：用户按句首动词，就把这件事交给助手做（用户 10-07 决定，见 YIS-106）；任务里遇到登录、付款等，仍按原规则停下。
- 约定：会话就绪前不允许发送；用户提前输入的内容留在新会话的草稿里。
- 检查：点建议后输入框出现内容，发送前没有模型或页面操作；慢连接和切换会话时，已有的草稿和附件不被覆盖。

**助手在工作**

- 约定：展示当前任务的状态；页面控制以程序状态为准。语音状态不应用写死的文字冒充实时事实。
- 检查：真正运行、暂停、交接三种状态分别检查；不凭光球在动就断言任务仍在跑。

**查看结果**

- 约定：先给简洁结论。用户需要核对时，能找到来源、实际变化和未完成的部分；不用信心分数代替依据。
- 约定：执行过程里的「核对 n/m」是代码对回复和文件做的核对，只数这一轮适用的几条；一条都不适用时不显示。这些核对只标出可疑处，不判断结果对错，也不拦下结果。
- 约定：改过网页的一轮，侧栏先显示程序从网页读回的实际内容，助手的回答等目标核对出结论再显示（[验收](evals/20261009-claim-after-check.md)）。
- 检查：用有来源的结果、缺依据的结果和部分完成的结果分别检查。

**要求有误**

- 约定：用户能在当前会话补充或纠正，原页面、附件和任务身份保留。记录诊断不应冒充纠正。
- 检查：修改后接回原任务；诊断按钮不重新派发、不改语音状态，并写明用途。

**执行与撤回**

- 约定：网页操作直接执行、不逐次确认（2026-10-04 用户决定，见[网页操作不再逐次确认](browser-confirmation.md)）。结果未知时不重做；中止后不复活旧动作。
- 检查：原授权、变更参数、中止、迟到回执各测一次；不把撤销页面上的界面当作撤回已发出的消息。

**发生故障**

- 约定：说明实际失败在哪里，保留未送达的草稿和已完成的结果，提供真实可用的继续方式。
- 检查：断连、无回执、部分失败三种场景；不应把“未运行”写成成功。

**长期使用**

- 约定：记忆、观察和模型选择都可查看、可控制；成本与技术细节只在影响判断时显示。
- 约定：用户原话直接记，并给撤销。从纠正里归纳的做法先问用户，用户点「记住」才生效，可改范围、撤销、忘记。网页内容和助手自己都不能写入记忆。
- 检查：重开侧栏和切换会话后验证。更换模型时复用行为评测，不因模型新就认定更可靠。纠正询问按[记住我的纠正](evals/20261001-remember-corrections.md)的场景检查。

## 对原文全部原则的处置

编号沿用原文，右侧是本产品落点，不逐条复刻通用原则。

| 原文编号 | 本产品落点与边界 |
|---|---|
| 1–3 | 模型用于理解/生成，控制闸门和请求身份仍由程序判断；普通阅读与多步操作沿不同交互路径，不把所有动作改成对话审批 |
| 4–9 | 新会话入口和角色说明；保留现有模型入口（教学、示范入口已于 10-04 删除），不改已定角色视觉，也不添加“拟人客服”承诺 |
| 10–15 | 结果来源、未完成项目和内容依据；代码具备 Markdown 链接不等于所有答案都已正确引用，不凭本文宣称已通过来源质量评测 |
| 16–18 | 摘要与细节分层、真实工作进度；完成状态归到结果，历史成功恢复回执收进对应过程，输入区保留尚需行动的信息；语音诊断属于排障细节，不应与用户任务状态混排 |
| 19–24 | 纠正、暂停、手动接管、键盘可达与偏好；只在影响结果的歧义处追问，已知授权不反复确认 |
| 25–28 | 原任务上下文保留、部分完成和失败回执；外部动作不假装可一键撤销，不添加没有实际恢复能力的按钮 |
| 29–31 | 草稿可改、建议可忽略、发送由用户决定（侧栏主动卡的动词是用户明确按下的发送）；普通探索不额外设置审批步骤 |
| 32–35 | 已有授权票据、页面归属、记忆/观察边界；网页内容是数据，不自动变成指令，也不因本文扩大数据采集 |
| 36–39 | 等待可理解、可叫停、变更后有回归；继续保留真实路径与真人语音的分层验收，不应用使用次数证明价值 |

本文作为后续交互改动的检查入口。当前完成情况只看 [STATUS](STATUS.md)，本次证据见 [落地验收](evals/20260914-human-ai-interaction.md)。

执行过程里的“本轮结束”只表示这一轮停止运行，不代表用户的目标已完成；部分结果和结果未知的操作仍由回执说明。模型内部的状态字段不作为面向用户的说明。
