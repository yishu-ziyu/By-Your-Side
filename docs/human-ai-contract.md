# By Your Side 的人机协作约定

来源：[Taras Bakusevych，39 Principles for Designing Human–AI Interaction](https://syntaxstream.substack.com/p/42-principles-for-designing-humanai)，由 [Adham Dannaway 转发](https://x.com/AdhamDannaway/status/2097328604128374967)。结合 [Will's S Design Note / AI产品设计指南](https://app.notion.com/p/1f8886bc60ff81f8ba2bdf6c65d28bef)。以下是本产品的应用判断，不是原文翻译，也不是自动新增功能的清单。

设计目标：用户知道如何开始，能核对 Agent 的结果，能在出错时带着原任务继续。新增功能不能以增加提示、确认或诊断信息代替解决问题。

## 每条使用路径都要检查的事

| 使用时刻 | 本产品的约定 | 检查方式 |
|---|---|---|
| 打开新会话 | 看得出这是浏览器 AI 助手，并有少量真实可做的起点；建议只填草稿，用户决定发送；会话就绪前不允许发送，提前输入仍留在新会话草稿 | 点建议后输入出现，发送前无模型/页面操作；慢连接和切会话时已有草稿/附件不被覆盖 |
| Agent 在工作 | 展示与当前任务有关的状态，控制权以程序状态为准；语音状态不能用写死文字冒充实时事实 | 真正运行/暂停/交接分别检查；不靠光球动了就断言任务仍在跑 |
| 查看结果 | 先给简洁结论；需要核对时能找到来源、实际变化与未完成部分；不能用信心分数代替依据 | 用有来源的结果、缺依据结果及部分完成结果分别检查 |
| 要求有误 | 能从当前会话补充或纠正，保留原页面、附件和任务身份；记录诊断不能冒充纠错 | 修改后接回原任务；诊断按钮不重派发、不改语音状态，并明确其用途 |
| 执行与撤回 | 沿用已有授权范围；后果较大的动作在真正发生前给可核对的确认；停止后不复活旧动作 | 原授权/变参/停止/迟到回执各测，不把撤销页面UI当作撤回已发消息 |
| 发生故障 | 说明实际失败处，保留未送达草稿和已完成结果，提供真实可用的继续方式 | 断连/无回执/部分失败场景；不能把“未运行”写成成功 |
| 长期使用 | 记忆、观察与模型选择可查看可控制；只在影响判断时显示成本与技术细节 | 重开与切会话验证；模型更换复用行为评测，不因模型名字新就保证更可靠 |

## 对原文全部原则的处置

编号沿用原文，右侧是本产品落点，不逐条复刻通用原则。

| 原文编号 | 本产品落点与边界 |
|---|---|
| 1–3 | 模型用于理解/生成，控制闸门和请求身份仍由程序判断；普通阅读与多步操作沿不同交互路径，不把所有动作改成对话审批 |
| 4–9 | 新会话入口和角色说明；保留现有模型/教学/示范入口，不改已定角色视觉，也不添加“拟人客服”承诺 |
| 10–15 | 结果来源、未完成项目和内容依据；代码具备Markdown链接不等于所有答案都已正确引用，不凭本文宣称已通过来源质量评测 |
| 16–18 | 摘要与细节分层、真实工作进度；语音诊断属于排障细节，不能与用户任务状态混排 |
| 19–24 | 纠正、暂停、手动接管、键盘可达与偏好；只在影响结果的歧义处追问，已知授权不反复确认 |
| 25–28 | 原任务上下文保留、部分完成和失败回执；外部动作不假装可一键撤销，不添加没有实际恢复能力的按钮 |
| 29–31 | 草稿可改、建议可忽略、发送由用户决定；普通探索不额外设置审批步骤 |
| 32–35 | 已有授权票据、页面归属、记忆/观察边界；网页内容是数据，不自动变成指令，也不因本文扩大数据采集 |
| 36–39 | 等待可理解、可叫停、变更后有回归；继续保留真实路径与真人语音的分层验收，不能用使用次数证明价值 |

本文作为后续交互改动的检查入口。当前完成情况只看 [STATUS](STATUS.md)，本次证据见 [落地验收](evals/20260914-human-ai-interaction.md)。
