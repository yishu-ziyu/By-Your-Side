# 网页操作

[当前状态](STATUS.md) · [不再逐次确认](browser-confirmation.md) · [下载](downloads.md) · [结果不确定的边界](unknown-results.md)

本页是“网页操作现在做到哪、还差什么”的唯一位置。STATUS 只留一句摘要。

## 现在

- 点击、填写、回车直接执行，不弹批准卡（[验收](evals/20261004-remove-approvals.md)）。
- 下载完成或中断都如实回报（[下载](downloads.md)）。
- 取到的数据可以直接存成侧栏文件（[验收](evals/20261001-data-to-file.md)）。
- 原地打转时，助手自己停下并说明。
- 点「发送」前，先在网页上问用户（10-09，[验收](evals/20261009-send-confirm.md)）。
- 付款按钮永远由用户自己点（10-10，[验收](evals/20261009-pay-stop.md)）。
- 助手在后台标签页里做事，不换走用户正在看的页。只在发送确认、付款停下、交给用户、教用户一步时，才把自己的页切到前台（10-10，[验收](evals/20261010-keep-foreground.md)）。
- 目标被挡住时，助手不点，工具结果写出挡住它的元素。目标不可用（disabled、aria-disabled）时，助手不点，工具结果说明原因，不再写「页面没有变化」（10-11，[验收](evals/20261011-click-blocked-reason.md)）。
- 点击和回车之后，网站还有没回来的请求时，程序等它回来再判断页面变没变，最多等 3 秒。所以结果晚到的页面不再被说成「没变化」；回车也报告页面有没有反应（10-11，[验收](evals/20261011-settle-after-requests.md)）。
- 用户说「教我…」「一步一步指给我看」时，助手一次只教一步：圈出目标，光标停在旁边，等用户自己点，自己从不点。点错时页面上提示，步骤不变；点中后页面在 3 秒内毫无变化，就提示「好像没有生效」，这一步不算完成（10-11，[验收](evals/20261011-guided-teaching.md)）。
- 助手把登录、验证码、卡号这类只有用户能做的一步交给用户时，页面上用橙色圈圈出要填的栏和要点的按钮。用户填好一栏，这一栏的圈就淡出；交还或停止时圈全部清掉（10-12，[验收](evals/20261012-handoff-circle.md)）。
- 用户说「切到某页」「给我看某页」时，助手把那一页切到用户眼前；平时照旧不换用户眼前的页（10-11，[验收](evals/20261011-show-page-to-user.md)）。gpt-6-luna 上还做不到，见验收里的 10-12 复查。

## 还差

- 失败时会露出 Chrome 错误码。
- 教学只认网页顶层文档里的点击：iframe 里的目标教不了；整屏、浏览器外的教学也不做。打字、拖动这类点一下确认不了的步骤，只在回答里说明。
- 交给用户时，跨域 iframe 里的单个栏圈不到，只能圈整个 iframe；这类圈不会淡出。
- 回车发送、iframe 里的按钮、页面脚本直接点击，都不经过发送确认，所以不拦。
- 助手点开新页的同一刻，如果用户也在自己的页上点开新页，扩展可能跟错页。
- 点击只发出 GET 请求、页面又没变时，工具结果写「页面没有变化」：GET 故意不算有反应，因为统计、轮询这类后台请求多是 GET。
- 动作之后隔一段时间才发出的请求（输入防抖、定时器里的请求），程序等不到。
- 带 aria-disabled 的按钮一律不点。少数网站故意这样写，点了会弹出「请先填完」这类提示；在这些网站上，助手会少做这一步。
