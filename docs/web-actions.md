# 网页操作

本页是“网页操作现在做到哪、还差什么”的唯一位置。不逐次确认的决定见[网页操作不再逐次确认](browser-confirmation.md)。

## 现在

- 点击、填写、回车直接执行，不弹批准卡。
- 下载完成或中断都如实回报（[下载](downloads.md)）。
- 原地打转时，助手自己停下并说明。
- 点「发送」前，先在网页上问用户。付款按钮永远由用户自己点。
- 助手在后台标签页里做事，不换走用户正在看的页。只在需要用户看或动手时（发送确认、付款、交给用户、教用户一步），助手才把自己的页切到前台。
- 目标被挡住或不可用时，助手不点，工具结果写出原因，不写「页面没有变化」。
- 填写用真实键盘输入写进框里，只认真实键盘的搜索框、按 beforeinput 更新的编辑器也收得到；日期、下拉框这类照旧直接设值（[真实键盘填写](evals/20261014-fill-typing.md)）。搜索框和普通单行框可以「填完回车」；旁边有「发送」「支付」、像消息框、多行框和编辑器都不给。
- 点击和回车之后，网站还有没回来的请求时，程序先等它回来再判断页面变没变。所以结果晚到的页面不再被说成「没变化」。
- 用户说「教我…」时，助手一次只教一步：圈出目标，等用户自己点，自己从不点。点中后页面毫无变化，就提示「好像没有生效」，这一步不算完成。
- 助手把登录、验证码、卡号这类只有用户能做的一步交给用户时，页面上圈出要填的栏和要点的按钮。用户填好一栏，这一栏的圈就淡出。
- 用户说「切到某页」「给我看某页」时，助手把那一页切到用户眼前。gpt-6-luna 上还做不到。

## 还差

- 失败时会露出 Chrome 错误码。
- 教学只认网页顶层文档里的点击：iframe 里的目标教不了；整屏、浏览器外的教学也不做。打字、拖动这类点一下确认不了的步骤，只在回答里说明。
- 交给用户时，跨域 iframe 里的单个栏圈不到，只能圈整个 iframe；这类圈不会淡出。
- 回车发送、iframe 里的按钮、页面脚本直接点击，都不经过发送确认，所以不拦。「填完回车」不在这些框上按回车，但助手单独按回车仍然可以发出去。
- 助手点开新页的同一刻，如果用户也在自己的页上点开新页，扩展可能跟错页。
- 点击只发出 GET 请求、页面又没变时，工具结果写「页面没有变化」。GET 故意不算有反应，因为统计、轮询这类后台请求多是 GET。
- 动作之后隔一段时间才发出的请求（输入防抖、定时器里的请求），程序等不到。
- 带 aria-disabled 的按钮一律不点。少数网站故意这样写，点了会弹出「请先填完」这类提示；在这些网站上，助手会少做这一步。
