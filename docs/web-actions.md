# 网页操作、安全边界与组合执行

[文档导航](README.md) · [协议](protocol.md) · [目标核对](goal-check.md) · [当前状态](STATUS.md)

本页是网页操作、不再逐次确认、结果未知边界、页面读数、站点用法笔记与组合执行的唯一位置。

## 现在与还差

### 现在

- 点击、填写、回车直接执行，不弹批准卡。
- 助手在后台标签页里做事，不换走用户正在看的标签页；新开标签页或跳转后直接带回新页面内容，回答下方给「切过去看」入口。只在需要用户看或动手时（发送确认、付款、交给用户、教用户一步），助手才把工作标签页切到前台。
- 目标被挡住或不可用时，助手不点，工具结果写出原因，不笼统写「页面没有变化」。
- 填写使用真实键盘输入写进输入框，按 `beforeinput` 更新的控件也收得到；富文本编辑器支持子块定向修改与末尾光标追加，拦截 `execCommand` 的现代编辑器自动回退到单事务 `ClipboardEvent('paste')` 写入；日期、下拉框直接设值。搜索框和普通单行框可「填完回车」；旁边有「发送」「支付」、消息框、多行框和富文本编辑器不自动回车。
- 把一页上已有的文字原样填到别处时，助手只指出源元素，由扩展直接搬过去，不经模型重打（避免慢、改标点或丢字）。密码、验证码、卡号栏和未显示的文字不搬。
- 填写还原：只还原助手这一轮填过、尚未提交且用户后来没改过的标准输入控件；动手前的值留在网页侧，不进工具结果、存储或诊断记录。表单已提交或页面已跳转时按钮灰掉并写明原因；富文本编辑器、自定义勾选/下拉框与已上传文件不自动还原。
- 点击和回车之后，网站还有未返回的同源请求时，程序先等请求返回再判断页面变化，避免晚到结果被误判为「页面没有变化」。
- 用户说「教我…」时，助手一次只教一步：圈出目标并等用户自己点，助手从不代点；点中后页面毫无变化则提示未生效，不算完成。
- 登录、验证码、卡号等只有用户能完成的步骤交给用户时，页面圈出待填栏和按钮；用户填好一栏，该栏的圈淡出。

### 还差

- 失败时仍可能露出底层错误码；画板（Canvas）内部像素没有无障碍节点和 DOM 突变，感知与动作核验受限。
- 教学只认网页顶层文档里的点击，不支持 iframe 内目标或打字、拖动步骤；交给用户时跨域 iframe 只能圈整个框架，圈不会随填写淡出。
- 助手点开新页的同一刻，若用户也在自己的页上点开新页，扩展可能跟错页。
- 点击只发出 GET 请求且页面无 DOM 变化时，工具结果仍写「页面没有变化」（统计、轮询多为 GET，故意不算有反应）；动作之后隔一段时间才由防抖或定时器发出的请求等不到。
- 带 `aria-disabled` 的按钮一律不点；少数网站靠点击禁用态按钮弹出必填提示，在这些网站上会少做这一步。

## 网页操作不再逐次确认

产品负责人决定：助手在网页上的操作直接执行，不弹批准卡；删除、提交类按钮也不拦下等用户确认。产品没有受信任网站名单。

两个硬例外：

- **发送。** 助手点击名字以「发送 / Send」开头的按钮前，程序先停下，在网页圈出目标并在侧栏出确认卡（显示网站、按钮名与附近草稿）。用户只有点「发送」才执行；点「先不发」、按 Esc、关掉所有侧栏、中止、接管或超时都不发。拒绝发送保留已交付资料，同一轮（到用户再说话为止）不再尝试任何发送路径。
- **付款。** 助手永远不点付款按钮，用户在会话里同意也不点。程序在网页上圈出付款按钮，由用户自己点。

已知后果与发送确认缺口：

- 网页里注入的恶意指令可能让助手在已登录网站上点击、提交，因为没有逐步审批拦截。
- 按回车（`press_key`）：焦点在有字的多行输入框、可编辑区或带发送按钮的表单内时走发送确认；焦点在普通单行框且附近无发送按钮时不问。
- 页面脚本路径：脚本运行期间点发送按钮、提交带发送按钮的表单、合成回车、路径像发送接口（`send`、`message`、`comment`、`reply`、`post` 等）的 `fetch`/`XHR`/`sendBeacon` 会先拦下走同一个确认；但脚本用定时器延迟发送、接口路径名字不像发送、或页面自有代码异步发送时拦不到。
- 发送按钮在 iframe 里、只有图标没有可读名字、或网页在点击前一刻换掉按钮时，程序认不出或拦不住；「发送验证码」这类以发送开头的按钮也会停下问一次。
- 等待确认的状态只在扩展后台内存里，扩展后台重启时等待作废、按钮不点。

## 结果未知的边界

「结果未知」指一个可能造成后果的动作出错或超时，程序不知道它做成了没有。

- 程序把这一步记成「结果未知」，不记成「失败」，也不暂停写入或用锁拦住后续调用；助手先重读页面，再决定是否重做。
- 代价：助手可能把已经生效的普通动作再做一次（付款不受影响，因为助手从不点付款按钮）。
- 扩展后台重启后，带有结果未知步骤的任务不自动接着做，等用户点「继续原任务」。接管、中止和重启都不自动重放原动作。

## 页面读数：截断文字与输入范围

页面读数指快照、读元素和填写的工具结果交给模型的内容，各读取入口共用同一套规则：

- **截断文字给出完整值**：页面把长文字截成省略号显示时，读数在显示文字后附上页面自己提供的完整值（不靠猜）；用 CSS 省略号截断的文字页面里本来就是全文，不另附。
- **范围输入框带允许范围**：时间、日期、数字和滑块输入框的读数附带页面允许的范围（全页快照对无障碍树缺失的时间/日期范围另行补读）。越界按浏览器自身判定作为写入后警告写入工具结果，不与页面给出两套结论；时间框格式无效时不执行并保留原值。
- **表单包裹正文回退**：页面正文被顶层 `<form>` 包裹（如对话类网站）时，抽取正文自动回退读取表单内段落，避免正文读出为空。

## 站点用法笔记

- 任务经目标核对判做成后，后台判断从本轮操作记录里提炼最多 3 条通用网站用法（每网站最多存 5 条，只存本机），并在回答下方显示「记下了某网站的 N 条用法 · 查看」。
- 只记网站怎么操作，不记用户这次填的具体值或查询串（用户输入词替换为占位符，仅保留 `#` 等词首符号）。匹配按主域名，打开或跳转到该网站及在该网站开工时自动带上。

## 组合执行

组合执行（`browser_run`）让模型写一段 JavaScript，在一次调用里组合多个浏览器工具：

- **为什么用组合执行**：页面或接口取到的大段数据可在程序里拼好后直接存成会话文件，模型不必重打一遍；等待页面状态和条件不成立时停手都不必来回调用模型。
- **隔离与控制闸门**：解释器使用 QuickJS 独立堆，不能访问本机文件或网络；沙箱内无 `window`/`document`/`fetch`，页面函数交由页面脚本入口序列化执行。每次子调用仍经过相同的任务身份、接管状态和发送/付款控制闸门；程序里点「发送」按钮会被拒绝，改由单独点击触发用户确认。
- **会话文件区**：程序存的文件与文件工具共用当前会话的文件区，只有标明交给用户的文件才显示侧栏文件卡片（见[文件、下载与页面阅读](artifacts.md)）。导出诊断记录时遮住程序源码，防止泄露内嵌填写值。
