# 浏览器组合执行

组合执行让模型写一段异步 JavaScript 函数体，程序在函数体里通过 `browser` 对象调用现有的浏览器工具。
页面与标签页仍由扩展持有，所以组合执行不创建另一条浏览器连接。方法清单以 [`agent/src/browser-program.ts`](../agent/src/browser-program.ts) 为准。

## 用法

- `browser` 的方法与独立工具一致，返回原始数据。任务宿主另外提供等待、睡眠、存文件等辅助方法。
- 等待只读页面，不改页面状态。正常业务应该等页面状态，而不是猜一个睡眠时长。
- 每个操作都要 `await`。同一程序的浏览器操作按顺序执行；程序结束后，没有等待的剩余调用不会再落地。
- 截图作为图片附在工具结果里，程序本身只拿到截图的元数据。
- 程序变量只在这一次调用里存在。标签页、助手的原目标和现有会话按原机制保留。

## 存文件

页面或接口取到的大段数据，应该在程序里拼好后直接存成本会话文件。这样模型不必拿到数据后再用 `artifacts` 重打一遍。

- 程序存的文件和 `artifacts` 存的文件共用同一个会话文件区和文件名规则，同名会覆盖，侧栏显示同一种文件卡片。
- 文件正文不进模型上下文，程序步骤只记文件名与字数。
- 只用页面 `js` 取数时不必写程序，因为 `js` 可以直接把返回值存成本会话文件，模型只拿到长度回执。
- 程序沙箱里没有 `window`、`document`、`fetch` 等页面全局对象。程序用到它们时，报错会说明该改用哪个 `browser` 方法，而不是只报「is not defined」。
- 只有带交付的主会话有文件区，所以没有文件区的会话里没有存文件方法。程序在保存前被停下时，文件不落盘。

## 控制与权限

- 解释器用 QuickJS。它的独立 JavaScript 堆只暴露浏览器桥接函数，不能访问 Node 进程、模块加载、本机文件或网络。
- 页面 `js` 直接执行（见[网页操作不再逐次确认](browser-confirmation.md)）。解释器隔离只隔离程序本身，不保证网页上的业务安全。
- 每次子调用都经过与独立工具相同的控制闸门。用户接管期间，程序的子调用连只读工具也会被拒绝；独立调用的只读工具在接管期间的行为不变。
- 取消、接管错误、断连或 RPC 超时会永久停止当前程序的后续调用，脚本里的 `catch` 不能解除这个停止状态。新程序只有在现有控制机制允许时才能继续。
- 已经派发的动作按原机制排空，程序不宣称撤回。程序不会代替用户点击确认。
- 程序里点「发送」按钮会被拒绝，因为程序等不了用户确认；助手改用单独的点击，用户在网页上确认后才发（见[网页操作不再逐次确认](browser-confirmation.md)）。
- 程序也能自己停：`assert` 条件不成立时，程序走同一条停止路径，后面的动作都不执行，`catch` 也救不回。
  任务宿主拿到停在第几步、步骤名、原因和已完成步数；侧栏把那一步标为失败，模型看到的是结果而不是报错。
- `check` 只在任务宿主里轮询页面文字或目标，到时返回假，不抛错，也不调用模型（[验收](evals/20261008-check-assert-referee.md)）。

## 执行预算与观察

- 每个程序有总时限、内存与调用数上限，数值以代码为准。这是单个程序的执行预算，不是任务级的固定次数熔断。
- 程序内部每一步都在侧栏步骤卡里显示为子步骤，并记进诊断记录。
- 诊断记录隐藏程序源码，因为源码里可能内嵌填写值，记下源码会绕过填写值的脱敏规则。
