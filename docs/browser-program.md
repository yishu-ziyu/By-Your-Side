# 浏览器组合执行

组合执行让模型写一段 JavaScript，在一次调用里组合多个浏览器工具。页面与标签页仍由扩展持有，所以组合执行不创建另一条浏览器连接。

## 为什么要组合执行

- 页面或接口取到的大段数据，程序里拼好后直接存成会话文件。这样模型不必拿到数据后再重打一遍，文件正文也不进模型上下文。
- 正常业务应该等页面状态，而不是猜一个睡眠时长。
- 程序可以自己停：条件不成立时，后面的动作都不执行。侧栏把那一步标为失败，模型看到的是结果而不是报错。等待和停止都不调用模型。

## 存文件的坑

- 程序存的文件和助手用文件工具存的文件共用同一个会话文件区，同名会覆盖。只有标明交给用户的文件才有侧栏文件卡片（[文件卡片](artifacts.md#文本文件)）。
- 程序沙箱里没有页面全局对象（`window`、`document`、`fetch`）。程序用到它们时，报错会说明该改用哪个方法。
- 程序在保存前被停下时，文件不落盘。

## 控制与权限

- 解释器用 QuickJS，因为它的独立堆不能访问 Node 进程、本机文件或网络。本项目不把 `node:vm` 当作权限隔离的依据。
- 解释器隔离只隔离程序本身，不保证网页上的业务安全，因为页面脚本直接执行（见[网页操作不再逐次确认](browser-confirmation.md)）。
- 每次子调用都经过与独立工具相同的控制闸门。用户接管期间，程序的子调用连只读工具也会被拒绝。
- 取消、接管、断连或超时会永久停止当前程序，脚本里的 `catch` 不能解除。已经派发的动作程序不宣称撤回。
- 程序里点「发送」按钮会被拒绝，因为程序等不了用户确认；助手改用单独的点击，用户在网页上确认后才发。
- 程序的执行预算只管单个程序，不是任务级的固定次数熔断。
- 诊断记录隐藏程序源码，因为源码里可能内嵌填写值，记下源码会绕过填写值的脱敏规则。
