# 待审提案：完成标准模板增加使用入口字段

- 状态：待审，未落地。
- 目标：`AGENTS.md` 中的“完成标准格式”模板。
- 来源：[验收入口错位的经验](../patterns/acceptance-entry-mismatch.md)。

## 建议改动

只在现有模板的任务标题与“完成标准”之间增加一行：

```diff
 # 任务: <一句话，用户能观察到的结果>
 
+使用入口：<用户实际操作的宿主、界面或命令；只填写影响本任务结果的部分>
+
 ## 完成标准
```

例如本次应填写“当前 Codex 主代理在开发任务验证后、最终交付前执行收尾”，旧 Kimi SessionEnd 就不会被默认当作同一个入口。

## 理由与边界

“改动前先对齐目的与范围”已经得到用户授权并写入规范，本提案不重复请求这项授权。这里单独建议的是**改变验收文档模板**，让实际使用入口成为可见字段，便于在实施前发现错位。

收益是减少读者从实现方案反推用户入口的需要；代价是每份验收文档多填一行。对不影响结果的环境信息不要求罗列，也不要求回填历史文档或新增后台机制。

## 证据与待决事项

[前轮验收](../../../docs/evals/20260909-wiki-consolidation-repair.md)只证明 Kimi 入口；[当前已确认目标](../../../docs/evals/20260909-codex-experience-closeout.md#已确认的目的与范围)是 Codex 任务收尾。二者不等价，已由用户反馈确认。

用户需要判断：这一固定字段是否值得加入模板。模板当前未改动，不宣称该字段已证明能减少未来错误。
