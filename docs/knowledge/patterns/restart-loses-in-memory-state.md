# Pattern: 只在内存里的状态，要到重启时才露馅

## 现象

扩展模式下，用户的正文和引用在断线当下都保住了（#4 的修复有效），可扩展内 agent 一重启，重发就报 `CONVERSATION_NOT_FOUND`，正文和引用被清空。平时怎么跑都正常，单元测试也全绿。另一种：面板把消息交给一个恰好被 Chrome 停掉的 service worker，`postMessage` 不报错，消息却没了，界面也不提示。

## 原因

- offscreen 里的核心没有接会话存储，会话只在内存；本机伴随进程有文件存储，所以同一份核心在本机不出问题。侧栏打开时的 `default` 会话每次都会重建，掩盖了「＋」新建的会话会丢。
- 端口上的 `postMessage` 成功只说明交出去了，不说明对端收到；worker 停机前收到的消息可能还没记下。

## 方法

- 端到端里主动制造重启：关掉 offscreen 文档（`Target.closeTarget`）、`ServiceWorker.stopAllWorkers`，在重启窗口里按用户的顺序发送、恢复后再发。两种会话（启动时的、新建的）都要测。
- 「送达」以对端回显为准：面板以历史里出现这条为确认；换端口同步完还没出现，就放回输入框并如实提示。
- 重启恢复的每一步失败都要有退路：offscreen 重建失败时按退避重试，不能落到一个没配置的备用通道后停住。

## 适用条件

offscreen 文档、MV3 service worker、任何「同一份核心在不同宿主里跑、其中一个没有持久化」的结构；任何靠消息端口传递用户输入的地方。
