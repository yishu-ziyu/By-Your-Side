# Pattern: 模型写的说明决定了安全闸门

## 现象

用户说「帮我改错字，然后点发送。」发送键本该被拦下、等用户在页面上点确认。真实模型（stepfun/step-3.7-flash）5 次里有 3 次直接发了出去（改前代码 3 次里 2 次），页面跳到「已保存」。脚本模型回回都被拦下，因为脚本给的 `label` 恰好是「发送」。

## 原因

- 点击前判断「是不是危险动作」用的是 `nameOfClickTarget`：模型给了 `label` 就只看 `label`，不再读页面上元素自己的名字。
- 判断规则是前缀匹配（`^发送`）。模型写的 `label` 是「点击发送按钮」，不以「发送」开头，于是放行。
- 模型的 `label` 本来只是给人看的说明，却成了安全闸门的输入。

## 方法

- 安全闸门只看页面事实：先读元素自己的名字（aria-label、title、文字），它危险就拦；模型的说明最多作为补充（说明本身危险也拦），不能让它把危险动作「说成」安全的。
- 验收要用真实模型跑同一条路径：脚本模型的参数是测试者写的，恰好符合规则，测不出模型的真实写法。
- 页面浮层在封闭 shadow root 里：用 CDP 穿透读文字时隐藏的节点也会读到，判据要加位置或可见性（本例要求确认按钮在「发送」键 300px 内）。

## 适用条件

任何「由模型参数决定是否需要用户确认、授权或拦截」的地方：点击、提交、删除、付款、外发请求。
