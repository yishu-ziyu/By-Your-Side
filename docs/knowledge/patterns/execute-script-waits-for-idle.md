# 经验：页面加载中，`chrome.scripting.executeScript` 会等到页面空闲才执行

## 现象

2026-10-06 查 #18：少数派页面刚打开就发问，开工前读页 4 秒超时，模型拿不到页面，多跑一整轮（一次 34 秒）。同一页第二次读只要 0.1 秒。

## 根因

`executeScript` 默认在 `document_idle` 时注入。页面还在加载时，调用会一直挂到加载完成，实测卡 6.4 秒。接上调试器（0–9 毫秒）和取无障碍树（0.04–0.3 秒）都不是瓶颈。先猜「第一次接调试器慢」，测量后推翻。

## 方法

- 只读、不依赖页面加载完的注入加 `injectImmediately: true`。
- 计时先拆到单个调用，再下结论；同一页「第一次慢、第二次快」不一定是连接冷启动。

## 适用条件

后台在用户可能刚打开、仍在加载的页面上注入脚本。要等 DOM 稳定的写入类脚本不适用。

## 验证

页面打开 0.8 秒发问，读页 0.04–0.38 秒，一次模型请求答完（3/3）。见 [首个反馈](../../evals/20261006-first-feedback.md)。
