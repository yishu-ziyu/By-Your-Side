# 经验：要分清「框架变好」还是「换了模型」，就用旧代码和同一个模型对照

## 现象

用户问一个月来哪些指标变好、是不是因为框架变好了。手里有 172 份「日常基线」，但每天的任务集和模型都不一样（6 种模型），按日期画出来的趋势混着模型的差别，回答不了这个问题。

## 方法

- 把要比的几个旧版本各建一个工作树并构建（`git worktree add --detach <旧提交>`，各自 `npm ci`），用现在的验收工具通过 `SIDEAGENT_ACCEPTANCE_DIST=<旧版 dist 的绝对路径>` 装进隔离 Chrome。
- 旧版只改调用线路这类与比较无关、又必须改的地方（例如阶跃旧版走按量计费的 `/v1`，改成 Step Plan），在记录里写明。
- 同一模型、同一批任务、各版本交替跑，每格至少 3 次；比轮数和发给模型的 token 比比秒数可靠。
- 旧设置页可能导不出诊断记录，数字取网络请求和侧栏读数。
- 跑完先核对每个输出目录名和计划是否一一对应，再算数（这次进度页函数改掉了循环变量，16 次全跑错，标签却是对的）。

## 适用条件

要把一段时间的变化归因到代码还是模型、配置；或者怀疑某个版本变慢了。

## 验证与来源

- [一个月对照](../../evals/20261011-month-time-machine.md)：三版 × 三任务 × 3 次，现在的代码在同一模型上快 2–5 倍。
- 2026-10-11，本轮主代理。
