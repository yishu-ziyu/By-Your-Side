# Pattern: 扩展自己画的东西，核验看不到，agent 就一直找

## 现象

用户说「圈出保存按钮给我看」。标注一分钟内就画好了，agent 却接着用 `read_elements` 换选择器找标注（`[class*="mark"]`、`svg`、`canvas`……），全部 0 命中，一直转到 240 秒超时，侧栏停在「正在读回多个元素」。同一用例有时过、有时不过，很像是刚做的那次重构引起的回归。

## 原因

- 标注画在封闭的 shadow root 里。页面选择器、`read_elements`、页面 JS，以及核验时的整页读取，都看不到它。
- 复核只被允许相信宿主读到的页面状态，不认「工具调用成功」。手里只剩回执时，概率在门槛（0.9）上下摇摆：判得松就过，判得严，模型就接着找。
- 所以「时过时不过」来自复核的随机性，和同时段的代码改动无关。

## 方法

- 扩展自己画在页面上的东西（标注、翻译……），在内容脚本的隔离环境里留一个只读读数，由 `snapshot` 带给核验：`window.__sideagent.marksState()` 进 `snapshot.marks`，再作为 `hostDrawnMarks` 交给复核。先例是 `readTranslationDisplay`。
- 读数写「圈住了哪个元素（标签名、可读名字）、此刻是否显示」，不写 `@24` 这类传输编号。
- 在工具说明里告诉模型：这类东西会自动出现在核验读数里，不要去 DOM 里找。
- 判断是不是回归之前，先看失败轨迹里每轮调了什么、拿回了什么。「工具几毫秒就返回、模型每轮 30–50 秒」说明是在空转，不是卡在某次调用上。
- 真实路径用例成败都保存数据目录（会话与轨迹），否则通过的那几次无法复查完成依据。

## 适用条件

agent 要证明「用户能在页面上看到某个东西」，而这个东西是扩展自己画的、放在隔离层里的场景。

## 验证与来源

- 未验证：没有构造「标注在别的元素上」的反例，复核会不会误认，目前只靠说明里的规则约束。
