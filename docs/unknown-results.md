# 结果未知的边界

[返回协议](protocol.md)

结果未知时，只拦再做一次可能重复造成后果的调用（2026-10-01 用户裁决：不确定刷卡成没成，就不让它再点付款）。哪些调用算数，以 [`shared/task-results.ts`](../shared/task-results.ts) 为准。

- 被拦：点击、填写、按键、页面脚本、POST 或带 body 的 `fetch` 等。
- 照常：读页、截图、导航与标签页、不带 body 的 GET `fetch`、存文件、处理原生弹窗。这些调用不核销旧的结果未知项，也仍受用户接管、中止和页面归属约束。
- 确认弹窗会上锁但不被锁拦：它可能就是「确定付款」那一下，但弹窗只能确认一次。
- GET `fetch` 出错或超时只是取数失败，不上锁。
- 确定没执行的不上锁，例如派发前的目标检查失败、脚本编译失败。
- 同一项只核验一次。查不清时，不再读页面，直接告诉用户「这一步结果查不清、没有重复执行、请你看一眼」并结束本轮。
- 之后，用户在会话里决定是否继续；没有恢复确认卡（见[网页操作不再逐次确认](browser-confirmation.md)），锁照旧挡住重复。

点击后页面弹出原生弹窗时，点击一看到弹窗就返回弹窗内容，不等满超时。组合执行逐个子调用按同一规则判定，见[组合执行](browser-program.md#控制与权限)；验收见 [20261001-unknown-lock-scope](evals/20261001-unknown-lock-scope.md)。
