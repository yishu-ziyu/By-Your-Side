# 结果未知的边界

[返回协议](protocol.md)

本页是结果未知锁的唯一说明。哪些调用被锁拦，以 [`shared/task-results.ts`](../shared/task-results.ts) 为准。

## 规则

- 结果未知时，程序只拦可能重复造成后果的调用。依据是 2026-10-01 用户裁决：不确定刷卡成没成，就不让助手再点付款。
- 读页、换页、GET 取数和存文件照常运行。这些调用不核销旧的结果未知项，但仍受接管、中止和页面归属约束。
- 确认原生弹窗会上锁，但不被锁拦。上锁是因为这次确认可能就是「确定付款」那一下；不拦是因为同一个弹窗只能确认一次。
- GET 取数出错或超时只是取数失败，不上锁。
- 确定没执行的调用不上锁，例如派发前目标检查失败、脚本编译失败。

## 核验与收尾

- 每个结果未知项只核验一次。
- 核验查不清时，助手不再读页，直接告诉用户「这一步结果查不清，没有重复执行，请你看一眼」，然后结束本轮。
- 之后由用户在会话里决定是否继续。产品没有恢复确认卡（见[网页操作不再逐次确认](browser-confirmation.md)）。用户说继续后，锁照旧挡住重复的调用。
- 用户说「继续」不清除历史结果未知项。接管、中止和重启检查点不重放原动作。验收见 [MDN 阅读恢复](evals/20260930-mdn-reading-recovery.md)。

## 组合执行与原生弹窗

- [组合执行](browser-program.md)按每个子调用判定，不整段拒绝程序。程序走到可能重复造成后果的那一步才停。
- 任务宿主自带的只读探测（等加载、查页面信息、等元素）不算重做页面脚本。模型写进条件里的代码照旧受阻（[验收](evals/20261001-data-to-file.md)）。
- 点击后弹出原生弹窗时，点击一看到弹窗就返回弹窗内容，不等满超时。

验收见 [20261001-unknown-lock-scope](evals/20261001-unknown-lock-scope.md)。
