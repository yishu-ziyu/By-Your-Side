# 文档维护

[文档导航](../README.md) · [项目规则](../../AGENTS.md) · [检查命令](checks.md)

## 写到哪里

项目自有说明统一进入 `docs/`。根 README 只给概览与导航；AGENTS 只放开发约束与入口。工具自动加载的入口、随第三方源码保留的来源说明、锁定评测原件不得为整理而搬走；准确例外清单在[文档策略](../documentation-policy.json)。新增例外必须解释真实的路径依赖。

| 内容 | 唯一归属 |
|---|---|
| 现在做到哪里、已知缺口、下一步 | [STATUS](../STATUS.md) |
| 安装步骤与配置 | [源码安装](../guides/getting-started.md) |
| 用户如何操作、数据与权限 | [使用说明](../guides/usage.md) |
| 模块职责与边界 | [架构](../architecture.md)、[协议](../protocol.md)及对应专题 |
| 方向变化的理由 | [路线](../ROADMAP.md)、[开发日志](../devlog/) |
| 任务施工、标准、失败、验证 | [任务书](../tasks/)、[验收记录](../evals/) |
| 可复用的已验证教训 | [经验库](../knowledge/index.md) |

一个事实只维护在一个权威位置。代码类型定义负责精确接口；文档解释语义并链接代码，不再手抄第二份接口表。STATUS 引用验收结论，不复制整份日志。

## 渐进式披露

先概览，再按问题链接到细节。新文档必须从对应入口或主题页能找到，并给出相关说明或返回入口。已有文档能容纳同一主题时直接更新，避免不断新增相近文件。

篇幅预算以策略文件为准，同时限制字符数和行数；入口比专题更短。超出时按独立问题拆分，原页留下地图和链接，不删约束、不压成长行规避检查。

历史原件保留原始结论和失败，不为了篇幅改写证据。旧 STATUS/NOTES 的原文快照作为文本放入 `history/`，避免里面的旧标题、旧路径和“下一步”继续充当导航；日常只通过短索引访问。新结论写在对应主题，不继续堆进历史快照。

## 每次功能修改

开始前，从策略文件的 `syncRules` 找对应长期说明；匹配按顺序取第一条。新增子系统时先补真实归属，不通过放宽匹配躲开同步。

同一变更中更新行为、边界、配置或用户操作说明；纯重构说明对外契约为何不变。只更新 STATUS 或新增验收报告不能代替功能文档。验证后把施工中得出的长期结论回到其归属处，任务记录保留证据并引用它。

运行 `npm run check:docs`，再用 `npm run check:docs -- --base <比较基线>` 核对功能同步。PR 检查会对其共同祖先到候选工作树的改动执行同一命令，不依赖本地是否已经提交。

## 检查的能力与边界

检查器复用仓库已有的 Marked 解析 Markdown：检查文档位置、当前说明篇幅、相对文件链接和 HTML 图片路径，并按代码归属要求对应说明发生变更。代码块中的示例不当成真实链接。

历史记录不参与当前篇幅门槛；`--all` 额外扫描其文件链接并输出完整提醒清单，历史缺页只报告，不能据此宣称历史证据完整。本地 `out/` 产物与仓库外路径不要求干净 clone 携带。网页链接、`#片段`锚点、文本是否准确反映实现仍需人工核对。

文件被修改不证明内容真的同步。每个 PR 和里程碑，维护者必须从真实用户入口核对：说明是否仍正确、同一事实是否重复、历史待办是否混入当前状态、任务结论是否回流。复核记录写回本次验收，不再新建一套状态台账。

## 经验库迁移

经验库已由 `.kimi-code/wiki/` 移到 `docs/knowledge/`，现有角色与 hook 只同步资料路径。旧 hook 的项目门控和启用状态保持原样，本轮不激活后台模型复盘。原会话轨迹、锁和本地日志不是项目说明，不因目录整理自动复制或上传；新旧轨迹目录和锁文件都保留在 `.gitignore` 中。
