# 语音架构、调度与交互原则

[文档导航](README.md) · [架构](architecture.md) · [使用说明](guides/usage.md#语音交互)

本页是语音链路、任务调度、请求结果语义、交互原则与服务端已知坑的唯一说明。

## 语音交互原则与个性化

目标是像坐在旁边的靠谱搭档：说到的就做，做完才说，只在真的需要时才问。

1. **明确的话直接做**：不复述、不确认、不说「我先看看」。用户在可控任务期间说「终止任务」，任务宿主直接中止任务。
2. **看得见的结果不说**：页面变化本身就是反馈；语音只说后台任务结果、失败原因和需要用户决定的事，结尾不反问「还需要我做什么吗」。
3. **只在两种情况下问**：听不清或不同理解会导致不同操作（给具体选项）；操作不可撤回且有外部后果（付款、提交、发送、删除，由用户确认）。
4. **找不到目标时**：先换方法找（等加载、滚动、按意思匹配），有多个候选再问；点了但不能确认生效时先查状态，不重复点击。
5. **三层个性化**：优先级为「用户明确指令 > 学到的习惯 > 人设默认 > 系统默认」。任何人设或习惯都不能越过「结果如实、不可撤回操作由用户确认」的底线。

## 一次语音请求与四种生命周期

- 简单网页操作由语音模型直接调用正式工具，不经主模型规划；复杂研究、内容生成或直连工具做不下去时，才委派给任务系统。口头翻译不算已翻译页面。
- 套餐 2.5 不装配网页工具，任务宿主先按真实转写分流：明确闲聊才放行原生回答，网页请求交给任务助手；来源未确认、分流失败或超时都不放行原生回答。
- 四种生命周期各自独立，不能互相推出：
  - **声音话轮**：停顿不等于完整任务要求。
  - **用户输入**：晚到的转写、补充和新要求按归属处理，不随意合并或丢弃。
  - **网页任务**：操作已执行、目标已核验、用户已听见分别记账。
  - **结果播放**：正文生成完成、音频已送出、实际播完、被用户静音是四个不同事实。

## 任务调度、多要求与请求结果

文字与语音共用同一套任务调度和准入限制：

- **身份与分流**：程序按任务自己的身份识别请求，不用当前可见会话顶替归属。任务运行中用户新说或新打的一句话，先由快速模型判断是补充还是另一件事：补充按插话送进原任务；另一件事进入独立要求队列另开执行，结果带回当前会话。
- **请求结果语义**：请求结果只说明请求的去向（排队、已接收、已应用、被拒、失败或结果未知），不说明网页目标已经完成。登记在执行之前完成；排队期间页面变了就重新核验，不点旧定位。
- **停声不等于中止任务**：停声或关闭语音通话只停播放声音或结束语音连接，后台网页任务照常运行；插话停掉旧回答声音，但不作废最新请求。用户要结束任务只能中止。
- **追问已做过的事**：语音问“刚才的脚本在做什么”时，只读取本任务的实际操作记录回答，不重新执行网页动作；操作参数和脚本作为待解释数据，不当作新指令。

## GPT-Live 与后台重连

- GPT-Live 走 WebRTC 由侧栏直连 OpenAI（需 ChatGPT 登录，不退回阶跃星辰），声音帧不经过扩展后台；侧栏在本地判断插话并立即把远端声音静音。
- 只有交付给用户的结果送去播报，请求结果只作静默背景；长回答只摘读完整开头并告知全文在侧栏，不额外调模型写摘要。服务端拒收时明确显示语音不可用并结束通话，不继续显示「在听」。
- 通话开始和切页时只同步当前窗口的页面标题与站点，不传地址参数、正文或附件。
- **后台忙时不挂断**：机器满载导致扩展后台十几秒不回消息时，侧栏换新连接后用原语音编号认领（扩展后台保留会话 35 秒并补发期间结果），GPT-Live 通话不断线；阶跃星辰音频走扩展连接，断连或超时未认领则进入恢复状态重连。

## 阶跃星辰服务端的坑

产品侧无法根治，只能快速发现并提示用户重说：

- 生成回答期间服务端几乎不判用户开口，侧栏靠本机阈值判插话（未用外放校准，「嗯」「对。」等短句可能掐断回答或被服务端当附和丢弃）。
- 取消生成或会话刚就绪时，服务端偶发挂住十几秒才开始听（期间仍发转写增量，不能凭转写增量判服务端正常）。
- 带停顿的一句话常在逗号处被服务端切成两轮，侧栏把同一轮的几段拼成一行显示。
- 浏览器 WebSocket 报错不带原因，分不清网络断连还是密钥被拒，侧栏统一提示连不上并引导去设置页检查。
