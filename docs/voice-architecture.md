# 语音架构

本文写语音链路的设计约束与实测边界。已加载哪一版、验收了什么只看 [STATUS](STATUS.md)。旧 2.5 的问题和改造计划见[历史](history/20260920-voice-architecture-snapshot.md)。

## 一次语音请求

- 默认按量语音接 StepAudio 3 Realtime。设置可选套餐 2.5，下次开启生效；无效选择拒绝启动，不回退按量。
- 按量语音模型可以只读当前页、查询任务、直接做网页操作或委派任务。只读问答与修改页面分开，不把口头翻译当成已翻译网页。
- 简单的网页操作直接调用正式工具，复用页面身份与执行回执，不经过另一个主模型规划循环。工具列表只在[Realtime 工具定义](../agent/src/realtime-browser-tools.ts)维护。
- 复杂研究、内容生成或直连工具不能继续时，委派给任务系统。诊断连接不装配可写入口。
- 操作已执行、目标已核验和用户已听见分别记账。

套餐 2.5 不装配网页工具。宿主先根据真实转写分流，明确闲聊才放行原生回答，网页请求沿用任务助手。未确认来源、分流失败或超时不放行原生回复；新开口使旧分流失效。用户选择与边界见[套餐验收](evals/20261008-voice-plan.md)。

直连工具的结果回传后照常请求一次续答。曾试过按请求判断是否省略口头结果，已随 Jev 删除；记录见 [V2.3](evals/20260922-v22-spoken-result-shadow.md)。

## 四种生命周期

| 对象 | 身份 | 不可混淆 |
|---|---|---|
| 声音话轮 | voiceId、turn | 停顿不必然等于完整任务要求 |
| 用户输入 | 真实转写、来源片段、response 绑定 | 晚到转写、补充和新要求不能随意合并或丢弃 |
| 网页任务 | requestId、runId、controlVersion、页面身份 | 停声或关通话不等于中止任务 |
| 结果播放 | deliveryId、responseId、播放回执 | 生成完成、已送音频、实际播完是不同事实 |

## 提示词和程序分别保证什么

| 行为 | 实现方式 | 能证明的边界 |
|---|---|---|
| 简短回复、不先朗读计划、结尾不反问不客套、选择操作而非读页 | 系统提示与工具说明引导模型 | 不能保证每轮遵守，应复核实际工具与内容 |
| 音色 | `voice` 配置，加同一说话人的提示词 | ID 回显不证明听感稳定，应由真人试听 |
| 人设 | 设置页填写，开启语音时带上；插在身份句之后，并写明与规则冲突时以规则为准 | 配置送达可由机器检查；口吻像不像只能人判断。实测放在规则末尾几乎无效；示例句会被照搬 |
| 同一输入不重复派发、旧话轮不执行 | 输入消费集合、调用去重、话轮与来源检查 | 拦重复与过期；不能证明模型理解正确 |
| 工具结果回传 | 按生成状态决定何时送回 | 等对应生成结束；不等前导语播完；已接收的异步任务不额外生成一遍计划，等正式结果；主动通知仍受播放状态限制 |
| 已播报状态 | 通知接收确认、delivery/response 绑定与 `playback_done` | 不把生成完记成用户已听完；超时涵盖前方未播音频，仍有上限与缺回执失败 |
| 可控任务期间说「终止任务」不被抢答 | 转写闸门：有可控任务时，先扣住服务端自动回复，等本轮转写。明确的终止句取消模型回复，由任务宿主直接中止任务；其余放行 | 实测转写比首帧音频晚约 70–140ms，只在可控任务期间多等这一段。中止成功时，由中止回执触发播报；失败时如实说未停 |
| 用户开口时旧回答停声（插话） | 侧栏在回答播放中按回声消除后的麦克风音量本地判定开口，立即停播并通知任务宿主取消旧回复；迟到音频不再下发。不作废最新请求、不中止后台任务，与「停声」按钮不同 | StepFun 生成回答期间几乎不断句：实测 75 秒长回答里用户开口始终没有 `speech_started`，所以不能等服务端。取消生成后它有时 1 秒内开始听，有时 19–20 秒才生效或随后挂住，这时新问题丢失、由挂住检测提示重说。阈值未经真人外放校准，附和（「嗯」）也会掐断回答；见[插话验收](evals/20260925-voice-barge-in.md) |
| 开口不丢字 | 连接前说出的第一句话应保留，就绪后自动处理，不要求重说。诊断会话不留 | 音频送达不等于处理完成；用完整转写与实际回答核对，见[首句验收](evals/20261008-voice-first-utterance.md)。服务端断句仍会偶发不响应（见下一行） |
| 服务端断句延迟与不响应 | 无产品侧补救；只做快速发现：有人声却久无回应时报可恢复错误并断开，侧栏自动重连后提示「刚才语音服务没有响应，请再说一遍」。不补发旧音频，避免重复执行。验收把音频送达与断句结果分开记 | 2026-09-25 实测 StepFun 的 `speech_started` 比人声晚 2–10 秒；会话就绪后 1 秒内开口时，约四成完全不回断句事件，约 60 秒后断开。卡住时服务端对 `input_audio_buffer.commit` 和 `response.create` 都不回应，主动提交救不回来；挂住时仍每秒发两三条 `transcription.delta`，所以它不算回应 |
| 被切开的一句话 | 侧栏「你：」这一行把同一轮的几段按到达顺序拼起来，晚到的前半句拼在前面；助手答过才换新问题 | 只影响显示；模型本来两段都收到。带停顿的句子会在逗号处被切成两轮。切句不受 `silence_duration_ms` 控制：逗号停 340ms，设 300/600/800ms 都 3/3 被切；官方 `turn_detection` 没有语义断句参数，判断是 StepAudio 3 自带的话权协调按语义切。前半句常在服务端已开始回答后才转写完，这时网页操作被拒，模型改用 `read_elements` 找目标，所以它的每个命中都带唯一 `target`。调用发出后用户又开口而作废时，工具结果如实说没执行、合起来重新调用 |
| 要操作页面却先读页 | 能直接操作页面时，`read_page` 的结果附下一步提示：要操作就先 snapshot 再调用对应工具，只问内容就直接回答 | 通用指令要求读页后直接回答，实测模型读完页说「我先获取快照」就结束（同时段 5/7） |
| 服务端附和判定 | 未公开事件 `input_audio_buffer.speech_backchannel` 后复位「用户在说话」 | StepFun 会把「对。」这类短句当附和清掉，且不发 `speech_stopped`、不给转写；复位只防后续回复被卡住，那句话仍然丢失 |
| 页面读写权限与新鲜度 | 观察令牌、页面身份、任务控制和执行回执 | 由程序检查；提示词不是授权替代品 |
| 侧栏语音区的状态文字 | 就绪时显示「已连接，可以说了」，不露型号；连不上时只说「连不上语音服务」和去哪儿查，底层原因只进诊断记录；「停声」只在助手回答时出现 | 浏览器的 WebSocket 错误不带原因，分不清是网络还是 key 被拒 |

## 耗时怎么定位

分开测：说完→服务端判停，判停→实际工具调用，工具调用→结果就绪，就绪→结果送回，后续生成→浏览器首声/播完。`first_audio_since_vad_stop` 是服务端判停后的音频到达指标，不是用户实际听到答案的时间。

日常记录可从设置页导出；逐帧事件和录音只在诊断模式产生。日常记录的识别结果落在 turn 2 是正常的：服务端检测到第一段说话才进入 2。查开口问题用开口时间线（见[验收入口](testing/acceptance.md)）。

扩展内部 Port 是本地消息传输，不是另一次模型推理。代码或拓扑不能证明它零开销；归因需要同轮时间戳。旧分类/主模型/TTS 串行数据只适用于旧版本。
