## 2026-09-16 明确记忆与后台学习

用户已认可“产品维护明确事实，EverOS 后台整理经验”的方向，随后明确修订开启条件：先在日常使用中积累，再判断是否有效，不再等生成技能才启用。已用独立常驻接收器连接现有 ExperienceStore；勿误删为临时实验或把早期未接入结论当当前状态，见[启用记录](evals/20260916-everos-enable.md)。结构化语义判断采用现有模型按需核对，不引入 TypeSafe Python 服务或每轮前置分类。纯记忆请求不能顺手提交网页，但“助手先问邮箱，用户给邮箱并要求记住”仍要续接原报名任务：只隔离页面内容，不能丢掉可信直接对话的指代关系。来源与失败证据见[专项验收](evals/20260916-memory-implementation.md)。

## 2026-09-16 回应区与品牌

用户选定暖纸底、双斜杠 Logo 与气泡，否定回应区的混杂元素，并明确保留原光球。最终沿用现有消息流，统一过程/工具/协作详情与回答层次，不引入另一套加载动画或任务状态机。Beautiful UI 是信息组织参考，不是许可扩大产品行为的依据。旧固定/随任务原型已退役；见[实际落地验收](evals/20260916-paper-response.md)。

## 2026-09-16 顶部入口整理

用户已认可渐变和会话为主的预览，低频入口收进更多。正常连接弱化不代表删去断连/控制提示；示范收进菜单后必须保留菜单外的结束入口。可见预览使用生产构建、模拟连接，不能作为真实 Agent 执行验收；见[顶部验收](evals/20260916-sidebar-header.md)。

## 2026-09-16 划词阅读交接

阅读提问与主任务插话是两种意图，不能随主任务忙闲自动互换。完整交接同时依赖面板的启动选择和模型上下文的持久化：只把消息广播给侧栏、或只给 Pi 追加 custom context 都不足以保证续聊。因果与证据见[阅读验收](evals/20260916-selection-reading.md)。本轮用户明确要求主代理独立实现，不使用 DeepSeek 开发委派。

## 2026-09-16 语音修改免读回

用户要求Voice改造先从全栈梳理架构并解释方法。声音片段、对话请求、网页任务、播放交付是不同生命周期，见[架构](voice-architecture.md)。多要求检查进一步确认：自动另开会话会绕开当前语音的结果订阅，放开start检查还会触发fleet.reset。因此要求登记与交付回传必须一起设计，不能先放开入口再补播报。真实三任务进一步发现，结果已生成但客户端未听见时的插话会永久静音该结果；保留未听见的任务交付并仍按其任务版本核验，不能把它与已听见一部分的音频精确续播混为一项。见[实施证据](evals/20260916-voice-multi-request.md)。保留Pi、授权和页面归属边界，先自动化跨层场景，再让真人判断声学体验。

本轮用户明确只能购买阶跃星辰或MiniMax服务，当前沿已有阶跃链路提升自然连续对话，不把GPT-Live/Gemini Live作为接入前提。用户认可按听见、停住、接话、任务并行推进。麦克风漏检诊断不能只看成功转写：本次中等置信度输入被本地阈值挡住的证据支持调低阈值，但原始声音未保存，合成噪声通过不证明扬声器回声不误触。见[收音诊断](evals/20260916-voice-input-diagnosis.md)。

用户明确否定了“所有运行中修改都先复述确认”的旧策略。普通 steer 与文字输入一样送达；不能因为历史 listen-back 文档再次恢复强制确认。原页面/附件/版本检查与具体动作授权仍是执行层职责，终止任务读回暂保留。原始对话和新验证见[专项验收](evals/20260916-voice-direct-steering.md)。

## 2026-09-16 整页翻译

显示方式是当前文档内的状态，切换仅译文/双语应复用结果，不重新请求模型。语音分类标签不能单独代表实际执行：空闲时的 steer 已会在 manager 转成新任务，验收要走到网页变化。本轮没有修改语音规则，边界和失败依据见[翻译验收](evals/20260916-page-translation.md)。 长文必须用真实文章验收：最低思考等级仍可能一直输出思考到截断；段落转换无需可选思考。模型失败与落页 RPC 失败要分开记录，已确认部分结果不能变成全任务未知，也不能伪称全部完成。见[长文故障](evals/20260916-page-translation-failure.md)。

## 2026-09-16 连续插话与控制优先

用户要求本轮子Agent结束后不再委派，余下工作由主代理完成；不要在本任务续接时恢复默认委派。连续插话的接收回执不证明模型已处理；旧写入闸门有效也不能掩盖逐条消费产生的反复。手动装配团队的验收必须给主模型完整的助手/页面上下文，否则会把测试台遗漏当成汇总能力故障；同时保留修改回执之后是否发生旧写入的独立证据。原始失败、修正依据和最终结果见[专项验收](evals/20260915-continuous-steering.md)。

## 行为与验证

- 执行账本的 satisfied 只表示已记录动作完成，不等于用户目标已完成；正式交付有独立生命周期。这个区别曾导致提前收尾和重复交付，见[账本验收](evals/20260911-turn-economy-ledger.md)。
- 确认需要保留原请求页面、附件、任务身份；孤立的确认和预观察测试都通过也可能丢跨模块载荷。原生入口和生产装配测试不能互相替代，见[确认上下文](evals/20260912-voice-confirm-context.md)。
- 页面控制按tab归属，不按整个成员停工；同一成员可能还在别页。授权必须绑定原参数与身份，不能因收到旧“好的”放行。见[移交与授权](evals/20260913-architecture-closures.md)。
- 跨页提示的外层当前性检查不足，ensureCursor之后也可能迟到；共享提示清理必须按owner撤回。先后顺序和最终显示都需检查，见[同类缺陷](evals/20260913-interaction-loop-audit.md)。
- 重新打开侧栏是新会话；连接恢复不是重新打开。历史上下文恢复不自动重放网页动作。实际草稿与控制隔离证据同上。

## 环境与证据

- 隔离浏览器运行器复制dist后移除manifest key，因此不能接上日常native host。隔离测试、真实侧栏与真人声音分别留证；不可把任一种冒充另一种。
- 测试下载用 SIDEAGENT_DOWNLOADS_DIR 指向临时目录。生成物与个人运行数据不进入生产源码。
- 原生电脑控制曾出现截图/AX时序与下拉菜单焦点异常。动作报错不证明没发生；先核对新画面和有时间戳的日志，别重复发送。旧wrapper stderr多进程混写，不能按行序推断时间。
- 评测门槛以 eval/protected/quality-gates.json 为准；历史保护/发布情况不是新授权，缺真人或留出集仍记未通过。

### 2026-09-13 首声等待：供应商往返是地板

语音首声 4.9–7.7 秒里，两段模型往返占 5.2 秒；其中意图分类这 1.7–2.7 秒**等于同一供应商跑极小提示的下限**（实测 1.4–4.7 秒），所以削分类提示词、加 `reasoning:"minimal"` 都不会有收益——别再从这两个方向找速度。本地模型池不是捷径：候选要么 4.2–4.4 秒（比现用更慢，且把「把姓名改成李明」判成闲聊），要么返回空文本。TTS 侧同理：建连加 `tts.create` 只值约 270ms，剩余约 540ms 是服务端从收到文字到出声的固有时延，为此改语音流生命周期不值得。

要显著更快只能让分类与回答并行（预期 -2 秒），但那会动刚确认的回答归属规则，属用户裁决范围。探针在 `scripts/experiments/voice-latency/`，结论见[首声验收](evals/20260913-voice-first-audio-latency.md)。
