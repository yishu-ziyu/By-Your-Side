# 模型能力、思考档与后台判断

[文档导航](README.md) · [架构](architecture.md) · [当前状态](STATUS.md)

本页写模型能力、思考档、后台判断与模型出错切换的取舍。档位表、重试次数与超时以代码为准。
验收与实测见 [20261001 思考档与后台判断](evals/20261001-model-effort-and-side-judgments.md)。

## 能力从哪里来

模型能力只登记在 [`shared/model-capabilities.ts`](../shared/model-capabilities.ts) 一处。

- pi-ai 目录里有的模型，照目录取能力。
- 目录缺失或与实测不符的模型，按「服务商/模型 id」精确登记实测结果，并写明依据。
- 两边都没有的模型按保守默认处理：不发思考参数，只收文字。程序不按名字或同服务商的相近模型去猜。
- 截图能不能发、设置页列出哪些模型，都和取档用同一份登记。
- 登记新模型时，先实测，再登记。

## 后台判断

目标核对、记忆判断和语音判断都走同一个后台判断入口，见 [`side-judgment.ts`](../agent/src/side-judgment.ts)。

- 后台判断取该模型允许的最低档。服务端拒绝某档后，本会话的所有调用都跳过这一档。
- 回复不合要求时，程序只带更严格的要求重试一次。
- 仍然失败时，程序只报原因类别，不带服务商原文。

划词问答、整页翻译和正式回答不走这套重试，但同样取最低档。

## 主任务的思考档

主任务从中档起步，见 [`main-effort.ts`](../agent/src/main-effort.ts)。

- 任务宿主只在已记录的信号上升档：同一操作连续失败、原地打转被停、目标核对判没做完、用户中途纠正或插话。
- 程序不为判断任务难度额外调用模型。
- 新任务回到起始档。

## 主任务的模型服务出错

实现见 [`agent-loop.ts`](../agent/src/agent-loop.ts)，验收见 [20261004 模型切换](evals/20261004-model-failover.md)。

- 首个事件的等待上限按实测定：日常首个回应 p90 约 4.7 s，最慢约 12 s。
  ChatGPT 的 gpt-6 系列在服务端偶尔排队 16–17 s 后仍正常答完，所以能力表给它单独登记更长的上限，其他模型不变（[首个反馈](evals/20261006-first-feedback.md)）。
- 超时、连接错误、限流或服务出错第一次出现时，任务宿主就换成设置里的快速模型接着做，不在原模型上重试。
  侧栏显示从哪个模型换到哪个模型；换过之后，这个会话继续用快速模型。
- 只有没设快速模型，或快速模型就是主模型时，任务宿主才在原模型上重试。侧栏的人话错误末尾写出出错的模型。
- 自动切换只保护任务循环里的模型请求。目标核对这类单独的模型请求出错时，任务宿主不换模型。
  例如目标核对失败时，任务宿主只在诊断记录里记下这次核对没有结论，不改用别的模型重试。
