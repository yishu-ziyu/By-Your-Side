# 模型能力、思考档与后台判断

[文档导航](README.md) · [架构](architecture.md) · [当前状态](STATUS.md)

本页写模型能力、思考档、后台判断与模型出错切换的取舍；档位表、重试次数与超时以代码为准。验收与实测见 [20261001 思考档与后台判断](evals/20261001-model-effort-and-side-judgments.md)。

## 能力从哪里来

只有一处：[`shared/model-capabilities.ts`](../shared/model-capabilities.ts)。

- pi-ai 目录里有的模型照目录。
- 目录缺失或与实测不符的，按「服务商/模型 id」精确登记实测结果，并写明依据。
- 两边都没有的模型按保守默认：不发思考参数、只收文字。不按名字或同服务商的邻居去猜。
- 截图能不能发、设置页列出哪些模型，都和取档同源。
- 登记新模型：先实测，再登记并补测试。

## 后台判断

目标核对、记忆判断、语音判断都走 [`sideJudgment`](../agent/src/side-judgment.ts)：

- 取该模型允许的最低档。服务端拒绝某档后，本会话所有调用都跳过它。
- 回复不合要求时只带更严格的要求重试一次。
- 仍失败时只报原因类别，不带服务商原文。

划词问答、整页翻译、正式回答不走这套重试，但同样取最低档。

## 主任务的思考档

[`MainEffort`](../agent/src/main-effort.ts) 从中档起步。

- 只在任务宿主已记录的信号上升档：同一操作连续失败、原地打转被停、目标核对判没做完、用户中途纠正或插话。
- 不为判断难度额外调用模型。
- 新任务回到起始档。

## 主任务的模型服务出错

见 [`agent-loop.ts`](../agent/src/agent-loop.ts)，验收见 [20261004 模型切换](evals/20261004-model-failover.md)：

- 首个事件等待上限依据实测：日常首个回应 p90 约 4.7 s、最慢约 12 s。ChatGPT 的 gpt-6 系列服务端偶尔排队 16–17 s 后正常答完，能力表给它单独登记更长的上限，其他模型不变（[首个反馈](evals/20261006-first-feedback.md)）。
- 超时、连接错误、限流或服务出错，第一次出现就换设置里的快速模型接着做，不在原模型上重试。侧栏显示从哪个换到哪个，换过后这个会话继续用它。
- 没有快速模型或它就是主模型时，才在原模型上重试。侧栏的人话错误末尾写出错的模型。
