# 模型能力、思考档与后台判断

本页写模型能力、思考档、后台判断与模型出错切换的取舍。

## 能力从哪里来

- 模型能力只登记在一处。截图能不能发、设置页列出哪些模型，都和取档用同一份登记。
- 登记里既没有、模型目录里也没有的模型按保守默认处理。程序不按名字或同服务商的相近模型去猜。
- 登记新模型时，先实测，再登记。

## 后台判断

目标核对、记忆判断和语音判断都走同一个后台判断入口，取该模型允许的最低档。失败时，程序只报原因类别，不带服务商原文，所以错误里不会带出凭据。

## 主任务的思考档

- 任务宿主只在已记录的信号上升档，不为判断任务难度额外调用模型。
- 新任务回到起始档。

## 阅读卡的深度档

阅读卡默认仍用快速模型和该模型允许的最低档。选「深度」时改用主模型，思考档取主任务在新任务上的起始档（同一套档位表，不按模型名字猜）。不跟着这一路任务已经升过的档，也不跟着侧栏输入框旁的「快 / 深入」。

## 主任务的模型服务出错

- 模型服务第一次出错时，任务宿主就换成设置里的快速模型接着做，不在原模型上重试。侧栏显示从哪个模型换到哪个模型；换过之后，这个会话继续用快速模型。
- 只有没设快速模型，或快速模型就是主模型时，任务宿主才在原模型上重试。
- ChatGPT 的 gpt-6 系列在服务端偶尔排队很久后仍正常答完，所以只有它登记了更长的首个回应等待上限。
- 自动切换只保护任务循环里的模型请求。目标核对这类单独的模型请求出错时，任务宿主不换模型，只在诊断记录里记下这次没有结论。
