# 任务: 接管/交接 —— 页面上同一时刻只有一方在点

来源：`docs/ROADMAP.md`「接管/交接按钮」。2026-09-04 全栈探查：五层都没有旁观态，只有 overlay `pointer-events:none`（你能点，它也在点）。本卡先定价值函数，**现在不实现**。

对照：Nielsen「系统状态可见性」「用户控制与自由」；Apple Agency（我知道发生了什么，也能决定下一步；只保留必要控件）；Shape of AI Controls（停 ≠ 继续；继续不得重开一轮）。本仓库设计取向：可依赖 = 用户始终知道 Agent 在做什么。

```
Change:     运行中的任务，用户能把页面拿过来自己点；拿过来之后 Agent 不再 click/fill/type；还回去之后 Agent 读当前页接着干，不把任务重来一遍。
Not this:   中止后再发一条新消息；光标层点得透但 Agent 同时在点；教学模式；侧栏多一个不管事的「接管」按钮。
Evaluator:  人评硬场景 + 协议/状态单测。本卡未开做，条目全空。
Evidence:   真机路径见下；观感由用户裁决。
```

## 为什么要做（现象，不是功能名）

现在两个人抢同一块屏幕。用户不知道「现在归谁」。Nielsen：状态看不见，就没有信任。Apple：界面的任务是让人能决定下一步，不是让人服从流程。

已有的「中止」是紧急出口（Nielsen 用户控制），但出口等于任务死掉。Shape of AI 写过这个坑：停了再开，结果可能和刚才不一致；要的是**继续**，不是重来。

prompt 里已经有半截：遇到登录 / 验证码 / 2FA，Agent 应停住让用户自己做完再说「继续」。那是文本里的交接，没有状态、没有停手保证。

## 何时做 / 依赖什么

**现在不实现。** 接管的验收按 B。就地确认仍是另一张卡（危险动作上点确认），不替代 B。

依赖（五层都缺，开做时一起补，只补按钮不算）：

| 层 | 现在 | 要补的现象 |
|---|---|---|
| 界面 | 无键 | 能看出「现在归你 / 现在归它」，并能切 |
| 前端 | 点得透，tool_call 照执行 | 旁观时 click/fill/type/js 不落地 |
| 传输 | 只有 idle/running、abort | 多一个旁观态；继续 ≠ abort |
| 后端 | abort 杀整轮 | 会话还在，只是不发操作；继续则 snapshot 当前页往下走 |
| 数据 | 无 | 旁观是会话态，不必跨 Chrome 重启持久化 |

还依赖：当前页感知（还回去时要知道用户点到了哪）。

## 两档标准（先裁哪一档）

**A. 让路（推荐先做，且应并进就地确认 / 登录场景，不单开常驻按钮）**

Agent 已经停住等你（确认删除、登录、验证码）。页面上能做完，再还回去。这是「紧急出口」的对偶：不是逃离任务，是任务让路。

**B. 抢方向盘（完整接管）**

Agent 还在跑，用户随时拿过来。五层都要上。

2026-09-04 先裁 A，同日改裁 **B**：要的就是运行中抢方向盘，还回去接着干。A 是 B 的子集（它停住时让路仍然成立），不够。

## 验收标准

- [ ] 1. 旁观期间 Agent 不再对页面做 click / fill / type_text / press_key / js；光标隐藏或明确闲置。— evaluator: 协议/执行层单测（旁观态下这些 tool_call 被拒或根本不发）+ 人评
- [ ] 2. 还回去之后 Agent 先读当前页再继续，不重新打开站点、不把已做步骤重来。— evaluator: 人评。场景：flomo 定位笔记过程中接手，改点另一条，还回去后它处理的是你点的那条
- [ ] 3. 运行中随时能拿过来（不只等 Agent 先问）。— evaluator: 人评
- [ ] 4. 用户始终能看出现在归谁（状态可见）。拿过来、还回去都有即时反馈。— evaluator: 人评。对照 Nielsen：只显示能据此行动的状态，不堆内部细节
- [ ] 5. 旁观 ≠ 中止：会话还在，工人若有则停手不断开；中止键仍是杀任务。— evaluator: 单测 status 旁观 ≠ idle；abort 仍能杀
- [ ] 6. typecheck / test / build 绿；协议有旁观态正反例。— evaluator: `npm run typecheck && npm test && npm run build`

## 为什么是这个标准

- 第 1 条：没有停手，按钮是假的（Not this：点得透但两边同时点）。
- 第 2 条：Shape of AI——继续必须带着上下文，否则用户不敢放手。
- 第 4 条：Nielsen 状态可见 + 本仓库「可依赖」。看不见归谁，就没有掌控。
- 第 5 条：中止已经有了；再做一个同义键是层级浪费。
- 不做「必须是侧栏两颗按钮」：形态未定。过的是现象，不是控件名。

## 边界与不做

- 现在不实现；不先画按钮方案
- 不做就地确认（另一张卡）
- 不把 abort 改名为接管
- 不做跨会话持久化「现在归用户」
- 不做三个并列聊天线程、不改教学模式
