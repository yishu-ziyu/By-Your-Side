# 任务：从短入口找到项目事实，修改功能时不遗漏对应文档

## 完成标准

- [x] 自有项目说明集中在 `docs/`；根 README/AGENTS、工具加载入口、第三方来源说明、受保护评测原件列为明确例外。迁移经验库时同步已有 hook 的路径，不启动这些 hook 的模型任务。
- [x] 根 README 与文档导航只给概览和入口；STATUS 只留当前结论、未决问题和下一步，原历史完整保留，不把旧测试结果改成新验收。
- [x] 文档检查能阻止目录外新增说明、当前文档超长、仓库内断链，以及修改功能却只更新 STATUS/验收记录的变更。
- [x] 通过真实临时 Git 仓库运行检查命令，覆盖通过、失败及工作区/已提交变更；检查器测试先于检查器实现。
- [x] `npm run check` 接文档检查；PR 检查使用明确比较基线；提供人工复核清单，不声称机器能判断文档语义正确。

检查者：当前主代理运行文档检查及命令级验收；维护者检查文字是否真正对应功能变化。

## 实现前失败场景

迁移后入口断链；只按行数漏掉万字长段落；历史中的过期“下一步”仍当现状；Markdown 示例被误当真实链接；中文/空格路径解析错误；只写验收记录绕过功能文档；基线无效却静默跳过；已有 dirty 文件被覆盖；工具仍向旧 wiki 路径写入。

## 范围

整理入口、文档路径和维护检查，不改产品逻辑，不构建、不重载、不请求真实模型、不 commit/push。历史验收和锁定评测不重写结论；历史原件可保留长度，日常只通过短索引访问。

## 实际整理与发现

26 份散落说明迁入 docs：24 份经验/提案、验收脚本说明与 EverOS 说明。旧 hook 的项目门控不改，只更新其资料路径；原始轨迹和运行日志不自动搬运。

根 README 从 6,381 字符收为 1,046 字符，NOTES 从 6,868 收为 1,165 字符；STATUS 从 27,958 收为 1,660 字符。三个旧入口完整保存为 history 下的文本快照；README 快照与入场 HEAD 原文按字节相等。历史中的旧状态与原始失败没有删除。

同步检查第一次发现语音文档欠账：代码已接 Realtime 直连工具，长期说明仍称操作统一经任务引擎。读取 `realtime-browser-tools.ts`、`voice-service.ts` 与 `realtime-voice-session.ts` 后更新语音架构，说明直连、委派与诊断连接的边界，不靠空改一行消除错误。

本轮修复了迁移直接造成的 7 个历史链接。剩余 46 条是已有本机绝对路径、`:行号` 格式引用或已移除脚本，不伪造缺失证据，也不把审计退出 0 表述为所有历史链接完好。

迁移还必须保留本地原始会话的忽略规则：`git check-ignore --no-index` 在新轨迹/锁路径上先返回 1，说明原规则不覆盖新路径；补充 `.gitignore` 后返回 0，两个新路径均被忽略。只允许脱敏经验进入版本库，不把原始对话搬到 docs 后意外纳入提交。
