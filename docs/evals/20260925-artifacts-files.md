# 任务: 说「导出成 CSV / 整理成文档」时，侧栏出现一张文件卡片，点一下就能下载

## 背景

Sitegeist 复现（[记录](20260925-sitegeist-parity.md)）里「导出 CSV」一直失败：我们没有生成文件的能力，模型只能把 CSV 文本贴在回答里。Sitegeist 的这项能力来自 Pi 的界面包 `@earendil-works/pi-web-ui`（产物工具 + 产物面板）。它的工具实现写在 Lit 面板组件里（`ArtifactsPanel.tool`），不能单独取用。用户 2026-09-25 选择「拿 Pi 的工具，面板自己画」：沿用它的工具约定（create / update / rewrite / get / delete），卡片按侧栏现有风格画。

## 完成标准

- [x] 1. 要求导出 CSV 时，侧栏出现文件卡片；像用户一样点「下载」，下载目录里有 CSV，含全部商品和价格 — 谁检查: `everyday-baseline.mts --suite=sitegeist --only=export-csv`（脚本先把按钮滚到可见处再点）
- [x] 2. CSV 用 Excel 打开中文不乱码（文件以 UTF-8 BOM 开头） — 谁检查: 读下载文件的前三个字节
- [x] 3. 卡片在回答下面，读完回答就能看到 — 谁检查: 侧栏截图（人看）
- [x] 4. 其余 Sitegeist 用例与日常请求不受影响 — 谁检查: 套件全跑 + 日常底线 5 条（见证据）
- [ ] 5. 网页文件在侧栏里预览运行 — 第二步，未做

## 边界与不做

- 只做文本文件；PDF、Word、Excel 不做。
- 文件只在本会话内存；宿主重启后模型读不回旧文件（卡片随侧栏历史仍在，可下载）。
- 不自动下载，由用户点。

## 去掉假的「没做完」（用户 2026-09-25 选定下一步）

原因：导出 CSV 时模型把「导出成文件」当成「把页面原文复制进文档」，登记了「取原文」和「逐字填写」两类目标。逐字填写只能核对页面上的输入框，核对不了文件，于是永远未完成：回答末尾出现「仅交付部分结果」、侧栏出现「还有 N 项没完成 [继续]」；取原文又被核对模型反复打回，8 次调用花在这上面。

做法：沿用「逐字一致只管复制任务」的裁决，把判断抽成 `shared/copy-request.ts`（关卡二与此共用）。用户原话没有复制、粘贴、原文、一字不差等说法时，`task_goals` 拒绝登记「取原文 / 逐字填写」两类目标，并提示直接完成交付；工具说明与执行约定同步改成「用户明说要照原文搬运时」。复制任务不变。
