# 任务: 在网页上按住右 ⌥ 说话，松开后这句话交给助手去做，侧栏关着也行

来源：#125 第 1 步（总览 #106）。10-07 用户定：按住说话走「听写 → 助手 → 念结果」；听写用 Step Plan 套餐的 `stepaudio-2.5-realtime`，只做转写，不让它回话。本任务只做到「交给助手」；页面胶囊、念结果是第 2、3 步。

## 规则

- R1 在网页上单独按住右 ⌥ 超过 0.15 秒开始录音；松开后听写，文字作为一条用户消息交给当前会话的助手，带上这个网页（与在输入框打字发送相同）
  - 例子(正)：在供应商页按住右 ⌥ 说「把这三家公司整理成一张表」，松开后会话里出现这句话，助手开始做 — 谁检查：`ptt-dictation.mts`
  - 例子(反)：⌥ 和别的键一起按（打特殊字符、快捷键），或按住不到 0.15 秒，都不开始录音；按住时按 Esc 取消，不发消息 — 谁检查：`ptt-keys.test.ts`
- R2 侧栏关着时同样能用：消息进入当前会话并开始执行，重开侧栏能看到这句话和回答
  - 谁检查：`ptt-dictation.mts`（全程不开侧栏，结束后再打开核对）
- R3 听写只连 `wss://api.stepfun.com/step_plan/v1/realtime`，模型 `stepaudio-2.5-realtime`，只开文字、手动提交、不请求回复；不连按量的 `/v1`
  - 谁检查：`ptt-dictation.test.ts`（发出的地址与事件序列）；`ptt-dictation.mts`（离屏页面的 WebSocket 地址）
- R4 麦克风没授权时打开授权页；听写失败或没听到话时，会话里出现一行说明，不静默吞掉
  - 谁检查：`ptt-dictation.test.ts`

## 还没答上的问题

- 无

## 技术前提

- 前提：侧栏从没打开过，离屏文档（reason `USER_MEDIA`）在扩展来源授权过一次后能拿到麦克风；未授权报 `NotAllowedError`。小实验：无头 Chrome，两个资料目录对照。结果：通过（10-07，`scratchpad/ptt-probe/offscreen-mic.mts`；24kHz 有信号，RMS 0.22）。
- 前提：网页脚本能收到右 ⌥ 的按下与松开（普通页、输入框聚焦）。小实验：CDP 发键，按住 0.8 秒测得 818–830ms。结果：通过（`hold-key.mts`）。
- 前提：套餐 Realtime 2.5 可只做听写：手动提交后返回 `conversation.item.input_audio_transcription.completed`，不发 `response.create` 就不回话。小实验：同一句 4.9 秒录音 3 次，提交后 847 / 866 / 2074 ms 得到全文，3/3 正确。结果：通过（`plan-realtime-asr.mts`）。

## 边界与不做

- 页面底部胶囊、按住时的声波、Esc 的可见反馈：第 2 步。念结果：第 3 步。
- 焦点在地址栏、Chrome 自带页面、PDF 阅读器时网页脚本不在，按住说话不可用；退路（扩展快捷键切换）以后再做。
- 网页自己在捕获阶段抢先拦掉所有按键时收不到（脚本在页面加载完后才挂上）。
- 免按键模式（Realtime 3）不变。

## 实测

- 单元：`ptt-keys.test.ts` 6 项（轻点、⌥ 当修饰键、自动重复、Esc/失焦、左 ⌥、连按两次）；`ptt-dictation.test.ts` 4 项（只连套餐地址、只开文字且关 VAD、配好前的音频补发、松开后提交并等全文、从不请求回复、空话/出错/超时不当成功、取消不提交）。
- 真实路径 `ptt-dictation.mts`（只装扩展的无头 Chrome，假麦克风放 say 合成的「把这三家公司整理成一张表，按营收排一下。」，听写连真实的 Step Plan 套餐，助手用脚本模型）通过：全程不开侧栏；按住 5.9 秒、松开后 2.5 秒助手收到这句话（含听写与交给助手）；离屏文档只建了 `wss://api.stepfun.com/step_plan/v1/realtime?model=stepaudio-2.5-realtime` 一个连接；之后打开侧栏，对话里有这句话和回答。
- R4 只覆盖到听写层（空话、出错、超时、取消都有明确结果）；后台据此打开授权页或在会话里写一行说明，这一段没有单独的测试，靠代码审阅。
- 没测：真键盘在 macOS 上的手感；开麦需要的一两百毫秒里说出的第一个字会不会丢（假麦克风从开麦那一刻才开始放，测不出）。
