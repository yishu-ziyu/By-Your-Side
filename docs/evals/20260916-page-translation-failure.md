## 原因与修改

1. **同页复现的直接原因：可选思考耗尽输出预算。** 两次第一批输入 4117 字符 / 40 段内文本片段，均在 47–49 秒后返回 `stopReason=length`；输出只有 thinking，约 32920 字符 / 11024 token，没有正式译文。原始 native 日志只保留了统一错误，故不能把原调用的 stopReason 当作已记录事实；复现与原调用 45.53 秒的行为一致。
2. **确定的连锁缺陷：组合工具继承了前一次 collect 的 executed 事实。** 模型生成失败没有落页，但被写入账本解释成未知写入；后续重试和显示操作都被锁。现在在生成阶段明确记录：此前 0 段为 not_executed，已有确认段落为 executed；后者在翻译这种只收集未译段落的可恢复工具上记为 blocked，不能记成已完成。真正 RPC 超时仍为 unknown。
3. 段落翻译不再请求可选思考，不改变主会话的模型和思考设置。模型失败记录 stopReason、耗时、输入规模和用量，不记录页面/推理正文。
4. 空白和独立标点由页面保留，模型只处理有语言内容的片段。每批最多 8 个段落、常规最多 24 个文本片段，单个原段落保持完整。译文按 id 核对与匹配，JSON 顺序变化不误判；缺项、重复、空译文仍拒绝。
5. 格式不完整时只在模型生成阶段局部重试一次，尚未写入页面；两次不合格明确报错并保留已完成段落。不为翻译解除其他工具的未知写入保护。
6. 侧栏消息、思考区、步骤区、输入框采用细滑块和透明轨道；不修改网页自己的滚动条。
