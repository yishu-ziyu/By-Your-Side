# 任务: 助手把页面交给你时，网页上圈出要你填的栏和要你点的按钮

来源：用户认可的预览 [handoff-circle](../previews/handoff-circle/index.html)（2026-10-12，橙色圈、填好一栏就淡出）。补的是[交给你](20261010-hand-to-user.md)里未做的 R2，不做那里的橙色整页边框，因为右上角的「现在归你」已经说明页面归谁。做法参考 bigarrow（macOS 命令行工具，代理只指不点）：要人亲自做的一步，直接指出在哪。

## 规则

- R1 助手交给用户时带上目标，页面上这些目标被橙色手绘圈圈出：第一个要填的栏挂名牌「你来填 · <各栏名字>」，按钮挂「填完点这里」（没有要填的栏时写「点这里」）。
  - 例子(正)：本机账单页，脚本模型调 `hand_to_user`，目标是卡号、有效期、安全码三栏和「保存」。那么页面上出现 4 个圈，卡号栏的名牌写「你来填 · 卡号、有效期、安全码」，「保存」的名牌写「填完点这里」 — 谁检查：`npx tsx scripts/acceptance/real-path/handoff.mts --headless`
  - 例子(反)：让交给用户时不画圈，用例必须失败 — 谁检查：同一命令（故意弄坏一次）
- R2 用户填好一栏，这一栏的圈淡出；名牌移到下一个还空着的栏，只写还剩的栏。用户点了圈出的按钮，按钮的圈淡出。
  - 例子(正)：用户填好卡号，那么卡号的圈淡出，有效期栏的名牌写「你来填 · 有效期、安全码」 — 谁检查：同上
- R3 页面不再归用户时，圈和名牌全部清掉：用户交还、用户点停止都算。
  - 例子(正)：用户点「做好了，交还」，那么页面上不再有交给用户时画的圈；助手照常接着做 — 谁检查：同上
- R4 圈不上不挡交还：目标找不到时，页面照常交给用户，其余目标照常圈。模型不会收到哪个没圈上，因为这时页面已归用户，模型也做不了什么。
  - 例子(正)：目标里有一个页面上不存在的选择器，那么页面照常归用户，其余目标照常圈出 — 谁检查：同上

## 还没答上的问题

- 无。颜色和淡出由用户在预览里认可（10-12）。

## 技术前提

- 前提：交给用户之前，扩展能用 `mark`、`guide_step` 已有的定位（@ref、`loc=`、CSS）找到目标并画手绘圈。依据：两者已上线的验收（[圈画](20261009-mark-text.md)、[教学](20261011-guided-teaching.md)）。结果：通过（已有验收）。
- 前提：用户点停止时，页面上的「现在归你」条会收起，所以把圈的生命跟这条绑在一起就能覆盖交还和停止。小实验：本任务的验收用例直接测停止路径。结果：通过，停止后页面条和圈都收掉了（见下方结果）。

## 边界与不做

- 不加整页橙色边框。
- 跨域 iframe 里的单个栏圈不到；模型可以把整个 iframe 当目标圈出来。
- 语音的固定工具表不改。
- 用户没填就交还时，助手要不要再交给用户一次，由模型按页面决定；本任务不加程序规则（原 R3）。

## 结果

2026-10-12，分支 `feat/handoff-circle`，脚本模型。证据在 `out/acceptance/handoff/<run>/`。

- `handoff --headless`：17/17 通过（`fix-final`）。R1 圈出 4 个，不存在的目标跳过；名牌贴着自己的圈，不挨着别的按钮、输入框和名牌。R2 填好卡号后名牌移到有效期，点保存后按钮的圈淡出。R3 交还和停止后都没有圈，停止后页面条也收起。原有的交给用户、交还、领取检查照常通过。
- 反例：后台不画圈，R1、R2 失败（`circle-falsify`）。页面条收起时不清圈，两条 R3 都失败（`circle-falsify-r3`）。名牌不要求贴着自己的圈时，「填完点这里」漂到「领取 $30」旁边，名牌检查失败（`fix-falsify-label`）。
- 第一版名牌会沿圈的上下方向平移最远 480 像素，「填完点这里」落在「领取 $30」旁边，用户会读成点「领取」。现在名牌必须和自己的圈横向或纵向重叠。找不到不压文字的位置时，名牌可以压文字和别的圈，但不压控件，名牌之间也不互相压。测试页三栏在同一行，所以卡号的名牌落在卡号栏右下方。
- 已有值的栏照样圈；用户交给之后自己输入过、而且有值，才算填好。这样下拉框的默认值、浏览器自动填的值不会让圈一出现就淡出。

没验到的：

- 真实模型会不会带上 targets，以及 @ref 形式的目标；验收只用了 CSS 选择器。
- iframe 目标、包着输入框的 label 或 div、一开始就有值的栏：只改了代码，没有场景。
- 接管失败或超时后收起页面条和圈：只改了代码，没有场景。
- 网页重画目标栏（换了节点）后，圈和「填好没有」的判断还跟着旧节点。
- 真人没看过真实网页上的圈。
