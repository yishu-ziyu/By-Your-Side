## 完成标准与证据

- [x] 分类早于下一段、晚于下一段转写、晚于第三段转写，都按原顺序组合文本。— 机器：生产会话参数化回归。
- [x] 输入只等待上一段意图分类，不等后台网页任务结束。— 机器：生产会话回归。
- [x] 页面资料变慢时，音频commit仍即时进入识别；资料按原turn返回，原页面身份不被新页替换。— 机器：relay/会话/协议回归与真实无头扩展。
- [x] 三段快速连续输入，最早的迟到转写仍保留、排序且只消费一次。— 机器：旧实现真实扩展失败，修复后同脚本通过。
- [x] 真实阶跃识别、生产输入协调、真实任务模型、真实浏览器读页贯通，得到页面的开放时间与价格。— 机器：隔离无头全栈验收。
- [x] 新扩展后台加载内容与本地构建一致；加载前确认没有运行任务。— 机器：只读状态检查、重载及脚本内容核对。

## 全栈设计改动

依照[架构梳理](../voice-architecture.md)，分清声音片段、完整请求、任务和播放。没有替换Pi、供应商或执行权限链。

- **扩展传输**：commit不再等页面资料，携带contextPending后立即送达；异步input_context消息单独补充原turn的页面身份。切会话/换语音lease后不再投递；面板不能伪造relay生成的input_context消息。
- **输入账本**：在现有VoiceInputLedger集中管理片段身份、迟到文本、上下文准备及原页面引用。保留20段有界身份，晚到文本按声音片段序号排序，重复结果不重复消费。页面资料超时明确终止本句派发，不用新页补齐旧请求。
- **语音协调**：分类决定有独立完成信号，与网页执行/播报完成分开。下一段可等分类结果来决定拼接，但不等整个后台任务。已排队转写按顺序消费，过期的尚未派发片段并入当前完整表达。
- **协议**：增加contextPending和input_context，并复用原页面/附件的输入校验。没有放宽runId、controlVersion或页面观察授权。

复杂度增长集中在有界的输入账本及分类/执行完成信号分离。上下文的计时器、清理和原页引用集中到输入账本，未继续散放在语音大类。新增的上下文协议是为了让收音不等待页面资料，不是通用消息框架。
