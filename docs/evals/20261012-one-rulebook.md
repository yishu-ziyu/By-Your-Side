# 任务: 新会话只读一页现行规则，规则之间不再互相矛盾

开发环境优化第一项（B）。另外三项（A 测试、C 文档、D 工作线）各自另开验收。

## 为什么

2026-09-12 至 10-12 的复盘：提交量在 10 月涨了几倍，但是用户能看到的成果没有跟着涨。增加的时间主要花在等测试、改文档、对规则上。

- 记忆里有 55 条规则，项目规则又分散在 AGENTS.md 和协作方式里。旧规则几乎不删，至少 5 组直接矛盾（工作区、汇报方式、开工前确认、子代理、测试轻重）。
- 结果是每个会话挑不同的规则遵守，用户反复纠正，每次纠正又新增一条规则。
- 协作流程本身一个月改了 43 次。

## 规则

- R1 项目的现行规则只在 AGENTS.md 一处，规则条目不超过 40 条。
  - 例子(正)：新会话读 AGENTS.md 就能知道开工、工作区、测试、汇报、分工怎么做 — 谁检查：人
  - 例子(反)：记忆里还有一条“每次改动都开看板页”，和 AGENTS.md 的汇报规则冲突 — 谁检查：人（逐条对照记忆索引）
- R2 用户 10-12 裁决的 4 组矛盾，AGENTS.md、协作方式和记忆里只剩一种说法。
  - 工作区：每任务一个短期工作树，主目录只同步。
  - 汇报：只在需要用户判断时开 cmux 页面。
  - 开工：新功能和换方向先一句话对齐（界面类加预览）；修 bug 和改环境直接做。
  - 子代理：设计由主会话做；规格清楚的实现拆小块并行派出。
- R3 项目层开场注入的规则（AGENTS.md + 记忆索引）比改前少一半以上。 — 谁检查：`wc -c`

## 技术前提

- 前提：Claude 每次开场读 `CLAUDE.md`（指向 AGENTS.md）和记忆索引；Codex 读 AGENTS.md。所以规则放 AGENTS.md，两种代理看到的是同一份。小实验：无，直接看会话开场注入内容。结果：通过。

## 边界与不做

- 不改跨项目的 `~/.claude/CLAUDE.md` 和 `~/.codex/AGENTS.md`，因为它们也管其他项目。
- STATUS、验收文件、NOTES 的写法放到 C 项再减。

## 结果

- R1 通过：AGENTS.md 从 89 行改为 49 行，规则 25 条。验收文件模板移到[文档维护](../development/documentation.md#验收文件模板)。
- R2 通过：协作方式的七步流程改为按改动类型区分；被取代的 36 条记忆移入记忆目录的 `archive/`，不再被索引。
- R3 通过：AGENTS.md + 记忆索引从 12,233 字节降到 5,958 字节（-51%）。全局 `~/.claude/CLAUDE.md`（6.9 KB）没动，所以 Claude 开场总量约降 33%。
