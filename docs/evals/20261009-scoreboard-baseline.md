# 成绩表底子：做得准（2026-10-09）

用户 10-09 定下第一阶段方向「做得准」。以后每周只攻分数最差的一条路，改完用同一套测试重跑，用前后数字说明变好了没有。本文是第一次量的底子。

## 产品承诺（草稿，待用户确认）

你在浏览器里说一句要做的事，它做对；做不到时直接告诉你哪里没做到。

## 规则
- R1 每条路的分数只看真实结果：页面、下载的文件、草稿框和练习站收到的请求，不看助手怎么说。
  - 例子(正)：草稿框里正好是第一句英文原文，且练习站没收到保存请求，记做对 — 谁检查：日常请求底线脚本
  - 例子(反)：回答说「已填入」，草稿框里却是「Note」，记没做对 — 谁检查：同上
- R2 每次都从没有过往任务的新浏览器资料开始，使 5 次互不影响。
  - 例子(反)：同一份资料连跑，第 2 次起回答下面出现「按上次做过的…」，这一组不进成绩表 — 谁检查：人读回答

## 技术前提
- 前提：日常请求底线脚本已有这些路的判据，本次不新写用例。小实验：无。

## 怎么量

- 每条路跑 5 次，每次都是新的浏览器资料，没有任何过往任务。只装扩展，从设置页配默认测试模型 GPT-6 Luna（ChatGPT 登录）。练习页全在本机。
- 没有用用户日常 Chrome 里的模型设置，所以这张表不代表用户日常配置下的分数。
- 三个数：做对几次（看页面、文件和草稿框的真实结果，不看助手怎么说）；整轮耗时中位数；没做对时回答里有没有说「已完成」（下表记作「说做到了」）。
- 主干 `7606c23`。命令见 [日常请求底线脚本](../../scripts/acceptance/real-path/everyday-baseline.mts) 文件头，每次用 `--only=<路>` 单独起一个进程。

## 发现

- **复制最差，而且会说假话。** 4 次没做对：3 次只填了框里的粗体标题「Note」，1 次填了两句。其中 3 次回答写「已把第一句英文原文填入草稿框」，只有 1 次承认填错了。根因还没查。
- **过往任务不看相关不相关就带上。** 先用同一份浏览器资料连跑时，从第 2 次起回答下面都有「按上次做过的…」，引的是同一网站最近的任务，包括无关的任务（复制任务引了圈画任务，导出任务引了汇总任务）。原因：同一网站最近的 3 条任务会直接交给助手，不判断相关性（[代码](../../agent/src/memory-context.ts)）。真实网站上，用户在 GitHub 的最近 3 件事会跟着每一个新的 GitHub 请求。这一组连跑 34/35 做对，复制也错了 1 次，所以错复制不是带上过往任务引起的。
- **耗时波动大。** 同一句话，最快和最慢能差 4 到 8 倍（导出 4.9–39.7 秒）。这次不攻速度，只记下。
- **诊断记录清不干净。** 连跑那一组在设置页清空诊断后，导出里仍有 1 条任务记录。

## 没量到的

- 用户日常配置下的分数；真实网站（练习页之外）。
- 「说做到了」只在没做对的那几次里人工读回答判；做对的那几次没有核对回答的说法。
