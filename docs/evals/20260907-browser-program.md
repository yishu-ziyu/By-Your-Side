# 任务: Agent 能在一次模型工具调用中组合浏览器操作，并保持逐步可观察和可中断

起草日期：2026-09-07。
校验角色：独立校验代理 recovery_evaluator。本文先于实现编写；实现方不得自行修改完成标准，范围变化交编排或用户裁决。

## 完成标准

- [ ] 1. 模型可在一次组合工具调用中编写并执行具有顺序、条件分支和有界等待的浏览器操作。至少能依据一次观察结果选择后续动作，等待满足条件后继续；等待条件始终不满足时明确返回超时，不无限执行。必须观察到多个真实子动作由一次模型工具调用发起，不能由宿主预设成功结果或多轮模型调用伪装。 — 谁检查: 机器，组合执行聚焦测试及第 7 条真实任务。
- [ ] 2. 组合中的浏览器子动作经过现有生产工具链与 RPC，复用当前工作标签页、工具行为、权限与控制状态。既有独立工具仍可调用；普通 hover、click、snapshot、fill 等原路径不回归。不能通过另起一套不受控制的浏览器操作通道满足本条。 — 谁检查: 机器，生产转发集成测试与现有相关回归测试；编排检查实际调用轨迹。
- [ ] 3. 用户取消或接管后，组合程序不能发起任何新的浏览器子动作。此前已经派发的动作按现有控制语义处理，不伪称已撤回。危险 click 返回 held 时，同一组合调用中的后续浏览器动作必须停止；用户后来确认该动作，不得自动解除该段程序已经停止的状态。脚本捕获异常、继续循环、发起未等待的调用或等待结束后继续，均不能绕过这三个停止条件；新任务或后续合法续跑沿用现有控制流程。 — 谁检查: 机器，分别覆盖取消、接管、held 的控制测试，包含脚本 catch 后继续调用及等待期间接管；至少一次真实扩展操作验证接管后无后续填写。记录接管时间与最后实际派发动作，不能仅断言组合工具返回失败。
- [ ] 4. 每个子动作可在现有执行观察渠道中识别名称、顺序、参数摘要、开始、完成或错误，并关联所属组合调用。诊断日志保留每个子动作的实际结果和耗时；组合总结果不能替代子动作记录。复用现有脱敏、图片省略和数据量限制；日志失败不改变原动作结果。未执行的动作不能记录为成功，危险动作 held、取消、等待超时必须可区分。 — 谁检查: 机器，事件与日志聚焦测试；编排核对第 7 条真实工具轨迹及可见执行状态。不要求新增 UI。
- [ ] 5. 组合程序不能访问宿主 Node 文件系统、进程环境、启动进程或任意宿主网络能力；不得把 `node:vm` 当作这些限制的安全保证。通过程序全局对象、模块加载或暴露的宿主对象获取这些能力的尝试必须失败。页面侧既有 js 桥的原有能力可继续使用，不将其误报为新增宿主权限，也不为本轮额外扩展其权限。 — 谁检查: 机器，负向测试分别覆盖宿主文件、环境、进程启动、模块加载和直接宿主联网；编排检查隔离边界及暴露接口。测试报告说明阻断发生在哪里，不能仅以提示词禁止代替权限限制。
- [ ] 6. 一般运行错误明确对应到出错子动作，任务结果不虚报成功；用户可据现有上下文继续处理。组合执行有可验证的资源/执行时间边界，无限等待或不结束的脚本不会持续占住任务而无法取消。边界触发时报告原因，不声称原任务完成。 — 谁检查: 机器，普通错误、等待超时及不结束程序的聚焦测试；验证取消后控制通道仍可用。这里限制一次程序的执行资源，不要求新增任务级固定步数停止策略。
- [ ] 7. 使用真实模型、真实扩展、真实生产 RPC，在本地可控页面完成以下三个任务，并分别与现有逐工具调用方式对照。两种方式使用相同模型配置、相同任务目标与初始页面条件，至少各运行一次；记录准确分母，不以单次结果声称总体成功率提高。A：真实 hover 显示隐藏编辑入口，点击打开表单，填写测试草稿且不提交。B：入口延迟出现，等待到真实可用后打开并填写指定草稿；未出现前不能绕过页面条件直接修改状态。C：从至少三条真实页面数据提取指定字段，结果逐项符合夹具预期；若选跨页面版本，则读取来源页后把指定内容填写到目标页，保留来源对应关系且不提交。验收依据是独立检查的页面状态或数据结果，不能仅用程序最后返回 `ok`。 — 谁检查: 机器操作真实产品，编排核对截图/快照、真实模型日志、逐项预期值和实际值。夹具预期值不能由待测模型自行生成。
- [ ] 8. 第 7 条每次运行记录是否达到完整目标、模型轮数、模型工具调用次数、实际浏览器子动作次数、总耗时与人工介入次数，附模型标识、任务起点、命令或 UI 操作及工件路径。至少一个真实任务展示一次组合调用完成多个子动作。只有完整结果同样成立，才比较调用量；少填写、少提取、提前退出不能算效率改善。对照失败或新方式未减少模型往返也如实记录，由编排决定是否需要修复或缩小结论，不虚构性能门槛。 — 谁检查: 机器采集、编排核对；用户评价体感速度和执行过程是否容易理解。
- [ ] 9. 实现说明引用已读取的本地 ego lite 实际工具/技能材料，明确本轮借鉴的组合操作方法及其在真实任务中的表现。常用浏览器能力与组合执行保持可理解的一致关系；不凭产品名称或用户对成功率的描述声称已经复现其全部能力。 — 谁检查: 编排，核对实际来源和实现说明。
- [ ] 10. 新增聚焦测试先通过，再通过 `npm run typecheck`、`npm test`、`npm run build`。记录新增测试的准确命令和上述结果；新增失败或新改动才重复必要检查。不能修改断言来掩盖安全、控制、任务结果回归；基线问题由编排判断并明确记录。 — 谁检查: 机器。

## 边界与不做

- 不新增通用任务框架、工作流编辑器或新的产品 UI；本标准规定验收结果，不指定实现架构。
- 不新增全宿主 Node 执行权限，不绕过已有 RPC、安全确认、接管和取消机制。
- 不以减少模型调用替代任务完成，不把整段程序成功等同于页面操作成功。
- BOSS 原站只读检查或打开编辑器属于可选补充验证；不得填写、保存、提交用户简历。其结果不能替代本地三个完整对照任务，也不能以本地通过宣称 BOSS 原任务已修复。
- 本地填写仅使用测试草稿；不提交外部数据，不用真实用户凭据验证日志脱敏或隔离失败。
- 浏览器任务结果和控制行为由机器先验收；主观速度、清晰度与使用意愿由用户裁决。
