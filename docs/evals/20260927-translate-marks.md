# 任务: 翻译时，待翻的段落有占位，译文到了原地替换，停止后占位收掉

来源：2026-09-27 用户讨论「翻译这个过程是怎么被体验的」，看过四版同时播放的对照预览（[预览](../previews/translate-feel.html)）后选定：第一块先做待翻段落标记；翻不成的段落收掉标记、恢复原样。想法与后续块见 `.ship/ideas/translate-feel.md`（主工作区，未入库）。

## 完成标准

- [x] 1. 说「把这个页面翻译成中文」后，第一段译文出现之前，页面上已有待翻占位 — 谁检查: `everyday-baseline.mts --only=translate-long` 的 `firstMarkMs < firstTranslatedMs`，并有 `translate-long-page-marks-only.png`
- [x] 2. 某段译文到了，这段的占位消失；翻完后页面上不留任何占位 — 谁检查: 同上，`translatedTimeline` 里 pending 随 blocks 增加而减少，结束时 `pendingMarks = 0`，109 段全部译出
- [x] 3. 翻到一半按停止，没翻的段落在 3 秒内收掉占位、恢复原样 — 谁检查: `--only=translate-long-stop`（30 秒时点停止）的 `stopClearMs ≤ 3000`
- [x] 4. 占位不被当成原文再送去翻译，也不改动网站自己元素的样式 — 谁检查: 同 1 的译文段数仍为 109；代码审阅（占位是插入的独立元素，带 `data-bys-translation`，翻译取词时排除）
- [x] 5. 改前对照：同一脚本跑在 main 上，页面上没有占位（`firstMarkMs` 为空），并留同一时刻截图 — 谁检查: 同一命令对 main 构建
- [ ] 6. 在日常 Chrome 里亲手翻一篇真实长文，前后两版对比，判断是安心还是吵 — 谁检查: 人。**2026-09-27 第一次试：不通过**（见下「日常试用」）

### 修订（2026-09-27，日常试用不通过后，用户同意扩大范围）

先让长文在用户日常的 Kimi 编程套餐上能译完，再把占位改成跟着整次请求走。

- [ ] 7. 用 `kimi-coding/kimi-for-coding` 翻 hamel.dev evals FAQ（约 720 段）能全部译完，一次翻译调用内完成，不因并发超限失败 — 谁检查: `everyday-baseline.mts --inproc=kimi-coding/kimi-for-coding` 的真实网页用例
- [ ] 8. 翻译过程中页面不再整体弹跳、占位不再成片消失又出现 — 谁检查: 同上时间线（pending 只减不增），加用户日常再试
- [x] 9. 阶跃上的长文翻译与停止收占位不退化 — 2026-09-27 修复后重跑：长文 109/109，停止后 0.25 s 收占位 — 谁检查: `--only=translate-long,translate-long-stop`

写代码前列出的失败方式（被服务商拒绝并发时）：

1. 服务商因并发拒绝（403/429「concurrent request limit」「rate limit」「too many requests」）：应降低同时在途的批数并稍等再发，不算失败、不立刻原样重试。
2. 降到 1 批仍持续被拒（例如别的会话占着额度）：有限次数后如实停止并说明，不无限重试。
3. 鉴权失败、额度用完等非并发错误：不能当成限流反复重试，照旧按失败报告。
4. 在等待期间用户按停止：立即停，不再发请求。
5. 被拒那批的段落要回到待翻队列，既不丢也不重复翻。
6. 一直没有进展时，180 秒无进展停止照样生效。

## 边界与不做

- 不改翻译速度、分批与并发；不做「一说就开始」（第二块）与翻完的收尾信号（第三块）。
- 与预览的差异：预览里段落左侧有一条细线；真实网页上画这条线要改网站元素的边距或阴影，可能弄乱卡片等布局，所以只保留段落下方的占位条（带一点蓝色）。由标准 6 让用户判断是否够。
- 语音说「翻译这页」走同一工具，本轮只验文字输入。

## 证据

环境：隔离 Chrome for Testing（无头）、当前源码构建的解压扩展、只装扩展；设置页配置 `stepfun/step-3.7-flash`（Step Plan，用户 2026-09-27 批准 3 次长文翻译）。命令：`CASE_LIMIT_MS=900000 npx tsx scripts/acceptance/real-path/everyday-baseline.mts --headless --inproc=stepfun/step-3.7-flash --only=translate-long,translate-long-stop`。产物在 `out/acceptance/real-path/`（本地、不入库）。改前是同一脚本配 main `c13cf60` 的产品代码。

| 运行 | 占位出现 | 第一段译文 | 结果 |
|---|---|---|---|
| 改前 `translate-long` | 无 | 22.2 s | 109/109，86 s 译完；等待期间页面无任何变化 |
| 改后 `translate-long` | 7.6 s | 18.7 s | 109/109，74 s 译完；占位 109 → 0，逐批与译文此消彼长；结束时 0 个占位 |
| 改后 `translate-long-stop` | 7.2 s | 14.2 s | 30 s 点停止；0.25 s 后占位 0 个；已译 43 段保留 |

- 第 3 条第一次运行失败：停止后 94 个占位没收掉。宿主日志显示收尾调用到了扩展，被「原任务已停止或发生变化，操作未执行」拒绝（`extension/src/background/index.ts` 的任务身份检查）。改为只对 `settle` 豁免后重跑通过。中间一次重跑因阶跃接口暂时连不上（curl 15 秒无响应）未能开始，不计入结果。
- 译完那次（改后 `translate-long`）跑在这两处修正之前；两处修正只影响收尾调用本身，其后的翻译相关单元测试 44/44 通过，未再花模型额度重跑。
- 「只有占位」截图在 7.6 s 取得；「占位与译文并存」那张截图比计数晚一帧仍无中文，时间线数据为准。
- 单元测试：`agent/test/page-translation.test.ts` 3 条核对页面动作序列的用例末尾加 `settle`（新增的对外动作）；中间仍不允许出现 `apply`，原保护不变。

## 日常试用（2026-09-27，不通过）

用户在日常 Chrome（模型 `kimi-coding/kimi-for-coding`）翻 hamel.dev 的 evals FAQ（720 段）：「翻一段时间后整个页面突然弹一下，然后流光又出现；没翻完就出现、消失」。诊断记录（经 9222 只读扩展自己的 `sideagent-diagnostics`，快照在 `out/daily-traces/`，不入库）：

- 一次请求里 `page_translation translate` 被调用 4 次（12.0 / 17.8 / 24.9 / 31.3 s），每次约 3 秒就以「翻译生成失败……可继续翻译」结束；之后模型改用脚本读全文，页面最终只译 32/720 段。
- 每次 4 批并发里 3 批返回 `403 permission_error: You've reached your concurrent request limit`，同批重试立即再 403；只有 1 批成功。
- 根因：占位跟着单次工具调用走，`finally` 里的 `settle` 在每次调用结束时一次撤掉约 700 个占位，页面高度骤减（弹一下）；模型再调用，`begin` 又全部标上（流光又出现）。隔离验收用阶跃、单次调用就译完，没有覆盖到这条路径。
- 同时暴露范围外的已有问题：请求池宽度 4 超过 Kimi 编程套餐的并发上限，403 不降并发、不退避，长文翻译在这个模型上基本失败（改前同样，本块未引入）。

## 修订后的检查（2026-09-27）

复刻 Kimi 限制的本机脚本服务商（`--scripted-throttle`：翻译请求同时只接 1 个，超出回 403 `concurrent request limit`；`failTranslations` 让指定数量的请求回 500），真实扩展、隔离无头 Chrome，不花模型额度。命令：`CASE_LIMIT_MS=600000 npx tsx scripts/acceptance/real-path/everyday-baseline.mts --headless --scripted-throttle --only=translate-throttle,translate-resume,translate-long-stop`。

| 用例 | main（改前） | 本分支 |
|---|---|---|
| `translate-throttle` 限流下长文 | 失败：8/109 段（与日常试用同形） | 通过：109/109，1 次调用；诊断记录 18 次请求中 2 次 403 |
| `translate-resume` 第一次调用失败、模型再调用 | — | 通过：2 次调用（第 1 次「可继续」失败），占位只减不增 |
| 同上，去掉 15 秒保留（改回立即撤除） | — | 失败：「占位消失后又成片出现」 |
| `translate-long-stop` 5 秒时停止 | — | 通过：0.34 s 撤掉占位，已译 29 段保留 |

- 阶跃真实网页（`--inproc=stepfun/step-3.7-flash --only=translate-real-hamel,translate-long,translate-long-stop`）：hamel.dev evals FAQ 一次调用译完，572 段成段英文剩 2 段无译文，结束 0 占位，但用时约 12 分钟（116 次请求，7 次 `length`）。当时判「失败：占位回升」——占位在约 43% 处由 414 升到 417。诊断记录：开始 720 块、结束回执 723 块，即翻译途中网页新出现 3 段并被加上占位，不是旧占位消失又出现。阶跃长文 109/109、停止后 0.25 s 收占位均通过。
- 判据第二次修正：闪烁改为「占位回升且（占位 + 译文）总数没超过此前最高值」。第一次改写多加了「回升前占位数大于 0」，把「撤到 0 再全部标回」的真闪烁也排除了，反例误判通过；去掉该条件后反例正确失败（记录到 0 → 102、总数 109 = 此前最高），本分支 4 条脚本服务商用例全过（含 hamel.dev 真实网页 667 块）。阶跃真实网页未按新判据重跑（约 12 分钟额度），依据是上面的块数证据。
- 判据修正：「占位只减不增」最初按 0.25 秒采样判断，去掉修复后仍判通过（两次调用间隔只有几十毫秒，采样漏掉）。改为页面内监听占位数量每一次变化后，反例正确失败。
- 标准 7、8 的真实 Kimi 部分未跑：Pi 里的 Kimi 令牌已过期，刷新会轮换令牌、可能影响日常扩展的登录，未刷新。改由用户在日常 Chrome 用 Kimi 重试同一页，事后读诊断记录核对。
- 同类风险（未改）：并行子任务（主任务 + 最多 2 个）在 Kimi 上同样可能超并发上限。
