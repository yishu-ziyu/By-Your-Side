# 任务：回答下方显示「用了 N 条记忆 ›」，展开后每条可「忘掉」或「这里别用」

[记忆模型](../memory-model.md#10-01-架构与交互调研后的决定) · [issue #56](https://github.com/yishu-ziyu/By-Your-Side/issues/56)

## 规则

- R1 这一轮带了记忆，回答下方就有一行「用了 N 条记忆 ›」，默认折起；N 等于这一轮带进去的记忆条数加过往任务条数。没带记忆就不出现这一行。
  - 正：已记住邮箱和「回复用中文」，问一句话，回答下方显示「用了 2 条记忆 ›」。机器检查：`scripts/acceptance/real-path/memory-used-line.mts --headless --scripted`
  - 反：记忆为空时问同一句话，回答下方没有这一行。机器检查：同上。
- R2 点开以后列出每条原文，过往任务显示摘要。每条都有「忘掉」和「这里别用」。
  - 正：展开后两条原文都在，各有两个按钮。机器检查：同上（截图留证）。
- R3 点「这里别用」：在同一网站，下一轮不再带这条；换到别的网站照样带。记忆面板里这条标注「在 某网站 不用」，并且可以恢复。
  - 正：在 A 网站点「这里别用」后再问一次，发给模型的请求里没有这条；到 B 网站再问，请求里有。机器检查：同上（读请求内容）。
  - 反：「这里别用」不删除记忆，记忆面板里仍能看到这条。机器检查：同上。
- R4 点「忘掉」的效果和记忆面板里的「忘掉」相同：下一轮不带，并且给「撤销」。
  - 正：忘掉以后再问，请求里没有这条；点撤销后再问，请求里又有了。机器检查：同上。

## 还没答上的问题

无。

## 技术前提

- 前提：程序已经按编号记下每一轮带了哪些记忆（`memory_context` 决定记录），所以侧栏能拿到准确的条目，不必猜。小实验：读 `agent/src/memory-runtime.ts` 的 `selectContext`。结果：通过。

## 边界与不做

- 不做「某条记忆改变了做法时自动展开，写明『因为你之前说过……』」：这需要判断是哪条记忆起了作用，留到真人试用以后再定。
- 不改记忆怎么挑、带多少。
- 「这里别用」只按网站区分，不按会话区分。
