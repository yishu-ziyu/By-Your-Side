# 任务: 遇到只有用户能做的一步，助手自己把页面交给用户，用户交还后接着做完（YIS-140）

起因：用户认可了[先说一句与交给你](../previews/speak-and-handoff/index.html)里的新路径。以前助手遇到卡号、验证码、登录、付款授权时，只发一句“做完后说继续”，用户要自己点「接管」、再打字。本任务只做 R1。

## 规则
- R1 任务走到只有用户能做的一步时，助手自己把页面交给用户，这一轮停下；用户点「做好了，交还」后，助手从用户所在的页面接着做原任务。
  - 例子(正)：助手填好账号名称后要用户填卡号。侧栏出现「需要你来这一步」卡，写明要做的事、「交给你期间，我不读也不动这个页面。」和「做好了，交还」；页面右上角写「现在归你 · 在左边填好…」。交给用户期间，模型不再收到请求，网站不收到助手的写入。用户填好、保存、点「做好了，交还」后，卡片收成「你已交还 · 我从你所在的页面接着做」，助手重读页面并领取 $30 — 谁检查：`npx tsx scripts/acceptance/real-path/handoff.mts --headless --run=final`
  - 例子(反)：交给用户的工具不暂停任务。页面条不出现，用例必须失败 — 谁检查：同一命令（故意弄坏一次，见结果）
- R2 未做：交给用户期间，页面加橙色边框，并圈出要用户填的字段。
- R3 未做：用户没填就交还时，助手说明还缺什么并再次交给用户；助手从不自己填被圈出的字段。
- R4 用户在交给期间填的卡号等值，交还后不发给模型。交还时的页面读取与助手平时读页面是同一条路，由[读页面隐私](20261010-snapshot-privacy.md)一并处理。`handoff` 用例检查交还后发给模型的内容里没有用户填的卡号。

## 还没答上的问题
- 无（R1）。

## 技术前提
- 前提：已有的暂停通道（语音“暂停”用的那条）能在任务运行中由助手发起，并且不会等自己而卡住。小实验：没有单独写；R1 验收脚本首次运行即证明成立。结果：通过。
- 前提：交给用户必须在这一轮结束前生效，因为任务停下后不能再接管。所以助手的工具等扩展确认页面已归用户后才返回。

## 边界与不做
- 只做 R1。R2–R4 见上。
- 助手交还后再动手时卡片就收起，所以重放历史不会留下可点的「交还」；用户在交给期间点「停止」时卡片收成「任务已停止」。这两条已改，但没有用例验证。
- 只在本机测试页上验证，没有在真实网站上试。

## 结果（2026-10-10）
- 最终轮：9 项全部通过。证据：`out/acceptance/handoff/final/`（result.json、payloads.json、交给前后的侧栏与页面截图）。
- 故意弄坏：让交给用户的工具什么都不做（不暂停），用例在“页面条出现”处超时失败。证据：`out/acceptance/handoff/falsify/`。
