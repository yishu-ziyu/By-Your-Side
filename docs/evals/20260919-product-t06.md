## 用户可见变化

改前：正式交付只有模型写的正文，界面看不到「这次到底交付了什么、依据是本 run 哪几个真实页面、还有什么没做完」；补发（模型空响应/工具连续失败）产生的交付连结构都没有；结果卡永远不显示未完成项；晚到的旧 run 交付可以改写当前结果卡；模型把某一步说成完成了，界面没有可核对的第二来源。

改后：

- 正式交付（`finding`）带一份与正文分开的宿主事实链：交付范围（`complete`/`partial`）、结果账本里已满足项、仍未完成项（带未完成/受阻/结果未知）、以及本 run 真实打开或读到的页面。模型正文写不进这些字段；旧记录缺字段照常显示。
- 结果气泡在正文下多一个事实块：部分完成时显示「部分完成 · 还有 N 项未完成」、已完成项摘要、未完成清单；有真实来源时列出可点开的链接（新标签页），来源文字只用地址或宿主记录，不用模型自述。
- 结果卡（task strip）在有未完成项时显示「还剩……」；旧 run 的晚到交付只能归档到历史位置，不再改写当前任务的结果卡；跨会话交付在真实中转层就被过滤。
- 结果（`finding`）与普通回答一样有「复制回答 / 继续追问」；正文+事实块一起可复制。工具连续失败、运行出错、锁定来源等场景显示为部分完成并写明卡点，不再只有一句过程日志。
- 过程仍然全部收在运行块 `details` 里默认收起，结果在其后独立呈现；交付事实块没有下载/导出入口。

## 实现要点（本票范围）

1. **事实链字段走兼容扩展**（`shared/voice.ts`）：`UserDelivery.facts?: { outcome:'complete'|'partial'; delivered:string[]; remaining:{id,description,status}[]; sources:{url,title?}[] }`，数组/长度有界，`isUserDelivery` 严格校验；`complete` 与任何未完成项并存时整条记录在解析边界即失败（漏项报完成 0 个假通过）。旧记录无字段仍有效。
2. **只有宿主投影事实**（`agent/src/user-delivery.ts`、`task-progress.ts`、`session.ts`、`conversation-manager.ts`）：工具路径、补发路径、工具连续失败路径都用同一份 `deliveryFacts()`（账本 satisfied/pending…，`isSupersededUnknown` 排除已被满足项取代的未知）+ `nextStep.delivery` 定 outcome。来源只记 `navigate`/`open_tab` 的真实 URL 与读取观测里的真实 URL，去重有界；恢复后不猜测补齐。
3. **呈现决定抽成纯函数**（`extension/src/sidepanel/delivery-facts-view.ts`）：`deliveryPresentation` 定义同 id 重放只更状态、正式结果不被晚到流覆盖、取消前缀不复活；`buildDeliveryFactView`/`renderDeliveryFacts` 只消费字段；`DeliveryPresentationTiming` 记录「收到交付→结果可见下一帧」。旧记录无字段返回 null，不渲染空壳。
4. **面板装配**（`main.ts`）：交付落点按会话身份过滤；结果卡只认当前 run；流/交付走同一呈现决定；验收模式（`?acceptance=t06`）暴露只读采样与信封接收钩子。

1. **C01/C04 内容层仍不合格（T01 既有发现，非本票范围）**：Agent 优先用 `fetch` 读跨页来源，被私网安全闸门拒绝后不再回退导航，重试 3 次后停写。本票只保证这条路诚实地交付部分结果与卡点（已做到），没有修 fetch 回退策略。

3. **恢复后来源会少**：`sources` 只在内存按 run 收集，快照不持久化；host 重启后继续的 run 不猜测补齐，交付可能没有结构化来源（正文链接仍在）。这是有意的诚实边界。
4. **事实链未完成项是账本口径**：未登记进结果账本的任务级缺口（例如某个来源打不开）不会出现在 `remaining` 里，由正文与 T01 oracle 判定；不要把「卡片没有未完成项」当成内容正确。交付文档与实现注释均已标注。
5. **验收时序的测量边界**：50 次采样从面板收到交付信封起算，不含 host→background 转发；真实模型生成时间单独排除，未混入 P95。
6. 验收脚本的 50 次采样用真实面板接收路径 + 脚本化交付输入（不是 50 次真实模型调用）；真实模型路径由 6 臂覆盖。`?acceptance=t06` 钩子只在显式验收参数下存在，随扩展发布但不影响日常面板行为（同 T05 钩子模式）。
