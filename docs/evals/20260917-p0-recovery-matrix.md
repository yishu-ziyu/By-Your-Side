## 验收分层

开发检查证明执行边界与状态迁移；真实 Chrome、扩展重载、native host 杀进程、跨日与真人操作另留证。P0.4–P0.5 的实机验收在用户指定的后续阶段进行，本文件不以自动化单测替代它。

## 实现前发现

`ConversationManager.disconnect()` 目前只停止运行时，未持久化中断状态；`TaskQueue` 恢复时将未派发的 queued 与 starting/running 全部归为 unknown。恢复入口只检查当前页可读，没有核对保存的原页身份。恢复读页与 abort 同在串行控制队列，取消可能排在慢读页之后。

## 实现与可观察行为

连接丢失后将活动任务持久化为中断，停止尾部事件不能再将它变成普通空闲或完成；准备页面、尚未发出 agent_start 的任务也能保留。恢复读页走普通接收通道，暂停/取消可以先使它失效；恢复返回后重新检查任务、控制版本和 session epoch，旧读数不能启动旧 prompt。保存检查点失败会明确报错，但仍执行停止，不能因为磁盘故障让操作继续。

任务输入改为单独保存实际目标与补充要求，不从最近聊天猜哪些用户发言属于当前任务。保存上限为 64 条、合计 64,000 字符；超限拒收，不静默裁掉后半句。页面只保存 URL 指纹与标签编号，不将私密查询串写入进度；图片最多 16 份，通过内容哈希关联现有 Pi 会话文件中的原始附件，不创建第二个任务数据库。缺原图时保持检查点，不能拿另一张图替代。

继续前核对保存的 URL 指纹，再核对新 snapshot 返回的标签与 URL。同 URL 的新标签可用于恢复，其他 URL 不直接接续写入。snapshot 还会核对读取前后 URL，防止同一文档内的 SPA 跳转将新页内容贴上旧地址。页面变化清除旧读数和前后核查基线；新页面不能用旧证据放行完整交付。

未派发待办重启后为 suspended，保留 queued 回执，不再误报未知写入；明确重新安排后才执行，原要求与附件不丢。已经派发却没有确定回执的任务仍为 unknown。部分结果可以沿原任务身份继续，旧完成项不自动重做，未知写入仍锁住写入。无账本绑定的辅助脚本若在途退出，单独保留不确定性。迟到回执中的 unknown 或 not_executed 不再被误升为执行成功。

## 实机待验与已知边界

用户指定后续由本地 Agent 验证真实 Chrome、隔离扩展重载、native host 杀进程、账号/登录变化与老检查点等场景。本轮没有执行这些操作、没有调用产品模型、没有重载日常扩展，也未提交或发布。开发与测试准备已完成，P0.4–P0.5 的真实验收仍未完成。

URL 指纹不是账户身份；同 URL 换账号需要核对页面显示与必要的人类确认。旧版本检查点缺少任务级输入或页面元数据时，不伪造历史身份，也不将无关对话当成新授权。通用语义级去重仍无证明；不同选择器/脚本可能指向同一动作，保守防重也可能阻止合法的重复控件操作，这些要用真实任务验证。原始未知结果不能凭一次新读数就解除，缺可靠证据时仍只能观察、报告部分结果或请用户决定。

12 个公开场景是开发测试集，不是独立留出集。逐场景实际结果、纠正与恢复失败指标已在本轮实测取得（见下节），但独立留出集与聚合成功率仍无。执行入口、故障注入、原始证据要求与后续分工见[本地 Agent 交接](20260917-p0-local-agent-handoff.md)。
