# 浏览器组合执行：结果与决定

日期：2026-09-07。独立标准：`docs/evals/20260907-browser-program.md`。

## 决定

保留 `browser_run` 为可选能力，移除试验中加入的“默认执行”强引导。原有独立工具继续可用。本轮验证了组合执行、控制和隔离边界，但没有证明当前 MiniMax-M3 会因此稳定提高效率。

## 实现

- `agent/src/browser-program.ts`：QuickJS 独立解释器；顺序与条件程序；复用全部 17 个浏览器方法；有界 waitFor/sleep；截图回传；资源限制；控制停止状态不能被 catch 解除。
- `agent/src/tools.ts`：新增本地 `browser_run`，子动作仍走 ToolRpc，不增加另一套浏览器执行器。
- `agent/src/rpc.ts`、`shared/protocol.ts`、`extension/src/background/index.ts`：子调用带 programId；接管或排空期间程序的读写子动作都拒绝，普通独立工具保持原行为。
- `agent/src/session.ts`、`agent/src/run-trace.ts`、`extension/src/sidepanel/steps.ts`：SDK 更新转成现有步骤事件，子动作有父 ID、实际结果与耗时，日志继续脱敏和限量。
- `agent/package.json`、`package-lock.json`：固定依赖 quickjs-emscripten 0.32.0。没有宿主 Node 任意执行入口。
- `.gitignore`：现场截图和记录只保留本地。合成会话测试使用无落盘日志替身，避免挤占用户 trace 保留窗口。
- 三个真实任务的脚本/夹具、原生接管脚本和开发说明：`scripts/acceptance/program-run.mjs`、`program-control-run.mjs`、`extension/test/fixtures/browser-program.html`、`docs/browser-program.md`。

## 实验过程

模型均为 `minimax-cn/MiniMax-M3`，使用同一任务目标与相同起始页面。程序模式保留普通工具，实机操作和填值只发生在本地夹具，提交次数为 0。

1. 只增加工具：三个任务均完成，但模型完全没用 browser_run，不能算组合执行验证。
2. 加入默认提示：三个任务均完成，仅延迟入口任务用了程序，且仍有过细拆分和错误引用。
3. 明确指定组合方式：三个任务均实际使用 browser_run 并完成；其中可观察到一次程序含多个子动作。
4. 基线隐藏入口第一次请求遇服务端 529 过载，保留失败记录，随后只补跑该项。

总计：逐步基线 4 次尝试（3 次完成、1 次服务请求失败）；带组合工具的 9 次尝试都完成目标，但只有后面明确使用程序的三个任务构成下表的组合方式对照。不能把另外六次全部算作组合程序成功。

## 原生接管验证

命令：`node scripts/acceptance/program-control-run.mjs`。

真实 native Agent 只调用一次 browser_run，完成悬停、等待入口、打开编辑器，然后在程序等待阶段接管。接管通过生产按钮使用的同一 control 消息触发；由自动化扮演一次人工接管，不冒称用户亲自点击。

- 接管请求：1788783854608 ms；确认：1788783854722 ms。
- 确认后继续观察 10.5 秒，后续子动作数量为 0。
- 编辑器已打开，草稿为空，提交次数为 0。
- 一次程序调用，总验收耗时 20.014 秒。
- 工件：`out/acceptance/program-control-2026-09-07T12-24-05-351Z/`，包含事件、结果及 `after-takeover.png`。

脚本通过后通过正常 abort 收尾自己的测试任务，并关闭自有标签，没有操作 BOSS 表单。

## 机器检查与边界

- `npm test`：46 个文件、439 项通过。
- `npm run typecheck`：通过。
- `npm run build`：通过。
- 最后撤回默认强引导并隔离合成测试日志后，定向 61 项通过。
- 权限负向测试覆盖 process、文件 require、child_process import、fetch 和 Function 构造器；它们无法获得宿主能力。
- 控制测试覆盖接管错误、断连、RPC 超时、held 后并发排队/catch、等待中取消，以及无 await 剩余调用。CPU 不结束与异步不结束程序能结束，并允许下一程序运行。
- 单程序资源限制不是任务级固定步数熔断。已经派发的动作不能被宣称撤回。
- 本轮不新增任意 CDP 命令入口，不扩大页面 js 既有权限，不验证 BOSS 写入/提交。
- 既有 HANDOFF BOUNDARY 跨任务干扰、AX viewport scope 和截图尺寸问题没有在本轮修复。

## 从 ego lite 学到与尚未证明的部分

借鉴的是同一脚本组合浏览器 helpers、在程序内等待、返回证据再交给模型判断。来源为本机官方 ego-browser skill 与公开执行器，具体链接见 `docs/browser-program.md`。

实验证明程序执行底座可用。没有证明更多权限或更长程序会自动使模型更会操作。下一项影响结果的工作应是让目标定位与程序分段更可靠，再决定是否推广组合方式；不继续堆叠工具数量来代替这个判断。
