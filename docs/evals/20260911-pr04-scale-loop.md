# 任务: 两万条回执时，伴随进程仍能及时接手说话和接管

用户能观察到：回执很多时，开口打断、点接管不会卡一小会儿才反应。机器门槛是事件循环延迟 p95 ≤20ms（B01）。2 小时堆增长（B02）要单独跑满时长，没跑满不能 PASS。

## 完成标准

- [x] 1. 20_000 条回执写入后，`list` 热路径不再扫目录、不再同步读五千个文件。 — 谁检查: `agent/test/task-dispatcher.test.ts`（二次 list <50ms）
- [x] 2. 同一规模下事件循环延迟 p95 ≤20ms，样本 ≥1000。 — 谁检查: dispatcher 单测 + `scripts/eval/scale-loop.mts` p95=1.43ms（未含活跃语音）
- [x] 3. 旧 requestId 不会因为索引/清理而重新执行。 — 谁检查: 既有 dispatcher 去重测试
- [x] 4. 2 小时固定负载后堆增量 ≤50MiB（B02，本轮负载）。 — 谁检查: `eval/runs/scale-heap-2026-09-11T13-16-44-896Z.json`：721 点，前 30 分钟均值 16.91MiB，后 30 分钟 16.35MiB，增量 **-0.56MiB**。未开 `--expose-gc`，不是规格里的「后 GC」；无 200 会话、无活跃语音。
- [ ] 5. 人眼确认卡顿 — 谁检查: 人（本轮不拦机器项）

## 边界与不做

- 不改 live 150 门槛，不重跑模型。
- 不把 2 小时没跑完写成 PASS。
- 不删用户回执文件来换速度。
