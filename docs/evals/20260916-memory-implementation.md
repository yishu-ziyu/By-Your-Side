## 实现约束

- 统一 user_memory 工具提供 recall/change，不增加模型可见工具数量。
- 主模型按需发起操作；修改时做一次仅含当前直接用户消息、已有记忆及产品维护的有限对话上下文的隔离语义核对。网页与工具结果不进入该核对；旧对话只解释指代和未完成任务，不产生新的记忆授权。普通对话/查询不增加模型前置调用。这比直接信任主模型提议多一次修改时调用，换取独立来源边界，测量真实耗时。
- 语义结果是明确操作、内容、原文依据、作用域和目标版本，不使用未校准置信度阈值。
- 程序负责来源引用、目标身份/版本、范围和原子写入；仅来自当前直接请求的修改可写入，不自动重放旧聊天生成个人事实。
- EverOS 不直接覆盖用户确认的个人事实，不启用默认人格推断；先验真实收益，不重写 Agent Loop。
- 日常浏览器不用于验收；使用无头隔离扩展和合成资料，不向外部网站提交。

## 基线

自然表达拒存、报名语句缺少邮箱时漏召回、新旧默认并存已在[对照探针](20260916-memory-options.md)复现。更换原正则测试时保留其来源/范围/过期请求的产品断言；语言理解改由真实模型用例验证，不以 mock 判断结果冒充语言理解通过。

## 实现与验收结果

- 正则入口替换为按需语义操作。统一 `user_memory` 工具读/写，模型可见工具总数不增；不接入 Python 判断服务。语义模块与原存储、运行时分开，未新增生产依赖和存储迁移。
- 保存/更新/忘记在原锁内复核目标版本并原子执行；同一轮成功或失败只判断一次，防止重复调用产生多条记录或反复判到允许。过期/取消的核对与排队写入不落盘。
- 自然语言更新可替换同一事实的重复条目；临时使用保持默认；查询按当前任务需要的字段进行，不需再问已保存的邮箱。
- `taskRequested` 区分纯记忆请求与同时进行的网页任务。仅修改记忆的轮次在回执后限制工具执行，不能顺手提交网页；已询问缺失资料的原报名任务可在收到邮箱后继续。
- 原来维护固定句式和站点语序的代码减少；新增语义结果校验与原子应用。记忆运行时+存储+新增决策模块净增长约二十余行；会话接线约十余行。共享会话/提示词文件已有大量并发改动，本轮只检查自己的接线与一条范围提示，不把整个工作区 diff 算成本轮增长。

### 失败、修正与测量边界

1. 第一版验收等待旧 `user_message` 帧，但当前入口发送 `task_action`，产品已成功保存。改为等待实际入口，保留 live-attempt1。
2. live-attempt2 原八项表面通过，但复核发现“以后换邮箱”被顺手提交。补充“纯记忆请求不得碰页面”的真实断言，增加工具边界；旧记录保留，不再当最终通过。
3. 新边界必须允许原任务补资料。使用项目已有 recentTurns 解释仍未完成的直接用户任务，不读页面、不把旧记忆请求当新授权；补上原始两轮路径，最终通过。
4. 同会话紧接下一轮时，测试只等后台状态而没有等模型尾部/侧栏状态落定，发出了过期 steer 并被产品如实拒绝。最终驱动等待实际 session 与面板结束；保留 live-ui-race。未修改范围外的前端控制竞态，也不把极快连续输入的全部边界称为通过。
5. 语义用例“这个项目”缺少项目身份时应澄清，旧探针强制期待全局保存会错误放宽范围。保留 decisions-scope-failure，改成未命名项目应澄清，并加 Neptune 明确项目条件保留的反例；缺站点澄清时要求输出无写入的中性 scope，最终通过。
