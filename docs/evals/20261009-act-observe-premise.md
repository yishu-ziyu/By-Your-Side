# 任务: 点击、填写后自动带回页面，能不能少等一轮模型（前提实验，结论：不做）

起因：拆 ego 浏览器的一次 Codex 会话时，看到每段脚本最后都打印页面快照，下一轮直接动手。我们的点击、填写只回回执，所以猜模型要多花一轮看页面。10-07 的[时间拆分](20261007-time-breakdown.md)显示，会动手的任务 98% 的时间在等模型，所以少一轮就快 3–4 秒。

## 规则
- R1 只有“写操作之后白看一轮”占全部模型轮数的比例够大，才改产品。
  - 例子(正)：白看的轮数占全部轮数 10% 以上，才值得让写操作自动带回页面 — 谁检查：`npx tsx scripts/probes/observe-after-write.mts <out/acceptance/real-path> 2026-10-0`
  - 例子(反)：只看“写操作后白看的比例”（26%）就说成立。这个比例不说明省多少时间 — 谁检查：人

## 技术前提
- 前提：已有真实路径测试的诊断记录能分出每一轮调了什么工具，不用改产品就能数。小实验：`scripts/probes/observe-after-write.mts`。结果：通过（275 次运行都能读出）。

## 结果（10 月以来的真实路径测试，275 次运行，1146 轮模型）

| 数什么 | 数值 |
|---|---:|
| 组合执行 | 273 次，其中 245 次（90%）在程序最后已经带回页面 |
| 单独的点击、填写等写操作 | 86 次，其中 22 次的下一轮只看页面 |
| 组合执行之后下一轮只看页面 | 13 次 |
| 白看的轮数合计 | 35 轮，约占全部轮数的 3% |

- 结论：不改产品。平均每次任务省不到半秒。ego 的这个做法，组合执行已经覆盖了大部分。
- 事先定的门槛错了：门槛原是“写操作后白看 ≥ 1/4”，算出 26%，按字面算成立。但这个比例不说明省多少时间，所以改用 R1 的比例，原门槛和小实验的退出码都保留不改。
- 拆同一次会话的时间后看到：ego 那边模型每步思考 4–6 秒，并不比我们的 3–4 秒快。用户觉得快，来自动手前先说一句、每一步看得见、少返工。后续改进走[先说一句与交给你](../previews/speak-and-handoff/index.html)。

## 边界与不做
- 没有拿同一个任务让 ego 和我们各跑一次。
- 只数了“下一轮只看页面”，没有数“下一轮看页面又做了别的”的情况。
