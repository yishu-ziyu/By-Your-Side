# 任务: 直接选择模型支持的思考档位，并看见自动升档后的实际档位

## 规则
- R1 模型菜单使用离散滑块，只提供当前模型实际可请求的档位；同一服务端档位的别名不占两个刻度。
  - 例子：选择中档，输入框显示中，下一次真实模型请求也使用中。谁检查：`model-menu.mts`。
- R2 保留自动升档。界面显示实际档位，并说明从哪个手动起始档升来；普通续接不算纠正。
  - 例子：用户纠正正在运行的低档任务后，实际请求与界面都升到中，而不是仍显示低。谁检查：`model-menu.mts`。
- R3 按模型记住手动起始档，重开或另一窗口恢复偏好不重置当前自动升档。
  - 例子：模型甲选低、乙选高；切回甲仍从低起步。谁检查：`model-menu.mts`。
- R4 拖动、键盘、恢复默认和模型切换仍在同一个菜单内；减少动态效果和深色模式可操作。
  - 谁检查：真实扩展截图、键盘操作与主会话复核。

## 还没答上的问题
- 无。用户明确选择保留自动升档，不采用此前“手动固定、不再自动升档”的建议。

## 技术前提
- 已读取用户提供参考对应的 ChatGPT 前端组件 `ModelPickerPowerSliderImpl`，确认它将输入层和视觉滑块分开，并区分预览与确认。采用这种交互结构，不复制整个前端包，也不新增 UI 框架依赖。
- 模型目录与实测登记提供可选档位；各模型同名档位的速度与质量未统一标定，因此不写通用的性能承诺。

## 边界与不做
- 调整主任务模型的思考档位，不切换语音服务、登录方式或用户选定的模型。
- 不把模型档位升高当成浏览器环境问题的补救。
