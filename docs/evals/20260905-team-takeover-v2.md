# 任务: 全队接管/交还 v2 —— Lead 与所有活跃 worker 一起停手并各自续跑

本标准由 Codex（校验）在实现开始前锁定。实现者不得修改本文件、降低断言，或用只暂停 Lead、逐个手动暂停 worker、新开会话等方式替代全队接管。

```
Change:     用户发起一次接管，Lead 与当时全部活跃 worker 作为同一组停手；交还后，每名仍有绑定页的 Agent 从自己页面的新鲜状态继续原任务。
Not this:   只改界面文案；只暂停当前可见 Agent；仅隐藏光标；交还时让所有 Agent 共用当前活动页；关闭一个 worker 标签后结束整组任务；用中止后重发任务冒充交还。
Evaluator:  协议、组状态、写闸门和会话恢复自动测试 + 已加载生产扩展的真实浏览器路径。信息是否清楚由人裁决，具体布局由后续人评决定。
Evidence:   测试输出、按 Agent 标识的工具事件与控制状态记录、两名 Agent/两个真实网页的连续截图或录屏、关闭 worker 标签与独立中止复核。
```

## 完成标准

- [x] 1. 一次“接管”覆盖发起时的完整活跃组：Lead 与所有处于运行、等待工具或等待消息状态的 worker。不能要求用户逐个操作；接管进行中不得把新成员悄悄加入或漏掉原成员。— 谁检查: 组成员快照/状态机单测 + 人
- [x] 2. 发起接管后，组内所有新的浏览器写动作立即被挡住；只有每名成员已经开始的写动作都已结束或取消，界面才可宣告全队归用户。至少覆盖 Lead 与 worker 的 open/switch/navigate、close_tab、click、fill、type_text、press_key、scroll、js、mark/clear_marks。任一成员未停住时不得显示全队接管成功。— 谁检查: 多 session 并发、迟到调用、超时与过期确认单测 + `npm run accept:team`
- [x] 3. 用户控制期间，Lead 和每个 worker 的会话、任务上下文、消息/工件等待状态及各自 working tab 绑定都保留；侧栏关闭重开、普通页面刷新或切换当前可见标签，不得把接管变成 idle、中止或新任务。— 谁检查: 会话/持久状态单测 + 真实浏览器
- [x] 4. 用户执行一次交还后，系统按成员分别读取其绑定页当下的 tabId/title/url 与新 snapshot；不能把浏览器当前活动标签的 snapshot 复制给其他成员，也不能用接管前缓存代替新状态。取得某成员的新状态之前，该成员仍归用户且不得续跑。— 谁检查: 协议路由、按 session 取页、快照新鲜度与错配反例单测 + 事件记录
- [x] 5. 交还成功的每名成员复用原会话，并从自己绑定页的新 snapshot 继续原任务；不重新打开站点、不重复已完成步骤、不串用另一名 Agent 的上下文、标签或邮箱工件。Lead 与 worker 可以先后恢复，但界面必须如实表达每名成员的结果，不能在仍有人暂停时笼统显示“全队已恢复”。— 谁检查: 同一 session 身份/上下文续跑单测 + 真实浏览器
- [x] 6. 若某个 worker 的绑定标签在用户控制期间被关闭，交还时该 worker 保持暂停并明确说明“绑定页已关闭，未续跑”；其他绑定页仍存在的成员照常读取新状态并续跑。不得擅自为该 worker 新开页面、回退旧页或让它阻断整组交还。— 谁检查: 关闭标签正反例单测 + 真实浏览器独立路径
- [x] 7. 中止与接管/交还是两条不同路径：中止终止 Lead 和全部 worker 的任务图，清掉等待、在途执行与控制状态；之后不能再用“交还”恢复原图。接管和交还不得清空任务图。— 谁检查: 组中止、接管、交还状态转换单测 + 人
- [x] 8. 界面必须表达这些信息，但本标准不规定布局、控件位置或视觉样式：本次操作覆盖哪些 Agent；正在排空、用户控制、恢复中、已恢复、因绑定页关闭而保持暂停、已中止；每名 Agent 绑定的是哪一页；什么时候可以交还。不得用单一“暂停/运行”掩盖部分失败。— 谁检查: 人
- [x] 9. 接管、交还、单成员保持暂停和中止后均无残留 loader、旧光标继续移动、旧控制条复活或成员状态错位。— 谁检查: overlay/界面检查 + 真实浏览器
- [x] 10. `npm run typecheck`、`npm test`、`npm run build`、`node extension/test/overlay-check.mjs` 全绿；新增组成员快照、全组排空、session/tab 路由、逐成员新鲜 snapshot、部分恢复、关闭标签、过期确认、断线与中止正反例。— 谁检查: 机器
- [x] 11. 仓库提供 `npm run accept:team`，通过真实加载的当前构建扩展及其 background/content-script/CDP 链执行，不复制生产控制逻辑。它在隔离状态下连续三次证明：两名 Agent 在两个页面运行、全组接管确认后两页均不再被 Agent 写入、分别交还后两名 Agent 只从各自新 snapshot 续跑；任一轮失败须非零退出并保存脱敏证据。— 谁检查: 机器
- [x] 12. 在 `local.yishu.chrome-main` 完成一条可见真机路径：至少两名 Agent（Lead + 一名活跃 worker）分别绑定两个不同的真实网页并同时工作；接管后两边都停手；用户在两页分别制造可见的新状态；一次交还后，两名 Agent 的原会话各自识别自己页面的新状态并继续，且没有重开或重做。— 谁检查: 人
- [x] 13. 另跑一条可见异常路径：全队接管后关闭 worker 的绑定标签，再交还；Lead 从自己的新页面状态继续，worker 明确保留暂停且没有新开页面，其他成员不被阻断。再单独执行一次中止，证明中止不会被呈现成交还或可恢复暂停。— 谁检查: 人

## 真机证据要求

证据存入 `docs/evidence/20260905-team-takeover-v2/`，至少包含：

- `README.md`：浏览器、当前构建、两名 Agent 标识、各自页面、每一步动作、观察结果与失败边界。
- 一段连续录屏或 GIF：同一轮展示两名 Agent/两个真实网页运行、全队接管、用户分别改变两页、一次交还、两名原会话各自续跑。不能剪接不同轮次冒充连续路径。
- 同一轮关键帧：接管前双 Agent 运行；全组归用户且两页停手；交还后两边各自从新状态续跑。截图须同时保留足以核对 Agent 身份、页面和控制状态的信息。
- 单独异常路径证据：关闭 worker 标签后，Lead 已续跑、该 worker 仍暂停且未新开页。
- 单独中止证据：全图结束、无 loader/光标/控制条残留，且不能再交还恢复。
- 工具事件或验收日志：按 sessionId 列出接管组成员、最后一个在途写动作结束时间、接管确认时间、各成员 handback snapshot 的 tabId/title/url/采集时间、恢复结果。正文和截图不得包含 cookie、token、页面私密正文或完整无关浏览历史。

仅有单测、构造的 HTML、fixture 页面、后端状态或两张互不连续的截图，不算第 12、13 条通过。

在仓库根目录运行：

```bash
npm run typecheck
npm test
npm run build
node extension/test/overlay-check.mjs
npm run accept:team
```

随后由独立校验者核对测试名称覆盖第 1–11 条，并在 `local.yishu.chrome-main` 目视第 12、13 条的连续路径。自动测试全绿但真实路径未出现，仍不算完成。

## 边界与不做

- v2 只扩展既有 Lead/worker 任务图的接管与交还，不改变并行拆解、邮箱拓扑、危险操作确认或 worker 数量上限。
- 不替人决定按钮位置、侧栏布局、颜色、动效或文案风格；只要求第 8 条信息可见且不误导。
- 不要求已关闭标签的 worker 自动恢复；恢复策略另开标准。
- 不承诺完整关闭并重启 Chrome 后恢复同一任务图。
- 不允许用中止后重发任务、新建 Agent、复制上下文或重新打开页面冒充同一组交还。
