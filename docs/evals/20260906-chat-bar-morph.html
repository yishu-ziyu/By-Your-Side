思考强度真实性原则：严禁全量硬编码 Medium / High

严格绑定真实能力

参考图中每个模型粗暴挂着 Medium / High 仅为视觉样张。在生产落地中，思考强度直接取决于当前底层模型是否具备分档能力。我们项目当前接入的模型分为三类，原型中已严格对齐：

M MiniMax-M3 (默认) 原生内置思考
拥有极强推理链与 1M 上下文，但推理强度为原生内置，不支持外部手动分档。界面如实标为 内置深度思考 · 1M 上下文。
O GPT-5.6 / o3-mini 支持 Reasoning Effort
API 官方支持 reasoning_effort: low | medium | high。原型中提供真实三档就地切换，选择后动态回传。
K Kimi for Coding 极速直接响应
针对编程高吞吐优化，无思考链阶段。不应伪造档位，如实标注 代码极速 · 直接响应，用户所见即所得。

核心裁决点 (待人评确认)

  • 1. 形态选择：方案 A 保持了现有 SideAgent 的大文本输入习惯与顶栏信息排布，形变只在芯片局部绽放，最克制高效；方案 B 单行式适合轻量 Prompt 场景。
  • 2. 思考强度严谨性：已将「真实现存模型」与「思考档位开关」严格绑定——对可调模型提供 Low / Med / High 切换；对 MiniMax-M3 保留内置深度标签；绝不无中生有。
  • 3. Ambient Glow 职能：用于连接用户与系统状态（就绪绿、接管橙、确认红、并行蓝），提供了极高的高级工具触感。
