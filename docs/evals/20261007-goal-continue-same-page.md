# 任务: 回答之后的续做只发生在原网页上，并且侧栏写明为什么又动起来

来源：#105（总览 #106）。10-07 体验走查：长文翻译交付一半后，目标核对判「没做完」，续做落到了同一标签页里的下一个网页上；回答下面又冒出「正在思考」，看不出原因。

## 规则

- R1 目标核对判「没做完」、准备续做前，再看一次标签页；已换到别的网页就不续做，结果按「还差」收尾
  - 例子(正)：交付后核对期间标签页从文章换到另一个网页，模型收不到续做提示，侧栏不再出现执行中 — 谁检查：`goal-continue-same-page.test.ts`；`goal-continue-same-page.mts` B
  - 例子(反)：只换了页内锚点（#section）算同一页，照常续做 — 谁检查：`goal-continue-same-page.test.ts`
- R2 模型自己交代了「部分完成」时照旧自动再试（用户 10-07 裁决），受 R1、R3 约束
  - 谁检查：原有行为，`goal-continue-same-page.test.ts` 的反例覆盖
- R3 续做时侧栏新一轮的标题写「还没做完，接着做」，下面一行写「还差：<剩下的事>」，这一轮结束后收起
  - 例子(正)：同一页漏做第三条要点，续做时看到这两行，做完后侧栏里没有「还差」行 — 谁检查：`goal-continue-same-page.mts` A，截图 `a-continuing.png`、`a-finished.png`；观感由人看
- R4 核对期间用户停止或另发任务，续做作废
  - 谁检查：`goal-continue-same-page.test.ts`（原有保护，补测试）
- 反例：页面没换、确实漏做，仍然续做 — 谁检查：`goal-continue-same-page.test.ts`；`goal-continue-same-page.mts` A

## 还没答上的问题

- 无

## 技术前提

- 前提：改前，核对期间把标签页换走，宿主仍续做，下一步读的是新网页。小实验：脚本模型 + 真实会话，核对模型作答时把标签页地址换掉。结果：通过（复现，续做读的是新网页）。小实验本身没有入库：它与 `goal-continue-same-page.test.ts` 的 P1 重复，P1 在改前同样失败。

## 边界与不做

- 「换页」以交付后核对开始时读到的地址为准。用户在交付后、核对读页之前就换走（几十毫秒内）不在保护范围。
- 助手自己在任务里打开别的网页不算换页：比的是交付时与续做前，不是交代任务时的网页。
- 长文翻译每批 60–100 秒、常整批作废以致翻不完：另开 issue，排在 #104 之后。

## 实测

- 单元：`goal-continue-same-page.test.ts` 4 项；改前「换页仍续做」失败，其余 3 项（同页续做、停止、另发任务）改前改后都过。`npm run check` 通过（2473 项）。
- 脚本模型真实路径 `goal-continue-same-page.mts`：改后 A、B 都通过，A 续做时标题「还没做完，接着做」、下面「还差：列出第三条要点」，做完后不留；同一脚本在改前代码上 A 失败（侧栏不写原因）。
- 真实模型（gpt-6-luna，只装扩展的无头 Chrome）：
  - `unfinished-turn.mts` 通过：回答说出「升级套餐」，没有卡，回答后没有再出「正在思考」。
  - everyday 全套 15/16。普通翻译（/en）交付后核对判「没做完」，此时标签页已被脚本换到下一项的 /long；宿主没有续做，诊断记录 `goal_check` 带 `pageMovedTo`。这正是 10-07 走查的失败方式，改前会在 /long 上接着翻。
  - 未过的一项是 translate-real-hamel：240 秒内没翻完、没交付，与交付后的续做无关，归「长文翻不完」新 issue。
