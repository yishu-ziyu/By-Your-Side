# 任务：不展开工具日志也能辨认助手职责、等待与交付

依据用户本轮批准的 [诊断与最小方案](20260915-cast-diagnosis.md)。本轮由主代理独立实施，不委派。

## 完成标准

- [x] 创建回执、执行行与页面光标同名；同任务两位助手不撞名，历史回放保持身份 — 主代理：定点测试、实际运行与浏览器证据。
- [x] 分工说明通过正式消息出现；默认摘要展示每位助手的本次职责 — 主代理：同类真实双方案任务。
- [x] 等待关系来自实际消息来源和职责；来源缺失诚实概括；失败和停止不伪装已交付 — 主代理：定点边界测试及真实运行。
- [x] 子助手完成不消除其他助手的状态；最终交付仍是一份答案；短任务不出现空协作区 — 主代理：定点测试、真实界面。
- [x] 所需契约、类型、构建检查通过；检查实际 diff 与复杂度增长 — 主代理。

## 边界

沿用现有形象、颜色、对话和接管/交还；不添加常驻团队卡、不扩张角色人格、不改变执行权限。保留任务开始前所有未提交改动。真实测试明确区分生产文本入口、隔离输入与人评，不用模拟截图冒充运行。

- 两位助手的 post done 成功后，分别显示“方案 A/B 摘要已交给主助手”。失败/停止/迟到成功回执由定点测试验证不冒充已交付；没有把这些合成边界当作真人失败路径。

### 改动与维护成本

- shared/cast：创建时选择未占用角色，角色编码进实际 worker id。现有面板与网页光标从同一个 id 读身份，无需维护跨端身份映射表。旧记录沿用原散列，不伪造旧职责信息。
- fleet / protocol：增加 worker_task 事件，携带简短职责、预期产物和创建调用关联。事件进入已有传输、历史回放；不扩张 TeamControl，不创建另一套持久任务存储。
- sidepanel/collaboration-progress.ts：125 行，单个执行块从真实事件推导成员状态并渲染摘要；与工具详情分离，避免把状态分支继续堆进大面板文件。临时 pending 工具记录随结束清理。main 只接入事件、摘要与创建回执，保留原有日志折叠和统一交付。
- 开始说明复用正式 ack 通道，不把内部文本直接泄露为用户消息；在 UI 将 ack 排在当前执行块前。
- 保留开始任务前已有的 main.ts/styles.css 及其他未提交改动；本次差异单独对照任务前副本检查。增长主要来自可回放状态和边界测试，没有新依赖或通用框架。

可继续的人评：看前后对照中的默认摘要，判断信息密度是否合适。已授权且可执行的验证已完成。
