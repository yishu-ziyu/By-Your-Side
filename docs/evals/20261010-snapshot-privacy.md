# 任务: 助手读页面时，看不到用户填的卡号、安全码、PIN

## 为什么

10-10 一次探查（装真实扩展、无头 Chrome、本机脚本模型）发现：助手用 `snapshot` 读一个已填好的付款页，模型收到的请求里有卡号、安全码、name=card_number 的卡号、name=pin 的 PIN 原文。每个值出现两次：输入框那一行的 `value="…"`，和输入框下面的一行 `text: …`。密码栏没有泄露，只是因为 Chrome 的无障碍树本来就把它显示成圆点；密码栏点「显示密码」变成普通文本栏之后，没有任何遮挡。

填写之后的读回早已不给这类栏的值（[读回隐私](20261009-claim-after-check.md) R1）。读页面这条路没有用同一条规则。交还页面时附上的快照走同一个读页面函数，所以也带着这些值。

## 现在模型看到什么

- 敏感栏那一行写 `value=<filled, hidden>`（栏里是空的就不写 value），下面不再有栏里文字的那一行。模型知道用户已经填了，但不知道填的是什么。
- 敏感栏的判定与填写读回相同：密码栏、曾经是密码栏的栏、卡号/安全码/有效期/一次性验证码的 autocomplete、字段名或标签像密码/验证码/卡号/PIN 的栏。
- 页面里查不到的输入栏也按敏感处理，因为少给模型一个值比泄露一个值好。
- `read_element` 读这类栏只给长度，例如 `<16 chars>`。

## 规则
- R1 助手读页面时，敏感栏的值不进模型请求；普通栏的值照常进；敏感栏的那一行写明已填。
  - 例子(正)：页面已填卡号、安全码、card_number、pin，助手读页，模型请求里没有这些值，有普通栏的值，Field X 那一行写 `value=<filled, hidden>` — 谁检查：`scripts/acceptance/real-path/snapshot-privacy.mts`
  - 例子(正)：密码栏点「显示密码」变成 type=text 后再读页，值仍不在请求里 — 谁检查：同上
  - 例子(反)：敏感栏判定返回空集合，用例失败 — 谁检查：同上，故意弄坏产品复跑
- R2 助手用 `read_element` 读 name=card_number 的栏，值不进模型请求。
  - 例子(正)：模型收到 `"value":"<16 chars>"` — 谁检查：同上

## 技术前提
- 前提：无障碍树节点的 backendDOMNodeId 能在页面里解析回元素，并在一次调用里判定。小实验：沿用快照里补读范围输入框的做法（同一文件），结果：通过（10-10 用例通过）。

## 边界与不做
- 页面脚本（`js`、`browser_run`）按设计可以读 `.value`，本次不限制。
- 决策观察（`snapshot` 带 decision）里的控件 `value` 仍照抄无障碍树的值。10-10 核对：模型的工具和扩展代码都不发起决策观察，所以这些值现在进不了模型请求。以后有调用方时要补上同一条规则。
- 简化 DOM 快照（`scope=viewport` 和回退路径）本来就不输出值，不改。
