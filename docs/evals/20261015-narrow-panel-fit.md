# 任务: 侧栏拖窄到 280 px，卡片按钮、「回到底部」和输入框底栏都不被遮、不被切

以前 300 px 宽时出错卡底部被输入框挡住一截，「回到底部」只露出半个。做法按侧栏自身宽度分两档（340 px、280 px），出处是预览页第 12 项。

## 规则
- R1 滚到底时，最后一张卡里每个按钮整个露在对话区里，点按钮中心点到的就是它。
  - 例子(正)：400、320、280 px 下出现「额度用完」错误卡，滚到底，「换一个模型」「稍后重试」都完整可点 — 谁检查：`npx tsx scripts/acceptance/real-path/narrow-panel-fit.mts --headless`
  - 例子(反)：按钮下半截落在输入框后面，点下去点到输入框 — 谁检查：同上
- R2 上翻后出现的「回到底部」贴着对话区底边，不压在输入框上；输入框长高时它跟着上移。
  - 例子(正)：三个宽度下圆钮整个在对话区里，点它回到底部 — 谁检查：同上
  - 例子(反)：圆钮按侧栏底边量固定距离，被输入框盖住一半 — 谁检查：同上（故意改回固定距离时失败）
- R3 输入框底栏一行放下，不横向溢出；窄于 340 px 模型按钮只留短名；任何宽度都不收掉按钮。
  - 例子(正)：模型名 `openai-codex/gpt-6-luna-preview` 在 280 px 下显示成省略号短名，＋、话筒、语音、发送都还在同一行 — 谁检查：同上
  - 例子(反)：底栏折成两行，或某个按钮被挤出框外 — 谁检查：同上

## 技术前提
- 前提：卡片被切的原因是停在底部的人改窄侧栏后，正文换行变高，对话区不再停在底部；滚到底时卡片本来就放得下。小实验：`narrow-panel-fit.mts` 记录改宽后离底部的距离（`result.json` 的 `gapAfterResize`） 结果：从 400 改到 320、280 px 后离底部 130–150 px
- 前提：「回到底部」用 CSS 锚点定位贴对话区底边，需要 Chrome 125 以上。

## 边界与不做
- 改宽后自动回到底部要改滚动脚本，不在这次的样式改动里。
- 运行中（「接管」出现时）的底栏宽度这次没验。
