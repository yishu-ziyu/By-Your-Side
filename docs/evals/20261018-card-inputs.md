# 任务: 算账、比价这类卡片里，用户能直接调一个条件（月数、人数、数量、利率），卡片里的数当场重算，重开侧栏还在

用户 10-18 看过对照页（左边现在的订阅卡，右边可点的加减示意）后认可。来源：ChatGPT Intelligent UI 的“回答里能动手改”，我们只做固定组件里的一个可调的数，不放开模型写网页。

## 规则

- R1 模型写 `<input>` 时，卡片里画出名字、减号、数值、加号（范围大时另有滑块）；调到范围外被夹回范围内。
  - 例子(正)：`<input id="months" label="月数" value="12" min="1" max="36" />`，点两下加号，数值变成 14 — 谁检查：`scripts/acceptance/real-path/card-inputs.mts`
  - 例子(反)：已经是 36 再点加号，仍是 36 — 谁检查：同上
- R2 改了以后，用到它的算式当场重算：数字格、选项的价、表格格子、依据面、正文里的 `{=名字}` 都换成新结果，算式说明也跟着换，不问模型。
  - 例子(正)：`value="=68*months+398"`，月数改成 14，数字格显示 ¥1,350 和“68 × 14 + 398”，正文“一年共花 ¥1,350” — 谁检查：同上
  - 例子(反)：故意让侧栏不重算，用例报“合计仍是 ¥1,214” — 谁检查：同上（弄坏一次）
- R3 用户在卡片上动过的东西（调过的数、勾过的清单项）重开侧栏后还在。
  - 例子(正)：月数调到 14、勾上第一项，关掉侧栏再打开，仍是 14、¥1,350、第一项已勾 — 谁检查：同上
  - 例子(反)：另一张卡片的勾选不受影响 — 谁检查：同上
- R4 真模型会用：用户多半想换个数再看的问题（订阅按几个月、几个人分、贷款利率）写 `<input>`，算式引用它；页面写死的数、一句话问题不写。
  - 例子(正)：gpt-6-luna 回答“几个人 AA 每人多少”，卡片里有人数可调 — 谁检查：`tmp/genui/run.mts` 小实验 + 人看
  - 例子(反)：问“这个网站是哪家公司做的”，没有卡片也没有可调的数 — 谁检查：同上

## 技术前提

- 前提：侧栏的消毒规则留得住数字输入框和它的范围属性。小实验：用例 R1 直接看 DOM。结果：通过
- 前提：真模型在产品提示词里会写 `<input>` 并在算式里用它的名字。小实验：`tmp/genui/run.mts`（本机，不进仓库），gpt-6-luna，5 道可调题、2 道卡片题、1 道一句话题，各 3 次。结果：第一版失败，可调题 15 次只 4 次用上：模型想写房贷的乘方和分档折扣（`qty>=50?0.85:…`），算式不认，只好心算；每轮附的提醒里也没提可调的数。算式加上 `^`、比较、`? :`、min/max/round，提醒里加一句后：可调题 14/15 用上，卡片题和一句话题 0 次误用（1 次网络失败不计）。
- 前提：模型在正文里写可调的数本身（“按年利率 3.5% 计算”），用户改了数正文还是旧的。结果：正文也能写 `{=名字}` 引用可调的数，提示词要求这样写。

## 边界与不做

- 只有数可以调；不做下拉、开关、文字输入。
- 标了“最低”“推荐”的那一项不跟着重算换人：提示词要求可调的数不决定谁赢。
- 助手看不到用户调过的数；复制、朗读用的是原来的数。
- 回答在卡片写完之前被停下时，这张卡上调过的数不保存：没写完的卡片还没有固定的存储键。
