# 按住说话：提前准备播报连接

## 规则

选段或按住说话时，已经配置且启用的播报会提前准备网络连接；这一步不开麦、不请求合成声音。回答出来后可复用连接，原有的改口停声、换段和排队播报继续工作。浏览器没有采用预连接时，仍正常发起播报。

## 技术前提

先试了提前准备听写：五组真实提问对照没有证明整体提速，候选未安装。进一步的网络记录显示，播报的首次 TLS 握手有过五秒后断开重试，等待发生在服务开始合成之前。

单独加匿名预连接仍没有复用：浏览器把它与原先的请求分到不同连接池。正式请求也采用不带 Cookie 的方式后，真实路径上复用了提前建立的连接。API key 仍由显式请求头发送，声音、正文和模型没有变化。

## 验证与边界

- 固定正文、同一服务与声音，五组交错对照；两组都有相同的八秒准备窗口，这是实验控制，不是产品新增等待。发起播报到首段音频排程，中位从 1132 ms 降到 484 ms。五对都改善，超过预登记的 200 ms，单侧精确符号检验 p=0.03125。十次均正常播完，准备期间没有合成请求或麦克风调用。
- 真实维基提问的候选路径，正式请求复用连接，约 333 ms 收到声音数据；关键路径没有再握手。故意保留连接池不匹配的对照不能通过这项判定。
- 完整阅读、改口、换段、停声用例，原版和候选均 19/20。同一失败是合成语音里的 flomo 被听成 Flamo；单句重放又能识别正确。此识别问题未修，没有把失败改算通过。
- 输入是合成语音，输出依据浏览器音频数据与排程；没有真人麦克风、扬声器回录，整轮回答 P95 和真实外放听感无法判断。听写、意图分流和模型生成仍可能等待较久。

复跑：`npx tsx scripts/acceptance/real-path/voice-reading.mts --headless`；`--first-only` 只跑首次问答，结果明确记录模式。测量包与原始结果在 `out/voice-speech-ready/`，包含登记、逐对数据、网络时序、反例和录像；不是总体语音可靠性证明。
