# 任务: 光标不干活时待在角落，要点再飞过去点

来源：2026-09-04。加强光标存在感；先 HTML 确认，不改产品。

```
Change:     闲着时页面角上还能看见这支光标，而且它是停着的；要点就沿路飞到目标点一下，点完回角落。用户能指出左上还是右上。
Not this:   把箭头再放大；闲着还在呼吸/漂；点完消失；点完停在按钮上不回去；改产品。
Evaluator:  人评 HTML。点一列。
Evidence:   本卡 + docs/evals/20260904-cursor-perch.html
```

## 这一屏要判断的事

1. 「待在角上」是不是你要的存在感（对比左列：点完消失）。
2. 左上还是右上。
3. 飞过去再点、点完回家，这条节奏对不对。

## 对照过的 Will's S，以及为什么落到这一页

读过再写。每条都对应页上的一个做法，不是读完再另发明一套。

1. **NNGroup《The Role of Animation and Motion in UX》**
   - 动效用在反馈、状态切换、空间隐喻。周边视野对运动极敏感，无关运动就是干扰。
   - 同页 Cuisinart：远处小徽章变了，人看不见，会重复点。
   - **所以**：点击必须让光标从角落走过去（路径 = 空间隐喻 + 防变化盲视）；待命必须静止（不能漂、不能呼吸）。左列「突然出现再消失」是变化盲视那一类。

2. **Apple Motion 动效设计**
   - 目的性动效，不为动而动；简短精准；少让人等动画结束。
   - 稳定参考点；禁止约 0.2Hz 持续振荡。
   - **所以**：飞一次约 420ms 就点；闲着钉死在一个角，不振荡。角落就是参考点。

3. **Apple Live Activity 的 UX 设计要点**
   - 正在发生的事要一眼可扫；紧凑态一直在，有要事才展开。
   - **所以**：任务还在跑，光标不撤。角上是紧凑态；飞到按钮是展开去干活。不是 Live Activity 皮肤，是同一条「人还在」的规则。

4. **Refactoring UI《Emphasize by de-emphasizing》+《Labels are a last resort》**
   - 重点不够抢，先把次要的变淡；标签能不用就不用。
   - **所以**：存在感不靠把箭头撑得更大。待命只留箭头停在角上（位置即状态）；飞起来才出名牌，点击才按下 + 波纹。
