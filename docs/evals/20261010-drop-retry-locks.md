# 任务: 一步没做成或结果不明时，助手可以重读页面再试，不再被规则逼着放弃

[当前状态](../STATUS.md) · [开发日志](../devlog/20261010-01-capability-over-caution.md)

10-10 用户决定：「因为这是我的一个自用产品，我宁愿它的功能性强过它所谓的'安全正确性'。」「安全限制太多太傻逼了。」用户同意去掉让助手放弃、不再重试的规则。本文件是 A 部分（结果未知锁、防重复、连续失败停止、原地打转门槛）。核对与交付一侧的同类规则由另一项任务处理。

## 规则

- R1 一步写入的结果未知（超时、断连、派发后出错）之后，程序不暂停写入，不拒绝重做同一步，不要求先核查，不替助手结束本轮。助手重读页面后，可以重做同一步、换方法，然后交付回答。重做同一步成功后，原来那一步记为做成，回答不再标成没做完。
  - 例子(正)：练习页「保存」按钮在点击前一瞬不可见，第一次点击回执「结果未知」，网站没收到；助手重读页面后对同一个 @ref 再点，网站收到 1 次；侧栏有最终回答，没有「没有重复执行」「已暂停」「查不清」，也没有标成没做完 — 谁检查：`retry-after-unknown.mts`
  - 例子(反)：恢复「同一目标结果未知就拒绝重做」的闸门，第二次点击回执「不能自动重做」，网站收到 0 次，用例失败 — 谁检查：同上，故意弄坏产品复跑
- R2 已有成功回执的一步，再做一次照常执行：同一栏同一个值重填、同一个按钮再点、读回对不上的同值重填、被网页换掉的下拉框重选，都不再被拒。
  - 例子(正)：提交按钮点过一次后续做再点，服务器收到 2 次 POST；同一句重填照常执行 — 谁检查：`refill-after-check.mts` 2、3、5、6
  - 例子(正)：浏览器在提交回执挂起时崩溃，重启后不自动重放；用户说「继续原任务」后，助手重做这一步，程序不拦，服务器收到第 2 次 — 谁检查：`session-durability.mts`
- R3 同一操作连续三次出同样的错，程序不再停下本轮。第二次出同样的错时，主模型的思考档照旧调高。
  - 例子(正)：「不发」「付款」被拒后同一轮再点三次，没有「连续三次」的停下说明 — 谁检查：`send-confirm.mts` c、`pay-stop.mts` b（去掉规则后这两项必然通过，所以它们只防这句话回来，不证明 R3）
- R4 原地打转的自停保留，门槛放宽，让助手多试几步再停。门槛数值以[代码](../../agent/src/no-progress-policy.ts)为准。
  - 例子(正)：没有真实路径用例覆盖这条 — 谁检查：人看代码差异

## 技术前提

- 前提：在真实扩展里，能稳定地让一次点击得到「结果未知」。做法：snapshot 拿到按钮的 @ref 后，页面让按钮短暂不可见，点击时量不到元素位置，扩展按结果未知回报。小实验：改动前的代码直接跑 `retry-after-unknown.mts`，结果：通过（第一次点击回执「结果未知」，第二次点击被「不能自动重做」拒绝），证据 `out/acceptance/real-path/2026-10-09T18-35-19-181Z-retry-after-unknown/`。

## 边界与不做

- 保留不动：付款按钮永远由用户自己点；点「发送」前先在网页上问用户；用户接管或插话后，在途的写入被拒；能力上做不到的拒绝（不是输入框、没有这个选项、取数限制）；重启检查点在用户说继续之前不执行写入；原地打转停下后同一轮不再写入。
- 结果未知、之后也没有重做成功的一步，仍列在回答的「还没做完」里，回答标成部分完成。这是如实记账，不拦任何操作。
- 语音实时通道没改：原任务缺少执行记录或有结果未知项时，新的语音输入仍不清掉旧任务的记录，缺执行记录时仍拒绝语音写入（`agent/src/conversation-manager.ts`）。语音的写入另行决定。
- 「ref 已失效，操作未执行，请用新的 ref」这类回执没改：这类操作确定没执行，换新 ref 再做是对的指引，不是禁止重试。
- 协议里 `repeatRefused` 字段和侧栏对它的处理、侧栏对旧原因（结果未知待核对、连续失败）的文案没删：它们不再产生，但是删掉要改侧栏文件，那里有并行的改动。旧存档里的这些原因仍能读入。
