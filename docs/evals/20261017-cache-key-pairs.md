# 固定安装缓存键：配对小实验未见收益

关联 [#291](https://github.com/yishu-ziyu/By-Your-Side/issues/291)。本次没有证据支持把产品改成固定安装缓存键，暂不采用该方案。新会话可能整段不命中缓存的现象仍未解决。

## 技术前提

使用 ChatGPT 登录的 `openai-codex/gpt-6-luna`，固定合成提示，每次输入 10,826 tokens，只要求输出 `OK`。比较每次新建的会话缓存键与实验内固定的安装缓存键：两组各预热一次，随后做 6 组 AB/BA 交错配对，共 14 次请求。

14 次请求全部成功。去除 `prompt_cache_key` 后，所有请求的 payload 哈希一致；14 次请求使用独立的 session 和 request 身份。实验没有复用对话历史，也没有发送真实用户请求正文。

## 结果

下表只统计正式配对的 12 次请求，不含预热。

| 指标 | 每次新建的会话键 | 固定安装键 |
|---|---:|---:|
| 请求数 | 6 | 6 |
| 缓存 token 为 0 | 5 | 5 |
| 缓存 token 为 10,624 | 1 | 1 |
| 缓存 token 的 p50 | 0 | 0 |

两组都只有 1/6 请求出现非零缓存命中，本次未见固定安装键提高命中。样本较小，不能据此证明两种方式等效，也不能断言固定键在所有负载和请求形态下均无效。

首字耗时的 nearest-rank p50（每组第 3 小的值）分别为 1,465 ms 和 1,470 ms。同期有真实语音扩展验收请求，因此这里只保留该观测，不据此比较时延或宣称性能改善。

## 规则

#291 要求的配对小实验已完成。将该方案关闭为 `not_planned`，原因是本次未见收益，暂不实施固定安装键；关闭不代表缓存问题已经修复。原始请求级记录留在本机 `out/`，不随本文入库。
