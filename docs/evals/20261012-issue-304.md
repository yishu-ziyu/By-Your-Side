# 任务: 没拿到内容的 fetch 算失败，侧栏写一句人话原因

来源：[#304](https://github.com/yishu-ziyu/By-Your-Side/issues/304)。BYS-114 评测里助手同时抓 5 个接口，多次返回 `HTTP 0 (not ok) … 0 bytes`，但 `isError=false`，侧栏把死路当成成功。622 轮评测里 36% 有工具失败，HTTP 0 这类还没算进去。是 #263 分支图「死路灰色 + 原因」的前置。

## 规则

- R1 fetch 没拿到内容算失败：status 0、非 2xx、或 2xx 但正文空，`isError=true` 并带 ≤16 字的人话原因（「连不上这个地址」「页面不存在（404）」「要登录才能下」「接口没返回内容」）。
  - 例子(正)：status 0 空 body → `isError=true`，reason「连不上这个地址」；404 带内容 → reason「页面不存在（404）」；200 空 body → reason「接口没返回内容」 — 谁检查：`npx vitest run --config docs/tasks/20261012-issue-304/vitest.config.mts`
  - 例子(反)：HTTP 200 有内容 → 不设 `isError`，照旧成功 — 谁检查：同一命令
- R2 给模型的文字不变：仍含 `HTTP 0 (not ok)`，`formatFetchReply` 输出原样，失败标志与原因只进 `isError`/`details`。
  - 例子(正)：status 0 的结果 `content[0].text` 与 `formatFetchReply(data)` 完全相等 — 谁检查：同一命令
- R3 click/fill/navigate/js 等工具失败也带 `reason`：工具自己在 `details.reason` 写明了用它；没写就从错误原文取一句人话（`plainToolError`），剥掉选择子、`@N`、loc、英文括注和不可信标记；没有中文就写「没做成」。
  - 例子(正)：「未找到元素: #gone」→「没找到目标」；「目标不可用（disabled）…」→「目标现在不可用」；挡住回执带出「被「Cookie 设置」挡住」 — 谁检查：同一命令
- R4 侧栏显示原因：tool_end 的 `reason` 字段直接画在步骤后，没有原因才写「没做成」；用户没让执行（heldReason）和拦重复执行的步骤不画成失败。
  - 例子(正)：点击找不到目标，步骤行写「点「不存在的按钮」 · 没找到目标」 — 谁检查：`npm test` 的 answer-straight 用例
- R5 RepeatedToolFailurePolicy 不误升档：三个不同 URL 各失败一次不算重复；同一 URL 同样错误第二次才升档一次；成功一次清掉同工具记录。
  - 例子(正)：a/b/c 三个 URL 各 fail 一次 → 不升档；同一 URL fail 两次 → 升档一次 — 谁检查：同一 vitest 命令

## 技术前提

- 前提：`AgentToolResult` 支持 `isError` 且 `details` 会原样带进 `tool_execution_end` 事件，所以 fetch 不用抛错也能标失败、带原因。小实验：读 `pi-agent-core/dist/agent-loop.js` 的结果包装与 `tool_result` 钩子。结果：成立。
- 前提：操作键是工具名 + 排序后的输入参数，不同 URL 本来就是不同操作，不会误升档。小实验：读 `tool-failure-policy.ts` 的 `operationKey`。结果：成立。
- 前提：侧栏失败只有一处文案「· 没做成」，加 `reason` 字段即可替换显示。小实验：读 `main.ts` 的 `onToolEnd`。结果：成立。

## 边界与不做

- 不改给模型的文字，不改 `formatFetchReply`。
- 不新增 UI：只在现有步骤行的失败尾巴上换文案。
- 用户没让执行（heldReason）、拦重复执行（repeatRefused）的步骤照旧不算失败，不带 reason。
- BYS-114 原始 trace 在仓库外的评测包里，不做离线回放；同等路径由 answer-straight 真实用例覆盖（点击失败 → 侧栏写原因）。

## 结果

- 实现：`fetchFailureReason`（`agent/src/fetch-result.ts`）判失败并给原因；`tools.ts` 的 fetch 在失败时返回 `isError:true` + `details.reason`，给模型的 `content` 不变。`plainToolError`（`shared/user-facing.ts`）把已知错误翻成 ≤16 字人话。`tool_end` 新增 `reason` 字段（`shared/protocol.ts`），`session.ts` 在四条失败路径上填它（正常执行、显示直连、程序子步骤、重读页失败）。侧栏 `onToolEnd` 用 `ev.reason ?? "没做成"`。
- 通过：`docs/tasks/20261012-issue-304/failure-reason.test.ts` 19 例（fetchFailureReason、fetch execute、plainToolError、RepeatedToolFailurePolicy）。
- 实测抓到一处漏：answer-straight 侧栏把「未找到元素: #gone」整句画成原因 —— 半角冒号没被剥掉、选择子漏进 UI。已修（半角冒号同全角剥掉，「未找到元素」归入「没找到目标」），并加回归用例。
- 通过：`npm run typecheck`；`npm test` 核心真实路径用例（见下「验证记录」）。
