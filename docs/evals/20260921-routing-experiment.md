# 实验：路由裁决对照（旧分类器 / Realtime 3 / Jev）

日期 2026-09-21。目的：用真实使用记录回答"一句话该走哪条道，谁判得准、多快"，替代空谈。范围只到离线对照；未改产品代码，未连语音服务，未动正在运行的 host。脚本与原始输出在 [20260921-routing-experiment/](20260921-routing-experiment/)。

## 数据

- 语音：`~/.sideagent/voice-capture/*.jsonl` 全部 ASR 记录，60 句（56 current，4 filtered）。9/10～9/11 走旧 2.5 分类器，9/20～9/21 走 Realtime 3。
- 当时的路由决定：旧分类器取 `agent.log` 的 `route_result`（含 elapsedMs）；Realtime 3 取 `tool_call`（按 voiceId 与 25 秒时间窗关联）；两代都再用 `task-receipts` 按原话精确匹配补派发动作。
- 文字/语音任务请求：`task-receipts` 中 action=start 的去重原话 225 条（含 9/11～9/13 评测夹具，不全是日常真实使用）。
- 标注：由本轮主代理逐句手标，8 条道：chat / answer / page_question / task / steer / control / status / incomplete；有第二合理读法的标 alt，两者任一即算对。标注人不是用户，结论待用户看分歧句子复核。
- Jev：`jev-1.13.0`，与生产 `goal-evidence-judge.ts` 同一端点与格式。每句两问：Choice 选道；Noul "用户是否要页面本身发生变化"。为控制调用数按 10 句一请求批处理；另单句请求 8 次测延迟。共 37 次请求，185,864 输入 / 28,056 输出 token，已记入 `eval-spend.json`。

## 结果

| 数据集 | n | 当时路由器判对 | Jev 判对 |
|---|---|---|---|
| 旧分类器时代语音 | 24 | 14 | 21 |
| Realtime 3 时代语音 | 28 | 12 | 26 |

延迟：Jev 单句 820～922 ms（8 样本，含两问，本机到 API）。旧分类器日志 189 次：中位 1974 ms，p90 6877 ms。Realtime 3 的决定发生在它自己的回复生成里，无法单独计时。

### Realtime 3 判错的句子（全部列出）

| 用户原话 | 它做了什么 | 应该 | Jev |
|---|---|---|---|
| 帮我把这个标签也贴到 B 站那一 | read_page | 切标签任务 | task |
| 不是说把标签页切到 B 站那一个，不是表情。 | read_page | 纠正 | steer |
| 呃，不是要你在这里翻译，是要你把这个页面上的内容给翻译掉。 | 自己开口 | 纠正 | steer |
| 嗯，把它改成中文，然后 | 自己开口 | 翻译页面任务 | task |
| 可以先将它的前三段进行翻译吗？ | 自己开口 | 页面翻译任务（alt：口头回答） | task，页面变化 0.78 |
| 我的这个浏览器当中，目前有多少个标签页啊？ | task_status + read_page | 列标签任务 | task |
| 嗯，有看到吗？ / 读到了什么呢？ | 没调工具 | 读页 | page_question |
| 它确实打开了，我需要移动到 15 分钟啊 | 新任务 start | 纠正 | steer |
| 嗨，你好呀 / 嗨，晚上好 / 嗨，你好（4 次） | read_page | 闲聊 | chat |
| 置办了一文 / 只保留一吻（ASR 误识） | read_page | 碎片 / 纠正 | task（也错） |

前六行就是 9/20 "你他妈瞎呀"和 9/21 翻译两次事故的原句。Realtime 3 的问题集中在"要页面产出的请求被自己吃掉"，而不是执行能力。

### Jev 判错的句子

9 句，其中 6 句是 ASR 碎片或误识（"帮我把当前的这个标签页。""让位是你把它切过去，就是。""置办了一文"等），Jev 倾向判成 task，置信度 0.51～0.70；1 句纠正判成 task（0.58）；1 句评论判成 answer（0.74）。对碎片设置信度下限并等待后续语音，可拦住多数。

### 225 条已派成任务的请求

Jev 认为 78 条不需要浏览器任务引擎：page_question 23（"请告诉我当前页面的标题""这篇帖子的主要观点是什么？""只回答这两项，不要操作网页"）、answer 14（"1+1等于几""中秋国庆假期之前大概多长时间""你能为我做什么"）、chat 21（问候、"是的，确认。"）、steer 13（多为任务已结束后的纠正，派成新任务未必错）、incomplete 6、control 1。文字入口目前把一切送进任务系统，没有轻量道。

## 结论与边界

- 在这批真实句子上，Jev 选道明显优于两代实际路由器，且比旧分类器快一倍以上；错误集中在可用置信度阈值处理的碎片上。
- 样本小（52 句可比），标注来自代理而非用户，Jev 状态缺页面标题与任务快照（日志没存），批处理请求与生产单句形态不同。结论足以支持下一步实验，不足以直接改生效行为。
- Realtime 3 自己执行页面动作是否更快，离线无法测；但其失败都在"选道"，多给它工具不解决这个问题。

## 建议的下一步（待用户同意）

在日常版本加"影子路由"：每句用户输入落定时，宿主并行问 Jev 选道，只记录不干预，日志同时保存 Realtime 3 / 文字入口的实际决定与页面标题、任务快照。用一周真实使用得到带上下文的对照，再决定是否把裁决权交给宿主 + Jev、文字入口是否加轻量道。这一步不改任何用户可见行为。
