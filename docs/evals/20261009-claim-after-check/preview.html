复制到草稿框：现在 vs 先核对再说完成

同一个失败：助手把框里的标题「Note」当成了第一句。左边是 10-09 真实运行的侧栏截图；右边三格是提议的同一次运行，按时间先后。

现在（真实截图）

先说「已填入」，1 秒后又说「还没做完」。没说草稿框里实际是什么。

提议 ① 动作刚做完（约 0–2 秒）

程序直接显示草稿框里的实际内容；助手的话先不放出来，等核对。

把蓝色 Note 框里的第一句英文原文复制到下面的草稿框里，不要保存。
System One 与草稿
做了 1 件事 ›
草稿框现在是：「Note」
正在核对结果…

提议 ② 核对发现不对

不出现假的「已填入」，直接说哪里不对、正在改。

把蓝色 Note 框里的第一句英文原文复制到下面的草稿框里，不要保存。
System One 与草稿
做了 1 件事 ›
草稿框现在是：「Note」

核对发现：「Note」是框的标题，不是第一句。正在改…

提议 ③ 改好之后

最后的回答和程序读到的实际内容一致。

把蓝色 Note 框里的第一句英文原文复制到下面的草稿框里，不要保存。
System One 与草稿
做了 2 件事 ›
草稿框现在是：「Jev currently accepts text input only.」

已把第一句英文填入草稿框，没有保存。

来源 · 9 秒
  • 只对会改动网页的任务这样做（填写、点击、输入）。只读、问答类任务照旧马上回答。
  • 做对的时候：回答比现在晚约 2 秒出现（10-09 实测核对用时 1.5–2.2 秒）。核对太久时，先显示回答，并标「还在核对」。
  • 「草稿框现在是」由程序从网页读回，不经助手转述，所以助手说错时你也能一眼看出来。
  • 折叠区里的「核对 3/3」改成只数真正适用的检查；这次三项都不适用，就不显示。
