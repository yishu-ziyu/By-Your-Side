## 规则

- R1 逐个核对三个会话的原始要求、实物、未完事项，不以回复或 issue 状态作完成依据。
  - 正例：主会话已有收尾回复，但欢迎页未交付，仍留在未完清单。检查者：主代理读原始记录、源码与实测。
  - 反例：两个会话有收尾回复，就只接第三个会话。用户指出此判断错误，已纠正。
- R2 完成已确认的动作核对、目标变化保护、回执核对，并验证真实扩展路径。
  - 正例：条件失败后练习站没收到后续请求；侧栏显示对应失败。检查者：[专项验收](20261008-check-assert-referee.md)。
- R3 补齐主动卡忙时、助手断开、扩展后台重启三条客观验收。
  - 正例：旧卡保留；恢复后同一意图只办理一次。检查者：`proactive-card-boundaries.mts`。
- R4 保留用户原有改动、数据和会话；新方向先给产品预览，不替用户做体验取舍。
  - 正例：欢迎页前后可操作；套餐语音的分流取舍仍单列。检查者：主代理、用户。
