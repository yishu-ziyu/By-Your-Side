# 任务: 步骤能对上页面上的按钮；接管时先退场再写「你在操作」

来源：设计稿 A4 / A5 / A10。用户看「做了几步」时要对上刚才点的按钮；接管时先看见页面上的光标退走，再看见侧栏写「你在操作」。交还后等助手真的重读完页面，光标才回来。

## 规则

- R1 步骤有可读名字：过程列表里点过的一步写目标上的字或角色，不写「点这里」。
  - 例子(正)：点了按钮「作品」，展开后那一行是「点「作品」」— 谁检查：`scripts/acceptance/real-path/step-page-highlight.mts`
  - 例子(反)：六步都写「点这里」— 谁检查：同上
- R2 悬停或键盘聚焦某一步，网页在那个元素外画一圈；元素没了或页面跳了，这一行写「页面已变」，不假装高亮。
  - 例子(正)：还在原页时圈出「作品」；跳到空白页后再聚焦，出现「页面已变」，页面上没有圈 — 谁检查：`step-page-highlight.mts`
  - 例子(反)：跳走后仍在旧坐标画圈 — 谁检查：同上
- R3 接管：光标和边缘光先退场，侧栏再出现「你在操作 · 助手在旁边等」。交还：先写「助手先重读页面」，重读完成后光标才回来。不用定时器估重读结束。
  - 例子(正)：点「接管」后先看不见光标，再看见「你在操作」；点「交还」后先看见「助手先重读页面」，快照回来后光标再出现 — 谁检查：`scripts/acceptance/real-path/control-handoff-motion.mts`
  - 例子(反)：按钮字一换就写「你在操作」，或交还后用固定等待假装重读完 — 谁检查：同上
- R4 侧栏动效只走 5 个时长和 4 条曲线；token 文件以外不许出现裸的 cubic-bezier 或短时长。
  - 例子(正)：`npm run check:motion` 通过 — 谁检查：该命令
  - 例子(反)：styles.css 里再写 `180ms cubic-bezier(...)` — 谁检查：同上

## 技术前提

- 前提：content script 的光标层能画持久描边，并且能按选择器重新找到当时的元素。小实验：本机练习页点击后悬停步骤。结果：通过（见上述用例）
- 前提：交还时 background 先 `snapshotTab` 再让光标回来，这一顺序是真实事件而不是延时。小实验：同上交还用例。结果：通过

## 边界与不做

- 页面上「填完点这里」的交还圈不改文案。
- 不把「控制权」写进界面。
- 不为每个工具加单独的对照协议；对照挂在已有的点/填/看结果上。
