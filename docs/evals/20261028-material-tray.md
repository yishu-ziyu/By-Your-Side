# 任务: 在输入框上方看到并管理这次要交给助手的全部材料

## 规则

- R1 材料夹汇总当前页、选区、@ 标签页和本地附件。
  - 例子(正)：在网页上输入问题并附上一份 PDF，材料夹显示当前页和 PDF，计数为 2。— 谁检查：`file-attachments` / 人工查看材料夹
  - 例子(反)：只有输入框有字、没有页面和附件时，材料夹只显示空提示，不伪造材料。— 谁检查：`composer-expand`
- R2 状态只写当前已知事实。
  - 例子(正)：当前页标“自动带入”，选区标“原文”，本地文件读完才标“已读”。— 谁检查：人工查看材料夹
  - 例子(反)：附件还在解析时标“在读取”，不提前写“已读”。— 谁检查：`file-attachments`
- R3 选区、@ 标签页和已读完的附件可以多选后移出，并在同一次草稿里撤销。
  - 例子(正)：选中两个附件并移出，计数从 3 变为 1；点“撤销”后回到 3。— 谁检查：材料夹人工验收
  - 例子(反)：当前自动带入的页面没有移出勾选，不能假装发送时能排除它。— 谁检查：人工查看材料夹
- R4 材料夹不截断发送流程。
  - 例子(正)：文件刚附上就发送时，仍等读完再发，模型收到完整文件文字。— 谁检查：`file-attachments`
  - 例子(反)：发出后输入框、选区、@ 标签页和附件都清空，材料夹不留在下一轮。— 谁检查：`file-attachments`

## 还没答上的问题

无。

## 技术前提

- 前提：现有草稿已经有页面、选区、@ 标签页和附件的真实来源，材料夹只做只读汇总。结果：通过，未新增消息协议或权限。

## 边界与不做

- 不把材料夹做成跨会话文件管理器；它只显示这次草稿真正会送出的材料。
- 不支持从 Chrome 标签栏直接拖进侧栏；标签页仍通过输入框 `@` 或材料夹的 `@` 按钮加入。
- 当前页由发送流程自动带入，本版不提供“排除当前页”的开关。
- 不读取已下载文件的内容，不把页面内容自动写进长期记忆。
