# 任务: 网页循环与实时判断改为向 Jev 问窄问题，30 轮验收达标后才合并

来源：船长 2026-09-26 批准的重设计（设计调查 `bys-jev-design-r1` 报告与原型 `32f5103`，上一轮三处循环补丁 `fm/bys-jev-fix-r1`）。本文件在实现前写下，门槛原文不因结果修改；之后的修订写在「修订记录」。

## 用户能观察到的结果

- 「打开 Account 菜单点 Settings」「点 Late-Target」这类请求，循环自己判断完成，以「已完成，待核验」结束，不再以 `low_confidence` 交回。
- 页面上没有要找的控件时，循环读完全部分区才说没找到。
- 删除、付款、发送、发布这类控件不自动点，交回用户确认；用户明确要求的可逆写入（保存、打开开关）照常执行。
- 连接层故障（TLS 握手卡住等）自动重试一次，不再直接变成交回。
- 直接交付（循环判定完成且执行器确认点击送达，不再让主模型复核）只有在本验收「误报完成 = 0」时才打开。

## 边界与不做

- 不降低 0.85 门槛；不涉及翻译、语音。
- 不改其他 Jev 调用方（快捷判断、目标核验等）。
- 现有做法（对照臂）取 main 上的实现原样运行，不带上一轮未合并补丁。

## 修订记录

均发生在任何留出任务（H1–H8）运行之前。

- **对照工具的会话身份。** 原型工具以会话 `jevcmp` 调用执行器；这个会话不是可见会话，执行器按产品规则不把切换的标签页调到前台，H7 的判定（活动标签页）因此对任何做法都不可能通过。改为以默认会话（日常可见会话）调用，两臂相同。D5 冒烟据此确认切换与判定一致。
- **切标签页的核对方式。** 改为以执行器 `switch_tab` 回报的工作标签页为准，不再另读 `get_active_tab`（后台会话不调到前台时旧核对必然失败）。回执记为已执行、未另行核验。
- **「完成」的分母。** 门槛「成功运行中 ≥ 90% 由循环自己以 `needs_verification` 结束」只计需要动作的循环入口任务（S5 循环入口、S6、H1–H7）；S6N、H8 的正确结束是 `no_match`，S5 实时入口不经过循环（另报第三次判断是否给出 `needs_verification`）。
- **开发用页面。** D1–D5（`fixtures.mts` 的 `devPages`）只用于调试模板，是样本内数据，不进门槛。调试中据 S5/S6/D 页调整过：完成问题的措辞、`target` 问题改为「接下来要操作的」、已操作控件留在状态里但不再是选项、下拉/开关/填写控件不先悬停、动作事实只写控件名不写动作前状态、建连上限 1.2 → 1.0 秒。

以下修订发生在看过留出数据之后。

- **H5 不计入「完成」门槛（2026-09-26，用户裁决）。** 前 18 轮里，新做法在 H5 上 18/18 成功，但 0/18 由循环自己判定完成：两次点击都对了，最后的完成问题只给出约 0.70。原因是任务原文是“下载发票”，而夹具按钮只计数、不产生下载，动作事实里没有任何下载证据，交回复核正是期望行为。同一状态重复询问三次：原样 0.69–0.70；任务改写成“点击 Download invoice”后 0.87–0.89；动作事实加一句“文件开始下载”后 0.95–0.96（`out/jev-compare/diag-h5`，样本内诊断，不进门槛）。用户裁定这是正确结局，与 S6N、H8 同样处理，不计入分母；其他门槛和 0.85 阈值不变。原分母的结果照常报告：前 18 轮原分母 123/143 = 86%，去掉 H5 为 123/125 = 98%（`analyze.py` 的 `selfNeedsVerificationOriginal` 与 `selfNeedsVerification`）。
- **端到端加「主模型自己干」对照组（2026-09-26，用户同意）。** 原设计只比较新旧问法，回答不了“新问法的 Jev 是否比不用 Jev 更好”。端到端段新增 `main` 臂：不调用 Jev，同一句话、同一套工具、同一页面直接交给主模型，即日常扩展当前的默认配置（`browser_loop` 关）。firstmate 跑过的 5 次端到端（`docs/work/20260926-firstmate-handoff/jev-build-partial/gate-e2e.results.jsonl`）没有这一臂，因此三臂从第 0 轮重跑 30 轮，旧 5 次只留作原始记录。`main` 臂不进合并门槛。
  - **「日常侧栏是否打开 Jev」的参考标准（在看到 `main` 臂数据前写下）：** E5、E6、E6N 上，Jev 臂（`split` 或 `direct`）成功率不低于 `main`，错误写不多于 `main`，任务耗时 p50 不高于 `main`。三条都满足才建议打开；是否打开由用户裁决，不随本次合并自动生效。
