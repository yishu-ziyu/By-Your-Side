# 任务: 助手动手前先在侧栏说一句：打算做什么、哪些不会碰（YIS-139）

预览：[先说一句与交给你](../previews/speak-and-handoff/index.html)，用户 10-09 认可。

## 为什么

- 拆 ego 浏览器会话时看到：用户觉得顺畅，主要因为助手动手前几秒内先说一句计划和边界。模型每步思考时间并不比我们短（[前提实验](20261009-act-observe-premise.md)）。
- 我们 275 次会动手的测试里，模型在第一次动手前说话的次数是 0。用户只看到「正在思考」和步骤卡，不知道它打算做到哪、哪些不碰。

## 规则
- R1 会动手的任务，侧栏在第一个页面动作的步骤出现前，先显示一句助手的话，说要做什么和不碰什么；任务结束后这句话仍可见，不被收进「执行过程」。
  - 例子(正)：练习页说「把蓝色 Note 框里的第一句英文原文复制到下面的草稿框里，不要保存」，侧栏先出现一句含「不保存」意思的话，然后才出现第一步 — 谁检查：`scripts/acceptance/real-path/speak-first.mts`
  - 例子(反)：去掉提示词里的新规则，用例必须失败 — 谁检查：同上，故意弄坏产品复跑
- R2 这句话不多等一轮：它和第一个页面动作在同一次模型回复里发出。
  - 例子(正)：诊断记录里，开场这句和第一个浏览器工具调用属于同一轮（同一个 turn） — 谁检查：同上
  - 例子(反)：开场这句单独占一轮，下一轮才动手，用例失败 — 谁检查：同上
- R3 只问问题、不用动手的请求，不加开场这句。
  - 例子(正)：「这个岗位叫什么？在哪个城市？只回答这两项，不要操作网页。」侧栏只有回答，没有开场这句 — 谁检查：同上
- R4 正确率不降：复制任务的结果照旧按草稿框里的真实内容判，开场这句不能替代结果。
  - 例子(正)：草稿框是第一句英文原文，练习站没收到保存请求 — 谁检查：同上（沿用日常请求底线的判据）

## 技术前提
- 前提：默认测试模型 GPT-6 Luna 能在第一个页面动作的同一次回复里先写一句话；侧栏能把这句话留在回答区，不折叠。
  小实验：提示词要求用 `send_user_message(kind:"ack")` 开场，跑 3 次复制任务（`everyday-baseline.mts --only=copy-no-save`），读诊断记录和侧栏快照。
  结果：按原设计失败，但得到了可用的做法（10-09）。
  - 3 次里 2 次，模型没调 ack 工具，而是在 turn 1 同一次回复里先写一句文字，再调 `fill` / `browser_run`（「我把 Note 框里的第一句英文原文填进草稿，不会点击保存。」）。同一轮成立。但侧栏把这句收进折叠的「执行过程」，运行中 2 秒、4 秒截图里看不到。证据：`out/acceptance/real-path/2026-10-09T12-50-39-489Z-everyday-baseline-inproc-6468/`。
  - 另 1 次，模型在 turn 1 只调了 ack 工具（「我把 Note 的第一句英文填进草稿框，不会点击保存。」），第一个浏览器工具 `tabs` 在 turn 2，即单独占了一轮。证据：`out/acceptance/real-path/2026-10-09T12-47-34-113Z-everyday-baseline-inproc-95636/`。
  - 所以改成：提示词要一句普通文字、和第一个页面动作同一次回复；侧栏在第一次动手时不再折叠这句，把它留在过程行前面。改后验收见下。

## 验收结果（10-09）
- `speak-first.mts --headless --repeat=3`：复制任务 3/3 通过 R1、R2、R4；只问问题 3/3 通过 R3。证据：`out/acceptance/real-path/2026-10-09T13-07-35-003Z-speak-first-53992/`。
- 故意弄坏：只撤提示词，R1、R2 失败，模型第一次回复只有工具调用（`…13-17-38-896Z-speak-first-86440/`）；只撤侧栏改动，R1 失败，R2 仍通过（`…13-13-59-850Z-speak-first-74136/`）。
- 收窄排位规则后复跑 1 次，两条都通过（`…13-18-18-596Z-speak-first-88054/`）。
- 第一版侧栏改动漏了收尾排位：任务卡夹在用户消息和开场话之间，收尾时过程行插到任务卡前面，开场话落到过程行后面。R1 判出了这个问题，3/3 失败（`…13-03-56-573Z-speak-first-42620/`）；补上排位规则后通过。

## 边界与不做
- 不做中途补一句（计划变了时的说明）。ack 气泡放在步骤块前面，插不进步骤中间；中途补一句另起任务。
- 侧栏只改三处：第一次动手前的那句开场话不折叠；收尾排位时把它留在过程行前面；找「最近一条回答」时跳过它，所以任务没出回答就停下时，「用到的记忆」不会挂到开场话下面（这一处没有单独验）。之后各步之间的过渡话照旧收进「执行过程」。
- 没验：重开侧栏后回放历史时开场话是否照样显示；运行中插过话时开场话上的「已改方向」装饰。
- ack 气泡在任务结束后排到过程行后面，是已有的问题，本任务不修。
- 语音路径不在本任务内。
