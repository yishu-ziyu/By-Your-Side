# 任务: 底座换成 Pi 1.0 + pi-durable，接管后交还能接着做完，其余能力不退步

背景：重构方向见 [复杂度阶梯](20261006-complexity-ladder.md)。基线 before-1006 里 L6「接管后交还」0/3：交还后助手把被打断的那步记成「结果不确定」，然后停下。[pi-durable 实验](20261006-pi1-durable-spike.md) R5、R6 都通过，所以按约定换 Pi 1.0 + pi-durable。扩展现在锁在 Pi 0.84.4，Pi 1.0 删掉了我们用的 `Session`、`JsonlSessionRepo` 和 `convertToLlm`。

做法：会话层（`session.ts`）只通过 [`AgentLoop`](../../agent/src/agent-loop.ts) 用底层循环。新写一个 `DurableAgentLoop` 实现同一个接口，新旧并存。用同一把尺子比过以后，再删旧实现。不一次推倒重写。

## 分步

每一步单独验收、单独合并。尺子是 `node eval/harness/ladder.mjs --tag <步骤名>`，每题 3 次，和 before-1006 比。

| 步 | 用户看到的变化 | 主要改动 |
|---|---|---|
| 0 技术前提 | 无 | 3 个小实验，见「技术前提」 |
| 1 换底座 | 无（不退步就算成功） | Pi 包升到 1.0.4；`DurableAgentLoop`；会话存进 pi-durable 的 IndexedDB 存储；迁移旧会话 |
| 2 接管后交还 | 交还后助手接着做完，保留用户改过的值 | 接管 = `Conversation.abort()`；交还 = 同一会话发一条消息，附上当前页面 |
| 3 重启后接着做 | 扩展后台重启后，没做完的任务自己接着做 | 启动时 `resume()`；只读工具声明可以重放 |
| 4 删旧代码 | 无 | 删 `pi-agent-loop.ts` 里复刻的 AgentSession、`pi-session-persistence.ts`、`pi-session-idb.ts`；`pi-coding-agent` 只剩类型或者去掉 |

## 规则

- R1 不退步（步 1、3、4）：L1–L5、L7 每级通过数不低于 before-1006 减 1（每题 3 次的噪声）；中位耗时不超过基线的 1.2 倍；`npm run check` 全绿；`accept:real-path` 的用例结果和合并前一致。
  - 例子(正)：步 1 后 L2 9/9、L4 9/15 — 谁检查：`ladder.md`
  - 例子(反)：L4 从 10/15 掉到 8/15 — 谁检查：同上，判为退步，不合并
- R2 接管后交还（步 2）：BYS-149 3/3 通过，用户改的电话保留，其余格子填完。
  - 例子(正)：交还后助手填完邮箱、城市，电话仍是 13911112222 — 谁检查：judge
  - 例子(反)：交还后助手把电话改回去，或者又停在「结果不确定」 — 谁检查：judge
- R3 旧会话不丢（步 1）：升级前已有的会话，升级后在会话列表里还在，打开能看到原来的消息，还能接着发。
  - 例子(正)：升级前 3 段会话，升级后 3 段都在，最后一段发新消息能收到回答 — 谁检查：真实路径脚本（步 1 写）
  - 例子(反)：会话列表是空的，或者打开后消息缺一截 — 谁检查：同上
- R4 重启后接着做（步 3）：任务跑到一半时重启扩展后台，任务自己接着做完；已经做完的点击、填写不重做。
  - 例子(正)：填表做到第 3 格时重启，重开后填完第 4、5 格，第 1–3 格只填过一次 — 谁检查：真实路径脚本（步 3 写）
  - 例子(反)：重启后又从第 1 格填起 — 谁检查：同上，看页面上的执行记录

## 技术前提

每项一个不超过 50 行的小实验，放在 `scripts/probes/pi1-rebuild/`。三项都成立才开始步 1。

- P1 事件能对上：会话层用到的循环事件都能从 pi-durable 的 `watchEvents()` 得到，正文延迟不超过 150 ms。小实验：[p1-events.mjs](../../scripts/probes/pi1-rebuild/p1-events.mjs)。结果：通过（`out/pi1-rebuild/p1-result.json`，跑两次）。
  - 正文和服务商原文逐字一致。延迟按每批里最早的新字算：p50 104 ms，p95 107 ms，最大 108 ms。约 100 ms 的下限来自半截回答每 100 ms 提交一次。
  - `agent_start`、`agent_end` 不存在，对应 `run_start`、`run_end`。`toolcall_end` 没有对应的子事件，最近的是 `block` 变化；codex 的工具调用整条到达，不逐字。
  - `auto_retry_start` 只用注入的 503 测过。codex 服务商只把 5xx 的响应正文当错误文字，状态码丢了：正文里不写「503」时不重试。重试过一次的尝试会在记录里留一条空的助手消息。
- P2 后台进程里能恢复：在 offscreen 文档里跑慢工具，执行中 `closeDocument()`，重建后 `resume()`。小实验：[p2-offscreen.mjs](../../scripts/probes/pi1-rebuild/p2-offscreen.mjs)。结果：通过（`out/pi1-rebuild/p2-result.json`，跑两次）。会话记录还在；工具只执行过 1 次，结果是「被中断，可能执行了一部分」；随后答完。offscreen 文档里没有 `chrome.storage`，只能用 IndexedDB。
- P3 服务商都能用：pi-ai 1.0.4 下打包，并在扩展页面里流式回答。小实验：[providers/](../../scripts/probes/pi1-rebuild/providers/)。结果：部分通过（`out/pi1-rebuild/providers/`）。
  - 打包：6 家都能打包。ChatGPT 登录仍需把 `node:http` 换成替身。
  - 流式回答：ChatGPT（gpt-6-luna）通过，首字 1.7 秒。Kimi 的本机登录已过期，等用户重新登录后补测。DeepSeek、xAI 用户现在用不了，只查打包。GitHub Copilot 没有凭据，只查打包。
  - 升级要处理：1.0.4 不再导出 `./auth/oauth/*`，要加路径别名；仍要注册内置登录模块。`openai-codex` 在 1.0.4 里标为 legacy，并新增了 `openai-chatgpt`，步 1 前查清该用哪个。
  - pi-durable 1.0.3 起，存储接口多了 `openBinaryReader`、`openDirReader`、`watch` 三个方法，IndexedDB 存储要补上。

## 边界与不做

- 不改工具本身（点击、填写、读页面）和它们给模型看的说明。L4 的弹窗、上传、跨站 iframe 问题另开任务。
- 不改记忆的存储和判断。记忆的下一版在[记忆小考](20261006-memory-quiz.md)之后另开任务。
- 不做 MCP 对外接口。步 1 只要求工具定义不依赖新的循环，留出接口。
- 后台标签页里任务变慢（每次点击约 8 秒，前台约 2.6 秒）另查，不在本任务里。
