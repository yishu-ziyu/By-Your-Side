# 任务: 接管/交接 v1 —— 用户拿回页面，交还后原任务从当前状态继续

本标准由 Codex（校验）在 Grok（实现）动手前锁定。Grok 不得修改本文件、降低断言或用新开一轮任务代替继续。

```
Change:     Agent 运行时，用户随时接管当前页面；界面确认“现在归你”之后，Agent 不再改变浏览器。用户交还后，原会话先读取用户当前页面，再继续原任务。
Not this:   中止后重发任务；只隐藏光标；只靠 prompt 要求模型停手；交还后回到旧标签页或重做已经完成的步骤。
Evaluator:  协议/状态/执行层自动测试 + 本地安全页 + 真机 flomo 路径。观感由用户裁决。
Evidence:   测试输出、工具事件记录、接管与交还两个状态截图、真机连续路径。
```

## 完成标准

- [x] 1. 运行中始终能执行“接管”；收到接管确认后，界面明确显示“现在归你”，不与 idle、完成或中止混淆。— 谁检查: 人 + 状态单测
- [x] 2. “现在归你”期间，Agent 的浏览器写操作不能落地。至少覆盖 open/switch/navigate、click、fill、type_text、press_key、scroll、js、mark/clear_marks；不能只靠模型自觉。— 谁检查: 执行层单测 + 本地安全页
- [x] 3. 接管与同时到达的工具调用没有竞态：接管确认出现后，排队或迟到的旧调用也不能落地；已经开始的动作必须先结束或取消，之后才能显示“现在归你”。— 谁检查: 并发/迟到调用单测
- [ ] 4. 接管不结束原会话，不清空任务、对话或工作标签；“中止”仍单独终止任务。— 谁检查: 会话状态单测 + 人
- [ ] 5. 用户执行“交还 Agent”时，系统先取得当前活动标签的 tabId/title/url 和新 snapshot，再把控制权交还给同一会话。取不到当前页时停住说明原因，不擅自回旧页。— 谁检查: 协议/会话单测 + 人
- [ ] 6. 交还后 Agent 基于新 snapshot 继续原任务，不重新打开站点，不重复已经完成的步骤。— 谁检查: 人。flomo 场景：Agent 定位笔记过程中接管，用户改点另一条，交还后 Agent 处理用户当前这条
- [ ] 7. 接管、交还和中止后都没有残留 loader、旧光标继续移动或控制权文案错位。— 谁检查: 无头界面检查 + 人
- [x] 8. `npm run typecheck`、`npm test`、`npm run build` 全绿；新增协议正反例、执行闸门、竞态和恢复测试。— 谁检查: 机器

2026-09-05 Codex 机器复核：`npm run typecheck`、253 项测试、`npm run build`、`node extension/test/overlay-check.mjs` 全绿；启动顺序已改为先 hydrate 控制权再启动 uplink，并覆盖刷新重画、SW 恢复、断线保持和 `user ≠ idle`。条目 1、2、4–7 仍保留真人 flomo 连续路径裁决。

2026-09-05 Codex 真机复核：在真实 Wikipedia 任务中，接管成功；刷新与从 `Artificial intelligence` 跳转到 `Intelligent agent` 后仍保持用户控制，条目 1、2 通过。交还闭环失败：侧栏打开时「交还」被侧栏覆盖，收起侧栏后控制条不可见；触发同一 `handback_click` 后，存储已是 `owner=agent`、`lastStatus=running` 且工作标签为当前页，但旧控制条残留，重开侧栏后原任务/对话为空且未继续。条目 4–7 保持未完成。证据：`docs/evidence/20260905-takeover-handoff/`。

## 实现顺序约束

1. 先完成单 Agent、单标签页的完整竖切。
2. 硬闸门和同一会话恢复通过后，才接生产界面。
3. 生产界面的名称、位置和状态表达先做不超过三案的临时 HTML；对照 Will's S Design Note 后由人选择，再落地。
4. v1 真机通过后，另开标准把同一控制权扩到 Lead 和全部并行实例。

## 边界与不做

- v1 不处理多 Agent 同时暂停；先证明单 Agent 闭环。
- 不把教学模式、中止或危险确认改名冒充接管。
- 不做跨 Chrome 重启持久化。
- 不顺带做轨迹回放、技能录制或页面哨兵。
- 不允许实现者修改本标准；需要变更时退回 Codex 或用户裁决。
