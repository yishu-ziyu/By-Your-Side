# 任务：选一句按住右 ⌥ 问，光标、标记和阅读卡是同一个 BYS 的连续动作

## 规则

- 按住时 BYS 光标飞到选句末尾、名牌写「在听」并跟着音量动，这段标黄；底部胶囊不出现。松开后阅读卡在同一处展开，先引用这段原文、写「听写中…」，听到后换成听到的话，回答出来后边写边念。
  - 谁检查：`npx tsx scripts/acceptance/real-path/voice-reading.mts --headless`（在听、等答、开卡、念、全程）
- 再按住：旧声音立刻停，排着的句子不再念，旧回答停在已写出的地方不再变长；新要求接在同一张卡里。
  - 谁检查：同上（停声三条、改口两条；`--scripted` 撞上「回答还在写时按下」）
- 换选另一段问：按下时光标和卡片一起移到新段旁，松开后新一轮带自己的引用；旧回答原样留着，引用仍是旧段。
  - 谁检查：同上（在听、等答、换段）
- 继续滚动、缩放：光标跟着那段字走，那段滚出视口时光标靠在卡片角上；滚动中卡片和光标淡下去让开正文，停下就回来；页面位置只由用户改，回答不收起。
  - 谁检查：同上（跟字两条、稳定）

## 两种接入方式与取舍

- 方案一（采用）：页面里一个交流状态机（`content/ask.ts`）。按下时就在页面里抓住选区 Range，光标、黄色标记和阅读卡都从这一个 Range 取位置，同一帧排版；后台只管听写、分流、模型和念，每次按下给一个轮次号，旧轮次的结果到了就丢。
- 方案二（放弃）：后台像助手动手时那样经 `executeScript` 驱动光标，卡片仍各自定位。选区只能变成坐标送到后台，一滚动就过时；光标归后台、卡片归页面，两边各管一半，每一步要隔两跳消息，慢放能看出光标和卡片错开。

## 技术前提

- 光标原来只能停在元素上，不能停在一段文字上；加了 `cursor.companion()`，由阅读卡每次给出指向点，光标只负责飞和画名牌。
- 一张卡原来只有一段原文，换段就新开一张、旧回答消失；现在每轮可带自己的原文（`ReadingTurn.source`），给模型的资料里也写明哪一问针对哪段。

## 边界与不做

- 不做跟随用户鼠标的角色；光标只在按住说话以后出来，卡片收起就回角落。
- 没有选中的文字也没开卡时，按住说话照旧用底部胶囊，交给助手的话也照旧。
- 打字问的流程只改两处：卡开着时点空白处要过连击间隔才收（双击、三击选字不再误收）；卡开着时新选一段，打字问的就是这段，接在同一张卡里。
