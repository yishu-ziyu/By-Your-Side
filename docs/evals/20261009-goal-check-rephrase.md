# 任务：没换说法再找，目标核对不放行「没找到」；按钮确实不起作用时，不再反复催

YIS-136 / GitHub #174。用户 10-09 同意把死按钮实验的结论一起做进来。底子见[边说边做底子](20261009-voice-ideas-baseline.md)。

## 规则

- R1 回答说「没找到」，而助手只按原话找过：目标核对判「继续」，催它换说法再找。
  - 正：查维基「回声消除」，回答里有「回音消除」词条导言里的事实。检查者：`everyday-baseline.mts --suite=goal-check --only=wiki-lookup`，单独启动 5 次，至少 4 次通过。
- R2 用户要「每处」「每个」「全部」，结果更粗时不算完成。检查者：只写进了核对规则；圈高频词已由[按文字圈](20261009-mark-text.md)做到逐词，没有单独的反例。
- R3 按钮点了没反应：助手只点过一次时，核对最多催一次换做法；换过做法、宿主两次以上报告页面没变化、回答也如实说了，就判「受阻」，不再催。
  - 正：`--only=dead-save`、`--only=dead-next`，各单独启动 4 次，核对催的次数不超过 1 次。
- R4 网站连不上时，说明一次就停，不被催。检查者：`--only=unreachable`。

## 还没答上的问题

无。

## 技术前提

无新前提。核对模型看到的过程记录只有工具返回的结果，看不到助手搜索时用的词（`agent/src/session.ts` 收集核对输入的地方），所以「只按原话找过」由核对模型从结果里推断，不由程序判定。

## 边界与不做

- 不改主模型的查找办法。R1 没达到的部分另起任务。
- 不改续做次数上限。

## 做法

- 核对提示词加了 R1、R2 两条判断，并写明「建议用户自己去搜」不算等用户。
- 修了一个原有的 bug：判断「助手在问用户」时，程序把回答里网址的「?」当成问句，于是把核对的「继续」改成「等用户」。现在先去掉网址再判断。回答结尾带链接的任何任务都受过这个影响。
- R3 由宿主判定，不交给核对模型：宿主的点击结果两次以上报告「页面没有变化」，回答也说按钮不起作用，就直接判受阻。见 `agent/src/goal-check.ts`。

## 证据

2026-10-09，隔离无头 Chrome、只装扩展、gpt-6-luna（ChatGPT 登录），每次单独启动。改动前的数字在没有产品改动的工作树里测。

| 场景 | 改动前 | 改动后 |
|---|---|---|
| 查维基（R1，5 次） | 0/5；核对判「完成」或「等用户」，一次都没催；14 秒、6 轮 | 0/5；5 次都被催去换说法，催 1–2 次后判完成；22 秒、12 轮 |
| 保存按钮没反应（R3，4 次） | 2 次都在说明后又被催 2–3 次；22、39 秒 | 4/4 最多催 1 次；15 秒、11 轮 |
| 下一页没反应（R3，4 次） | 1 次被催 3 次（42 秒），1 次没做核对（16 秒） | 2/4；另 2 次仍被催 3 次；20 秒、11.5 轮 |
| 网站连不上（R4） | 判受阻，没催 | 判受阻，没催 |
| 真的不存在（「全双工芝士蛋糕定理」，1 次） | 判完成，9 秒、7 轮 | 核对 3 次都判「继续」，宿主按上限续做 2 次后停下；46 秒、20 轮 |

耗时和轮数是中位数。查维基这一行在最后一处改动（认程序步骤里的点击结果）之前测，那处改动只影响点击计数。真的不存在只测了 1 次：多花约 37 秒，比 issue 预估的 5–10 秒高得多。

R1 没达到：被催之后，主模型换的说法是「回声抵消」「声学回声消除」「回声抑制」，没有试只差一个字的「回音消除」，也没有顺着外语页面的语言链接回来；找到几个「相关条目」后，核对判完成。回答比以前好：以前说「你自己去搜」，现在列出提到回声消除的相关条目。试过让宿主在催的话后面固定附上换说法的办法（换近义字、从外语页面的语言链接回来），5 次仍是 0/5，主模型没有照做，所以没有保留。

## 测量过程中修正的判据

- 第一批改动前测量和改提示词在同一个工作树里进行，后几次运行带上了新提示词。这批作废，改在没有产品改动的工作树里重测。
- 提示词改了三轮，查维基一直被判「等用户」。原因是上面那个网址问号 bug，不是提示词。
- 死按钮判据从「一次都不能催」改为「最多催一次」：助手只点过一次时，催它换个做法是对的；这符合用户定的「换过做法才判受阻」。
- 「下一页」这题助手用程序步骤点按钮，点击结果是结构化的 `changed:false`，宿主判定一开始没认这种写法，4 次都被催 2–3 次。补上后重测。
- 判据原来只认「无法确认」，2 次如实回答「还没法确认第 2 页第一条」被判失败；补上「没法确认」后按新判据重新核对，这 2 次通过（核对直接判受阻，没催）。

## 遗留

- R1：主模型被催之后仍想不到只差一个字的写法，也不走外语页面的语言链接。要改主模型的查找办法，另起任务。
- R3：程序步骤里的点击有时不带「页面有没有变化」的结果，宿主数不够两次，「下一页」这题仍有一半被催 3 次。
- 回答末尾出现「按上次做过的「…」」，引用的是同一任务里前一次的回答（死按钮实验也看到），另起任务。
