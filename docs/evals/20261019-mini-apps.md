# 任务: 实验功能「回答里的小程序」：打开后，要动手试的问题由助手当场写一个小程序放在回答里，不联网、碰不到网页，改过的东西重开还在

用户 10-18 决定不否决、做成默认关闭的实验功能，并要求“打开时就一定要提供相应的服务”；认可对照页上的六条承诺，第一版不读实时网页（数据由助手写进程序）。来源：ChatGPT Intelligent UI 与 SwiftChat 的沙箱互动回复。卡片能说清的仍用卡片。

## 规则

- R1 开关在「设置 → 实验功能 → 回答里的小程序」，默认关。关着时助手不知道有小程序；以前写出的小程序只显示一句怎么打开。打开后下一个问题起生效，已显示的回答当场换成小程序。
  - 例子(正)：关着时回答里的小程序显示“在「设置 → 实验功能」打开…”；在设置页打开后，同一条回答里出现小程序 — 谁检查：`scripts/acceptance/real-path/mini-apps.mts`
- R2 出了就能用：写完才放进侧栏，写的过程中只有一块“正在写小程序…”的空位；高度跟着内容；报错或空白时，下面一行写出错原因并给「让助手修好」，点了才把错误发给助手。
  - 例子(正)：点小程序里的「加一」，下面出现小程序想放进输入框的话；框高跟内容走，不是固定 120px — 谁检查：同上
  - 例子(反)：脚本报错的小程序，下面出现“小程序出错了”和「让助手修好」，点了侧栏出现这句用户的话 — 谁检查：同上
- R3 出不了事：小程序不能联网、不能加载外部东西、不能把自己跳到外面网址；碰不到扩展和网页；只能提一句话等用户点「放进输入框」，不能自己发。
  - 例子(反)：小程序里用 fetch、图片、跳转往本机服务器发数据，服务器一次也收不到 — 谁检查：同上；沙箱各条路的小实验 `scripts/acceptance/real-path/mini-app-probe.mts`
- R4 重开还在：小程序用 bys.save 存的东西，重开侧栏后从 bys.state 拿回来。
  - 例子(正)：点两次「加一」，重开侧栏，小程序从 2 接着算 — 谁检查：同上
- R5 真模型会写、写得能用：要动手试的问题写小程序，卡片能说清的仍是卡片，一句话的问题是文字；写出的小程序在沙箱里不报错、不空白。
  - 例子(正)：gpt-6-luna 回答“贷款 100 万，利率、年限、首付都想拖着看月供” — 谁检查：`tmp/genui/run.mts` 小实验 + 人看

## 技术前提

- 前提：mini-app.html 自己的 CSP 在整页写入后仍有效，挡住请求、图片、脚本、样式、表单、弹窗。小实验：`mini-app-probe.mts`。结果：通过；只有“自己跳到外面网址”挡不住，服务器收到了 `/nav?d=secret`。
- 前提：侧栏页的 CSP 加 `frame-src 'self' blob:` 能挡住小程序自己跳到外面网址。小实验：同上。结果：通过（服务器 0 次请求）。`blob:` 留给文件查看页的 PDF。
- 前提：开关不改系统提示词，写法放在每次运行的上下文里，前缀缓存不受影响。结果：按此实现。
- 前提：真模型会写、写出来能用。小实验：`tmp/genui/run.mts`（本机，不进仓库），gpt-6-luna，3 道要动手试的题（房贷三个条件、8 款笔记本筛选、月预算比例）+ 比价卡片题 + 一句话题，各 3 次；写出的小程序再用 `scripts/acceptance/real-path/mini-apps-live.mts` 逐个放进真沙箱。结果：通过。要动手试的 9 次全写了小程序、都用了 bys.save、没有一个引用外部资源；卡片题和一句话题 0 次误写（1 次网络失败不计）；9 个小程序在沙箱里 0 个报错、0 个空白，高度 383–720px。

## 边界与不做

- 第一版不读实时网页：数据由助手写进程序。
- 报错不自动发给助手：要用户点「让助手修好」。原来承诺“自动修一次”，改成一键，因为自动发会在用户没看时多花一轮、还可能和正在做的事撞上。
- 小程序不能直接操作网页、不能直接发消息。
