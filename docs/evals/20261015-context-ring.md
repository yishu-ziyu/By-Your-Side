# 任务: 用户看得到这段对话占了模型多少上下文，快装不下前心里有数

## 规则
- R1 悬停或用键盘聚焦输入框旁的模型按钮，出一张卡片：「这段对话占了 N%（约 X 万 / Y 万字）」、一条进度条，和一句装不下时会怎样；Esc 收起。读屏名字里也带这句。
  - 例子(正)：脚本模型报这次请求 25600 token（其中 20000 命中缓存），窗口 12.8 万；悬停写「这段对话占了 20%（约 2.6 万 / 12.8 万字）」，卡片不出侧栏右边 — 谁检查：`npx tsx scripts/acceptance/real-path/context-ring.mts --headless`
  - 例子(反)：只算没命中缓存的那部分，写成 4%；悬停同时还冒出系统提示框；Tab 到按钮上不出卡片，Esc 收不起 — 谁检查：同上
- R2 占到一半或更多，模型名旁出一个小环，画的比例就是占用；不到一半不画。窄侧栏只剩图标时，有环就由环代替模型图标（两个圆并排分不清），没环还是模型图标。
  - 例子(正)：70% 时环画七成；20% 时没有环；360 宽环和名字都在；300 宽 70% 只剩环，40% 只剩模型图标 — 谁检查：同上
  - 例子(反)：20% 也画环；窄侧栏把环收掉，或环和模型图标挨着 — 谁检查：同上
- R3 关掉侧栏再开、切回这段对话，显示的是这段对话最后一次请求的占用；用户换了模型就不显示，下一次回答后按新的读数显示；新对话从没有读数开始。
  - 例子(正)：70% 后重开侧栏仍是 70%；换成 step-5-preview 后没有环、没有卡片；换回来答一句后写 40%；点新对话后没有环、悬停只出「模型：demo-model」 — 谁检查：同上
  - 例子(反)：重开后读数没了；换了模型还挂着旧模型的 70%；新对话还显示上一段的 70% — 谁检查：同上

## 技术前提
- 前提：「占用」= 最近一次请求的提示词（input + cacheRead + cacheWrite），各服务商适配层里 input 都不含缓存命中。小实验：本机诊断记录里 Kimi（kimi-for-coding 22 轮中 20 轮）、StepFun、MiniMax、gpt-6.1-sol 的 cacheRead 都有非零值。结果：通过；gpt-6-luna 的记录早于记用量，没有数据。
- 前提：读数带着发请求时选着的模型，只在开关上还是这个模型时显示，所以换模型后重开侧栏也不会回放出旧读数。验收里换去的阶跃星辰用的是假 key、不发请求（没有网），「新模型回答后再出」用换回脚本模型后的回答验。
- 前提：单位写「约 N 万字」而不写 token：用户不认识 token，token 和字不是一比一，所以加「约」，准的是百分比。

## 边界与不做
- 不改超窗口时的处理：宿主平时不删历史，只在模型报装不下后把早先的大段读页内容收成一行再问一次；没有可收的或收完还超就报错。卡片照这个说，不写「快满时」。
- 不显示套餐额度（预览里的 B 方案）。
- 不因用量高另外提醒或自动压缩。
