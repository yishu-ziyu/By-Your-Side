## 仍有的问题（产品侧发现，不属于本票修复范围）

1. C03/C04：Agent 优先用 fetch 工具读跨页来源，被私网安全闸门拒绝后未稳定回退到浏览器导航，任务卡死（C01 同条件下一次成功一次失败，行为不稳定）。
2. A02：运行中收到修改后，只执行了被修改字段，声称其余字段「已填入」但实际为空——虚假完成实例，证据在 v2/v3 run.json。
3. A03：交还后 Agent 按原指令重填，覆盖接管期间的人工修改（v2/v4 两次复现）。
4. A04：检查点恢复能触发（有恢复提示 + 页面重读），但续跑 turn 挂起无任何事件直至超时（v2/v4 两次复现，与 P0 恢复未结项同源）。
5. C03：v4 中来源已访问但结论未按修改后预算（青松/海风仍出现为缺失项）；v2/v3 中表现为 fetch 被拒后卡死。两种形态都不合格。
6. 已知评测边界：fixture 在 127.0.0.1，fetch 工具按设计拒绝本地地址；oracle 对自由文本的判定基于关键词/结构规则，reviewer 换材料时可抽查误判。
7. MiniMax 行为波动明显：C01/A02/C04 在不同轮次间结果不一致；单臂重放入口（--case）用于单独复核。
