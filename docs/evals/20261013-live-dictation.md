# 任务: 在输入框里边说边出字，说完自己确认再发

来源：用户 10-13 给的 Pitus 视频（输入框里边说边出字、下面一条随声音走的声波），试过本机样稿后说“对，接进侧栏”。现在的“按住说话”说的时候看不到字，松手就发出去。

## 规则
- R1 点输入框里的话筒：输入框换成实时文字，工具栏换成一行声波、计时、×、✓。字先浅灰（还在猜），定下后深灰。
  - 例子(正)：说“帮我把报名表填好，姓名写张三”，0.8 秒内出现“帮我…”，说完整句都在 — 谁检查：`scripts/acceptance/real-path/live-dictation.mts`（脚本识别）
  - 例子(反)：说完才一次性出字，或说的时候没有声波 — 谁检查：同上
- R2 点 ✓ 或按回车：字留在输入框，不发出去；点 × 或按 Esc：输入框回到说之前（原来写好的字还在）。
  - 例子(正)：输入框原有“前面写好的”，说完按 Esc，只剩“前面写好的” — 谁检查：同上
  - 例子(反)：按回车直接把话发给助手 — 谁检查：同上（模型请求数为 0）
- R3 Chrome 自带识别连不上服务时，改用阶跃听写，提示“改用阶跃 · 说完出字”；两种都用不了时说明原因。
  - 例子(正)：识别报 network，声波一行出现“改用阶跃” — 谁检查：同上
- R4 话筒是说话输入，声波图标是语音对话（ChatGPT 输入框的分法）。

## 技术前提
- 前提：Chrome 自带识别在扩展侧栏里能用。小实验（10-13，Chrome for Testing 侧栏）：开口约 1 秒出第一个字，之后每 0.03–0.4 秒更新。
- 前提：自动用例不能喂声音给它。小实验同一次：它不读假麦克风，直接听这台电脑的真麦克风（录到了房间里的说话）。所以用例换成脚本识别，真识别由人在日常 Chrome 里试；用例和小实验都不再开真麦克风。

## 边界与不做
- 声音由 Chrome 送到谷歌识别，免费、没有用量承诺；国内连不上时走阶跃。
- 阶跃那条路说完才出字（它的听写只在提交后给全文）。
- 不改“按住右 ⌥ 说话”和语音对话。

## 结果
- 还没做：日常 Chrome 里真识别、真麦克风的手感。
