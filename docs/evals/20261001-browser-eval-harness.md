## 事实、判断与限制

- 事实：每题上限 240 秒，从面板按下回车开始计时。成本按 OpenCode Go 单价，由伴随进程轨迹里的 token 数计算。
- 限制：成本只统计轨迹里记录到的调用，轨迹外的直接调用没算进去；轨迹自带的 cost 字段恒为 0。
- 限制：所有调用都在非高峰时段，DeepSeek 高峰翻倍价没有测到。
- 限制：关思考只跑了 58 题（BYS-001–057 加 BYS-128），图 1 里它和其他行不是同一批题。
- 过程问题：
  - 删除类确认曾让 harness 崩溃（BYS-065/069/131），修复后已重跑。
  - 服务器被其他任务压满（负载 60–77）时，关思考轮出现 4 个建环境失败，并出现 1 次未捕获的 ECONNRESET 导致整轮中断。修复后整轮 58 题重跑。
  - 当时受高负载影响的结果已隔离，不计入统计。
- 判断：通过率最高的是 v4.1-flash。v4-flash 最快，但每次通过成本最高；MiMo 最便宜，但慢且超时多。关思考能明显减少超时，但没有提高通过率。这些结论只基于一轮运行，而且判分未经人工复核。
