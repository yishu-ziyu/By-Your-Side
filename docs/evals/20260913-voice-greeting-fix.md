# 任务：一句招呼只得到一次完整、有声音的回应

## 完成标准

- [x] 普通闲聊由一条回答路径交付，不提前生成另一份招呼，不补“任务已收到” — 检查者：生产路由组合测试。
- [x] 问候、普通知识问题仍经过 Pi；读页与网页任务继续具有工具能力 — 检查者：组合测试、真实模型与隔离浏览器。
- [x] 文字/音频的两种到达顺序都保留合法音频，拒绝的内容仍不播 — 检查者：语音事件顺序测试。
- [x] 回答早于/晚于路由返回都只播一次；中途打断不复活旧声音；明确控制仍有确认 — 检查者：组合测试。
- [x] 合成语音经真实 ASR、分类、Pi、TTS 与生产 VoicePlayer，问候仅一段回答且音频可播放 — 检查者：隔离 Chrome 自动验收；不冒充真人麦克风。
- [x] 用户日常扩展已加载修改 — 检查者：重载结果与当前运行状态。
- [ ] 真人说“晚上好”并听到唯一的完整招呼 — 检查者：用户。

## 决定

保留现有 Pi 能力。由主 Agent 负责的回答，语音层等待并播放正式交付，不抢先另答；只有没有正式回答来源时才由实时语音回答。单步派发如实登记步骤。音频准许播报与是否已收到音频分开记录。问候不会因旁边存在页面资料而转为页面介绍。

## 原因与边界

见[诊断](20260913-voice-greeting-diagnosis.md)。本轮只修回答归属、音频时序与相应提示；保留 Stagehand、阅读外观与其它并发改动。后台监控保持暂停。

## 最终行为

- 主 Agent 负责的内容输入只播放正式答案；它额外发出的 ack 也被跳过。路由失败仍播出失败说明，长时间没有答案保留原来的 30 秒期限。
- 实时语音侧分开记录允许播报与已收音频；文字先到也保留后续音频，固定回执仍要求核对文本。
- 闲聊不自动读整页。原文、页面位置、选区、附件与工具能力保留；需要页面资料时仍能读取。明确页面问题、实际任务保留预观察。
- 新指令替换旧回答；空白/噪音候选恢复原答案，恢复过程中不再次派发、不再生成一个开场。覆盖了答案在空白识别前后到达、路由在空白之后完成三种顺序。

尝试“先问页面，再打招呼”时，第一步出现模型生成的 browser_run API 调用错误，随后工具调用与 CDP 超时；问候阶段未执行，不能算该阶段失败或通过。保留 out/acceptance/voice-greeting-live-2026-09-13T13-16-58-283Z。此处不修改浏览器工具来扩大本次语音修复范围。

后续将“已有页面资料后回到闲聊”独立检查：用固定页面的真实文字作为前一轮语音输入，真实模型回答后再打招呼。它检查话题转换，不替代自然页面读取能力；自然读页已有四项模式记录，也保留上述失败。


该连续对话样本实际返回“晚上好。还看那个招聘页面，还是有别的要办？”，一个音频回答，未重讲地点或经验要求；输出音频的独立 ASR 也确认了这句话。最初关键词检查把“招聘”一词直接判错，超出了“不主动介绍页面”的要求。主代理修正检查口径：允许简短承接用户刚聊过的话题，仍禁止重复回答、任务确认与主动补充页面事实。原自动失败保留，[判读与原始来源](20260913-voice-greeting-fix-evidence/history-adjudication.json)记录修订依据；自然程度仍由用户听感验收。[实际合成回应音频](20260913-voice-greeting-fix-evidence/greeting-after-page.wav)。该样本源码校验值与最终代码一致。
