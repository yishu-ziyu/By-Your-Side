# 任务: 用户说「切到某页」时，助手能把那一页放到用户眼前

10-11 用户要求做「切到某页」。方向是 10-10 用户定的：不再给[不抢前台](20261010-keep-foreground.md)逐个加例外，而是给助手一个通用的「给用户看这一页」能力，由助手按用户的话判断什么时候用（[续接要点](../NOTES.md)「修问题的方式」）。

为什么：10-10 和 10-11 两次同模型对比实验里，「切到youtube」是两组唯一都失败的任务（各 0/2）。助手只有「换工作页」，没有能让用户看到某一页的工具，所以切不过去。

## 规则

- R1 切页工具多一个动作「给用户看」（tabs show）：把这一页设为工作页，并切到它所在窗口的前台。工具结果读回这一页是不是用户眼前的页。只在用户要看、要去某一页时用；平时的 switch 照旧不碰用户眼前的页。
  - 例子(正)：用户在「我的页面」，说「给我看表单页」，助手用 tabs show。工具结果回到模型时，表单页是活动标签页，结果写明用户已在这一页 — 谁检查：`npx tsx scripts/acceptance/real-path/keep-foreground.mts --headless` f
  - 例子(反)：show 只换工作页不切前台，f 失败 — 谁检查：同一命令，故意弄坏一次
  - 例子(正)：真实模型下，用户在抖音页说「切到youtube」，用户眼前变成 YouTube 页 — 谁检查：`everyday-baseline.mts --headless --suite=compare --deep --model=openai-codex/gpt-6.1-sol --repeat=2 --only=switch-tab`
- R2 「不抢前台」的其余规矩不变：普通动作和 switch 不换用户眼前的页，任何时候都不聚焦窗口。
  - 例子(正)：keep-foreground 的 a–e 照旧通过 — 谁检查：同上

## 技术前提

- 前提：把工作页切到窗口前台的做法已有（交给用户、发送确认、付款停下都用它），直接复用（`extension/src/background/foreground.ts`）。不需要小实验。

## 边界与不做

- 不聚焦窗口：页在别的窗口、或窗口没有聚焦时，只换工作页，工具结果读回会写明用户可能没在看这一页。这沿用 09-04「不拽走 Space」。
- 「切到某页」在别的窗口时要不要把窗口拉到前面，没有定；需要时再由用户决定。

## 结果（10-11）

- R1：keep-foreground 的 f 通过；让 show 不切前台再跑，f 失败。真实模型（gpt-6.1-sol，high）跑「切到youtube」2/2：两次都是先列出标签页，再 tabs show，一步切过去。10-10、10-11 两次对比实验里这一条都是 0/2。
- R2：keep-foreground 的 a–e 照旧通过。
- 作废的一轮：第一次真实模型运行是 1/2。原因是我在它构建扩展的同时，在同一个 worktree 里为「故意弄坏」改了 show 的代码，这一轮装进去的是弄坏的版本（模型调了 show，读回却没切过去）。不在同一个 worktree 里同时跑用例和改代码。
