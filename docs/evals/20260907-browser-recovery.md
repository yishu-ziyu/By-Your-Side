# 任务: 浏览器定位失败后能恢复打开项目编辑器，并留下可复盘的执行记录

起草日期：2026-09-07。
校验角色：独立校验代理 recovery_evaluator。实现角色不得自行修改或降低以下完成标准；范围变化由编排或用户裁决。

## 完成标准

- [ ] 1. 不支持的定位串（包含本次失败的 `loc=h3:has-text("项目经历")`）返回模型可读的明确错误，并说明本工具支持的定位形式及可执行的下一步。不得把没有执行的点击报告成功。覆盖普通有效 CSS 和 `@N` 引用不回归。 — 谁检查: 机器，`npm test -- extension/test/target.test.ts extension/test/click-robustness.test.ts`，并运行实现新增的定位恢复测试，交付记录准确命令。
- [ ] 2. 引用失效后，反馈要求重新获取当前页面目标；模型可用新快照中的有效引用继续操作。不得自动把旧引用指向其他节点，或在目标不明确时猜测点击。 — 谁检查: 机器，针对真实恢复入口的回归测试；浏览器实测见第 5 条。
- [ ] 3. 同一任务的工具调用能按稳定任务/会话标识和调用标识串联。记录工具名称、参数、开始时间、结束时间或耗时、成功/失败及实际返回结果/错误；记录的 JS 返回文本足以判断它发现了什么。截断必须显式标记，不能把截断后的摘要伪装成完整返回。截图只需类型/大小或受控工件引用，不把 base64 大图写进文本日志。凭据、密码、令牌不进入诊断日志。日志写入故障不能改变原工具结果或中断用户任务。 — 谁检查: 机器，新增轨迹测试覆盖成功、失败、脱敏、截断和写入故障；第 5 条产出的真实日志可关联页面现象。
- [ ] 4. 不以固定工具次数、固定错误次数或固定时长强制宣告任务失败。已有安全确认、暂停、接管/交还能力不因恢复改动失效。点击派发成功的工具结果不能被描述成已打开编辑器或已完成任务。 — 谁检查: 机器，`npm test -- agent/test/safety-prompt.test.ts agent/test/session-helpers.test.ts extension/test/control-gate.test.ts extension/test/held-clicks.test.ts`，并由编排检查实际改动和第 5 条行为。
- [ ] 5. 在真实浏览器、真实扩展工具链、真实模型中复现三个可控场景：不支持的选择器、页面节点替换导致旧引用失效、点击可派发但页面不变。前两种收到失败反馈后，模型继续通过可用定位实际打开项目编辑器；第三种不虚报成功，并继续检查页面或明确报告未打开。成功依据为编辑器/目标可编辑字段在页面出现及对应截图/快照，不能仅凭工具 `ok`、脚本预设成功文本或模拟模型判定。可使用本地无账号夹具，通过独立工具操作制造错误，再将真实返回交给模型；需明确记录这种设置。 — 谁检查: 机器操作真实浏览器，编排检查工件。交付记录具体运行命令或 UI 操作、模型、起点、截图路径、日志任务标识、总耗时、工具次数、人工介入次数。现有 `npm run accept:browser` 可作基础烟测，但不能代替恢复场景。
- [ ] 6. 在用户原 BOSS 项目经历路径验证：从当前真实页面出发，由产品 Agent 找到项目经历并实际打开对应编辑器。只读定位与打开编辑器，不填写、不保存、不提交用户简历。记录起始页面、模型、实际是否打开、耗时与介入次数。若账号、页面、浏览器接入等条件不足，明确标为未验证并记录阻碍；本地夹具通过不得宣称原任务已修复。 — 谁检查: 机器操作真实产品，编排核对截图/快照与日志；用户裁决实际体验是否可接受。
- [ ] 7. 对 ego lite 至少记录一处已检查的实际工具契约或执行方法，说明本次恢复机制与其关系。用户给出的“成功率较高”作为待解释现象，不据此宣称已完成同任务成功率对照，也不能用缩短输出或提前放弃替代成功率改善。 — 谁检查: 编排，检查来源与实现说明。
- [ ] 8. `npm run typecheck`、`npm test`、`npm run build` 全部通过。聚焦检查先跑，相关检查通过后再跑上述完整命令一次；新失败或新改动才追加必要检查。若遇基线问题，记录具体失败并由编排裁决，不悄悄改断言。 — 谁检查: 机器。
- [ ] 9. 新增 `hover` 的模型工具说明、共享协议、工具转发、扩展分派与实际执行链一致。工具接受支持的目标定位形式，真实移动浏览器鼠标到目标，触发页面原生 hover 状态；不能只用 JS 派发合成事件伪装真实悬停。失效引用、目标不存在和错误选择器返回明确失败，不能报告已悬停。 — 谁检查: 机器，新增 hover 协议与执行测试，并运行 `npm test -- agent/test/protocol.test.ts`；第 10 条验证真实页面行为。
- [ ] 10. 本地夹具默认隐藏项目编辑入口，仅真实悬停项目区域才显示；由产品 Agent 实际完成 hover 显示入口、click 打开编辑器、fill 填入测试草稿。截图/快照确认编辑器及草稿文本出现，提交动作未发生。单纯 mock hover、直接 JS 修改显示状态、直接调用页面函数或绕过隐藏入口，均不算本条通过。 — 谁检查: 机器操作真实浏览器、真实扩展、真实模型；编排检查工具轨迹和可见页面结果。记录命令/操作、模型、耗时、介入次数及工件路径。
- [ ] 11. 在本地夹具沿用已有接管/交还能力：Agent 已持有原始填写目标和草稿时，人接管打开编辑器，交还后 Agent 在同一任务继续填入该草稿，用户无需重新描述原目标。测试不提交草稿，不新增接管 UI。此项计为一次人工介入后的继续成功，不计入第 10 条自主成功。 — 谁检查: 机器操作现有 UI 并核对实际文本与任务日志；用户裁决接管后继续的体验。

## 真实场景的判定边界

- 浏览器恢复成功：同一原目标仍保留，经历真实定位错误后打开目标编辑器；不能人工替模型点击编辑按钮后算自主恢复。
- 人协助后的继续可以另记为“人工介入后成功”，必须保留介入次数，不能计为自主成功。
- 第 5 条本地恢复路径通过与第 6 条 BOSS 路径通过分别报告；两者不互相替代。
- 本轮无预设耗时改善百分比。记录完成结果、总耗时、工具次数、介入次数；没有同起点重复对照，不声称总体成功率提升。
- 如果流程只能到请求帮助，报告具体障碍和需要人的动作，不宣称已完成原任务。完整新接管交互不在本轮强制实现范围。

## 边界与不做

- 不保存或提交用户简历，不擅自新增/覆盖真实项目内容。
- 不通过更换模型掩盖工具错误；模型若因可用性变化必须更换，明确记录，不能把不同模型对照归因于代码。
- 不新建固定步数熔断，不做侧栏视觉重设计，不扩展到通用任务规划框架。
- 不为了通过测试弱化断言，不把日志完善等同于任务成功。
- 仅本完成标准文档由校验者写入；实现、验收结果、开发日志与 NOTES 由各负责角色记录到对应项目文件。
