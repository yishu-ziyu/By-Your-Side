# 任务: 主动卡改成「动词即按钮」的一句话，按下后原位接着说（YIS-106）

来由：Hark Pro 发布视频 4:40–5:40（2026-10-06）的主动卡；逐帧笔记在 `references/hark-pro/notes.md`（不入库）。预览 [proactive-card-verb](../previews/proactive-card-verb.html) 用户 10-07 认可，预览即规格。用户决定：卡放在侧栏对话流里；付款、发送这类一按即执行，不加二次确认。

## 规则
- R1 一张卡只有一句话。第一个词是按钮（申请 / 值机 / 付 …），后面是宾语、对象图标和对象名，金额和日期都在句子里；下面一行小字写出处（哪一页、多久前）。没有标题、正文、独立文字的按钮。
  - 例子(正)：看过水费短信后，侧栏出「付 | ¥31.97 水费 ◎ 北京自来水 / 来自：缴费通知 短信 · 今天」 — 谁检查：人对照预览
  - 例子(反)：出「可以帮你缴水费」+「去缴费」黑按钮 — 不合格 — 谁检查：人
- R2 点第一个词就执行，不弹卡、不再问。卡片文字淡出、壳留在原位长高，再长出助手的三句话：在做什么 / 一个具体细节证明理解了 / 接下来或兜底；付款类写明用了哪张存的凭据。下面带一个步骤 chip：动作名、耗时、进行中 / 完成。
  - 例子(正)：点「申请」后同一位置出现「正在给全季酒店前台发邮件…」「你明天 10:40 的会在国贸三期…」「他们不同意我会再争取一次…」和「发邮件 · 全季酒店前台 2.4s 完成」 — 谁检查：真侧栏录屏，人看
  - 例子(反)：按下后卡片消失，结果出现在别处或要用户去找 — 不合格 — 谁检查：人
- R3 两个退路：点句子其余部分，这件事进输入框当草稿，发不发由用户定；悬停出 ×，点了这张卡收起。不承诺「以后不再出同类」。
  - 例子(正)：点「晚退房到 14:00」，输入框出现「关于「申请晚退房到 14:00」：」 — 谁检查：真侧栏，人
- R4 失败与被拒要有结果态：对方拒绝、网站打不开、凭据失效时，同一位置换成一句说明和下一步，chip 变失败；不能停在「进行中」。视频没展示这条，按我们的[人机协作约定](../human-ai-contract.md)补上。
  - 例子(正)：酒店回绝晚退房，原位出「酒店没同意晚退房，最晚 12:00。要我找附近寄存吗」 — 谁检查：模拟拒绝回复，人看

## 实测（2026-10-07，无头 Chrome、只装扩展、脚本模型）

`npx tsx scripts/acceptance/real-path/proactive-card.mts --headless`：8 项全过；录像与截图在 `out/acceptance/proactive-card/`。`scripts/probes/shell/draft-only.mts` 改成先关侧栏，页角卡路径照旧全过。

- R1 通过：卡出在侧栏对话流最新处，页角不出卡；「申请」是按钮，句子带站点图标和对象名，出处一行写「来自：订单确认邮件 · 正在看」。
- R2 通过：按下后卡淡成壳，原位换成这一轮的开头（动词实心），位置不动；下面步骤从「正在打开标签页」到完成，再接三句话。会话标题是卡上那句话，不是给助手的长指令。重开侧栏回放，两轮仍画成卡。
- R3 通过：点句子，输入框出现「关于「申请晚退房到 14:00」：」，不发出；悬停出 ×，点了收起，后台记下这一页本次不再建议。
- R4 通过：步骤失败、回答说酒店没同意时，标题写「做了 1 件事，有一件没成功」，失败步骤标红，回答原位说清原因和下一步。

与预览不同之处：
- 按下后卡没有整张消失，而是缩成这一轮的开头。这样回看记录时知道这段回答在回应哪件事。
- 三句话在步骤下面，不在上面。三句话是助手做完后的真实回答，不能在做之前替它写出来。
- 对象图标用出处页的站点图标；预览里是彩色字母圆点。

没验证：
- 真实模型能不能按新提示拆出「动词 + 宾语 + 对象名」：只用脚本模型跑过。
- 「助手没连上，再按一次」这条路没跑。
- 日常 Chrome 里的手感由人看。
