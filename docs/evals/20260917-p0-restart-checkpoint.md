# 任务：重启后的长任务保留检查点，并可安全继续

## 完成标准

- [x] 运行中或暂停中的任务恢复后明确为 `interrupted`，不冒充空闲、完成或仍在运行；原 goal、runId、补充要求和结果账本保留。— 谁检查：单元测试、持久化测试
- [x] 重启前已确认结果仍为已确认；在途写入恢复为 unknown，后续不会自动重做。— 谁检查：结果账本回归
- [x] 状态查询说明任务因重启中断，并给出“继续原任务”这一真实入口；不宣称自动恢复。— 谁检查：状态文案测试
- [x] 用户明确继续时保持原 runId，先取得当前页新快照，再启动模型；快照失败则保持中断且不启动。— 谁检查：会话与调度测试
- [x] 普通新任务仍可替换旧检查点；已正常结束的 idle 任务不会被误标为中断。— 谁检查：回归测试
- [x] 类型、相关单测、构建、模块边界和差异检查通过。— 谁检查：主代理

## 边界与不做

- 不在宿主重启后自动发送模型请求、自动点击或自动重放任何外部动作。
- 本轮只提供明确文字/语音“继续原任务”的入口，不新增独立恢复面板；现有会话列表只增加“已中断 / 已中断，可继续”状态。
- 旧 unknown 写入没有重启前后的可靠页面基线时，继续保持 unknown；不能用重启后的单次读数伪造成功或失败。
- 独立排队任务的跨重启重新编排、页面关闭后的重新定位、跨日恢复和发布门槛属于后续 P0 里程碑。
- 保留当前工作树中的翻译可靠性改动；不重载日常扩展，不提交或发布。

## 实现依据

现有 `TaskProgressSnapshot`、`TaskResultBook` 和 Pi session 自定义条目已经持久化目标、runId、用户补充和结果账本。缺口是恢复时把原 `running/paused` 压成普通 idle，用户无法分辨“已经结束”和“因进程重启停住”。本轮复用现有存储，不新增第二份任务数据库。

安全续接沿原任务身份执行：先用只读 `snapshot` 读取用户当前页并记录真实观察，再将原目标和检查点交给同一会话。已满足项仍由结果账本挡住重复执行，unknown 写入继续阻止后续写入，直到有充分证据或用户作出决定。

## 验证记录

- 新增 `interrupted` 与 `restartRecovery`：恢复出的活动 run 保留原 goal、runId、最近用户补充、正式交付和结果账本；进入续接后仍沿原 runId。正常结束的 idle run 不被误标，新任务会生成新 run 并清空旧结果。
- 恢复时丢弃重启前的 `lastReadAt`。用户明确说“继续原任务”后，运行时先对当前标签页执行一次只读 `snapshot`；读页失败、空内容、检查点已取消或模型尚未真正启动前失败，检查点仍可重试。重复继续和恢复期间的新任务由同会话围栏拒绝，不会并发启动两条 run。
- 新页面文本在写入事件、结果观察和模型提示前统一做凭据脱敏；结果账本作为不可信数据包裹。持久化的直接用户补充则作为可信修订重新送入，覆盖“暂停后补充尚未被模型消费就重启”的路径。
- `restartRecovery` 在原 run 续接期间持续生效：即使恢复后已经重新读页，重启前有成功回执且目标身份可识别的同目标写入仍不能重做；unknown 写入继续挡住所有后续写入。其他已确认项不会自动重放，并在续接提示中明确要求跳过。普通新任务才释放这层恢复锁；对无目标或语义等价动作的统一程序判定留给 P0.3。
- 文字入口只接受一组窄而明确的继续表达；明确语音继续不经过模型分类，直接把用户当前页送入同一恢复入口。语音终止中断检查点仍保留原有读回确认。会话摘要通过可选 checkpoint 字段显示“已中断”，不会误判为“空闲”或后台任务“已结束”。
- P0 定点 **11/11** 通过；全仓普通测试 **1858/1858** 通过。一次全仓串行后的规模阶段受环境拖慢，其中一项触发既有 5 秒超时；随后两次单独复跑规模测试均为 **2/2**（约 7.5–8.0 秒总耗时），保留该波动而不把首次失败删除。TypeScript、扩展构建、184 个生产文件模块边界与 `git diff --check` 通过。
- 本轮没有重载用户日常扩展，没有真实杀掉 native host 后操作网页，也没有提交或发布。当前证据覆盖真实 Pi 会话文件、生产会话/调度逻辑、协议、侧栏状态文案和工具闸门；页面关闭后的重新定位、跨日恢复、排队任务复原和更完整的恢复详情仍属于 P0.3–P0.5。
