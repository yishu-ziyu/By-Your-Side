# 任务: 侧栏顶部只留一行会话导航，任务状态挪到输入框上方

来源：用户 2026-09-27 截图反馈「上半部分布局烂到爆」。当时对话开始前的头部占了约半屏：品牌出现两次（Chrome 标题栏一次，我们自己一次），会话名「点击登录 ▾」像一个要点的按钮，「帮我操作」单独占一行，任务卡把同一句话、「正在执行」和网站名 substack 各说了一遍。用户看过效果图 A、B、C 后，在 C（顶部管「在哪」，输入框上方管「在做什么」）的基础上问「能不能和 Chrome 标题栏合成一条」。结论是合不了：Chrome 侧栏 API 没有改标题栏的接口。所以改为底色接住标题栏，让两行看起来像一块。

设计依据来自 Will's S Design Note：
- 指引与反馈：状态要清楚、即时；
- 渐进式揭示：细节收起，但影响判断的范围不能藏；
- Apple 工具栏：导航和当前任务的操作分开放；
- Refactoring UI：元素有主次之分。

- [x] 3. 连接正常时顶部不显示连接状态；真实断开时出现，重连后消失 — 谁检查: `sidebar-header.mts`（停掉 service worker 记录状态变化）
- [x] 4. 「帮我操作 / 指导我操作」在输入框里 — 谁检查: `sidebar-header.mts`
- [x] 5. 任务进行中，任务条在输入框正上方收成一行，只写状态；任务页就是当前页时，网站名全侧栏只出现一次（在输入框的当前页标签里）。点开后能看到目标和带上的材料，网站只列一次 — 谁检查: `sidebar-header.mts`
- [x] 6. 小伙伴 M 不挡任务条和其他按钮 — 谁检查: `sidebar-header.mts`
- [x] 7. 原有任务条行为不变（发送中、可移除的草稿材料、控制失败重试、页面不一致提示照常显示）— 谁检查: `npx vitest run extension/test`
- [ ] 8. 用户看截图、装进日常扩展后认可 — 谁检查: 人

## 边界与不做

- 不改 Chrome 标题栏（没有接口），也不改变任务条的数据和状态机，只改摆放与收起方式。
- 深色模式的标题栏颜色按 `#1f1f1f` 估计，没有在真实深色 Chrome 里核对。装了彩色主题时，交界处会有色差。
- 会话被自动起名为「点击登录」的原因不在本次范围，另查。

## 证据（2026-09-27）

- `npx tsx scripts/acceptance/real-path/sidebar-header.mts --headless`：11/11 通过。
  - 隔离的无头 Chrome，只装扩展，模型是本机脚本模型，通过设置页「自定义地址」配置。
  - 截图和读数在 `out/acceptance/sidebar-header/`。`with-chrome-*.png` 是把用户截图里的 Chrome 标题栏拼在上面的效果，扩展截不到 Chrome 自己画的部分。
- 断线的真实记录：停掉 service worker 后，顶部显示「连接中…」，7 ms 后恢复为已连接。时间太短截不到图，所以另截了一张把状态停在「重连中」的样式预览（`5-disconnected-style-preview.png`），这张不作为连接判据。
- 改的过程中实测发现两个问题，已修：
  1. 小伙伴 M 盖住了任务条的展开键。原因是聚焦输入框时「趴」的动画还在跑，把 `resetToComposer` 的新位置覆盖了；现在复位时先作废旧动画。另外把任务条加进了 M 让位的卡片列表。
  2. lucide 图标不带 `.lucide` 类，所以样式表里针对 `.lucide` 的尺寸规则从来没生效，会话名和模型旁的箭头一直按默认 24px 显示。本次只修了这两处的尺寸。
- `npx vitest run extension/test`：105 个文件，985 项通过。
