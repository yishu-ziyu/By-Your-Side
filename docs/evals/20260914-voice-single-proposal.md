# 任务：一句话只经一次主 Agent 推理就得到回答

用户可观察的结果：说"嗨，晚上好"，首声从约 6.9 秒降到约 4 秒；且无论内部算了几份候选，只有一份能获得交付权，被丢弃的候选不产生任何用户可见输出或副作用。

起点：外部独立复核（基于提交 `90d796a`）指出——"必须有判定"是产品约束，"判定必须由前置独立分类器完成"只是当前实现选择。它给出的首选是：把判定并入主 Agent 的第一次推理，一次输出"意图计划 + 回答或首个工具意图"，执行权限仍由程序掌握。本文件是该复核落地前的冻结标准。

主代理已核对复核提出的两处代码事实，**均属实**：

- `session.ts:506` `sendUserMessage()` 在发模型请求前就改状态：`activeGoal`、`rpc.setPageTarget()`（换任务缺省页面）、`runTrace.begin()`；会话在跑时自动转成 steer。它不是"纯开始算答案"。
- `session.ts:1010` 在 `toolcall_delta` 阶段从**尚未执行**的 `send_user_message` 参数取正文，发 `user_delivery_stream`。交付流能在工具执行前漏出去。

## 必须过的反例（来自复核第 3 节）

| 情境 | 必须观察到的结果 |
|---|---|
| 校验很慢、模型很快，已产生完整回答甚至工具参数前缀 | 批准前没有正式文字、音频、工具执行、任务状态污染 |
| 生成中说"停"，随后注入旧 token、旧交付、旧 `agent_end`、重连事件 | 旧声音不恢复，旧候选不复活，不补说第二份回答 |
| 原任务执行中问进度或闲聊 | 原任务不被隐式 steer，不换工作页面，不被推测分支取消 |
| 页面导航／任务替换／控制版本变化后，旧提案才返回 | 旧提案不能对新任务或新页面执行；需要时重新读取，不用旧事实 |
| 只有页面标题没有正文；读页失败；操作回执 unknown | 不编正文、不宣称已看到或已完成、不自动重做未知写入 |
| 否定、引用、复合控制、重复 ASR 终稿 | "不要停""把'暂停任务'读一遍"不误停任务；复合动作保序；同一语音输入不重复执行 |

代码层不变量（进测试）：

```text
同一语义轮次，正式回答提交次数 ≤ 1
被丢弃的候选，产品可见输出与业务副作用 = 0
每次实际工具执行，身份、权限、执行版本仍有效
```

约束按**语义轮次**而不是 `runId` 或工具调用 ID 约束。已有空白输入恢复逻辑（空白候选恢复上一句）不得兑换成第二份回答。

## 实现范围

1. `agent/src/session.ts`：新增**无副作用**的提案入口（暂名 `prepareVoiceTurn`）。用当前主 Agent 上下文跑一次模型请求，要求只产出提案；期间不改 `activeGoal`、不调 `setPageTarget`、不 `runTrace.begin`、不派发浏览器 RPC、不发布任何交付。
2. 提案结构（放 `shared/` 或 `voice-intent.ts`）：`plan.steps[]` 沿用现有动作域；`next` 为互斥分支 `reply | tool_intent | control`。
3. `conversation-manager.ts`：`routeVoiceInput` 拆成 **准备 → 校验 → 提交** 三段。校验不通过或超时返回确定的失败回执，**不自动放行**。
4. 提交分支：`reply` 走现有正式交付通道；`tool_intent` 用现有工具链执行首个工具并把真实结果接回同一轮（不要批准后再把原话从头规划一遍）；`control` 走现有控制链。
5. 轮次协议：`PREPARING → COMMITTED → COMPLETED`，另有 `DISCARDED` / `INTERRUPTED` 两个终态。`PREPARING` 阶段的输出（含 `user_delivery_stream` 前缀）进缓冲区，只有 `COMMITTED` 之后才对外发。取消顺序：先失效凭证 → 被扣住的调用以取消结束 → 请求取消模型/TTS → 清空播放器待播。
6. 第二版才允许流式解析未完成 JSON。第一版等完整短提案通过校验再开放正文。

## 目标修订（已确认）

原目标"首声 ≤2 秒"在当前链路上不可达：识别收尾 0.7s + 一次模型往返 1.4s（`classifier-floor.json` 里最快的一次极小请求）+ 合成首帧 0.68s ≈ **2.8 秒地板**。

修订为：一句问候首声 **≤4.0 秒**，且不再随分类耗时波动。**用户 2026-09-14 同意此修订。** 账面上"拿掉分类往返"是 6.825 − 2.676 = 4.149 秒，合并后的请求负载与生成方式都会变，**必须重测，不能按账面宣布达成**。≤2 秒需要动识别或合成两端，另议。

## 边界与不做

- 不换 Step ASR/TTS，不换现有模型生态。
- 本轮**不做推测式并行**。复核结论：并行只接受"隔离候选"版本，作为合并路线之外的过渡；不接受把原话提前送进 `sendUserMessage` 再拦工具与声音。
- 裸"停"的语义不变（先停声音，再澄清任务范围）。若要让裸"停"同时冻结任务，那是产品语义变更，不在本轮引入。
- 分类超时不得自动放行。
- 已发出的网页写操作不能靠 `abort()` 假装回滚；结果未知走原有未知结果处理。
