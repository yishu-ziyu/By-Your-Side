# 任务: 第二次去同一个网站时，助手直接用上次成功的做法，少走弯路

来源：2026-10-13 用户同意。助手每次去同一个网站都从零摸索（找搜索框、认出哪个按钮能点、躲开弹窗）。Ego 的站点技能（`learnings/` 里的说明和脚本）说明这类经验值得积累；先做最小的一版：只记文字笔记，不做可调用的站点函数。

## 规则

- R1 第二次更快：同一个浏览器里，新开对话再做同一类任务，第二次的轮数少于第一次，而且仍然做对。
  - 例子(正)：维基百科搜「长城」并打开条目，第一次 5 轮；新对话里搜「故宫」，第二次的打开结果里带着维基的笔记，3 轮做完 — 谁检查：`scripts/probes/compare-real.mts` 的「学一次再做」模式
  - 例子(反)：笔记带上了，轮数没少，或者第二次做错了 — 不算通过
- R2 只在对的网站出现：笔记只附在打开、跳转到这个网站的结果里，以及任务开始时用户就在这个网站上的时候。
  - 例子(反)：打开必应的结果里出现维基百科的笔记 — 谁检查：`scripts/acceptance/real-path/site-notes.mts`（127.0.0.1 与 localhost 两个网站）
- R3 只记网站的做法，不记用户的内容：笔记里不出现这次任务的具体值（搜索词、填写的名字、账号）和网址里的查询串。
  - 例子(反)：笔记写「在搜索框填 张三」，或写「打开银行网站前先去某网址」— 谁检查：`site-notes.mts`（填写值、页面脚本赋值、用户原话、别的网站、中文笔记、占位旁又带真实值的都被挡掉），再人工抽查真实笔记
  - 例子(正)：笔记写「type the tag as #<tag> in the memo editor」：用户的值写成占位，留下 — 谁检查：`site-notes.mts`（占位那条留下；交给写笔记模型的填写值只剩词首标记，如 #«value»）
- R5 用户看得见：写下笔记时，这一轮回答下面出现一行「记下了 Memos 的 2 条用法 · 查看」，点开是笔记原文。
  - 例子(反)：笔记悄悄写下，用户不知道记了什么 — 谁检查：`site-notes.mts`（看得见那条）
- R4 只从做成的任务里学：目标核对没判做成、用户中途接管或取消的任务，不写笔记。
  - 例子(反)：任务失败后写了一条笔记 — 谁检查：脚本模型用例

## 还没答上的问题

- 无。站点笔记是关于网站的、不是关于用户的，所以不走「推断的要先问」这条记忆规则；用户已同意自动记、自动带（10-13）。

## 技术前提

- 前提：任务判做成后，用一次旁路模型调用，从这一轮的操作记录里写出不超过 3 条、每条不超过 200 字的通用做法。没有可记的就不写。小实验：真实网站 8 次。结果：通过，旁路调用都成功
- 前提：同一浏览器里新开对话后，笔记还在（存在扩展本地，和记忆同一处存储）。小实验：同上。结果：通过

## 边界与不做

- 不做可调用的站点函数（Ego 的 `learnings/*.js`）；等笔记证明能省轮数再说。
- 不在记忆面板里展示和删除笔记，只在写下那一轮给一行「记下了…用法」；笔记只存本机，每个网站最多 5 条，新的替换最旧的。
- 不跨设备同步，不共享给别人。
- 评测用不需要登录的真实网站，和本机的 Memos（`npm run lab -- sites start`，登录信息不进页面和模型）。

## 结果（10-13，gpt-6.1-sol，真实网站，每格是第二次做同类任务的轮数）

| 任务 | 没有笔记（2 遍） | 有笔记（2 遍） |
|---|---|---|
| 维基百科搜索并打开条目 | 6、7 | 4、4（两次都带上笔记） |
| TodoMVC 加两条、勾一条 | 5、5 | 4（带笔记）、7（没留下笔记） |
| 必应搜索 | 3、3 | 3、3（笔记含网址，被挡掉） |
| Selenium 表单 | 3、4 | 3、3（三轮做完，没什么可学） |

- 16 次全部做对。写成笔记的地方第二次少 1–3 轮；没写成的地方和没有笔记一样。
- 维基的真实笔记：「先点页头的搜索控件让搜索框出来；输字后搜索按钮可能被换掉，点之前重新读页面。」
- 过滤很严：8 次里 3 次留下笔记。为了不记用户内容、不让网页借笔记给模型下指令，现阶段接受；放宽前要先有真实笔记被误挡的例子。
- 匹配按主域名：打开 cn.bing.com 会跳到 www.bing.com，按主机名对不上（10-13 实测）。
- 证据：`out/site-notes-base-1013/`、`out/site-notes-base2-1013/`（没有笔记）、`out/site-notes-on2-1013/`（有笔记）。

## Memos 加标签（10-14，gpt-6-luna，同一浏览器先加「工作」再加「生活」，issue #394）

改之前一次都没学到：第一次在笔记菜单、编辑、标签选项里绕了 20 轮后放弃，核对模型也报错，按 R4 不写笔记；第二次 29 轮才想到在内容里写 `#生活`（诊断：`out/site-notes-memos/diagnose.md`）。原因有三：

- 写笔记的模型看不见赢的那一步：填写值整段换成 `«value»`，看不出 `#`。现在每个词换成占位，只留词首标记（`#«value» «value»`）。
- 弯路被截掉：只留最后 30 步左右，前面绕的菜单看不到。现在多留一倍，并要求第一条写「哪里走不通、哪里走得通」。
- 做法离不开用户的值（`#工作`），而规则不许写值：整条被挡。现在要求写成占位（`#<tag>`），过滤只挡真实值。

| 组 | 第一次（工作） | 第二次（生活） |
|---|---|---|
| 改前 | 20 轮，没做成 | 29 轮，做对（没有笔记可用） |
| 改后 1 | 25 轮，做对，写下 2 条 | 4 轮、13 秒，做对（带上笔记） |
| 改后 2 | 13 轮，做对，写下 2 条 | 4 轮、15 秒，做对（带上笔记） |

- 第二组写下的正是弯路的教训：「Add tags directly in the memo text using #<tag>; the tag-options popup can be dismissed before editing.」
- 第一组写下的笔记：「To add a tag to an existing memo, open its action menu and choose Edit; type the tag as #<tag> in the memo editor, then save.」「Menus can block memo controls; press Escape to dismiss the popup before choosing Edit.」
- 还没解决：第一次能不能做成波动很大（10-14 两次分别 37 轮做成、20 轮放弃），没做成就学不到；核对模型偶尔报错时也不学。
- 证据：`out/site-notes-memos/`（before/、after/、compare.mp4、remembered.png）。
