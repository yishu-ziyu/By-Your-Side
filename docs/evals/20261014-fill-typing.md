# 任务: 助手填的字，只认真实键盘的网站也收得到；搜索框能“填完直接回车”

用户 10-14 同意方向。复现：本机练习页上，只认可信 input 事件的搜索框，fill 后按回车，网站收到的搜索词是空的；只按 beforeinput 更新内容的编辑器，fill 后保存，网站收到的正文是空的。同一页上用真实键盘输入（CDP Input.insertText 加带 `\r` 的回车），网站都收到了完整的字，所以毛病在 fill 的写法：原生 setter 加脚本派发的事件不算可信输入，编辑器收不到 beforeinput。

## 规则

- R1 普通文字框（input、textarea）和编辑器（contenteditable）：先清空，再用真实键盘输入写进去；日期、时间、颜色、滑块、下拉框照旧直接设值。写完读回，连续两次读到一样才算数；结果分五级：一字不差、等价（只差空白或大小写）、网站改了格式、接在原内容后面了、没变。后两种先点一下这个框再写一次，还不行就用旧写法再写一次，再不行就如实说“没写进去”，并建议改用键盘逐字输入。
  - 例子(正)：练习页的搜索框、编辑器、仿 React 的受控框，网站收到的都是要填的字 — 谁检查：`scripts/acceptance/real-path/fill-typing.mts`
  - 例子(正)：练习页放在后台标签页、用户看着别的页时照样填得进 — 谁检查：同上
  - 例子(反)：强制只用旧写法时，搜索框和编辑器两项失败 — 谁检查：同上（故意弄坏）
- R2 填写可以带“填完回车”，省一轮来回；只给搜索框和普通单行文字框：type 是 search 或 text、角色是 searchbox 或 combobox，并且这个框所在的表单或附近没有「发送」按钮、框的名字不像消息框（消息、留言、回复、评论、聊天、message、reply、comment、chat）。多行框和编辑器不给：在这两类里回车常常就是“发送”，仍然走按键，现状不变。
  - 例子(正)：搜索框填完回车，网站收到搜索词 — 谁检查：`fill-typing.mts`
  - 例子(反)：在回车即发送的单行聊天框（旁边有「发送」）上要求填完回车：拒绝，什么都不发出去，框里留着字 — 谁检查：`fill-typing.mts`；按「发送」按钮那条路径仍由 `send-confirm.mts` 管
- R3 还原填写照旧：新写法写之前把原值记进还原填写的账本；密码这类栏读回的值不交给模型。
  - 例子(正)：`fill-undo.mts`、`fill-undo-button.mts`、`readback-privacy.mts` 照旧通过

## 技术前提

- 前提：真实键盘输入发到后台标签页也有效。小实验：练习页放后台（visibilityState=hidden、hasFocus=false），先 focus，再 Input.insertText 和带 `\r` 的回车：网站收到了完整的搜索词和正文。结果：通过（后台页的计时器被放慢，编辑器保存晚到了约 1 秒）
- 前提：“正在调试”提示条不会因此变多。今天读页（无障碍树）、点击、按键都走调试器，按编号（@N）的填写也走调试器（Runtime.callFunctionOn）；只有按 CSS 定位串的填写不挂调试器。新写法要挂调试器的只多了“按 CSS 定位、且前后 15 秒内没有别的读页或点击”的填写。

## 边界与不做

- 回车即发送的多行框、编辑器上，模型仍然可以用按键回车把内容发出去，这是已知缺口（docs/web-actions.md），这次不扩大也不补上。
- 网站自己画的下拉框、日期选择器、canvas 编辑器不在这次范围内，留给“截图加鼠标键盘”。
- 字里有换行时，真实键盘输入在编辑器里怎样换行，按实测写进实现，这里不预设。
