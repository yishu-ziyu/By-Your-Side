# 任务: 核查「伴读与改口」这条场景能不能一次走通，找出第一次断开的地方

[当前状态](../STATUS.md) · 研究材料：`/Users/mahaoxuan/Desktop/AI 产品/reading-companion-rea-20261010/REPORT.txt`

场景：用户指定文章中的一段，要求解释。解释过程中说「不是定义，我想知道为什么」。助手停止旧回答，围绕同一段解释原因。需要依据时跨页查证，再接回原文。用户确认记住「先讲原因」，新会话继续采用。

本轮只核查，不改产品代码，不提交。核查都在隔离无头 Chrome 里装真实扩展，模型是本机脚本模型，所以只证明产品怎么处理模型的输出，不证明真实模型会这样回答。

## 规则

- R1 改口后旧回答不再变长，新回答仍对着同一段，问题和来源都在。
  - 例子(正)：在阅读卡生成解释时，用户输入改口并按回车，那么 1.5 秒内模型收到带这一段的新请求，旧解释 1 秒内停止变长 — 谁检查：`scripts/probes/reading-correction.mts` A1、A2
  - 例子(反)：今天的阅读卡在生成中吞掉回车，A1、A2 失败（见「结果」）
- R2 跨页查证不换走用户正在读的页，结果可追溯到原文和证据页。
  - 例子(正)：助手在后台标签打开证据页 B 并读它，期间活动标签一直是原文页 A，A 的网址不变，回答的来源同时列出 A 和 B — 谁检查：`scripts/probes/reading-crosspage-memory.mts` C1–C5
  - 例子(反)：助手用 fetch 读 B，B 不进来源（C6 失败）；助手用 navigate 去 B，A 被换成 B（C7 失败）
- R3 偏好经用户确认才生效；可查看、修改、忘记；忘记后不再采用。
  - 例子(正)：新会话的请求带上偏好；修改后带新文字；忘记后不带 — 谁检查：同上 D2、D4、D5
  - 例子(反)：阅读卡的请求不带偏好（D3 失败）

## 还没答上的问题

- Q1 助手用 navigate 查别的页时，今天会把用户正在读的那一页换掉。要不要规定「用户在读时，查证一律在后台新标签做」？这会改变「打开某网址」这类请求的行为，所以要用户决定。
- Q2 用户明说「记住：…」时，今天直接存下并给「撤销」，不先问。场景要求「经用户确认生效」。用户的明说算不算确认？本文按「算」处理；改口后助手主动提出要记，才走「要我记住吗」的确认。

### 第一次断开的地方

按场景顺序，第一次断开在阅读卡改口：解释还在写时，用户输入「不是定义，我想知道为什么」并按回车，产品不发送、不停止、不提示，旧解释写到结束。用户要先点停止，再按一次回车。证据：探针 A1、A2 两次运行都失败，`out/probes/reading-correction/2026-10-10T08-05-54-071Z/`（截图 A2-card-after-enter.png）；同一段驱动代码在停止后 3 毫秒就发出了请求，所以是产品没有处理那次回车。

另有一处更早的断点，只出现在普通 http 网页：阅读卡的脚本在这类网页上一启动就出错，划词气泡完全不出现，场景第一步就走不了。原因是生成编号的浏览器函数只在 https 和本机地址可用（[代码](../../extension/src/content/page-sources.ts)）。https 网页不受影响。
