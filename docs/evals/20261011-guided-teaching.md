# 任务: 一步一步教我——圈出该点的地方，等用户自己点完再带下一步（YIS-154）

来源：用户认可的预览 [guided-teaching](../previews/guided-teaching/index.html)（2026-10-11）。依据：对 HeyClicky 1.0.53 教学功能的研究与独立原型（`~/Desktop/AI 产品/heyclicky-guidance-lab/`）。

与 10-04 删掉的「指导模式」不同：那次是全局模式开关，只看网址变化。这次是一个工具 `guide_step`：一次教一步，在工具调用里等用户自己点，并核对页面有没有变化。

## 规则

- R1 正确点击才推进，助手不替用户点（T1）
  - 例子(正)：假如本地三步测试页（设置 → Display → Dark theme），当用户依次点中圈出的目标，那么每一步都等用户点中、页面有变化后才出现下一步；最后页面是深色；整轮没有调用 click、fill 等写入工具。侧栏运行标题显示「第 N 步 · 等你操作」。 — 谁检查：`scripts/acceptance/real-path/guided-teaching.mts --headless`（脚本模型）；真实模型 5 次（同脚本 `--model=`）
  - 例子(反)：用户还没点，`guide_step` 不返回，下一步不出现。 — 谁检查：同脚本
- R2 点错不推进；光标停在目标旁，用户一动鼠标就让开（T1、T2）
  - 例子(正)：当用户点在目标外，那么步骤不变，网页上的名牌改成「这里不是要点的位置…」，圈仍在原目标上，光标停在目标右下角；用户随后移动鼠标，光标离开目标（回到停靠位）；再点中目标才推进。 — 谁检查：同脚本（读 `cursorState` / `marksState` 探针）
  - 例子(反)：减少动态效果时，光标直接到位，不飞行。 — 谁检查：同脚本 `reducedMotion` 组
- R3 点了但页面毫无变化：3 秒内提示，不算完成（T3）
  - 例子(正)：假如测试页的开关点了没反应，当用户点中它，那么 3 秒内名牌改成「好像没有生效…」，侧栏出现「点了「…」，页面没有变化」；这一步不算完成；第二次仍没变化时工具返回 `no_change`。 — 谁检查：同脚本（故障页）
  - 例子(反)：正常页面上点中目标后页面有变化时，不出现这条提示（核心路径 5 次里 0 次误报）。 — 谁检查：同脚本 + 真实模型 5 次
- R4 停下、接管、离开时马上收场
  - 例子(正)：等用户点的时候，用户点侧栏停止、接管页面、关掉或离开这个网页，那么等待马上结束，圈、名牌和光标都清掉，网页上不再监听点击。 — 谁检查：同脚本

## 还没答上的问题

- 无。完成判断沿用 HeyClicky 方式（用户 10-11 决定）：点中且页面有变化就推进，下一步由模型看页面决定；本地只拦「完全没变化」。

## 技术前提

- 前提：内容脚本在捕获阶段能先于网页自己的处理看到点击，CDP 派发的点击 `isTrusted` 为 true。小实验：`heyclicky-guidance-lab/prototype/acceptance/premise-extension.mjs`。结果：通过。
- 前提：一个工具调用可以挂起等用户最多约 2 分钟，并在停止时及时结束。依据：已上线的发送确认（[20261009-send-confirm](20261009-send-confirm.md)，`SEND_CONFIRM_MS`、`tool_waiting_user`）。结果：通过（已有验收）。

## 边界与不做

- 不做语音模式下的教学（语音的固定工具表不加 `guide_step`）。
- 不做整屏或浏览器外的教学；跨源 iframe 里的目标按 `mark` 现有的能力处理。
- 侧栏任务栏里的「已完成步骤清单」：预览把它放在底部任务栏；本次先用对话里的步骤行展示已完成的每一步，任务栏只写状态。差别交用户在真实侧栏里判断。
- 不改现有代办、发送确认和 `mark` 的行为。

## 结果

2026-10-11，分支 `feat/guided-teaching`。证据都在 `out/acceptance/real-path/` 下。

- 脚本模型 `guided-teaching --headless`：29/29 通过，覆盖 R1–R4 与按下就重画（Q）、@ref 目标被重画（QR）、慢网页 4 秒后才生效（L）、减少动态效果（R）。实测：点了没变化后约 3.0 秒出提示；点「停」后约 80 毫秒圈和光标清掉。主代理独立复跑通过（`2026-10-11T04-09-19-244Z-guided-teaching`）。
- 真实模型 `openai-codex/gpt-6-luna`，同一用例 5 次：5/5 通过。每次 3 步、页面最后是深色、Dark theme 开关只点 1 次、网页收到的点击都来自用户、没有「页面没有变化」误报（`04-01-20-129Z` … `04-03-53-376Z`）。
- 反例：把 @ref 目标的页面内定位改回 `@N` 原样，QR「圈跟到新开关上」失败（读数 `element:null`），其余照常（`2026-10-11T04-00-03-011Z-guided-teaching`）。
- 回归：`step-icons` 通过；`send-confirm` 25/25；`inproc-mark`（真实模型）4/4。`npm run check` 通过。

验收途中抓到并修正的问题：

- 真实模型把用户刚打开的开关又圈了一次（第一轮 5 次里 1 次，`2026-10-11T03-38-03-761Z`；旧判据仍算通过，所以收紧为「超过 4 步或开关点了不止 1 次算失败」）。原因：完成的结果只说页面变了，没说目标变成什么样。改为附上目标点完后的状态（`after`）。
- 独立评审发现：@ref 目标被网页重画后找不回；网页响应慢于 3 秒时被说成没生效或离开；画圈出错时页面监听残留；盖在目标上的东西被算成点中。都已修正，前两条有新场景（QR、L）。
- 停下、离开、点了两次没变化、2 分钟没点，原来在侧栏画成红色「没成功」。改为照实写原因，不算失败，也不计入连续出错。

没验到的：

- 2 分钟没点（timeout）、接管、关页、离开网页、「提示之后才换文档」、画圈出错，只改了代码，没有专门场景。
- 真实模型那 5 次的截图在目标圈出的瞬间拍，不证明光标停靠；光标停靠只由脚本模型的 N、M、R 场景证明。
- 真人没试过；侧栏里「已完成步骤」用对话中的步骤行展示，和预览把清单放在底部任务栏不同，待用户在真实侧栏里判断。
