# 任务：用户没在看侧栏时，做完和要你出手各响一声提示音

## 规则
- R1 前台窗口没开侧栏（用户在别的应用、或在没开侧栏的窗口里）时，任务做完响一声柔和的三音「做完」；要用户出手（网页上确认发送、教学一步等你点、页面交给你、目标核对判「等你」）时响另一声两音。开着几个侧栏时只响一次。
  - 例子(正)：窗口在后台时任务做完，侧栏响一次「做完」 — 谁检查：`npx tsx scripts/acceptance/real-path/attention-cues.mts`（A、E1、E3）
  - 例子(反)：用户正看着开着侧栏的窗口，做完不响 — 谁检查：同上（B、E2）
- R2 一个任务只在真正结束时响一次：要核对的一轮等核对结论再响，判「接着做」时不响、续做结束才响。
  - 例子(正)：核对先判接着做、再判做完，整个任务只响一次「做完」 — 谁检查：同上（D）
- R3 用户停下的任务、补放的历史、同一件事的重复通知都不响；语音对话里助手正在说话时不响。
  - 例子(反)：点停止后任务收尾，不响 — 谁检查：人
- R4 设置页「提示音」默认开，关掉后什么都不响。
  - 例子(反)：关掉后窗口在后台做完任务，不响 — 谁检查：同上（C）

## 还没答上的问题
无。

## 技术前提
- 前提：侧栏能分辨用户在不在看开着侧栏的窗口，并且不靠新的点击就能出声。小实验：`scripts/probes/attention-cues-premise.mts` 结果：通过。窗口在后台时 `chrome.windows.getLastFocused()` 报不在前台、无头时报在前台；`document.hasFocus()` 只看焦点在不在侧栏里：实验里点过侧栏后，窗口在后台它仍是 true；用户看着侧栏旁边的网页时它又是 false，所以不用它。`chrome.runtime.getContexts` 报出的侧栏窗口一律是 -1（无头和有窗口都是），所以各个侧栏自己报窗口。侧栏一次都没被点过时新建的 AudioContext 也直接是 running，时钟在走，分析器读到输出。

## 边界与不做
不用音频文件、不加通知权限；只为当前选中的对话响。记忆询问不响：它是一张可以不理的卡，任务照常进行。

## 踩过的坑与没跑的
用例在测试浏览器里静音（`--mute-audio`），判据是振荡器和分析器读数，不是耳朵。用例要有窗口的 Chrome，所以不进 run-all 整轮。未跑：日常 Chrome 里真人试听音量和音色。停止后不响、助手说话时不响、「要你出手」那一声，都没有自动用例。
