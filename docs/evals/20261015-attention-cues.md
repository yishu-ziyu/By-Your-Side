# 任务：用户没在看侧栏时，做完和要你出手各响一声提示音

## 规则
- R1 侧栏所在的窗口不在前台（用户在别的应用或别的窗口里）、或侧栏被收起时，任务做完响一声柔和的三音「做完」；要用户出手（网页上确认发送、教学一步等你点、记忆询问、页面交给你）时响另一声两音。
  - 例子(正)：窗口在后台时任务做完，侧栏响一次「做完」 — 谁检查：`npx tsx scripts/acceptance/real-path/attention-cues.mts`（A）
  - 例子(反)：用户正看着侧栏所在的窗口，做完不响 — 谁检查：同上（B）
- R2 用户停下的任务、补放的历史、同一件事的重复通知都不响；语音对话里助手正在说话时不响。
  - 例子(反)：点停止后任务收尾，不响 — 谁检查：人
- R3 设置页「提示音」默认开，关掉后什么都不响。
  - 例子(反)：关掉后窗口在后台做完任务，不响 — 谁检查：同上（C）

## 还没答上的问题
无。

## 技术前提
- 前提：侧栏能分辨用户在不在看它所在的窗口，并且不靠新的点击就能出声。小实验：`scripts/probes/attention-cues-premise.mts` 结果：通过。窗口在后台时 `chrome.windows.getCurrent().focused` 为 false、无头时为 true；`document.hasFocus()` 只看焦点在不在侧栏里：实验里点过侧栏后，窗口在后台它仍是 true；用户看着侧栏旁边的网页时它又是 false，所以不用它。侧栏一次都没被点过时新建的 AudioContext 也直接是 running，时钟在走，分析器读到输出。

## 边界与不做
不用音频文件、不加通知权限；只为当前选中的对话响。目标核对判「接着做」时，续做结束会再响一次「做完」。

## 踩过的坑与没跑的
用例在测试浏览器里静音（`--mute-audio`），判据是振荡器和分析器读数，不是耳朵。未跑：日常 Chrome 里真人试听音量和音色。停止后不响、助手说话时不响、「要你出手」那一声，都没有自动用例。
