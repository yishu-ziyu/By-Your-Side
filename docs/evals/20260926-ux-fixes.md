# 任务: 09-26 实拍发现的 10 个界面问题，在用户走的同一步上都不再出现

来源：功能实拍报告（firstmate `bys-features-r1`）列出的 10 个用户看得见的问题，外加 firstmate 追加的页面下载失败回答（露出 Chrome 错误码、「还有 1 项没完成」）。第 1–6 条和下载那条同属一类：宿主的核验、账本和原始报错直接漏到用户面前。

## 做法

- **一处翻译**：新增 [`shared/user-facing.ts`](../../shared/user-facing.ts)，工具名、元素编号、定位符、状态码、原始 JSON、Chrome 下载错误码只在这里翻成人话；翻不出来时说笼统但真实的话，不回退原文。任务条、过程行、没做完的那一行、授权卡、模型报错、下载回执、连续失败提示都经它。原文仍留在回执和诊断记录里。
- **拒绝是用户的选择**：用户在授权卡上点「拒绝」时，工具结束事件带 `declined`；账本不留待办、过程行不画失败、不给「继续」。授权卡里表单编码的正文按字段解码显示。
- **模型报错**：自动重试从 2/4/8 秒改为 1/2/4 秒，服务真坏了约 7 秒告诉用户；报错只说人话（「模型服务暂时出错……稍后再试，或在下方换一个模型」）。模型一步没做成时不再补发「任务状态：仅交付部分结果」这种只有账本口吻的回答；补在回答后的纠正句也改成人话。
- **页面上的确认**：光标拿住等确认时不再回角落，这一轮结束后「发送 / 取消」留在「发送」键旁边。被拦下的点击记 `awaitingConfirmation`：侧栏那一行写「等你在页面上确认：…」、不给「继续」，回答后的纠正句也说在等你确认。
- **等确认不占页**：只剩等确认的会话不再算占着页面，另一个会话可以接手；接手时旧会话留在页面上的确认一并收起。
- **任务卡**：没有任务时不显示目标和状态行，不放「（目标未记录）」「新任务」「准备中」；没被接收的消息不另起一张只剩占位的卡（原因在消息流里）；「待发送材料 / 材料」改为「发送时一起带上 / 随这条消息发送」。
- **语音面板**：「停声」只在正在回答时出现；连不上时只说一次「连不上语音服务」并指向网络或设置页的语音 key；缺 key 时指向「更多 → 模型与语音」；就绪时显示「已连接，可以说了」。
- **选中追问卡片**：打开时定一次放在选区哪边（默认下方，下方放不下才放上方），回答变长也不换边。
- **小伙伴 M**：输入框正上方叠着团队状态卡或示范记录时，M 趴到最上面那张卡片的上沿，不压按钮。
- **记忆和技能**：宿主在 `hello_ok.features` 里报有没有这两种存储；只装扩展时「更多」菜单不显示「示范给 AI」「技能与记忆」。
- **下载失败**：回执给模型的是人话原因（「服务器传来的文件不完整」），Chrome 错误码只留在回执数据里。

## 第 4 条：真实模型会不会在等确认时结束这一轮

会。`real-confirm` 组用真实模型说「帮我改错字，然后点发送。」：

- 改前 3 次：1 次被拦下，这一轮结束后页面上的确认收起了（`before-real2`，与实拍报告一样）；另 2 次**根本没拦**，直接发了出去，页面跳到「已保存」。
- 原因：拦不拦只看点击的 `label`，模型写的是「点击发送按钮」，不以「发送」开头，就放行了。已改为先看页面上元素自己的名字（见 [经验](../knowledge/patterns/model-label-decides-safety-gate.md)）。
- 改后 3 次：3/3 被拦下，这一轮结束后「发送 / 取消」仍在，都没有自行发出（`after-real1..3`，页面表单提交次数 0）；侧栏写「等你在页面上确认：点击「发送通知」」。

## 边界与未决

- 措辞和观感待用户判断；日常 Chrome 未重载。
- 翻译只挡住已知的内部文字；新工具没登记中文名时显示「处理这一步」，要在 `shared/user-facing.ts` 补上。
- 另开会话接手页面时旧会话的确认被收起，旧会话账本里那一步仍是「等确认」，回到旧会话时那一行不会自动更新为「已取消」。
- 模型出错后仍给「继续」（重试这一轮），没改。
- 只装扩展、还没配模型时建默认会话要 10 秒上下，这段时间发送键是灰的、按回车没反应；本轮只让验收脚本等它建好，没改产品。
- 连不上语音时浏览器不告诉原因，分不清网络还是 key 被拒，所以文案两样都提。
- 小伙伴 M 只避开输入框正上方那一摞卡片；别处的按钮没有逐个避让。
