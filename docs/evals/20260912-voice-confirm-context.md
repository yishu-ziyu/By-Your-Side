# 任务：语音纠正确认后，仍把完整要求送到原任务

2026-09-12。用户接受“第一轮最小范围：纠正 → 确认 → 送达原任务”。沿用现有当前会话、单步 steer/abort 的复述确认规则，不扩大到语音分类或停指令重设计。

## 完成标准

- [x] 1. 在 A 页提出纠正后，即使确认时活动页为 B，执行器收到的仍是原纠正文字、A 页锚点和原附件；确认轮资料不替换原要求。— 谁检查：主代理独立运行时用例与隔离无头浏览器
- [x] 2. 待确认资料是一份独立快照；之后输入对象的变化不能改变待确认要求。— 谁检查：行为测试
- [x] 3. 当前语音连接、相邻轮次、90 秒有效期、原 runId 与原控制版本共同约束确认；否认、过期、换连接、任务替换或接管后不提交旧纠正。重复确认不重复提交。— 谁检查：行为测试
- [x] 4. 确认前再次改口，最后待确认要求取代上一份；普通闲聊不被当作确认或终止。— 谁检查：行为测试
- [x] 5. 确认后的纠正实际到达 BrowserAgentSession，并对原页面做已有的新鲜观察；保留现有旧操作代次失效与用户接管闸门。— 谁检查：隔离无头浏览器及受影响控制回归
- [x] 6. 相关测试与 typecheck 通过；独立 DeepSeek 复核实际差异，主代理检查关键结果。— 谁检查：机器与主代理
- [ ] 7. 日常 Chrome 中真实中文语音纠正与确认的体验。— 谁检查：用户；合成转写和无头浏览器不能代替真人声学验收

## 边界与不做

- 保留当前确认频次和用语、ASR/TTS、模型、跨会话和多步计划语义；不新增快速停指令。
- 不提交、不推送、不重载日常扩展，不读写私人录音或凭据。浏览器验证使用隔离无头环境。
- 保留已有未提交改动；仅调整确认载荷及其有效性，新增行为证据。
- 原页关闭或读取失败时沿用已有明确页面锚点与读取降级，不把确认轮活动页冒充原目标；页面结果仍需执行器重新核对。

## 修复前证据

本任务前已用真实 ConversationManager + TaskDispatcher、替身分类器和执行端复现：A 页纠正 → 复述 → 切到 B 页回答“对” → 回执 accepted，但执行端 context 为空。无外部模型、音频或浏览器调用。原复现位于 `/tmp/ego-arch-lightness-20260912/repro-context.mts`，本轮在独立行为用例中保留失败断言。
