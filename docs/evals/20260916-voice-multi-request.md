## 本次实现

新增 TaskQueue 承担独立要求登记、持久化和准入，复用 TaskDispatcher 的去重、回执和控制通道。候选参数为全局2个根任务、8个等待独立要求；模型内部已有worker数另计，不能把2解读为供应商吞吐测量。初始任务的文字入口超过容量明确拒绝，不假称排队。

新标签页只有在模型先判为独立目标且原话明确新页时才脱离来源页；任务内的换页比较仍修改原任务。同页要求保留原上下文并等候，执行时继续走已有页面归属与观察检查。

任务来源关系保存到运行身份；语音只接收明确关联任务的结果，按结果自己的控制版本校验，播放回执不再写错原会话。等待回执沿既有侧栏回执显示；未新增大面积UI。

播报队列取消静默淘汰，生命周期仍限于当前语音会话。若客户端尚未听见正式结果，插话时保留待播。已经听见一部分的音频仍按原停播处理，本次未实现按字精确续播。

## 真实失败推动的修复

1. 第一遍真实分类把“同时在新标签页打开…”当作steer，未建立独立任务。修正为先比较任务目标；[失败记录](20260916-voice-multi-request/classifier-before.json)。随后反例发现同一电脑比较内的换页被分成新任务，再明确关系判断优先级；[反例](20260916-voice-multi-request/intent-before-goal-priority.json)、[6种表达复测](20260916-voice-multi-request/intent-result.json)。
2. 三任务检查中B文字已经生成、声音还未到时C插入，B被cancelSpeech永久静音。保留该类未听结果；[失败](20260916-voice-multi-request/unheard-before.json)、[三任务通过](20260916-voice-multi-request/three-task-pass.json)。
3. 最终复测还暴露“原任务照常，另外做一个独立任务…”被拆成无意义steer和observe。补充背景条件与任务内部读取步骤的边界，并收紧单个start内部读页合并条件；同一句真实模型连续3次均输出单个start，原文全部保留。
4. 一次探针把测试屏障工具同时提供给A/B，B也等待屏障，导致测试超时。屏障只给A；未将这次测试构造问题写成产品故障。

最终重跑同一句三任务路径与实际侧栏“已排队”显示均通过：[最终浏览器证据](20260916-voice-multi-request/final-browser.json)。
