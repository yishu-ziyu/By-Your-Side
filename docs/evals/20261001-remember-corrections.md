# 任务: 用户纠正助手后，助手开口问「要我记住吗」；用户点「记住」后，以后在对应网站照做，「记忆」面板里能看能删

询问样式 2026-10-01 用户在三个方向中选定 B「它开口问你」（[对比](../previews/20261001-correction-ask-options.html)）：助手接着说一句「以后在这个网站……我都……，要我记住吗？」，下面「记住 / 这次就行」两个浅色小按钮；点记住后变成「好，记住了。[范围] 撤销」。下文「卡片」均指这个询问。

修订（2026-10-01，加固块之后开工前）：
- 「不用」按钮改名为「这次就行」，「记忆抽屉」改称「记忆」面板（侧栏右上角 ⋯ → 记忆）；面板里的分组用已有种类名「做事的方法」，不另起「我的纠正」。

- 用户 10-01 决定与「GLM 只思考不回正文」小修复一起做（见末节 G1–G3）：两者共用同一条「后台问模型」的路径。
- 后台与侧栏之间的消息先定在 `shared/protocol.ts`：事件 `memory_ask`、请求 `memory_ask_answer`、结果 `memory_result` 的 `ask` 动作。
- 一句话只出一种记忆结果：纠正本身就是用户原话说的长期偏好（如场景 2「应该用中文回复我」）时，按[记忆模型](../memory-model.md)「原话直接记、归纳才先问」，已有的自动记忆可能直接记成「关于你」并给撤销，这时不再追问；需要归纳的（如场景 1 从「只导了当前页」归纳出「导出前选全部」）才问。场景 2 的期望相应改为「直接记下或开口问，二者恰好一个」。
- 场景 9「原话不进任何存储与记录」指记忆相关的存储与记录：记忆数据、补判队列、`memory_*` 诊断记录；对话本身的聊天记录照常保存用户发的话（那是用户自己的对话，不属于记忆）。
- 用户确认过的网站做法在该网站总是带上（受上限约束），不再按字面相关度筛；自动总结的旧做法维持原规则。

## 共用约定（各方据此独立实现与验收）

- 判断：用户直接发的一句话先过便宜的纠正检查（不像纠正、含密码类内容都不问模型，原话也不外传）；通过后在这一轮结束后问模型窄问题。系统提示以 `You review a direct user correction of the assistant` 开头。输入 JSON：`{userMessage, recentTurns, currentHostname, methods:[{id,text,scope}]}`。模型只回 JSON：`{"correction":bool,"reusable":bool,"about":"site"|"assistant","rule":"第一人称做法","evidence":"userMessage 里的连续原文","replaces":"已有做法的 id"|null}`。
- 代码决定：`correction && reusable`、evidence 是原话子串、rule 合法、同范围没有同样的生效做法、这次对话里没被「这次就行」过、这句话没有已被直接记下 → 发 `memory_ask`；范围 `about=site` 且有当前网站时为该网站，否则所有网站。每次判断写一条诊断记录 `memory_ask_decision`（问 / 不问 + 规则编号，不含原话）。
- 回答：`memory_ask_answer` 只认后台记下的询问（询问只存在后台内存里；后台重启后点按钮回「这条询问已失效」）。remember 存一条「做事的方法」（来源原话 = 用户那句纠正），有 replaces 时旧条目标「被替换」；结果 `memory_result{action:"ask", entry: 新条目, entries: 新条目及被替换的旧条目}`。
- 撤销：没替换别的 → 忘记新条目；替换过 → 对旧条目「撤销替换」。范围切换走已有 `memory_update`。
- 审查后补（10-01；其中「重新打开后旧询问不再可点」已被下一条「复审后补」取代）：含密码类内容的一句话连自动记忆也跳过（不问模型、不进补判队列）；自动判断失败进了补判队列的那句不再追问（避免一句两种结果）；「这次就行」与防重复同时按原话去重；规则里出现原话没有的邮箱、网址、长数字就不问；要替换的旧做法刚被改过时这条询问作废；同样的做法早已存在时结果带 `alreadySaved`，侧栏说「已经记着了」、不给撤销、不写入；`memory_ask` 带 `hostname`（纠正发生的网站），范围切回「这个网站」用它；侧栏重新打开后，回放出来的旧询问只显示问句、不再可点（后台询问只在内存里）。
- 复审后补（10-01）：侧栏不再按时间猜「是不是旧询问」。询问有结局时后台再发一条同 askId 的 `memory_ask`（带 `outcome`：remembered / already / once / closed），随对话历史保存；侧栏按最后一条画：记下了→「好，记住了。可在「记忆」面板查看或撤销」（不再给撤销按钮，因为之后可能改过）；这次就行→「好，这次就不记了。」；作废→问句加「这条询问已结束」；没有结局的照常可点（后台已不在时点了回「已失效」并收起按钮，结果带 `askClosed`）。同一句纠正再说一次而旧询问还没回答：旧的作废、问新的。点「记住」后这句原话也进防重复。询问的网站取当前页面，不从原话里解析网址。问模型前，前几轮里像密码的用户话先去掉（自动记忆同样处理）。
- 侧栏标记：询问 `[data-memory-ask="<askId>"]`；按钮 `[data-memory-ask-answer="remember"]`、`[data-memory-ask-answer="once"]`；记住后的范围 `[data-memory-ask-scope]`、撤销 `[data-memory-ask-undo]`；替换提示 `[data-memory-ask-replaces]`；「记忆」面板分组 `[data-memory-group="method"]`。

依据：用户 2026-10-01 确认的想法 `.ship/ideas/remember-corrections.md`（1A 2A 3A、记忆存取设计、加「不限存储」权限）；[路线图](../ROADMAP.md)第 10 条。本任务同时是第一个「决定点」样板：模型答窄问题、代码按规则决定、留决定记录、配检查场景；做完单独给用户看它具体长什么样，再决定是否推广。

## 边界与不做

- 不做「改一下」（第二块）、不做「查记忆」工具（下一块）、不做导出导入（紧接着的一块）、不做演示学流程。
- 不跨设备同步，不上传规则。
- 不改现有「关于你」的自动记忆行为，只让规则与资料分开计上限。
- 真实模型用用户指定的 DeepSeek v4.1-flash（OpenCode）与 GLM-5.3-flash（智谱编程套餐），按提供方分线串行，跑完报告用量。

验收中修正的测量方法（保留原失败记录）：
- 真实模型模式下验收工具的辅助页（`voice-permission.html`）停在前台，侧栏把它当成当前页；脚本改为每次发话前把练习站切到前台，并逐轮核对 `run_start` 的当前页，不对就标「验收前提不成立」，不算产品结论。没有自己 `run_start` 的接续回话（「确认，继续」）只记「无法核对」。
- 记忆底座 D5 原按航班号找行程，会先找到本轮新记的另一条过往任务；改为按预置编号找（`memory-foundation.mts`）。

真实模型发现、已修的产品问题：规则存到扩展页编号上（只有 http/https 页面才算网站）；带密码的纠正进了过往任务（只隐去密码值，普通订单号、「忘记密码的入口」原样保留）；网站上的做法被自动记成「关于你」（纠正类消息的自动记忆只收个人资料）。

仍存在：
- MiniMax 不遵守「纠正类消息只记个人资料」，会把网站做法记成「关于你」（用户能看到「已记住…撤销」）；要靠代码而不是提示词挡住时再处理。
- 规则带上后照不照做取决于模型（GLM 表单场景未照做）；后续可在回答下方显示「因为你之前说过…」（见[记忆模型](../memory-model.md)10-01 决定）。
- 后台问「要不要记」这一步网络出错时，这句纠正不会自动再问，用户需再说一次。
- 标准 2 的人工判断、标准 3、8 待用户看。
