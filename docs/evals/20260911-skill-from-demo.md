## 完成标准

- [ ] 1. 示范期间系统不动手 — 谁检查: 机器（单测 + 隔离浏览器：示范中写类工具被硬闸门拒绝并留回执）
- [ ] 2. 成功的一遍被编译成脚本 — 谁检查: 机器（脚本可读、可复算；含每步前提与完成凭证）
- [ ] 3. 步骤与脚本里没有坐标、没有 DOM 路径字面量 — 谁检查: 机器（schema 校验；换一批数据仍能解析出目标）
- [ ] 4. 第二次执行零模型调用 — 谁检查: 机器（trace 里没有 LLM 请求；这是「更快」唯一的硬证据）
- [ ] 5. 更快且结果一致 — 谁检查: 机器记耗时比值 + 人看交付物对不对
- [ ] 6. 漂移不许点错 — 谁检查: 机器反例（改一个文案/挪一个位置 → 必须停下来说清楚，不许点错、不许假装完成）
- [ ] 7. 失败会退 — 谁检查: 机器（脚本跑不动时退回模型或停下等用户，不硬重试）
- [ ] 8. 每一步可查、可忘记 — 谁检查: 机器单测 + 人点一次（删掉后不再被引用）

- 只读任务。写入类（填表、发送、下单）第二刀，且写入永远走现有确认闸门。

## 第三刀：在用户真浏览器里按真实点击跑通（2026-09-11 凌晨）

用 `huashu-mac-use` 的窗口/空闲观测 + CDP（零焦点）在**用户日常 Chrome**里走完整流程：真的点「看我做」、真的点页面链接、真的点「做完了/编译成脚本/照上次那样跑」。不是合成输入到夹具页，是他自己的浏览器和自己的伴随进程。

结果（终局）：

```
运行记录: {"at":1789070061730,"ok":true,"elapsedMs":1443,"steps":5,"value":{"done":true,"steps":2}}
面板:     照上次那样跑完了：5 步 · 1.4 秒。
事实行:   跑过 1 次 · 上次 1.4 秒
页面:     /issues → /labels（脚本真的做了事）
```

**零模型调用**的证据：运行窗口内没有产生任何 session/run trace（模型回合必然产生 trace），run 记录里只有 tool 子步骤；1.4 秒完成，模型一次往返都不止这个时间。

### 这一刀抓到的四个真缺陷（都已修 + 单测锁住）

1. **示范跨页就断。** 内容脚本随导航消失，第二次点击不再被记录（真机实测：点 Issues 后停在 1 步）。修：导航完成后把「已记下的步骤 + 已过毫秒」喂回去续录（`resumeDemoIfRecording`），修后两次整页导航都记上（2 步）。`performance.now()` 每次导航归零，所以传的是"已过多少毫秒"。
2. **生成的脚本在页面上是语法错误。** 解析器把选择器写成 `"[data-sideagent-target=\"1\"]"`，内层转义被外层字符串吃掉，页面代码变成 `"...target="1"]"` → 真机报 `js: SyntaxError: Unexpected number`。修：选择器改用不带值的形式 `[data-sideagent-target]`（一个转义引号都不需要），并在打标记前清掉上一次的标记保证唯一。**新增的测试直接用真执行器跑一遍生成物并把页面代码丢给 `new Function` 解析**——这条测试就是为这个 bug 写的。
3. **完成凭证取到裸标签。** 示范最后一步是匿名点击时，凭证变成「必须还能找到 a 」，等于没凭证。修：优先取最后一个**有可访问名**的目标。
4. **跨导航留下的无名点击步**（一次点击跨导航时被记下的残影）会让每次运行都停在第 3 步。修：编译时丢掉"既没名字也没角色"的点击并计数，卡片上如实说明「示范里有 N 步没记到对象名，已跳过」。

### 顺带确认到的两件好事

- **漂移停下确实生效**：第 3 步找不到对象时，记录是 `failedStep:3 / 第 3 步的目标在页面上找不到了`，页面没有被继续点下去。
- 面板事实行、运行记录、技能列表在真机上都能用（`跑过 1 次 · 上次失败 · 1 次因为页面变了停下` → 修好后 `跑过 1 次 · 上次 1.4 秒`）。

### 工具教训（写给下次）

`127.0.0.1:9222` 是**用户日常 Chrome** 的调试口，不是 ego lite 的——ego lite 的窗口在 `mac windows` 里能看到，但在那份 CDP 目标列表里找不到。我因此把伴随进程重启错了两次（先杀了 ego lite 的、又杀了 Dia 的），直到核对 `ps -o ppid` 才找对。真机操作前先确认"这个端口是谁的"。

## 第五刀：用户在 B 站真机试出来的问题（2026-09-11 04:20）

用户自己在 B 站按了一遍，面板给出：

```
示范结束：记下 3 步
1. 点击div   2. 点击div   3. 点击div
编译没成：示范里没有可编译的步骤
```

根因两条，都是真机才暴露的：

1. **真实页面的点击落在裸 div 上。** B 站视频卡是 `<div>`（没有 role、没有 aria-label），名字（标题）在祖先生上，而录制只取被点元素自己的属性 → 三个「点击div」。原来那条「丢弃无名点击」的规则把三步全丢了 → 空技能。
2. 丢弃是**静默**的：用户只看到「没有可编译的步骤」，不知道发生了什么。

修法：

- **录制取名字更努力**：顺序改为 显式标签 > 占位 > title > 图片 alt > **祖先文字** > 自身文字；点击时若被点元素没名字，会向上找一层有名字的祖先（≤6 层）。
- **无名点击不再丢，标成弱步骤**：运行期认不出来就跳过并如实报「第 N 步没认出来，已跳过」。
- **新增诚实门**：所有动作都没认出来时，运行明确报「这一步都没认出来：技能什么都没做成，请重新示范一遍」，且这条判断排在完成凭证之前（否则用户看到的是"凭证不成立"，真因被埋住）。

测试：录制侧新增 2 项（祖先文字/title/alt 取名与优先级），编译侧新增 6 项（弱步骤保留与计数、程序里跳过而非停下、全军覆没报错、部分跳过如实记录）。全量 1277 项通过。
