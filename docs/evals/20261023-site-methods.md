# 任务：常用网站的方法提前准备，使用时少摸索且能核对

## 规则

- 用户在 B站、YouTube、X 上搜索或读取视频／帖子时，助手能按当前网站取用内置方法，不加载全部网站的说明。网站改版、登录受阻或内容未加载时明确缺口，不把脚本运行完当任务完成。
  - 谁检查：真实扩展里的方法验收，加真实公开网站试用；轨迹须能对应方法版本和实际网页来源。
- 方法只组合已有浏览器能力。停止、接管、跨标签页归属和外部写入确认沿用现有执行通道；网页内容不能注册方法或修改内置脚本。
  - 谁检查：隔离 Chrome 的正确网站、错误网站、伪造域名、取消与目标变化场景。
- 视频字幕与当前视频绑定；旧播放器数据或另一视频的轨道不能作为当前视频的字幕。没有字幕、没读到清单和拿到字幕是不同结果。
  - 谁检查：同一标签页切换视频的反例，以及播放器有／无字幕的真实扩展验收。
- 第一批收录六项：三个网站的搜索，B站和 YouTube 的字幕，X 的指定帖子读取。分别记录已验证和未验证，不以收录数量或内部 done 作为成功率。
  - 谁检查：同网站不同内容的保留样本；成功条件是结果与页面对象、查询或字幕来源一致。

## 取舍

内置方法随扩展版本分发，可以组合执行，避免模型每次重写常见脚本。用户的“/ 技能”仍是个人提示词入口，自动网站笔记仍是未核验经验；三者的可信程度不能混在一起。

Skill 用于描述何时使用、前提、方法与结果标准。MCP 用于接入浏览器现有能力之外的服务；本批不需要另装本机伴随程序，不为了包装现有浏览器工具再走一层远程服务。以后接入的外部工具也须回到同一授权、停止和结果记录通道。

## 还没答上的问题

- 不同登录态和站点改版下的覆盖率需要继续积累；首批证据不等于整个网站的所有功能都已支持。
- 简单事实问答的首字优化按同模型、同思考档位单独比较，不能把降低档位或减少引用混作提速。

## 技术前提

已在隔离真实扩展中验证：网站方法可以通过现有组合执行通道运行，搜索后的查询与页面一致；字幕可从播放器地址读取并在侧栏交付；不同视频的旧数据会被拒绝。脚本模型和拦截页面只证明执行与核对机制，真实网站、真实模型另留证据。

## 边界

本批只收录公开阅读、字幕发现和搜索。发帖、关注、私信、付款等不在首批方法内。候选方法必须保留失败证据，方法错误时回到现有页面观察流程，不反复执行相同脚本。
