# 任务: 点击后页面一有变化就通知效果判定，不再定时去读（#202 前提实验）

[当前状态](../STATUS.md) · [Issue #202](https://github.com/yishu-ziyu/By-Your-Side/issues/202)

#202 提议参考 Pine Computer 的「变化主动通知 AI」：点击后用页面里的 MutationObserver（浏览器自带的 DOM 变化监听）唤醒现有的效果判定，代替后台定时读页面。Issue 要求先做前提小实验（S0），有收益再改产品代码。本文件记录 S0。没有改产品代码。

## 规则

- R1 点击前装在「效果判定已经在读的地方」（被点元素、元素所在区块、页面顶层、提示区）的监听，页面因点击变化时收到通知；页面自己在别处乱动时收不到通知。
  - 例子(正)：点击后加弹窗和提示、300 ms 后加提示、900 ms 后加提示、按钮 aria-expanded 变 true，都收到通知 — 谁检查：`scripts/probes/action-event-wakeup.mts`
  - 例子(反)：把页面顶层的监听改成监听整页所有层级，页面上与点击无关、每 50 ms 跳一次的计数器触发通知，实验失败 — 谁检查：同上，故意改坏复跑

## 技术前提

- 前提：监听能覆盖效果判定读的常见变化，并且不被页面噪声唤醒。小实验：`scripts/probes/action-event-wakeup.mts`（隔离无头 Chrome，CDP 鼠标事件点击，与扩展点击方式一致）。结果：通过（7 个场景都符合预期）。故意改坏（整页监听）后复跑：噪声场景失败，退出码 1。

## 结果

| 点击后页面怎么变 | 收到通知吗 | 说明 |
| --- | --- | --- |
| 立即加弹窗和提示 | 收到 | 变化一发生就收到 |
| 300 ms 后加提示 | 收到 | 现在的定时读页也能读到 |
| 900 ms 后加提示 | 收到 | 现在的定时读页等不到这么久，回执写「页面没变化」 |
| 按钮 aria-expanded 变 true | 收到 | 不到 1 ms |
| 勾选框被勾上 | 收不到 | 只改了元素属性值，没改 DOM。现在的判定直接读 `checked`，能看到。输入框的值、媒体播放状态同理 |
| 没反应的按钮，页面别处在跳数字 | 收不到 | 只盯相关区域就不被噪声唤醒 |
| 点链接跳到新页面 | 收不到 | 旧页面的监听随旧页面消失。这是「没有通知」，不是「没有变化」，必须保留现在「拿不到证据就不下结论」的处理 |

结论（事实）：

- 监听能及时发现弹窗、提示、展开这类变化，也能只盯相关区域避开噪声。
- 监听发现不了只改值的变化（勾选、输入值、播放状态），所以不能去掉读页面。改成监听后，仍要在页面里定时读这几个值，只是不用每次从后台跨进程去读。
- 有变化时，监听最多比现在早一个读页间隔（代码见 [shared/effect.ts](../../shared/effect.ts)）。没有变化时，两种做法都要等满整个等待时间才能下「没变化」的结论，所以用户等的时间不变。
- 跨进程读页一次花多久，本实验没有量（需要装真实扩展才能量）。

推断（未验证）：按 #202 的 S1 改，用户看得到的变化接近零：有变化的点击快不到 0.1 秒，没变化的点击一样慢。真正可能有用的是另一件事：900 ms 以后才出现的变化，现在回执写「页面没变化」，助手会多花一轮去读页。是否值得做，要先知道真实网站上这种迟到的变化有多常见，现在没有数据。

## 延伸：真实运行记录里，时间花在哪（10-10）

用户要求顺着「浏览器主动通知」的方向，找真正有收益的地方。来源：`out/` 下已有的诊断记录（387 份，多数是练习站，模型以 gpt-6-luna 为主）。没有用户日常 Chrome 的记录。

- 模型每轮首字中位约 1.8 秒，是最大的耗时。一个动作如果让模型多看一轮页面，代价约等于一轮模型。
- 点击：页面有反应时中位约 0.7 秒，没反应时约 1.2 秒。多出的部分就是等满效果判定的等待时间。剩下的大头是页面上光标飞到目标的动画。
- 点击回执写「页面有反应」后，模型很少再去读页面。回执写「没变化」后，大多数下一步是读页面。翻查这些案例，都是练习站故意不响应的按钮，不是漏判，所以没有找到「迟到的变化被漏掉」的证据。
- 打开网址（navigate）的等待有盲区：记录里有 5 次各等了 10 到 30 秒才超时返回。目标分别是会触发下载的导出链接（网页没有换，程序一直等新页面）、`chrome://downloads`、本机 `file://` 文件、一个慢站点。原因是程序靠往页面里注入脚本来问「加载好了没有」，这几类页面注入不了或不会换页面，只能等到超时。浏览器自己的标签页和下载事件能直接说明结果。
- 按键（press_key）和填写（fill）的回执不带页面变化，只有点击带。记录里按回车后 4 次全部接着读页面，填写后 17 次里 6 次接着读页面。
