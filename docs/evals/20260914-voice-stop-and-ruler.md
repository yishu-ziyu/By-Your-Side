# 任务：把语音验收的尺子校准（并首次测"任务正在跑的时候说停"）

用户可观察的结果：此后所有"首声几秒"的说法，都以"你说完话 → 听见第一声"为准；并且此前从未测过的一种情况——任务正在执行时喊停——被真正测了。

起点：外部独立复核指出当前验收的三处口径问题——计时起点在脚本喂完静音之后、用桥接传输代替日常路径、"暂停任务"只在空闲状态测过（测不到"能不能真的停住"）。

## 1. 尺子校准后的真实数字

同一次运行（`out/acceptance/voice-greeting-live-2026-09-13T18-46-20-275Z`），单位毫秒：

| 输入 | 协议 | **说完 → 听见** | 应用收到"说完了" → 首帧 |
|---|---|---|---|
| 嗨，晚上好。 | free_reply | **4121** | 3513 |
| 你好。 | free_reply | **4050** | 3432 |
| 十加七等于多少？ | free_reply | **3904** | 3297 |
| 当前招聘页面要求几年经验？ | plan→原派发 | **8230** | 7614 |
| 暂停任务（空闲） | plan→控制链 | 3607 | 3000 |
| 继续（空闲） | plan→控制链 | 4107 | 3500 |

**与之前报告的差别**：此前报"3.4 秒"用的是"应用收到说完了"起点，比"你说完"晚约 0.5–0.6 秒（脚本先补 500ms 静音再计时的口径问题）。按"说完 → 听见"算，**问候是 4.0–4.1 秒，差一点没进 4 秒**；这一轮页面问答 8.2 秒（上一次是 5.9 秒，波动大）。真人端的停句判断（服务端多久认定你说完了）本脚本仍测不到，真人验收时另计。

## 2. 新发现：任务正在跑的时候说停，它会哑掉

第一次真正测到这个场景就失败了（同一次运行，第 8 轮）：

| 时刻（相对喊停时提交） | 发生了什么 |
|---|---|
| +2480ms | 暂停请求被受理：`task_control {action:"pause", runId:"7150a1be…"}` |
| +3648ms | 被停的那个任务自己送来一份 `finding` 交付（页面句子清单） |
| +30002ms | 该轮 30 秒期限到达，语音层报 **"语音答复超时。如已有任务回执，请按回执查询结果，不要重复下达。"** |
| +30106ms | 侧栏补一条通知："执行结果尚无法确认；不会自动重做。" |

**这一轮一帧音频都没有播出**（事件里 `voice.audio` 计数为 0）。用户听到的是：喊停之后约半分钟完全静默，然后一句超时提示。

这是本轮之前从未覆盖过的路径（此前"暂停任务"只在空闲状态下测过，那时它只会回答"当前没有正在执行的任务"）。**原因尚未定位**，已确认的只有现象与时间线。不把推测写成原因。

## 3. 测试口径的其他改动

- 脚本拆出 `send()`（只把话说完）与 `settle()`（等回答并收数据），以便"说完不等它答完"的场景。
- 运行中暂停失败时会换更长的任务重试（最多三次）；三次都测不到（任务在暂停落地前就结束）即判失败，回执里写明"任务在暂停落地前已结束"，不允许假过。
- 汇总增加 `branchUserWaitMs`，与 `branchFirstAudioMs` 并列保留：前者用于体验判断，后者用于同一送法下的版本对照。

## 边界与不做

- 本轮只改验收脚本与记录，未改任何产品代码。
- 未测：正在播报时说停、工具已排队时说停、工具执行中时说停（外部复核点名的四种时刻，本轮只覆盖"正在生成/执行中"这一种）。
- 未测：真实麦克风的停句判断与总等待。
- 日常扩展的 native-host/侧栏完整传输路径仍未被本脚本覆盖（本脚本走桥接传输），此项留在真人验收。
