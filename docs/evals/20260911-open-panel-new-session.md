# 任务：每次打开侧边栏 = 一段新的会话页面

来源：用户 2026-09-11 截图指出"打开面板会翻出上一段任务的一长串记录"（那种"已接收新任务／原话：…"的流水），
要求"每次打开进入时，都是一个新的会话页面"。实现前已按用户指定的四段格式（谁在什么场景 → 屏幕上有什么零件 →
点了之后发生什么 → 边界/别做的）说明方案，本文件是标准与结果。

**目标（用户可观察）**：真正打开面板（面板文档新建）时，消息区是空的、标题是「新会话」；上一段不会被自动翻出来，
但它仍在会话切换列表里、状态（运行中／空闲）照旧，一点就能切回去。

**范围**：`extension/src/sidepanel/main.ts` 的打开进入路径（会话选择）。后台、agent、协议、任务执行、
控制闸门、台账语义均不动。

## 完成标准

- [ ] 1. 打开时若上一段有内容：不自动切到它、不回放它的记录，发出一次新会话请求；收到回执后落在空白的新会话页。— 谁检查: 机器（`scripts/acceptance/panel-open-session.mts`）
- [ ] 2. 打开时若上一段仍是空白（标题还是「新会话」且空闲）：直接复用它，不新增空会话。— 谁检查: 同上
- [ ] 3. 上一段正在跑时打开：新会话页可正常出现，上一段仍在切换列表里、并显示「后台运行中」入口。— 谁检查: 同上
- [ ] 4. 拿不到会话清单或后台未连接时不把面板卡死：连上后再决定，超时兜底新建；新建无回执时退回显示上一段。— 谁检查: 同上（兜底分支）
- [ ] 5. 运行态渲染（状态行、执行块、光球）不回归。— 谁检查: `scripts/acceptance/run-status-ui.mts`
- [ ] 6. 现有测试、typecheck、build 全过。— 谁检查: npm test / npm run typecheck / npm run build

## 边界与不做

- 不改「＋ 新会话」按钮语义、不改会话切换与草稿行为。
- 不删、不隐藏任何历史会话；旧会话仍在列表里可切回。
- 不动任务执行、页面控制权、台账与协议。
- 观感（打开时是否利落）由人裁决；机器只给结构事实。
