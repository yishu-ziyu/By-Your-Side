## 三、需补的验收能力与证据

已存在的独立机器入口：

- `npx vitest run agent/test/memory-eval.test.ts`：11 项固定断言，覆盖持久记录、相关性、精确 hostname、个人存储隔离、管理列表、CAS 更新、删除失效、多实例重读、20 项并发新增、旧选择重新核对、无效输入与失败。首次执行为红：生产 `memory-store` 尚不存在，测试未收集成功；这是实现前基线，不计通过。
- `node scripts/acceptance/cross-session-memory-run.mjs`：启动独立 Node 进程完成保存、读回、纠正、读回、忘记、读回与独立目录检查。检查生产存储，输出条目与版本证据；脚本语法检查已通过。它不检查模型、UI、浏览器重启、明确请求授权或接管，结果中显式列出这些未评项。

固定生产接口为 `MemoryStore(dir)`，异步 `list/create/update/forget/select/resolveSelected`。`create` 接受 `text/scope/sourceConversationId`；`update` 接受 `id/expectedVersion/text/scope`；`forget` 接受 `id/expectedVersion`。条目含 `id/version/text/scope/sourceConversationId/createdAt/updatedAt`；scope 为 `{kind:"all"}` 或 `{kind:"site",hostname}`。`select({text,url?})` 只选择本轮相关且范围匹配的条目；`resolveSelected([{id,version}],{text,url?})` 在注入前重新核对，旧版本更新或删除后不得转成新版冒充原选择，必须返回空；下一轮可重新选择新版。

仍需生产 Pi 与真实界面证据：合成数据隔离、全新 Pi 会话、明确用户请求及来源授权、检索/注入版本、保存/纠正/忘记回执、完整浏览器重启、范围负例、接管交错及失败时非零退出。由主线程负责真实浏览器与模型集成验收。不能直接修改存储后把截图当成用户保存成功。

产物至少包含每条标准的结果、动作时间线、合成条目 ID/版本、实际会话与进程标识，以及保存、使用详情、纠正、忘记四个关键界面的截图。模型输入证据只截取合成记忆段及其选择信息；不记录令牌、cookie、用户真实页面正文或真实历史。浏览器验收使用 `local.yishu.chrome-main`，不控制 `com.google.Chrome`。

## 四、实现前已确定的产品边界

1. 采用 A：会话内简短保存回执与记忆抽屉。第一版只接受用户明确要求记住；网页文字、普通聊天和会话结束不触发自动提炼。
2. 用户未限定站点时默认为所有个人会话；明确限定站点时保存规范化 hostname，回执显示准确范围。管理抽屉可查看和修改所有自己的条目，站点过滤仅作用于检索与注入。
3. 保留 Pi；浏览器配置与用户存储分离，不新增账户系统。自动学习、效率优化和旧历史批量导入不在本轮。
4. 以上是本次实现前由编排传达的用户选择。此轮变更纠正了先前把站点范围误当管理权限域的 R5；条目 ID、版本、存储隔离及迟到结果校验仍为硬条件。

## 边界与不做

- 本轮已授权产品实现；验收使用隔离合成数据，不自动迁移或批量写入用户旧历史。
- 不把效率、延迟降低或 token 节省列为本轮目标。
- 不更换 Pi，不把同一会话的历史恢复称为跨会话记忆。
- 不把整份旧聊天自动导入新会话，不自动学习或批量提炼现有历史。
- 忘记只承诺停止该条作为记忆的后续检索与注入；不承诺清除旧聊天、已发送模型上下文或所有备份中的原文。
- 不自动续跑重启前的网页操作，不放宽现有接管与页面归属规则。
