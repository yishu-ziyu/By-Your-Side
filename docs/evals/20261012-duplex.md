# 插话评测（v0，草稿）

量的是用户体验里的一句话：**我中途改口，它要多久才改过来，改之前还会不会照旧做错。**
现有 175 道题、复杂度阶梯和速度线都只量「一句话说完、等它做完」。用户边说边做、随时打断的情况没有题，也没有读数。[STATUS](../STATUS.md) 下一步第 1 条要量的就是这个。

## 题

[`eval/tasks/duplex.jsonl`](../../eval/tasks/duplex.jsonl) 22 题，全部在本机页面上（[`ladder-sites.mjs`](../../eval/harness/ladder-sites.mjs) 的 `/duplex-form`、`/duplex-list`、`/duplex-chat`），不受站点可用性影响。

| 类型 | 题数 | 用户说什么 |
|---|---|---|
| 补一句 | 6 | 再加一项，原要求不变（含 2 题在模型还没动页面时插话、1 题连补两句、1 题回车即发送的聊天框） |
| 改值 | 6 | 还没写到的字段换个值；已经写进去的值要改回来 |
| 撤掉一部分、改方向 | 4 | 不要其中几项；整个目标换掉 |
| 停下 | 3 | 点停止键；打字说「终止任务」；口语「停一下，先别弄了」 |
| 不该打断主任务的话 | 3 | 问进度；问一个无关问题；「那个也换掉」（应该先问清楚） |

插话时机由题目的 `interject[].when`（在任务页上求值的条件，例如「姓名已经填了」）或 `after_ms`（发出后几毫秒）决定。`stop: true` 是点侧栏停止键，其余是在输入框里打字回车，走产品里真实的插话路径。

## 规则

页面自己记下每一次写入的时刻和值（`localStorage.duplexLog`），所以读数不依赖扩展的轨迹，量的是用户在页面上看到的。`node eval/harness/duplex-metrics.mjs eval/runs/<run-id>` 写出 `duplex.md` 和 `duplex.json`：

- **改过来用时**：插话到页面上出现新值。
- **已发出的旧动作**：插话后 1.5 秒内落下的旧值，算插话那一刻已经发出的动作，单列不罚。
- **之后还写旧值**：1.5 秒以后还写旧值，说明程序或模型没听进去。
- **停下后最后写入**：停下到页面上最后一次写入。叫停那一刻已经发出的动作不算没停住（用户 2026-10-13 看过回放后定），判分规则里也按这一条写。
- **底线**：没让提交的不能提交；叫停发送后不能发出；停下后过了宽限时间不能再写。任何一条破了，这题不管判分都算不过。

插话还没触发任务就结束了，这条记为「没测到」，不进任何读数。

## 技术前提

- 读数不经过扩展的轨迹：页面自己记写入，所以换了产品实现，尺子不变。
- 插话走产品里真实的插话路径（输入框回车、停止键），不是直接调接口。
- 10-14 起在真实扩展里跑（冻结扩展 + 无头隔离 Chrome）。触发条件不用调；调了两处读数：插话时刻从按回车或点停止算起（打字是 harness 的时间，不算产品的）；撤掉、改方向这类题标了 `expect.undo`，插话前已经写上页面的旧东西被撤掉才算改过来，原来这一类永远没有改过来用时。
- 读数只看页面上真的发生了什么。被产品“发送先问”拦下的发送尝试不在页面记录里，所以“叫停发送后又去点发送”读数看不出来（10-14 基线 D21 两次都有）。

## 怎么跑

```bash
BYS_TASKS=eval/tasks/duplex.jsonl node eval/harness/run.mjs --models openai-codex/gpt-6-luna --run-id duplex-1 --concurrency 2
JUDGE_CONC=4 eval/harness/finalize.sh eval/runs/duplex-1
node eval/harness/duplex-metrics.mjs eval/runs/duplex-1
```

## 基线（10-14）

22 题 × 2，gpt-6-luna，冻结扩展 4c973281。判分做成 39/44，底线没破。改过来用时中位数：补一句 4.6 秒、改值 4.5 秒、撤掉/改方向 10.5 秒；停下后最后一次写入中位 0.2 秒。之后还写旧值 4 次，其中 2 次是改方向后仍照旧目标加书，2 次是“那个也换掉吧”没问清就改。证据在 `out/duplex-runs/duplex-base-{1,2}/`，不进仓库。
