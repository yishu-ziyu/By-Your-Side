# 任务: 问网页内容的结构（论证、分岔的流程、项目各部分怎么连）时，回答里画一张结构图，点方块能看到它出自网页的哪句原文

用户 10-18 看过左右对比预览（纯文字回答 / 结论加结构图，三个真实网页）后认可。执行过程仍是步骤行，不画成图：真实执行记录几乎总是一条直线，画成图不比列表多给信息，画计划又会把模型的说法当成事实。

## 规则

- R1 图等整张卡写完才画，一次画全：写的过程中只有一块空位，不边写边长、不重排。
  - 例子(正)：模型分四段写出图和两条原文，侧栏前 3 秒只有空位，卡片写完后图出现，方块数从第一帧起就是 5 — 谁检查：`scripts/acceptance/real-path/answer-diagram.mts`
  - 例子(反)：故意让图在卡片写完前就画，用例报「空位和图同时出现」「方块数 3 → 5」 — 谁检查：同上（10-18 弄坏两次都被拦住）
- R2 点有原文的方块，图下显示那句原文和出处；再点收起；键盘 Enter 也行；没写原文的方块点了不出东西。重开侧栏后照样能点。
  - 例子(正)：点主结论，图下出现「原文 · 开头」和英文原句 — 谁检查：同上
  - 例子(反)：原文里夹着 `<button action="say">` 这样的字，只按字显示，卡片上不多出按钮 — 谁检查：同上
- R3 字看得清：方块里的字显示出来不小于 11px。放不下时先换成左右排、长文字自动断行，还放不下就左右滑动，不把整张图缩成看不清的小字；侧栏拖宽拖窄时跟着变。
  - 例子(正)：真模型把 6 个分支排成一行，侧栏换成左右排，字 11px，右边可滑动 — 谁检查：`answer-diagram.mts --live`
  - 例子(反)：改之前同一张图缩到 4.2px，用例报失败 — 谁检查：同上
- R4 真模型会用、原文是真的：问结构时画图，每条原文都能在网页正文里逐字找到；一句话能答的问题不画图。
  - 例子(正)：gpt-6-luna 在 paulgraham.com/ds.html 上答论证结构，10-18 跑了 4 次，每次画出 7–11 个方块，共 27 条原文全部逐字在页面上 — 谁检查：`answer-diagram.mts --live`
  - 例子(反)：问「这篇文章是哪一年写的」，回答里没有图 — 谁检查：同上

## 技术前提

- 前提：Pele 1.6.0 能在侧栏页面里同步画出 SVG，单独打包、第一次出现图时才加载。结果：通过（只装流程图，构建产物 `diagram-engine.js` 约 190KB，未压缩）
- 前提：图的原文可以放进卡片 HTML 再整段消毒。结果：失败。DOMPurify 会删掉值里带 `-->` 的属性，流程图每条箭头都是 `-->`；改成编码后再放进属性。
- 前提：提示词能让真模型少画并排的方块。结果：失败。写了「最多 3 个并排」后 gpt-6-luna 仍画 6 个并排分支；这句话还会逼模型编出原文没有的分组，已删掉。宽度全靠侧栏处理（R3）。

## 边界与不做

- 执行过程不画成图。
- 只画流程图；其他图种（思维导图等）原样显示图的文字。
- 原文是否逐字出自网页只在评测里核对，侧栏不核对：侧栏拿不到模型读过的网页正文。
- 点方块不在网页上圈出原文。
