# 任务：点「新会话」后马上发的消息进新会话，不落进旧会话

10-08 删测试时发现这个问题（[记录](20261008-e2e-only.md)），用户 10-09 同意先复现、能复现再修。

## 规则

- R1 新会话建好前按发送，这条消息在新会话建好后自动发进新会话。模型收到的请求里没有旧会话的内容和文件。
  - 反例：消息进了旧会话，模型读到旧会话的文件。检查者：`session-durability.mts`（核心用例，`npm test` 跑）。
- R2 新会话建好前打的字照常留在输入框里，不被清掉。检查者：`new-conversation-draft.mts`。
- R3 新会话没建成、侧栏退回原会话时，挂起的这条不发进原会话，文字留在输入框。检查者：读代码（后台不回执的情况在隔离环境里造不出来）。

## 还没答上的问题

无。

## 技术前提

小实验 `scripts/probes/new-conversation-race.mts`：在只有一句话的轻会话里，点「新会话」后隔 0–2000 毫秒发消息，扩展重启前后都试过，消息都进了新会话。结果：轻会话里复现不出来。

## 边界与不做

- 不改新会话的创建方式，不加提示文字；发送键在新会话建好前仍可按。
- 不处理新会话建好前加的附件（切会话时附件照旧清空）。

## 原因

点「新会话」后，侧栏向后台要一个新会话。新会话建好之前，侧栏仍把旧会话当作选中的会话，发送也没有被拦住，所以这段时间里发的消息进了旧会话。

轻会话里这段时间只有几十毫秒，用户来不及发。旧会话里有大文件时（`session-durability` 里有一张约 1.9 MB 的截图），侧栏处理得慢，这段时间被拉长，屏幕上也一直显示旧会话，用户这时打字发送就会落进旧会话。

## 修法

侧栏在新会话建好前收到发送时，先记下「建好后发」，新会话建好、输入框里的字跟过去之后，立即发出。新会话没建成时，清掉这个记号。见 `extension/src/sidepanel/main.ts` 的 `sendAfterCreate`。

## 证据

2026-10-09，隔离无头 Chrome、真实扩展、脚本模型：

- 不带修复：`session-durability` 失败在「新会话不能读旧文件」，模型收到的请求里带着旧会话的全部内容和旧文件。另一次不带修复的运行先失败在更早一步（打开文件查看页时读页面为空），与本问题无关，记为用例偶发不稳定。
- 带修复：`session-durability` 通过；`new-conversation-draft` 通过；`npm test` 10/10 通过；`npm run check` 通过。
- 回归用例里去掉了 10-08 为绕开问题加的「等侧栏换完再发」，现在它直接测这个场景。
