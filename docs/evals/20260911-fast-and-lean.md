# 任务：单动作任务 ≤2 轮模型调用；模型面与用户面各收一刀

来源：用户 2026-09-11 在 claude 会话 `fc55696b` 批准三件事——①把「快而果断」定成硬指标；
②砍模型看到的面（工具合并、提示词瘦身）；③砍用户看到的面（单一运行指示、一条状态行）。
本文件是实施前冻结的标准。

**目标（用户可观察）**：一个页面已打开、目标明确的单动作任务（例如「把视频暂停」），
模型最多花 2 轮：第 1 轮观察并动手、第 2 轮收尾；首个改变页面的动作在收到请求后 5 秒内发生。
模型不再面对一堆同义工具；运行中的面板只剩一个「在跑」指示和一条「正在做什么 · 耗时」。

**范围**：`agent/src/tools.ts`（模型可见工具定义）、`agent/src/prompt.ts`、`agent/src/fleet.ts`
与 `agent/src/conversation-runtime.ts`（工具挂载）、`extension/src/sidepanel`（运行态渲染）。
扩展 RPC 名、控制闸门与账本语义不变。

## 完成标准

### A 快而果断（真实路径）

- [ ] A1. 单动作任务（页面已打开、目标明确、一步操作）模型轮数 ≤2，首个改变页面的动作 ≤5s。— 谁检查: 人（`scripts/acceptance/fast-turn-run.mts`，真模型 + 隔离浏览器，前后各 3 次）
- [ ] A2. 完成后一句话收尾，交付一次、不重复。— 谁检查: 同上

### B 模型面

- [ ] B1. 模型可见工具：无 worker ≤23、有 worker ≤27（现状 32）。— 谁检查: npm test（新增工具面测试）
- [ ] B2. 系统提示词 ≤15,000 字符（现状 17,418）。— 谁检查: npm test
- [ ] B3. 合并后行为不回归：标签页/标注两个合并工具在真实扩展路径可用；危险点击仍被拿住；写工具闸门集合不回归。— 谁检查: npm test + 隔离 harness

### C 用户面

- [ ] C1. 运行中只有一个「在跑」指示（光球与像素格二选一）。— 谁检查: 人（隔离面板截图 + 真实任务观感）
- [ ] C2. 状态卡、胶囊、思考块、工具 chip 收敛为一条「正在做什么 · 耗时」，细节可点开。— 谁检查: 同上

## 边界与不做

- 合并只发生在模型可见层：扩展 RPC 名（`list_tabs`/`switch_tab`/`clear_marks`…）、控制闸门
  `WRITE_TOOLS`、账本 `PAGE_IDENTITY_TOOLS` 的语义不动，避免波及执行层。
- 不重写面板骨架，不动语音、技能、记忆、多成员协作的功能路径。
- 不改危险确认机制与不可信页面内容边界。
- 本轮不提交、不推送、不重载用户扩展。

## 未跑 / 未验证（预期）

- 单动作 2 轮是提示词级约束，模型不保证每次都遵守；用 3 次小样本记录实际分布，不宣称稳定达标。
- 用户面改动的主观观感由用户裁决，机器只给结构事实（几个指示、几条状态行）。

- B1 ✅ / B2 ✅（`agent/test/tool-surface.test.ts` 固定上下限）。**标准修订**：原定 ≤22，实施中把 `take_tab` 留在常驻集合（23）。理由有二：它管的是跨会话页面所有权，不是"请人"；且 S1 起「写能力不完整时通用 JS 一并拒绝」的闸门把它算作写工具，若按 worker 数量隐藏，会让这条已验证的安全闸门在无 worker 的常态下失效或被迫放宽（原记录与理由见[开发日志](../devlog/20260911-02-模型面收窄与单动作轮数.md)）。隐藏的协作工具是 post / await_message / list_workers / stop_worker 四个。
- B3 ✅ 真实扩展路径（隔离 headless Chrome + 真实构建，`scripts/acceptance/merged-tools-run.mts`，7/7 PASS）：`tabs` 的 list/active/open/switch/close 各自落到对应 RPC 并真实生效（关闭后 `chrome.tabs.query` 确认页面消失）；`mark` 画标注后页面上真的挂出标注画布、`mark({clear:true})` 走 `clear_marks` 回执。

### A 组：单动作任务（真模型 MiniMax-M3 + 隔离浏览器，同一 case 各 3 次）

case：页面已打开、视频正在播放，用户说「把视频暂停」。脚本 `scripts/acceptance/fast-turn-run.mts`。

| | 模型调用轮数 | 首个页面动作 | 总耗时 | 交付次数 | 页面真的暂停 | 工具序列 |
|---|---|---:|---:|---:|---|---|
| 改前 | 4 / 4 / 5 | 4991 / 3022 / 3322 ms | 8816 / 7603 / 9563 ms | 1 / 1 / 1 | 3/3 | snapshot → click（第 3 次多一轮 read_element 复核） |
| 改后（最终代码，含 take_tab 常驻） | 5 / 4 / 4 | 2581 / 5007 / 4698 ms | 8246 / 9453 / 11424 ms | 1 / 1 / 1 | 3/3 | 第 1 次多一轮标签页接管，其余为 snapshot → click → 交付（最后是 SDK 收尾轮） |
| 改后（两组共 6 次，含上面的中间版本） | 4 / 4 / 4 / 4 / 5 / 4 | 2723–5007 ms | 6552 / 7453 / 8246 / 9453 / 11424 / 13191 ms，中位数 8850 | 6/6 各 1 次 | 6/6 | 结构同上 |

- A1 ❌ **未达标**：单动作仍是 4–5 次模型调用（改前 4–5 次，没有下降）。实测结构是「观察 1 + 动作 1 + 交付 1 + SDK 收尾 1」——最后那轮是 SDK 在最后一个工具结果后必然再问一次模型；要再往下压只有两个真实杠杆（见下）。首个页面动作 ≤5s 基本成立（改后 2581/5007/4698 ms，其中一次贴着 5s）。

**总耗时读数的更正（2026-09-11 晚，用户追问后补测）**：改前 3 次 8.8 / 7.6 / 9.6s（中位数 8.8s），改后 6 次 6.6 / 7.5 / 8.2 / 9.5 / 11.4 / 13.2s（中位数 8.85s）。中位数基本不动；方差主要来自模型每轮的思考延迟。逐轮 trace 归因（改后样本）：工具执行合计约 0.6s（snapshot 10–23ms、click 585–614ms、tabs 8ms、交付 1–3ms），其余全是每轮模型延迟（单轮 0.7–3.0s，其中一次交付轮 5.8s），交付后的收尾轮单独占 1.1–2.7s。所以「改后更慢」是 3 次小样本抽到慢样本（13.2s）造成的读数，不是改动引入的固定开销；改动引入的真实额外成本只有一处：最终版把 `take_tab` 放回常驻列表后，1/3 的运行先花一轮「接管标签页」（2.5s 换一个 8ms 的工具调用）。
- A2 ✅：三次都恰好交付一次，一句话；不再出现多余复核轮（改前有一次多花一轮 read_element）。
- 未达标原因与下一步（不改写本次结论）：① 模型没有按提示改用 `browser_run` 把「观察+动作」折成一轮，仍分两次调用；② 交付后的 SDK 收尾轮目前无法在工具层取消。要么预注入当前页观察（模型第一轮即可动手），要么在运行时判定 finding 交付后收尾，二者都动到当前架构，留给用户裁决。

**后续（2026-09-11 晚）**：用户裁决"两个都改，并做对照"。预注入与交付后收尾已实现，结果见[本轮验收](20260911-two-levers.md)：轮数中位 4 → 2、总耗时中位 13.5s → 5.3s。

### C 组：用户面（真构建面板 + 隔离 headless Chrome，`scripts/acceptance/run-status-ui.mts`，10/10 PASS）

- C1 ✅：运行中只有一个「在跑」指示——像素格 loader 整体移除（DOM 里 `.px-wrap/.px-grid` 为 0），状态行左侧是光球；`pixelDelay`、`.px-grid`、`pxSettleOut`、`settleOut()` 等随之删除。
- C2 ✅：状态行收成一条「正在做什么 · 耗时」（实测 `正在点击「暂停」` + `0.7s`），细节（思考块与工具 chip）默认收起、点开可见（实测 chips 2 个）；结束后落定为 `查看执行过程 · 耗时 0.8s`。
- 截图：`running.png`、`done.png`、`expanded.png`（隔离实例目录内）。
- **观感仍需人裁**：合成事件渲染，不等于真实任务里的密度与节奏；用户真机看过才算验收。
