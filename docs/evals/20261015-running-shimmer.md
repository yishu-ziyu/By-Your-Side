# 任务: 助手在干活时看得出它在动，回答的位置不是一片空白

用户 10-15 看到：运行中只有“正在思考 2 秒”这一行静止的字，过程行下面整片空白，直到第一个字出来。用户在借鉴候选页里选了第 2 项的“扫光字”和第 3 项的骨架。

## 规则
- R1 助手在想、在做一步时，过程行的标签（“正在思考”“正在定位当前页”这类）有一道扫光从左往右走；后面的秒数不扫，照常能读。助手在等你（确认发送、接管、教学等你点）时，标签不扫、回答位置也不放骨架。
  - 例子(正)：发一句话，模型想 2.5 秒、做一步、再想 1.5 秒：这期间标签一直在扫光，秒数是静止的字。 — 谁检查：`scripts/acceptance/real-path/running-shimmer.mts`
  - 例子(正)：助手点「发送」后过程行写“等你在网页上确认发送”：这期间标签静止、没有骨架。 — 谁检查：`running-shimmer.mts`
  - 例子(反)：标签是静止的字；或秒数也被扫得忽明忽暗；或等你确认时还在扫光。 — 谁检查：同上，去掉扫光动画、或等你时不停扫光，跑同一用例都失败
- R2 第一个字出来之前，回答的位置有三行在斜向扫光的骨架；第一个字出来时骨架淡掉、条不再扫，回答落在骨架第一条的位置，不往下跳。这一轮出过字，骨架就不再回来。上一轮出错后，下一轮照样有骨架。
  - 例子(正)：想的那几秒，过程行下面有三条长短不一的灰条在扫光；出字 400ms 后骨架看不见，回答的排版位置和骨架一样，骨架拿掉时回答不动。 — 谁检查：`running-shimmer.mts`
  - 例子(反)：想的时候过程行下面空着；出字后骨架还挂着，或回答先被骨架顶下去再跳上来。 — 谁检查：同上
- R3 骨架只陪这一轮还没回答的时候：出错卡、卡片一出来就收起，这一轮结束后一定不在。
  - 例子(正)：模型直接报错，出错卡出来时没有骨架，结束后也没有。 — 谁检查：`running-shimmer.mts`
  - 例子(反)：出错卡下面还挂着三条灰条。 — 谁检查：同上
- R4 系统设了“减少动态效果”时，标签和骨架都不动：标签是普通的字，骨架是三条静止的灰条。
  - 例子(正)：打开少动效，发一句话：骨架照样占着回答位置，标签和骨架上没有在跑的动画。 — 谁检查：`running-shimmer.mts`
  - 例子(反)：少动效下标签还在扫光。 — 谁检查：同上

## 技术前提
- 前提：扫光用遮罩只调标签的透明度，不改字色，所以动词墨色、对象浅灰在扫光时照样分得开；深色模式不用另配颜色。 小实验：用例里的深色模式截图 结果：通过

## 边界与不做
- 过程行原来的墨点心跳和秒数闪动保持原样。
- 回答一出字过程行就让位给正文，这是原来的行为，不在这里改。
- “出过字骨架不再回来”只在团队带头的会话里会碰到（那里开场话会先占回答位置、再收进过程）；用例没跑这条路径，靠代码复核。
- 只有卡片、没有正文就结束的一轮：卡片出来之前骨架会先出现一会儿，因为开始时不知道这一轮会以卡片结束。
