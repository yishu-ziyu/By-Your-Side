# 任务: 模型直接写正文回答时，侧栏也一个字一个字出来；设置里能选到能力表登记的模型

[当前状态](../STATUS.md)

## 起因（10-02 真人试用）

- 日常扩展选 MiniMax-M3.1，问「这个观点是什么意思啊？」：模型 28.0 s 开始输出、40.9 s 结束（诊断记录），侧栏等整轮结束才把整段一次放出来。
- 原因：主会话按「交付工具」流式显示；模型直接写正文时，正文被放进默认折叠的「执行过程」（`extension/src/sidepanel/main.ts` `appendLeadDelta`），整轮结束由宿主一次性交付。显示效果取决于模型选哪条路。
- 设置的模型列表只列模型库登记的模型，能力表里登记的 MiniMax-M3.1-Flash-Preview 选不到；10-02 只能直接写存储配置。

## 用户裁决（10-02）

选 A：正文直接流式显示；如果这段只是过渡话、之后又去操作网页，它自动收进「执行过程」。

## 完成标准

- [x] 1. 主会话里模型直接写正文（不走交付工具）时，正文在回答位置随生成逐段出现，首段出现时间与模型首个正文增量相差不超过 0.5 s — 谁检查: 机器，真侧栏 + 脚本模型
- [x] 2. 同一轮里这段正文之后模型又调用了工具：这段正文移入「执行过程」，回答位置不留重复内容；最终回答只出现一次 — 谁检查: 机器
- [x] 3. 走交付工具的回答、停止、出错、插话时的显示与现在一致（不重复、不丢） — 谁检查: 机器，现有测试
- [x] 4. 设置里服务商 MiniMax 下能选到 MiniMax-M3.1-Flash-Preview；列表来自能力表与模型库，不按名字猜 — 谁检查: 机器
- [ ] 5. 日常扩展用 M3.1 问一个页面问题，回答一个字一个字出来 — 谁检查: 人

## 边界与不做

- 不改交付工具的流式与核对流程；不改目标核对「先核对再显示」的裁决（用过网页工具时）。
- 不改思考过程的显示。

已知边界：
- 一轮里调过任何工具（包括 send_user_message 的开场确认）之后，正文仍按原样只进执行过程、由宿主核对后交付；宿主的「先核对再显示」只看非记账工具，侧栏这里更保守。
- 停止、出错时，已经显示在回答位置的半截正文会挪进执行过程（与改前最终样子相同），用户会看到它从回答位置消失。
