# 任务: 出错后用户能修掉原因、不用重述任务，助手从出错处自动继续（预览原型）

预览原型：`docs/previews/error-states.html`（浏览器直接打开，顶部切换 401 / 429 / 断网三场景）。
状态：预览已经用户目测认可（2026-10-06「还行的不错」）；以下是给工程实现的验收标准，产品代码尚未改动。

## 规则

- R1 错误卡按错误类型给动作，不再只有「继续原任务」一个按钮
  - 例子(正)：401 key 无效时，动作是「去换 key」「仍然重试」；429 限流时，动作是「换一个模型 ▾」「稍后重试」；断网时，动作是「重试」 — 谁检查：人（预览已演示）/ 工程实现后 Playwright 走三条路径
  - 例子(反)：key 填错时只给「继续原任务」，点了继续报错 — 谁检查：人
- R2 换 key 在对话内完成，不跳设置页；保存前必须先测试连接通过
  - 例子(正)：点「去换 key」→ 底部 sheet 升起 → 粘贴新 key →「测试连接」通过 →「保存并继续」才可点 → 保存后自动续跑 — 谁检查：Playwright（预览已跑通，receipt 文案「出过错 · 已换 key，已从出错处继续」）
  - 例子(反)：测试失败只露原始 JSON，或没测试就放行保存 — 谁检查：人
- R3 修复后助手从出错处自动继续，不要求用户重述任务；恢复后留一条回执说明出了什么错、怎么修的
  - 例子(正)：半截流式回答灰掉定格，修复后从该处续写完整答案，末尾出现绿色回执「出过错 · …已从出错处继续」 — 谁检查：Playwright 断言 receipt 出现且续写完整
  - 例子(反)：修复后对话停住，等用户自己再发一遍同样的话 — 谁检查：人
- R4 429 的「换一个模型」入口就在错误卡上，文案与入口一致
  - 例子(正)：点「换一个模型 ▾」弹出模型菜单，选中后自动重试 — 谁检查：Playwright（预览已跑通 DeepSeek 路径）
  - 例子(反)：文案说「在下方换一个模型」但下方没有入口（现状复现于 2026-10-06） — 谁检查：人
- R5 暂时修不了的错（断网）明确说清状态和下一步，重试有反馈
  - 例子(正)：断网点「重试」，网络未恢复时卡片抖动提示；恢复后自动续跑 — 谁检查：Playwright（预览已跑通）
  - 例子(反)：点了没反应，用户不知道是没点上还是没网 — 谁检查：人

## 还没答上的问题

- Q1 「仍然重试」（401 时不换 key 硬重试）是否保留？预览里留着用于演示边界，产品上可能多余 — 待用户裁决
- Q2 429 自动重试的倒计时秒数与退避策略（预览固定 4 秒）— 工程实现时按真实限流语义定，不阻塞预览结论

## 技术前提

- 前提：错误类型（401/429/网络）在侧栏可区分，且续跑能从断点恢复 小实验：预览原型 `docs/previews/error-states.html` 用模拟流式 + 断点续写演示完整闭环 结果：通过（Playwright 四条路径：401 换 key、429 换模型、429 稍后重试、断网重试，receipt 均出现，无 pageerror）
- 前提：设置页「测试连接」失败只给人话，原始 JSON 收进技术详情 现状：`extension/src/settings/main.ts:617` explainFailure 把最多 160 字原文直接拼在人话后面 — 工程实现时随本任务一起改

## 边界与不做

- 不改成错文案的语气与人话体系（现有文案已说人话，保留）
- 不做错误上报/遥测，不做「联系支持」入口
- 不覆盖模型侧不可恢复错误（如余额不足）的支付引导
