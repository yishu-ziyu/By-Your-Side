# 任务：浏览器每一步之后采用同一套继续、恢复、核查与交付判断

## 完成标准

- [x] 1. 由当前任务状态、真实结果账本、在途工具和动作后读回产生唯一下一步；覆盖继续、换方法、核查未知、询问用户、核对结果、交付、等待和停止。— 谁检查：状态表单测
- [x] 2. 主 Agent、成员写入闸门和每轮模型上下文复用同一判断；暂停、取消和重启检查点优先，不能靠改工具或再次登记绕过 unknown。— 谁检查：生产执行入口回归
- [x] 3. 已明确未执行的失败可观察后换方法；连续失败边界仍有界，达到边界后停止重试并如实报告。— 谁检查：失败策略与状态迁移回归
- [x] 4. 工具成功回执不能直接放行完整交付；有页面写入时必须取得动作后的真实读回。其他页面、旧读数、失败或截断读数不消除待核查；关闭标签页用真实标签列表核对已知目标消失。— 谁检查：事件序列测试
- [x] 5. 有 pending、blocked、unknown 或尚未读回时，完整交付被拒绝；允许显式报告部分结果并收束，不因未完成项而无限续跑。纯问答、只读研究不强加写入核查。— 谁检查：正式交付工具与生产接线测试
- [x] 6. 新任务、用户修订、跨会话、重启及迟到事件不污染当前判断；不新增模型调用或第二份任务数据库。— 谁检查：隔离、恢复、上下文与持久化回归
- [x] 7. 类型、工程回归、构建、边界检查和差异检查通过；记录真实浏览器验证未执行的部分。— 谁检查：主代理

## 边界与不做

- 当前 Chat 会话直接使用 DevSpace 修改本机 checkout；保留 P0.1–P0.2 与翻译修复。不调用开发子代理或模型 API，不安装依赖、不重载日常扩展、不提交或发布。
- 沿用 TaskProgress / TaskResultBook / Pi 循环 / send_user_message，不引入第二个调度循环；下一步是程序按事实计算的决策，不是模型自行填写的状态。
- 程序检查读回的来源、先后和页面范围；读回是否满足自然语言目标仍由 Agent 对照要求判断。`successVerified` 继续为 false，不把一次观察或助手报告升级为通用业务成功证明。
- 真实浏览器故障矩阵、跨日页面重新定位和留出任务成功率继续由 P0.4–P0.5 验收。

## 实现前核对

本地 main@7e58a76，工作树已有上一轮 P0 与翻译修复。当前 ProductContext 主要用提示词解释账本；主会话与 worker 各自检查 unknown；finding 只凭 pending/unknown 决定是否 terminate，没有统一的读回与部分交付规则。本轮以这些生产入口为接线与测试对象。

## 实现与证据

`shared/task-next-step.ts` 是唯一决策函数，TaskProgress 用真实回执和内存中的读回先后关系计算 nextStep；ProductContext 每轮替换旧投影，主会话和成员执行闸门复用同一函数。nextStep 是可解释的执行建议与边界，不是第二个任务循环，也不是模型提交的成功标记。

不确定写入优先于后续写入。原写入有完整、同成员、可识别页面的基线时允许走既有核查工具；没有基线则要求人工核对或明确交付部分结果。普通失败仍可依据观察换方法，连续相同失败沿用原三次上限并进入统一决策。通用脚本和参数相关的网络请求失败不能因缺少预登记而丢失 unknown；可写 tabs/fetch 通过回执上的 effectful 保留跨重启效果分类。账本达到上限后拒绝无法记录的新写入，不静默放行。

`TaskReadback` 只接受实际成功读取产生的内部观察，按执行成员、页面和操作序列核对；读请求在写入前发出，即使回执更晚到也不算写入后证据。打开新页后读取新工作页，关闭已知标签页后读取标签列表；列表不能冒充页面内容基线。成功但没有正文的媒体属性读取也可作为读回。页面内部目标的语义对应与最终要求仍由 Agent 核对，程序不把一次读数当作业务成功证明。

`send_user_message` 的 finding 增加 outcome（默认 complete）；当前事实未满足完整交付边界时拒绝 complete。partial 会附上程序生成的未完成说明、交付已知结果并结束本轮，但不会修改 pending/blocked/unknown。自动补交付也受同一边界约束，不能另调模型把未核对的写入改写成成功。任务结束但仍未完成时，窄表达“继续原任务”不再清空账本重建任务；原重启检查点的主动续接入口保持不变。

最终回答的参数生成发生在同批工具执行之前，即使生成时状态允许交付，也不能据此提前说成功。因此 finding 改为执行校验通过后才进入现有语音输出；ack 仍可提前流式回应。未增加模型调用，TTS 音频仍按原流式通道播放。真人首声与整体体验未在本轮验收。

### 失败保留与回归

首次新增状态/交付用例共 16 项，旧实现 **14 失败、2 通过**。除缺少新增决策字段外，实测旧交付工具在存在 pending 或写入后没有读回时仍接收最终报告；unknown 下的部分报告不能结束，且在途浏览器步骤也没有统一最终交付限制。

整合过程中保留了旧流式测试的失败：`streaming-voice` 与 `session-run-tail` 原来从尚未执行的 finding 参数期待语音。现在分别验证生成阶段不播、校验后的正式事件仍播，并保留失败交付与空响应反例。`user-delivery-runtime-evaluator` 原来期待点击后无读回仍由模型补结果；现在分别验证无读回只出部分报告、有真实读回仍能补有来源的正式结果。第一次完整检查的两项旧预期失败记录保留在 `out/acceptance/p0-next-step/check.log`，没有将其记作通过。

最终 `npm run check` **退出码 0**：普通回归 **201 个文件、1892/1892 项**（本轮 next-step 专项 **33/33**），规模测试 **2/2**，TypeScript、扩展构建与 **186 个生产文件**边界检查通过。原始记录：`out/acceptance/p0-next-step/check-final.log`。`git diff --check` 通过。

## 尚未验收与后续边界

本轮不运行真实模型、日常扩展、真实 Chrome 操作或 native-host 杀进程验收，也不提交、推送或发布。证据来自生产决策/会话/调度/交付入口、组合工具子步骤、协议、持久化与回归，不代替真实任务成功率。

不宣称通用语义去重已经解决：不同选择器/不同实现是否指向同一已完成业务动作，以及宿主退出前没有回执的所有辅助脚本效果，仍需恢复矩阵与真实任务验证。关闭页的原身份缺失时保持未核验，不猜已关闭目标。部分任务结束后的自然语言修订续接也不等同于重启检查点续接；本轮只阻止窄“继续”表达隐式清空账本。P0.4–P0.5 仍未完成。
