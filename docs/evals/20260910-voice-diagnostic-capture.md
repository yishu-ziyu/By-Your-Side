# 任务: 在日常 Chrome 侧栏记录并回放同一次语音的输入与转写链

2026-09-10 用户已同意诊断优先，并要求一步一步来。本轮是第1步：先让一条输入的记录可检查；三路同源真人对照与定位后的修复继续保留为后续步骤。用户明确要求子任务使用Go DeepSeek V4.1 Flash/Max，优先jcode，其次Pi；当前主代理负责标准、审查与真实验证。

## 完成标准
- [ ] 1. 当前ChromeMain扩展侧栏有显式诊断入口；手动开启且提示正在录音/不执行网页操作，停止后记录仍可查看、播放、导出或清空；普通语音入口行为不变。— 主代理真实浏览器；用户判断可用性。
- [ ] 2. 诊断记录保存classifier之前连续24k PCM（浏览器AEC/NS/AGC之后），在ArrayBuffer转移前复制；保留voiceId、样本序号、实际采样率/track settings，不把检测后声音叫连续收音。— 定点样本逐字节检查。
- [ ] 3. C1来自StepVoiceSession真实socket.send成功路径的input_audio_buffer.append/commit，附本次turn/段范围和event_id，并保留上游committed item_id。发送失败不得记为已发送。— 主代理定点桩与真实服务事件分别验证；不互相冒充。
- [ ] 4. 保存旧turn过滤之前的ASR原始转写、实际转发text事件、实际DOM最终显示；同一voiceId/turn/item_id能关联。新一轮开始后返回的旧转写仍出现在诊断记录中，正常输入/路由的旧轮行为此轮不改。— 延迟旧ASR反例+浏览器DOM检查。
- [ ] 5. 诊断模式服务端锁定不调用任务route/steer、不发出网页动作；客户端必须收到同voiceId的诊断模式确认才能送音频，旧backend无确认时失败关闭，不能仅凭前端开关或提示词保证不执行。— route/steer调用计数0及缺确认反例。
- [ ] 6. 记录有容量/时长上限；传输错误、重连缺口、截断、尚未返回的转写显示未完成而非完整；不自动刷新、播放、上传录音，不记密钥。录音默认仅内存，导出由用户点击，清空释放音频对象。— 定点生命周期与真实控件检查。
- [ ] 7. 相关定点、typecheck、build通过；主代理独立复查diff；ChromeMain在线构建身份和实际诊断控件路径留证。普通既有修改保留。— 主代理。
- [ ] 8. 用户真麦克风说一条核对过的话，实际ASR返回后能听两份声音、看三处文字，身份一致。— 用户说话/核对；主代理比对证据。没有真人样本时明确待采样，不能宣称语音已修复。

## 范围与不做
只加诊断记录与必要禁动作接线，不调Silero/RMS/前音/断句/回声/滤词，不修迟到输入或提前接话超时，不换语音供应商，不重构StepVoiceSession。不改既有光标、布局体系、人格或任务状态。
先实现当前B路径的一条输入取证。R/A/B对照不在本次第1步实现，后续复用同一记录链；不可用独立ASR页面绕开StepVoiceSession的旧轮过滤。
不提交/推送。不采集环境声音直到用户手动开启诊断；自动机器检查明确标记合成/桩。不能把build、子代理报告或合成检查当真人体验通过。
