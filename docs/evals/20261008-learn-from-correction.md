# 任务: 在网站 A 纠正 Agent 一次，看它记下的是带适用条件的知识还是操作步骤，到网站 B 能不能判断该不该用

来由：[导出迁移对照](20261008-export-transfer-ab.md) 两轮给了初步信号：直接给知识不乱迁移，直接给步骤会乱迁移。那两轮的记忆是实验种进去的。用户 10-08 选下一步验证「学习」这一步：知识要由 Agent 从真实纠正里自己提取。只是初步信号，不能说已证明知识优于动作。

分工（用户 10-08）：用户定产品目标与最终验收；代理定工程方案、实现与测试。

## 实验设置

实现：[`scripts/probes/export-transfer/learn.mts`](../../scripts/probes/export-transfer/learn.mts)，沿用对照实验的两个网站、任务原话和判分。

- 走产品现有的学习链路，不改产品：用户纠正 → 模型提取一条做法 → 侧栏问「要我记住吗」→ 用户点「记住」→ 保存。这对应 OOPSI 定的「AI 提取 → 用户确认 → 保存」。
- 纠正只说问题，不教步骤：「不对，你只导出了当前页的 20 条，我要的是全部 200 条。」原因：要看 Agent 自己提取出什么。
- 两个网站用不同域名。原因：产品按域名划分「这个网站」的记忆，同域名会让网站 A 的记忆假装到了网站 B。
- 用户确认这一步分两种：
  - **照默认记住**：卡片给什么范围就记什么。看产品默认行为。
  - **改成所有网站再记住**：模拟用户确认「这条到处适用」。只有这样记忆才到得了网站 B，才谈得上判断该不该用。
- 每种各跑 5 次，只统计网站 A 上复现了错误的那几次。修订（10-08，跑前）：原定各 3 次；试跑时 Agent 第一次就做对，错误不是每次复现。
- 每次运行一个新的隔离 Chrome、空记忆。网站 A 上先犯错、纠正、记住，再到网站 B 依次做 T2、T3（各开新对话）。

## 规则
- L1 先复现错误：网站 A 第一次导出的不是全部 200 条。不成立的那次记「未复现」，不计入后面几条。
  - 例子(反)：Agent 第一次就导出了 200 条 — 未复现 — 谁检查：脚本（下载文件）
- L2 纠正后提取出一条做法：侧栏出现「要我记住吗」卡片，卡片里有一条规则。
  - 例子(反)：纠正后没有卡片，或卡片没有规则文字 — FAIL — 谁检查：脚本（侧栏）
- L3 提取的是知识，不是步骤：规则写了适用条件或结果核对（例如「默认只导出当前页时」「核对条数」），且没有网站 A 的具体按钮步骤（「全选」「选择全部 200 位」）。
  - 例子(反)：「以后在这个网站导出，我都先勾全选再点选择全部」— 步骤 — 谁检查：脚本先按词预判，代理逐条读原文定稿，原文全部交用户复核
- L4 到网站 B 判断对：记忆到了 B 的模型请求里时，T2 导出 200 条且没勾「全选」，T3 只导出 20 条。记忆没到 B 时，记「没到达」，不算判断对，也不算判断错。
  - 例子(反)：B 站 T2 先勾「全选」再去找「选择全部 200 位」— FAIL — 谁检查：脚本（网站记录 + 下载文件 + 请求原文）

产品目标达成要同时满足 L2、L3、L4，而且是在记忆确实到了网站 B 的那几次。脚本跑完不等于目标达成。

## 结果（2026-10-08，gpt-6-luna）

跑了三批。第一批收卷过早（见[对照实验的修订](20261008-export-transfer-ab.md)），只保留其中网站 A 上的提取结果。

| 规则 | 结果 | 依据 |
|---|---|---|
| L1 复现错误：第一次导出不是 200 条 | 第一批 8/10，第二批 2/10 | 网站记录的第一次导出 |
| 同一轮做完后最终导出 200 条 | 第二批 10/10 | 下载文件 |
| L2 纠正后提取出一条做法 | 8/8 | 第一批 |
| L3 提取的是带条件的知识 | **0/8**：8 条都没有按钮步骤，也都没有适用条件或结果核对 | 第一批，代理逐条读原文 |
| 默认范围 | 5/5 只存给网站 A，到不了网站 B | 第一批 |
| L4 网站 B 判断对 | 8/8，记忆每次都到了 | 第三批：把第一批里改成「所有网站」的 4 条规则原样种进记忆 |

提取出的 8 条规则原文（第一批 `result.json` 的 `rule`）都是一个模子：「以后在这个网站导出列表时，我会（先确认 / 选择 / 确保）导出全部数据，而不是只导出当前页。」脚本按词预判把 all-2（「先确认导出范围为全部数据」）标成知识；人工复核不算：它说的是「先把范围定成全部」，没有「什么情况下」，也没有做完后核对。

### 分析

1. **错误时有时无，而且产品会在同一轮里自己补救。** 没有记忆时，第一次导出只导了当前页的比例波动很大（第一批 8/10，第二批 2/10，重跑 T1 对照组 2/2）。但只要让产品做完一整轮，最后都是 200 条：核对发现没做完，自己接着做。脚本原来的 L1 判的是最终文件，口径错了，第二批因此判成「10 次未复现」并跳过了纠正，这一批没有提取数据。
   - 所以在这个案例里，学习能带来的只可能是「第一次就做对、少走回头路」，不是「最终做对」。这正是用户 10-08 定的学习成功标准（第一次就判断正确）。
   - 已有的一点相关数据：网站 A 上，种了手写知识的 4 次里第一次就导出全部的是 3 次；同期无记忆 24 次里是 10 次。样本太小，只能当信号。产品自己提取的规则在网站 A 上第一次做得对不对，这轮没测。
2. **提取的不是步骤，也不是带条件的知识，是「目标」。** 规则只说要什么（全部数据），不说什么时候适用、怎么核对。没有照搬网站 A 的按钮，所以到了网站 B 不会乱套步骤：第三批 T2 没有一次勾「全选」，T3 也都只导出 20 条。代价是规则里没有可迁移的判断方法，和对照组相比看不出改善（对照组同样全对）。
3. **默认范围把迁移整个挡住了。** 卡片默认只存给网站 A，按产品默认，网站 B 永远用不上，好坏都不迁移。只有用户主动切成「所有网站」才到得了 B。
4. **文字和范围不一致。** 用户切成「所有网站」后，规则原文仍写「在这个网站」。网站 B 上 Agent 照样用了它，没有因为这句话而不用。
5. 推测（未验证）：提取提示词里的例句是「以后在这个网站导出，我都先选全部再核对条数」，8 条规则的句式与它高度一致，可能是例句在塑造输出。

### 失败案例

- 第一批 all-1、all-4 的 T3「没导出」：收卷过早，产品其实还在续做。作废，不是 Agent 的错。
- 第一批 default-1 的 T2：Agent 没点到网站导出，下载了网页本身（「下载.html」）。同样收卷过早，作废。
- 第三批 all-4 的 T3：文件正确，但 Agent 说「无法读取已保存的 CSV」，请用户上传文件核对条数。归入独立问题「看不清下载结果」。

### 结论

- 产品目标（L2、L3、L4 在记忆到达网站 B 时同时满足）**没有达成**：L3 是 0/8。
- 提取出的「目标型」规则在网站 B 上是安全的（不乱迁移）。但网站 B 默认就导出全部，无记忆时第一次也做对，正向迁移在 B 上测不出来。
- 第一批的纠正是在第一次回答和产品续做之间那几秒发出的。卡片和规则都是真实产品输出，提取数据可用；但这个时机是脚本造成的，真实用户会不会在那几秒插话，没有证据。
- 证据：第一批 `out/probes/export-transfer/2026-10-08T11-24-28Z-learn/`，第二批 `…/2026-10-08T11-45-50Z-learn/`，第三批 `…/2026-10-08T11-53-12Z-learned-on-B/`。均不进仓库。

## 边界与不做
- 不改产品的提取提示词、记忆范围规则和卡片界面；发现问题只记录。
- 不测「历史知识与当前明确要求冲突时听谁的」。
- 每种确认方式只有几次复现，只能给信号。
