# 任务: 点「发送」前停下，等用户在网页上确认

10-09 用户看过玻璃确认胶囊原型（#171）后决定：收不回来的操作先停下问用户，第一版只做「发送」。这部分收回了 10-04「网页操作不弹批准卡」的决定，见[网页操作不再逐次确认](../browser-confirmation.md)。预览：本地「发送前确认：一个具体的例子」页（未入库）。

## 为什么

- 10-04 去掉批准卡以后，网页里藏的指令可以让助手在用户已登录的网站上发消息，没有任何一步拦住。发消息发出去就收不回来。
- 用户只想在收不回来的时候被打扰一次，不要每一步都问。

## 用户的选择

- 第一版只拦「发送」按钮（10-09）。聊天框里按回车发送，第一版拦不住，见「已知缺口」。
- 确认长在网页上，样子借玻璃胶囊原型；原型用的玻璃库折射不到第三方网页的背景，所以用浏览器自带的背景模糊来做（库调研见本页「调研」）。

## 规则

- R1 助手点一个名字以「发送 / Send」开头的按钮时，程序在真正点下去之前停住，在网页上问用户。用户点「发送」才点；点「不发」、点「停」、离开或关掉这个网页、2 分钟没理，都不点，草稿留着。助手点不到这块确认。
  - 例子(正)：练习页的「发送」按钮，脚本模型去点，用户确认前服务器收到 0 条；用户点「发送」后恰好 1 条 — 谁检查：`send-confirm.mts`
  - 例子(正)：用户点「不发」，服务器 0 条，助手收到的结果写明用户没让发 — 谁检查：同上
  - 例子(正)：等确认时用户 40 秒后才点「发送」，这一步不被记成「结果未知」，服务器 1 条 — 谁检查：同上
  - 例子(反)：去掉停住这一步，服务器在用户确认前就收到了 — 用例必须失败 — 谁检查：同上，故意弄坏产品复跑
  - 例子(反)：脚本模型去点确认框上的「发送」，服务器 0 条 — 谁检查：同上
  - 例子(正)：名字不以发送开头的按钮（「保存」）照旧直接点，不停 — 谁检查：同上
- R2 等确认时侧栏写明在等用户；结束后侧栏说清结果（已发送并核对 / 用户没让发）。确认框上写网站、按钮名，和程序从网页读出的要发出去的内容；读不到内容时不编。
- R3 确认框的样子：小胶囊长成玻璃面板，关闭时缩回；减少动画设置下直接出现。

## 还没答上的问题

- 无。Q1（等 2 分钟会被什么掐断）10-09 查清：
  - 助手到扩展的调用 30 秒没回就记成「结果未知」并锁住。所以只在扩展报告「在等用户」时延长这次调用的期限；普通点击照旧 30 秒。
  - 「停」和「你来接管」今天会等进行中的点击结束，所以等确认时它们要能直接打断等待，按「不发」处理。
  - 网页脚本程序（browser_run）整段有 60 秒期限，不能在里面等用户；程序里点到「发送」时不点，告诉助手改用单独的点击。
  - 用户说「不发」以后，到用户再说话之前（包括任务运行中插话），助手再点同一个「发送」不再问，直接不点。用户一说话就重新问。

## 技术前提

- 前提：扩展后台可以挂着等 2 分钟，期间不休眠；等完点下去，网站收到请求。小实验：`scripts/probes/send-confirm-wait.mts`。结果：通过（10-09）。
  - 后台设好定时器后，小实验断开调试连接，因为调试连接本身会让后台一直活着。120.2 秒后定时器点下按钮，网站收到 1 条请求，后台还是原来那一个。

## 边界与不做

- 不拦「提交、付款、删除」，不拦回车。
- 不恢复 10-04 删掉的批准卡和每步确认。
- 不用玻璃库。

## 已知缺口

## 调研

- 10-04 删掉的批准卡是每一步都问，按工具名判断，不看按钮，所以不恢复。按钮名字表（删除 / 清空 / 支付 / 发送 / 归档）在 9-05 的「光标拿住」里就有，今天还在，直接用其中的「发送」。
- 玻璃库（Glass-HQ/liquid-glass 0.0.1，10-07 发布）有不依赖 React 的接口，但只折射它自己里面的内容；第三方网页的背景折射不到。它还要 WebGPU，并把缓存写进网页自己的存储。所以不用它。

做法上的取舍：

- 「发送」只认按钮自己的名字，不认助手写的说明。aria-label、title、文字分开看，任何一个以发送开头都算，所以 title 写成「按 Ctrl+Enter 发送」也躲不过。表单里的按钮在光标名牌上叫「提交表单」，但判断是不是发送时用原文。
- 目标和真正点下去的落点各读一次：点一个大容器、坐标落在里面的「发送」上，或者 force 点被盖住的目标，都要先问。
- 只有确认框所在的网页文档换掉或关掉才算离开；网页自己改网址（单页应用自动保存时常见）不算。同一页同时只等一个确认：第二个确认框会盖掉第一个，用户点了也回不到第一个等待，所以第二次点「发送」直接不点。
- 「不发」、停、接管、离开网页、2 分钟没理，都算用户没让发：助手收到没执行的错误，写明是哪一种，并写明不要按回车、不要点别的按钮；不算连续出错，也不进「换个办法试」的清单。但是助手反复去点时，「原地转圈」照常会停下这一轮。
- 「不发」只记到用户再说话为止。插话不换任务身份，所以按用户说话的次数另算；没有任务身份时不记。只记明确的「不发」，停、离开、超时不记。
- 确认框上的「发送」只认鼠标点击，不进 Tab 顺序，所以助手按键也按不到它。「不发」可以用键盘。
- 「发送」按钮不能双击，也不能连点（clickCount 大于 1）：一次确认只放行一下，连点可能发好几条，所以直接不点，让助手改用单击。
