# 任务: 思考还在写时，过程区只留最新一段

用户打开侧栏看执行过程：现在思考全文往下铺，卡片跟着长，把后面的回答顶走。要判断的是限高之后，流只钉住最新一段，看起来是否更清楚。

```
Change:     同一条「正在思考」路径并排三种占位，点重放能看见流式差异；用户选出一种。
Not this:   不改侧栏产品代码；不为原型打磨动效或配色。
Evaluator:  人：打开 HTML，看清三种差异并点选。
Evidence:   docs/evals/20260909-run-steps-live-viewport.html
```

## 这一步要判断的事

1. 思考还在写的时候，过程卡片要不要限高。
2. 旧内容是淡出、只留最新，还是还能往上滚回去。
3. 已经做完的步骤继续铺在上面，还是整段过程都收进同一块窗口。

对照 Will's S：
- 渐进揭示：复杂度先藏着，需要时再展开。
- 想突出重点，先弱化次要：加强调不如把旧思考写淡。
- 五秒里第一眼该看见「它现在在干什么」。

## 完成标准

- [ ] 1. 打开 HTML，三条同一路径并排：现在 / 只限思考 / 整段过程限高。重放时能看出思考流是否把卡片撑长。 — 谁检查: 人
- [x] 2. 用户要「只限思考 + 整段过程限高」的结合：步骤结构还在，过程卡片限高、上面淡出、对话不被顶走。临时页第三列展示该结合。 — 谁检查: 人

## 边界与不做

- 不改 `extension/` 产品代码
- 不改完成后的折叠态（「思考过程 4.2s」）
- 不改顶栏、输入区、配色
