# Jev 真实案例离线验证

## 完成标准（运行前固定）

- [x] 从历史真实 trace 提取有来源的决策片段，原输入不含测试结论或预期标签；独立复核标注。
- [x] 固定 jev-1.13.0 和 completion-question.json，逐例请求，重复两次；保留原始响应、错误、耗时、成本估算和输入指纹。
- [x] 历史记录与人为反例分开统计；比较历史模型判断时标明其输入并非与本次完全相同。
- [x] 报告错误成功判定、弃权、漏判成功、重复一致性和候选覆盖率；提出接入或不接入结论。

## 预设判定

此次主测“目标完成语义”。12例简单探针不纳入本轮分母。不得看完结果修改标签迎合 Jev，争议标注须按原证据裁决并保留记录。阈值预设 confidence>=0.9，只用于报告高置信度覆盖，不将其解释为90%正确率。任何错误 satisfied 都阻止进入生产接入；零错误也只允许继续扩大离线/影子验证，不能证明安全性。

本轮上限24个场景、各两次请求，最多48次，不重试，并发2，每次25秒；只调用已有授权的Jev，不启动产品浏览器或主模型服务。输入为经检查的脱敏片段及明确标为反事实的边界案例。不发送密钥、完整会话档案或图片。

历史模型判断属于当时整条任务链的观察基线，不是同输入模型能力A/B；当前代码的 delivery=report 是允许报告，不等于宣称业务成功，不能硬映射成 satisfied 来制造收益。

## 运行前来源裁决

独立提取提出8条候选。主代理查原始证据后保留5条P0片段，将1条翻译文档摘录单列 historical_summary；剔除两条仅给88/88计数的翻译成功候选（不足以独立核验翻译质量，且同文章覆盖重复），改用 receipt-loss 真实fetch返回的服务器记录作为成功对照。最终6条trace片段+1条历史总结+8条反事实，共15场景，30请求。rf01与rf07来自同一次运行的不同证据时点，不视为独立用户任务。

没有明确历史模型原话的条目 historicalDecision=null；不把页面的unknown文案当成模型判断。其余历史最终回答有精确事件索引，发生在片段之后，所以只做历史行为对照，不算同输入模型A/B。翻译总结片段单独报告，不能冒充原始trace。

## 实测结果

固定模型 jev-1.13.0。冻结数据集指纹（含标签与来源，不等于发送载荷指纹） `d801db11e17a579e53bc2a85c3d01011137b84b3390ab89ce4651eb6b1e2c2ae`。原始[冻结集](../../out/experiments/typesafe-real-20260918-105729/frozen.json)、[汇总](../../out/experiments/typesafe-real-20260918-105729/summary.json)及逐次响应全部保留。

| 来源 | 唯一场景 | 两次请求判对 | 错误判成功 | confidence≥0.9 |
|---|---:|---:|---:|---:|
| 原始 trace 片段 | 6 | 12/12 | 0 | 6/12 |
| 历史文档摘要 | 1 | 2/2 | 0 | 2/2 |
| 人为边界反例 | 8 | 12/16 | 0 | 6/16 |

两次重复15/15标签一致；重复不是增加独立样本量。全部30请求正常返回。成功请求的单案例延迟 p50=932ms、p95=1205ms（并发2，含网络，不含生产观察与回退）。总输入18682 tokens，按当日官方单价估算 $0.000785，非账单。

**保留的错误，不改标签、不重写提示词追分：**

- cf01：目标为A客户，只有B客户的保存成功证据。预期 insufficient，Jev两次均 contradicted，confidence=0.47/0.50。看到错对象不能推出目标对象未满足。
- cf06：要求昵称和城市，只有昵称保存成功，城市未读取。预期 insufficient，Jev两次均 contradicted，confidence=0.33/0.32。缺少某项证据不等于该项明确失败。

这两类误判不会直接放行错误成功，但可能让代理向用户误报失败或触发多余重做。不能因为都“没有说成功”就算正确。

**预设置信度阈值的实际作用：** ≥0.9覆盖14/30请求，这部分没有标签错误；但两个真正成功场景（rf07、cf04）的两次判断均低于0.9，没有任何成功确认被该阈值采纳。不能用“高置信度零误报”宣称已有可用成功放行器，也不能为了提高覆盖而在这批数据上调低阈值。

## 与原有判断的比较

有明确最终回答可对照的4个历史片段：rf02/rf03/rf05原模型均如实报告未完成，rf07原模型查询服务端后报告已保存；Jev与它们一致。本轮没有发现Jev纠正原模型错误完成声明的实例，不能宣称准确率提升。其余历史片段没有同时间点的明确模型裁决，标为不可比较。

当前代码回执与读回检查继续按其真实职责理解：delivery=report只是允许有来源的报告，不是业务目标已满足。本轮未把它作为错误的satisfied基线；也没有重跑主模型做同输入A/B。

## 结论与下一步

**不接入生产。** 本轮证明Jev能从少量真实执行证据识别明确未完成、未知回执和实际服务器成功记录；没有证明优于原模型，也没有形成可用的成功确认覆盖率。

值得继续的实验是将“证据是否覆盖目标对象及全部要求”与“有效证据是否显示冲突”拆成两个独立判断，由代码组合，不把证据缺失误报为业务失败。现有15例成为开发回归集；下一轮必须另取未见过的真实失败与成功记录作为留出，不能在本批调提示词后再称独立验证。待观察到可接受错误成功率、成功覆盖率以及包含回退的实际延迟，再考虑只记录判断的产品影子验证。

## 验证边界

- 已验证：发送给API的state不含预期标签/理由；用离线假响应验证错误成功和高置信错误计数；JSON、Python语法及差异空白检查。
- 来源经过主代理核对事件索引；历史摘要与trace分开，fixture仅虚构资料。提示词在读取新数据前固定。
- 未运行生产浏览器、未接生产路由、未改变现有模型/确认/写入/交付行为；未运行全仓产品测试或构建。


## 独立方法复核与最终口径

原生复核确认现有标签可辩护、预期答案未发送给Jev，且两项错判应保留。按唯一场景计为13/15：原始trace 6/6、历史摘要1/1、边界反例6/8；不能将重复请求26/30当作30个独立样本。6条trace来自5次任务运行，rf01/rf07只是同一任务增加证据前后两个时点。

三个目标标签均覆盖（3/3），这是标签覆盖，不是场景覆盖充分性。≥0.9的14/30是请求级阈值覆盖，不是独立案例成功率。此次所有请求都成功且30份usage都存在，所以记录成本未漏算已返回的usage；一般遇服务错误或缺usage时成本只能视为已知部分，不能填零当完整成本。

## 官方文档复核后的解释修订

用户要求从 Introduction 重新核对使用方式。已读 Introduction、AI primer、How to build、State、Use-case map、Noul、Confidence、Intent routing、Fan-out 与 Citation check，并对照之前读取的 Models、API 和 Jev 1.13 jaggedness。

**保留实验事实，收窄结论：本轮评估的是“整体完成三分类 + 人工预设0.9阈值”这一具体方案，不是Jev对产品的适用性。** 暂不接入该方案仍合理，但不能据此判断Jev不适合Agent Loop。路由、工具调用核验、错误识别与harness是官方明确列出的应用。

主要使用问题在问题粒度：一个Choice同时承担对象对应、观察是否有效、全部要求覆盖、保存证据和失败识别。官方How to build用工具调用trace示例明确要求把多个独立判断拆开。原始输入经过人工浓缩，这只能评估浓缩后的状态；不能代表从真实工具输出到结果的自动端到端链路。

Choice本身并没有用错：官方Citation check对每一条claim和对应section使用supports/contradicts/says_nothing三分类。因此不应机械改成两个笼统Noul；应先把要求与证据组织成明确对应项，再决定用Choice判断关系，或用Noul判断某个单独条件。

confidence是选项概率分布的集中程度，不是选中答案的正确率。之前保留完整probabilities，但主要按confidence>=0.9报告，尚未做领域校准、风险/覆盖曲线或概率评分。该阈值是预设诊断值，绝非官方生产门槛；低于它不证明模型无效。重复一致性也不证明校准或正确。

一案例一请求适合测请求级延迟，但同一案例内应并行问多个独立问题，发挥官方fan-out方式。不能把所有案例堆成大state再称天然更优：各问题仍能看到共享state，相关状态应聚在一起，避免无关上下文。也不能把同批问题的结果当成另一个问题已知的前提。

### 修订后的下一轮设计（未运行）

1. 由已有代码提供run/document/版本/时间与结构化工具事实；从当前要求得到逐项claim，保留原文和来源。若要求拆分借助主模型，其错误也计入整体评估，不将人工整理冒充自动系统能力。
2. 精确ID、schema、数值比较和回执存在性用代码。语义对象对应可让Jev在现有候选中选择，留no-match；需要前一选择才能构建对应证据时分两阶段，否则批量问独立问题。
3. 对每一项claim及其有效证据，使用Choice：supports / contradicts / does_not_address。例如分别判断“昵称为海风”“城市为杭州”“服务器保存完成”；不要一次问全部目标是否完成。确有独立用途时，再用Noul问“该段观察是否包含持久化确认”等窄问题。
4. 代码组合：任一适用证据明确冲突则未满足；没有冲突但有缺证项则证据不足；全部要求受支持才成为完成候选。低概率或低置信的具体项回退补读/主模型，不直接宣称失败或重做写入。不将多个相关问题的概率直接相乘当整体正确率。
5. 当前15例成为开发回归，不抹除原失败。在新的留出集上同时评估原方案、逐项Choice、必要的Noul组合；记录每项与最终判定、错误成功率、成功覆盖率、弃权率、概率质量及包含主模型回退的端到端时延。最后根据实际风险与收益选择阈值。
