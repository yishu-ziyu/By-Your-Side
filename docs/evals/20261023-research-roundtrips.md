# 跨网站查证：保留原文，减少无效核对

## 规则

- R1 日期、目标、英文引文和链接都须与独立读取的官网原文相符。逐次列出通过与失败，不能把产品自己的“完成”判定当作正确证据。
- R2 原有控件、状态、隐私边界和停止能力保持。增加段落文字不得挤掉原本可见的操作目标；整页输出预算不增加。
- R3 同任务、同模型、交错对照准确性、用户等待和总模型用量。存在退化的候选不发布；单次快结果不能证明稳定收益。
- R4 不读取日常登录网站和浏览历史；使用隔离扩展、公开网站和已授权的 ChatGPT 测试登录。

证据归档在主目录 `out/archive/research-roundtrips-20261024/`，下文路径都相对于它。

## 技术前提

- 原有快照把每个静态文本节点截到 200 字符，ESA 的具体彗星名称恰在段落后半部。候选先保留原有所有行，只有整页仍有剩余空间时，才把长段落扩到最多 1,000 字符。整页仍受原有 24,000 字符预算限制。
- 多页程序的合并结果进入核对时，只保留开头，后读的来源可能消失。候选只在纯导航程序返回多个原文前缀时，将这一条结果原有的 8,000 字符空间平均分给各来源，并保留返回键名与实际网址。短来源剩下的空间分给长来源；计算结果、写操作和无法对应原文的返回值仍走原路径。没有修改完成核对提示词或通过标准。
- 复制范围：判断复制意图时，同时记下用户要的句或段范围（第一句、最后一句、第二段等）。`fill` 的来源可带 `from.range`，扩展按句或段切出来源原文再写入。范围越界、与用户要求不一致，或用户要了范围而模型要整块复制时，拒绝写入并说明原因，草稿保持原样。没带范围的整块复制不变。

## 已有证据

- `snapshot-paragraphs.mts`：真实扩展读取包含长段落和末尾按钮的页面，然后使用读到的按钮编号完成操作。原版缺段落尾部，直接扩大单段上限的中间版挤掉末尾按钮，受剩余预算约束的版本完成了操作。脚本模型、本机网页，只证明程序层。
- `source-budget.mts`：真实扩展串行读三页，程序每页返回 6,500 字符；直接检查核对模型实际收到的请求。原版丢了第二页证据；候选保留三页标记和实际网址，合并结果为 7,998 字符，侧栏显示“已核对页面”。标记放在段落开头，避免段落截断干扰这项判定。脚本模型、本机网页，只证明程序层。
- `copy-range.mts`：真实扩展、本机页面，七种情况：第一句、最后一句、第二段、全部、越界、与用户要求不一致、用户要第一句而模型整块复制。候选 7/7：前四种草稿恰为所求原文，后三种拒绝写入并给出原因，草稿不动。原版 1/7：每次整块复制，只有“全部”通过。脚本模型，只证明程序层。
- 既有 `snapshot-privacy.mts` 在段落候选上通过。
- 主任务使用 NASA Voyager 1、ESA Rosetta、JAXA Hayabusa2；另一组使用 NASA Cassini、ISRO Chandrayaan-3。事实、引文与链接按独立加载的原文核对，故意把实际回答日期改错后必须失败，恢复后必须通过。
- 第一版请求允许模型自行选择引文，有些回答漏带日期。后续显式要求每行英文引文含日期写法和目标名，两版使用同一请求，判据不变；不同请求版本分开统计，不重写先前失败。
- JPL 页面在任务开始前连续两次返回 403；两版统一改用同任务的 NASA 官方页，原失败页仍保留。

## 原文复制回归

“把 Note 框第一句英文原文复制到草稿框，不要保存”曾在候选上连续两次失败：草稿里是整段，目标核对仍判完成；原版的一次对照通过。失败路径没有调用多页重分配，页面也没有长段落，两版提示词和工具定义指纹相同（`research/copy-scope-investigation.json`）。根因是复制工具只能整块复制所选元素，模型选中整个 Note 框时就没有办法只取一句；原版那次通过时，模型没用复制工具，而是写页面程序自己截出首句。另外，`everyday-baseline.mts` 有用例失败时仍返回 0，调用方据退出码会误判，改为有一条没过就非 0 退出。

补上复制范围后，真实模型同一用例通过：模型带上“第 1 句”范围，草稿恰为 “Jev currently accepts text input only.”，没有保存（`acceptance/real-path/2026-10-23T18-57-19-856Z-everyday-baseline-inproc-65525`）。

## 放弃的候选

曾增加组合正文读取，并修正隐藏菜单、并发读页争用和来源核对。这版在三站任务上有收益，但另一组固定五次对照中：原版 5/5 通过，新版 4/5；平均输入从 51,481 增到 58,719，中位可见结果耗时从 11.16 秒增到 14.152 秒。因此整体撤回，没有发布。

这些中间版本的补丁、逐次结果与失败记录保留在 `research/`。`comparison.json` 仅汇总原始记录，不混合不同请求的成绩。
