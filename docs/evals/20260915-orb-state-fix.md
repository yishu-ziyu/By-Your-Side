## 实现范围与维护

- 同步历史信封显式标记 replay；实时增量仍用既有历史事件流。保留原时间戳回放逻辑，批次结束后只启动当前实时主球；历史恢复等权威 status 到达后决定是否恢复运行。不会给已经完成的块重启动画。
- 独立 RunOrbActivity 记录在途工具并推导状态。执行优先于等待，等待优先于无工具思考；接管保持静止，主动停止优先于迟到事件。失败操作允许后续重试继续，未恢复的错误保持失败态。
- OrbHandle 增加 setState，使用既有 thinking-orbs 模式；等待放慢。完成沿用收拢，失败仅一次短反馈，停止立即静止。减少动态变化即时生效。清理移除的画布，切会话释放当前主球。
- 只修用户指定的主执行光球；没有把所有细节工具光球、记忆图标一并重新设计。
- 没有新依赖、没有另造动画引擎；状态推导单独放在小模块，避免继续把判断集中进 main.ts。

已构建并重载本地扩展，未提交/发布。真实任务覆盖思考/执行/等待/完成；接管、失败、停止与减少动态的完整业务链路没有全部重新跑，以上分别按实际证据层级记录。可由用户在演示页判断形态区分与节奏是否合适。


## 用户指定源仓库后的修订（当前结论）

用户确认唯一参考为 https://github.com/Jakubantalik/thinking-orbs 。核对上游 de85557ca220332586d070d8788c0e1d6e877a0d，版本 0.3.1。项目 vendored 引擎与源仓库的 18 组预设、54 组帧数据逐项深比较完全一致。没有更新或修改 vendor 引擎。

撤回此前自行设计的速度倍率、额外呼吸缩放、失败闪烁以及“完成=morph/失败=web”的映射。主球使用 20px inline 原预设：思考→solving、执行→working、等待→breathing；其余状态暂停当前帧，不冒用原库的其他工作语义。帧时间采用源库的共享时钟。原运行接线、历史区分、停止和减少动态修复保留。上文旧的 ribbon 思考采样与收拢/失败反馈描述属于修订前证据，不代表当前样式。

修订后类型、构建、26 项定点测试、12 次隔离前端状态/媒体查询检查通过；已重载扩展并更新演示。未重复跑整套模型任务，既有实际运行接线证据复用，形态/速度以源库深比较和当前前端检查为准。
