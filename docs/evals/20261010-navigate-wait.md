# 任务: 打开的地址变成下载、或是不能注入脚本的页面时，助手几秒内拿到如实的结果，不再干等到超时

[当前状态](../STATUS.md)

10-10 真实运行的记录里，助手打开三类地址时停了 10 到 30 秒，最后回执是「document: timeout」：

- 导出链接，服务器按附件回文件。Chrome 把它变成一次下载，标签页留在原页面。
- `chrome://downloads/`。扩展不能往这种页面注入脚本。
- 本机的 `file://…csv`。Chrome 也把它变成一次下载。

原因：打开地址后，扩展反复往页面注入脚本，等一个新文档就绪。上面三种情况都等不到新文档，所以只能等到超时。超时的回执还让助手以为页面没打开。

## 规则

- R1 打开的地址变成下载，或者是不能注入脚本的页面时，打开地址这一步（navigate，以及带地址的 tabs open）在约 3 秒内返回如实的结果，不等到超时。变成下载时，回执说明：这个地址开始了一次下载，没有打开页面，标签页留在原页面；回执写出文件名，以及 Chrome 报告的状态（已完成、失败、还在下载）。只有 Chrome 报告完成时，回执才说文件已存好。普通网页照旧等新文档就绪，回执照旧带新页面的快照。
  - 例子(正)：本机练习站的导出地址按附件回 `list.csv`；助手打开它，那么回执在 5 秒内回来，写着「document: download」、开始了下载、文件名 `list.csv`、Chrome 报告完成；下载目录里有 `list.csv`，内容等于服务器发出的字节 — 谁检查：`navigate-wait.mts` (a)
  - 例子(正)：助手打开 `chrome://downloads/`，那么回执在 5 秒内回来，写着「document: complete」 — 谁检查：`navigate-wait.mts` (b)
  - 例子(正)：助手接着打开练习站的第二页，那么回执照旧是 interactive 或 complete，并带第二页的快照 — 谁检查：`navigate-wait.mts` (c)
  - 例子(反)：去掉等待里的浏览器通知，只留注入脚本的轮询，那么 (a)(b) 各等满 30 秒，回执是「document: timeout」，用例失败 — 谁检查：同上，故意弄坏产品复跑

## 技术前提

- 前提：这三类地址打开时，扩展后台能收到浏览器自己的通知，不用注入脚本。小实验：`scripts/probes/navigate-events.mts`（这个脚本在 #202 的 PR 里，还没进本分支）。结果：通过。
  - 附件地址：发出跳转后约 8 毫秒，Chrome 报一次新下载，下载的地址就是要打开的地址；标签页没有任何更新，停在原地址。
  - `chrome://downloads/`：约 100 毫秒内，标签页先报「加载中」，再报「加载完」。
  - 本机 `file://` 的 csv：约 17 毫秒，Chrome 报一次新下载。
  - 普通网页：约 60 毫秒内，标签页先报「加载中」，再报「加载完」。
- 因为下载的通知在发出跳转后几毫秒就到，所以扩展先开始听通知，再发出跳转。

## 边界与不做

- 普通网页仍以注入脚本等到的新文档为准，因为调用方要用这个文档的编号。浏览器通知只补注入脚本做不到的情况。
- 不能注入的页面没有文档编号。回执说 complete，但是助手不能在这种页面上读页面或点元素。
- 带地址的 tabs open 走同一段等待，但是没有真实路径用例覆盖。打开新标签页时，标签页编号要等标签页建好才知道，所以扩展在建好之后才开始听标签页的通知。`chrome://` 这类页面如果在这之前就加载完，扩展收不到「加载中」，仍会等到超时。下载不受影响：扩展开始听的时候会补查刚开始的下载。
- 本机 `file://` 的 csv 走的是和附件地址相同的下载判断，没有单独的真实路径用例。
- 变成下载时，侧栏这一步的名字仍是原页面的标题，因为标签页没换页。
- 没有新增扩展权限，也没有新增给模型的工具。
