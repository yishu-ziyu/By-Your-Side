# 任务: 同一模型下，真实网站上扩展和「Codex 终端 + Ego」谁更准、更快

来源：2026-10-13 用户说终端里 Codex 用 Ego 操作浏览器「准确率很高，体感上不慢」，要求两边用同一模型在真实网站上重测。10-10 的同模型对比只用了本机练习页。

## 规则

- R1 两边都用 gpt-6.1-sol、思考强度高（扩展选「深入」），同样的话，同样的自动判据。6 个真实网站任务分三组（搜索、读取、填写），每边各跑 2 次。起点都是一个打开 example.com 的标签页。
  - 例子(正)：`npx tsx scripts/probes/compare-real.mts . out/compare-real-1013 ext` 与同一命令换成 `ego` — 谁检查：脚本按页面网址、页面内容或回答文字判定
  - 例子(反)：试跑时 Ego 一边被判失败，查明是脚本读不到被 Codex 交还的任务空间，Codex 实际做对了；修好读法后重判 — 谁检查：人工认领空间核对

## 技术前提

- 前提：Codex 关掉电脑操控类插件和 MCP，只走 ego-browser 命令行（做法同 10-10）。结果：通过，12 次里只有 2 次调用了别的命令。
- 前提：Codex 做完常把任务空间交还用户，脚本要先「认领」再读。小实验：试跑必应一条。结果：通过。
- 前提：Ego 的 `finish()` 只交还空间，不删除；关掉最后一页后它会补一个空白页。测试结束要用 `Target.closeTarget` 关掉空间里每一页，空间才会消失。结果：13 个测试空间全部关掉。

## 边界与不做

- 只选不用登录、结果能自动核对的网站：必应、中文维基百科、Hacker News、GitHub Trending、Selenium 测试表单、TodoMVC。
- Codex 的用时包含命令行启动和加载说明的固定开销，没有拆开，所以用时对比对 Codex 略不公平。
- Ego 一边的话多一句「我在任务空间 N 的 p1 页」和「做完把结果页留着」，因为扩展自动知道用户在看哪页，也从不关页。
- 只测了 gpt-6.1-sol。用户日常用的 Kimi 没有测。

## 决定

决定（用户 10-13）：结果页不自动切到前台；回复里给一个「切过去看」的按钮，并提前告诉模型不用切。

框架改动都是让模型醒来时手边已有它要的信息：开头附上所有标签页；新开标签页、程序中途换页后直接附上新页面，读之前等页面画完；零尺寸元素不给编号，输入框被重绘后按原特征找回；结果页留在后台，回复里给「切过去看」按钮，并告诉模型不用切。

- 维基搜索按钮在输字后会被换掉。点击不按特征找回，因为列表里同名按钮可能点错行（审查意见）。
- 没测：日常 Chrome、Kimi。已知未修：Chrome 显示「无法访问」时要等满超时才报错。
