# 任务: 同一模型下，真实网站上扩展和「Codex 终端 + Ego」谁更准、更快

来源：2026-10-13 用户说终端里 Codex 用 Ego 操作浏览器「准确率很高，体感上不慢」，要求两边用同一模型在真实网站上重测。10-10 的同模型对比只用了本机练习页。

## 规则

- R1 两边都用 gpt-6.1-sol、思考强度高（扩展选「深入」），同样的话，同样的自动判据。6 个真实网站任务分三组（搜索、读取、填写），每边各跑 2 次。起点都是一个打开 example.com 的标签页。
  - 例子(正)：`npx tsx scripts/probes/compare-real.mts . out/compare-real-1013 ext` 与同一命令换成 `ego` — 谁检查：脚本按页面网址、页面内容或回答文字判定
  - 例子(反)：试跑时 Ego 一边被判失败，查明是脚本读不到被 Codex 交还的任务空间，Codex 实际做对了；修好读法后重判 — 谁检查：人工认领空间核对

## 技术前提

- 前提：Codex 关掉电脑操控类插件和 MCP，只走 ego-browser 命令行（做法同 10-10）。结果：通过，12 次里只有 2 次调用了别的命令。
- 前提：Codex 做完常把任务空间交还用户，脚本要先「认领」再读。小实验：试跑必应一条。结果：通过。
- 前提：Ego 的 `finish()` 只交还空间，不删除；关掉最后一页后它会补一个空白页。测试结束要用 `Target.closeTarget` 关掉空间里每一页，空间才会消失。结果：13 个测试空间全部关掉。

## 边界与不做

- 只选不用登录、结果能自动核对的网站：必应、中文维基百科、Hacker News、GitHub Trending、Selenium 测试表单、TodoMVC。
- Codex 的用时包含命令行启动和加载说明的固定开销，没有拆开，所以用时对比对 Codex 略不公平。
- Ego 一边的话多一句「我在任务空间 N 的 p1 页」和「做完把结果页留着」，因为扩展自动知道用户在看哪页，也从不关页。
- 只测了 gpt-6.1-sol。用户日常用的 Kimi 没有测。

## 结果（10-13）

| | 做对 | 用时中位数 | 平均 |
|---|---|---|---|
| 扩展 | 12/12 | 37 秒 | 34 秒 |
| Codex + Ego | 12/12 | 71 秒 | 72 秒 |

| 任务（每格两次，秒） | 扩展 | Codex + Ego |
|---|---|---|
| 必应搜天气 | 44、22 | 69、88 |
| 维基百科搜长城并打开条目 | 50、46 | 67、85 |
| Hacker News 第一条标题 | 15、26 | 47、77 |
| GitHub Trending 第一个仓库 | 31、21 | 56、93 |
| Selenium 表单填三项并提交 | 37、41 | 65、73 |
| TodoMVC 加两条待办、勾掉一条 | 39、38 | 61、85 |

- Codex + Ego 的 GitHub 第 1 次，第一回是脚本开跑前取正确答案时网络失败，Codex 没有运行；补跑后做对（56 秒）。
- 结论：同一模型下两边一样准，扩展约快一倍。用户觉得 Codex「准」，主要来自模型，不是 Ego 的操作方式。

扩展 12 条里约三分之一的时间花在不干活的轮上（按诊断记录逐轮归类）：

| 白花的轮 | 出现 | 合计 |
|---|---|---|
| 开头先列出所有标签页 | 10/12 | 51 秒 |
| 结尾想把结果页切到前台，被「不抢前台」拦下 | 9/12 | 33 秒 |
| 打开页面后专门花一轮看页面 | 9/12 | 32 秒 |
| 点失败：必应零尺寸按钮 1 次，页面重绘后用了旧编号 2 次 | 3 次 | 13 秒 |

决定（用户 10-13）：结果页不自动切到前台；回复里给一个「切过去看」的按钮，并提前告诉模型不用切。

证据：`out/compare-real-1013/`（每条的诊断记录、Codex 事件流、`result-*.json`）。

## 框架改动后（10-13，同一脚本只跑扩展）

改了四处，都是让模型醒来时手边已有它要的信息：开头附上所有标签页；新开标签页、程序中途换页后直接附上新页面，读之前等页面画完；零尺寸元素不给编号，输入框被重绘后按原特征找回；结果页留在后台，回复里给「切过去看」按钮，并告诉模型不用切。

| | 改前 | 改后 |
|---|---|---|
| 做对 | 12/12 | 12/12 |
| 总轮数 | 73 | 42 |
| 用时中位数 | 37 秒 | 25 秒 |
| 开头列标签页 / 结尾切前台 / 打开后专门看页面 | 10 / 9 / 8 | 0 / 0 / 1 |
| 点失败重来 | 4 | 1 |
| 「切过去看」该出就出、点了切到结果页 | — | 12/12 |

- 剩下的「打开后看页面」是必应连接失败后模型确实要再看；剩下的「点失败」是维基搜索按钮在输字后被换掉。点击不按特征找回，因为列表里同名按钮可能点错行（审查意见）。
- 用时受外部影响：必应两次连接失败（约 50 秒），维基一次模型出错重试（99 秒）。
- 没测：日常 Chrome、Kimi。已知未修：Chrome 显示「无法访问」时要等满超时（约 14 秒）才报错。
- 证据：`out/compare-real-after2-1013/`；改动中途的一轮在 `out/compare-real-after-1013/`（按钮 6/12，因为新开标签页带回的页面没记进「读过的页面」，已修）。
