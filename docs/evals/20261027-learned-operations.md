# 任务：把核对做成的只读网页任务保存为可复用做法

## 规则

- 用户明确说记住做法时，只接受宿主最近一个最终核对为 done 的任务。候选必须用原输入和第二组不同输入真实运行；原输入还要再次通过原目标核对，全部通过才保存。
  - 谁检查：真实扩展保存路径；无成功核对、错误输出和第二组输入不符时都不能落盘。
- 保存的是参数结构、程序和验证元数据，不是旧答案或验证样例。下次由模型按当前站点选择做法并填入新参数，程序重新读取当前页面，最终仍过现有目标核对。
  - 谁检查：换说法、换查询值后返回新页面数据；浏览器重启后仍能复用。
- 第一版只允许当前标签页内的导航、读取、滚动、网络观察和 GET 请求，站点按完整来源（协议+域名+端口）判断，`alice.github.io` 与 `bob.github.io` 是两个站。点击、填写、按键、通用页面 JS、跨站请求、其他标签页和 `@N` 快照编号一律拒绝；同站跳转也钉在原标签页。
  - 谁检查：错误站点、另一来源、跨站请求、禁止方法和旧编号的反向用例；被拒绝的动作没有真实请求；同窗口已开着同一搜索页时仍留在原标签页。
- 名称、说明和契约会长期保存并进备份：凭据字样、像令牌的长串、契约里的说明和示例值都不收；程序里写死这次读到的答案，或两组不同输入读到同样数据，都不保存。验证后、写入前用户停止，也不落盘。
  - 谁检查：敏感名称、宽松契约、固定旧答案、相同答案、没读页面、取消验证、等存储锁时取消的反向用例。
- 空结果是 `empty`，前提失效是 `unavailable`，输出契约错误是 `invalid_output`，站点不符是 `site_mismatch`。失败后模型继续普通 Browser Use，不重复调用同一失效做法；用户可删除本机做法。
  - 谁检查：结构变化后的回退、删除后重启不复活、损坏存档不被覆盖。

## 还没答上的问题

- 真实模型生成符合受限 API 的候选有多高的保存成功率，复用后的端到端提速和成本是多少：单次冒烟已通过（见下），十次交错对照还没跑。
- 网站自己的 GET 是否都有只读语义无法由工具名证明；本批不开放写入工具，但仍以当前页面和结果核对为准。

## 技术前提

- 沿用现有 QuickJS、浏览器 RPC、控制闸门、目标核对、TypeBox 非 JIT 校验和 IndexedDB；不增加依赖或本机伴随程序。
- 普通 `browser_run` 不启用受限方法集合，原有行为不变；提示词技能、站点笔记和内置网站方法仍是不同能力。

## 边界与不做

- 不做写入类做法、自动识别重复任务、自动修复、跨标签页程序、语义向量检索或新的管理界面。
- 不接入 Pomerado、Playwright、MCP 或 Node 伴随程序。
- 第二组输入证明受限泛化，不证明所有页面结构、登录态和网站改版都可靠。

## 本轮结果

- 脚本模型 + 真实扩展（`npm run lab -- case learned-operations`）34 项全过、连跑 3 次稳定：保存、换输入读到新数据、同窗口不切标签页、另一来源回退、输出契约失败与页面失效回退、浏览器重启后复用、删除后重启不复活、全部反向用例、两种取消、损坏存档不覆盖。去掉写入前的取消检查后“等存储锁时取消”按预期失败。
- 真实模型 GPT-6 Luna + 中文维基百科（`npm run lab -- case learned-operations-live`）单次通过：模型自己写出并保存做法（程序不含“故宫”），换成“长城”后调用这份做法读到新结果，存档成功次数 0→1。
- 旧用例：`save-skill` 通过；`site-methods` 只在 `bili-search` 侧栏交付超时，主干未改代码同样超时，是已有问题。
- 独立审查两轮（Codex），所列问题均已修复。
- 没做：真实模型十次交错对照（首次学习成本与复用成本）。
