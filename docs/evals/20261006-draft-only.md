# 任务: 建议只填草稿、由用户发送；回答里的出处是链接前的站点图标

来源：Linear [YIS-74](https://linear.app/yishuyuki/issue/YIS-74)（flomo 09-14 截图，三条原则：点击只填草稿、用户改过再发、诊断收进折叠区；出处长在句子里，链接前一个小图标）。用户 2026-10-06 看过对照预览 `out/design-check/yis74/preview.html` 后选定：出处改成图标在前、去掉胶囊；建议卡点了只填进输入框。

## 规则
- R1 回答正文里指向读过页面的链接：站点图标在链接文字前面，链接后没有胶囊；图标是浏览器缓存的网站真图标，取不到时退回首字母方块；下划线很淡，悬停才变深。「来源」按钮和面板用同一个图标。
  - 例子(正)：「已打开 🌐体验页」，链接后面没有「1 127.0.0.1:端口」 — 谁检查：`scripts/probes/shell/answer-receipt.mts`
- R2 页角建议卡（#52）点按钮：侧栏打开，建议的话填进输入框；输入框已有字时接在后面，不覆盖；不发出，不开跑。
  - 例子(反)：点「帮我比价」后侧栏里出现用户气泡并开始思考 — 谁检查：`scripts/probes/shell/draft-only.mts`（真页面停留、滚动，脚本模型出卡，点卡上按钮）
- R3 「/ 技能」里不用回答问题的技能：选中后正文进输入框，不发出。带问题的技能仍由澄清卡上的「开始」发出。
  - 例子(正)：选「概括这页」，输入框里是它的正文，没有用户气泡 — 谁检查：同上
- R4 输入框随内容长高（最多 140px），填进去的多行草稿全看得见。
  - 例子(反)：三行草稿只露两行、要在框里滚 — 谁检查：同上（`clientHeight >= scrollHeight`）
- R5 好不好看由用户在真实扩展里裁决 — 谁检查：人

## 技术前提
- 前提：Chrome 的 `favicon` 权限能让扩展页用 `chrome-extension://<id>/_favicon/?pageUrl=…` 取到网站图标，安装时不弹权限提示。小实验：无（`answer-receipt.mts` 里图标 `naturalWidth > 0` 即证明）。结果：通过
- 前提：建议卡点击时侧栏可能还没打开，所以后台把话放进 `chrome.storage.session`，侧栏草稿恢复完再取走。结果：通过（`draft-only.mts`）

## 边界与不做
- 新对话的起点建议本来就是只填草稿，不变。语音诊断本来就收在折叠区、写明「只写进语音诊断日志」，不变。
- 不改代用户点击、提交前的确认流程。
