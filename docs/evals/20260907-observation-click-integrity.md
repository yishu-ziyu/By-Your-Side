# 任务：Agent 看对页面、使用当前目标、只点击一次，交还约束不串入新任务

日期：2026-09-07。校验/编排：当前 Codex 会话。实现：同 cmux workspace 的 OpenCode 与 Grok。本文在两位执行者动手前锁定；实现不能降低标准，范围变化由 Codex 编排裁决。

## 完成标准

- [ ] A1. 工作页截图的像素宽高正确且大于零；返回可核对的标签页/URL与CSS视口、DPR信息，模型能区分图像像素与点击用的CSS坐标。元数据来自真实捕获流程，不写固定值。— 谁检查：OpenCode聚焦测试；Codex真实ChromeMain截图、尺寸与视口对照。
- [ ] A2. CDP失败后，只允许回退捕获已确认是工作页的活动标签；捕获前或捕获后发现活动页/URL不匹配时明确失败，不返回其他页图片、不谎称工作页截图；worker不得为截图抢用户前台。— 谁检查：错误路径测试与Codex本地双标签实测。允许通过测试边界制造CDP失败，须标注，不得改产品错误分支来做通过。
- [ ] A3. snapshot(scope=viewport)确实只覆盖当前视口；full_page和viewport不能实际上相同且不说明。若最小实现使用已有DOM视口快照，应明确降级、正确切换ref登记，不能把DOM ref误作旧AX ref；full_page/AX原路径不回归。截断反馈必须提供有效恢复方式。— 谁检查：滚动/视口/AX到DOM引用切换聚焦测试；Codex真实长页验证。深层OOPIF完整支持不属于本刀范围，不得宣称已覆盖。
- [ ] B1. DOM回退路径一次click调用只能触发一次目标click处理器；不允许dispatchEvent(click)加HTMLElement.click双发。CDP已送达但后续返回异常时不能盲目再次点击。无法确认是否送达应返回明确不确定结果/错误，保留已发生动作的事实，不当作未执行。— 谁检查：Grok旧代码失败反例、修改后聚焦测试；Codex本地计数按钮真实CDP/回退验证。
- [ ] B2. 有target的点击在视觉等待后重新确认目标仍存在且可命中；动态移动、覆盖或重渲染不能点击原坐标处的另一个按钮。不能通过忽略目标、force点击或默选同名对象满足标准。原ref/CSS/坐标调用与危险确认边界保持；无法确认的坐标操作明确失败，不假成功。— 谁检查：移动/遮挡/失效反例与Codex真实页面干扰验证。
- [ ] B3. 接管/交还仍继续原任务，不重复已完成步骤；原任务结束后的新任务明确指定另一页时，不受上一轮“留在本页”约束限制。不能靠清空全部会话、重启浏览器或重新要求用户描述目标满足标准。— 谁检查：任务A接管交还后接新任务B的回归；Codex真实模型/同会话/两张本地页面。原control-gate和handback测试不得弱化。
- [ ] C1. 所有本轮错误分支都保持现有用户控制、危险确认、worker标签归属；不得绕过RPC/ControlGate、新起独立执行大脑或扩大宿主权限。— 谁检查：聚焦回归与Codex diff审查。
- [ ] C2. 先跑受影响测试，再通过npm run typecheck、npm test、npm run build。执行者只跑自己负责的聚焦测试，完整检查与build/reload由Codex统一进行。— 谁检查：机器，保留命令/退出码和测试数量。
- [ ] C3. 实机证据分别记录起点、具体操作、模型/浏览器配置、实际页面结果、截图/日志和人工介入；mock、采集脚本结果和真实产品结果分别报告。禁止操作真实简历填写/保存、支付、发布或删除私人资料。— 谁检查：Codex与用户。

## 边界与不做

- 本轮属于ROADMAP阶段0，只做上述已有能力的可靠性修复。
- 不整体替换Pi或浏览器驱动，不新增长期记忆、会话管理UI、语音、通用技能系统或全量OOPIF支持。
- 不默认推广browser_run；保留其可选状态。
- 不修改他人既有功能，不清理工作树，不提交/push/创建PR；提交边界由Codex之后决定。
- 样本通过不能声称全站点可靠或阶段0整体退出。
