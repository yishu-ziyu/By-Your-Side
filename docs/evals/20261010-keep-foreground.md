# 任务: 助手在后台标签页里做事，不换走用户正在看的标签页；只在要用户回答时把自己的页切到前台

来源：2026-10-10 用户原话：「目前让我觉得不爽的是，它做任何动作都会把我的前台占据掉。因为我们知道一个浏览器的里面可能开10多个窗口。」

用户在一个 Chrome 窗口里开着十多个标签页。以前，用户在看自己的标签页时，助手每做一步都把这个窗口的活动标签页换成助手的工作页。

2026-10-10 用户决定：「平时不切，需要你时才切」。

本文件取代[不拽走 Space](20260904-no-space-steal.md)的完成标准 3（「窗口已在前台时，仍把工作标签页切到该窗口内前台」）。那份文件的其余标准不变，特别是“任何时候都不聚焦窗口”。

## 规则

- R1 普通动作不改变任何窗口的活动标签页，也不聚焦窗口。普通动作是：点击、双击、悬停、填写、选择、输入文字、按键、滚动、截图、导航、上传、切换工作页（tabs switch），以及网页脚本程序（browser_run）里的同类动作。助手在后台的工作页里做这些动作。
  - 例子(正)：表单页被助手认领为工作页后，用户切回「我的页面」。助手在表单页点「保存」、填名字、按回车、滚动、开新页。每个工具结果回到模型时，以及整段每 100 毫秒，活动标签页都是「我的页面」。网站收到保存和回车，名字读回一致，表单页滚动了 — 谁检查：`npx tsx scripts/acceptance/real-path/keep-foreground.mts --headless` a
  - 例子(反)：恢复“每步把工作页切到前台”，a 的活动标签页采样变成表单页，用例必须失败 — 谁检查：同一命令（故意弄坏一次，见「结果」）
- R2 助手自己开的页（tabs open）不成为活动页。
  - 例子(正)：a 里助手开的新页存在，且不是活动页 — 谁检查：同上 a
- R3 只有三个时刻把助手的页切到它所在窗口的前台：助手交给用户（hand_to_user），点「发送」前的确认，付款按钮前停下。这三个时刻也不聚焦窗口。用户自己要看某一页的操作（侧栏里点页面链接、定位到页面上的内容）不变。
  - 例子(正)：助手切回表单页后，活动标签页仍是「我的页面」；助手点「发送」，确认框出现时表单页已是活动标签页；用户点确认框上的「发送」后网站收到 1 条 — 谁检查：同上 b
  - 例子(正)：助手切回表单页后交给用户，侧栏出现「需要你来这一步」时，表单页已是活动标签页 — 谁检查：同上 d
  - 例子(反)：去掉交给用户时的切页，d 失败（活动标签页仍是「我的页面」） — 谁检查：同上，故意弄坏一次
  - 付款停下：没有用例测“切到前台”这一步，见「边界与不做」。

## 技术前提

- 前提：隔离无头 Chrome 里，扩展看到的窗口是“已聚焦”，所以旧的“每步切前台”在无头里真的会切，用例才能被故意弄坏。扩展后台能读出窗口的活动标签页。小实验：`scripts/probes/headless-window-focus.mts`。结果：通过。
- 前提：CDP 的鼠标和键盘输入在后台标签页里照样生效。09-04 起窗口没聚焦时已经依赖这一点。结果：通过，以用例 a 为证（表单页处于隐藏状态时，网站照样收到保存和回车）。

## 边界与不做

- 不改光标动画、动作效果采样和语音默认设置。助手在后台标签页里移动的光标，用户看不见，这是预期。
- 用户在侧栏里重放上一次的光标轨迹时，仍切到那一页，因为这是用户要看。侧栏「接管」不切页；只有助手发起的交给用户才切。
- 付款停下切到前台：没有用例测这一步。现有 `pay-stop` 用例开始前工作页本来就是活动页。
- 点击打开的新页（target=_blank）：Chrome 自己把新页设成活动页，扩展不和 Chrome 抢。
- 切换工作页的读回核验仍按“用户看得见这一页”定义。现在切换后工作页通常不是活动页，所以读回写“不是活动页”，执行反馈不给成功资格。用例 b 里任务照常做完。要不要改核验的定义，由用户另定。
- CDP 截图失败时，可见截图的回退只在工作页是活动页时才拍。现在工作页通常在后台，所以这条回退会更常拒绝。拒绝提示仍叫助手“切到工作页或切到前台”，但切换工作页已不再切前台，这句提示没有改。

## 结果

R1、R2、R3 做完（10-10），用例没有进 `npm test` 的核心清单。

- 通过：9 项全过，证据在 `out/acceptance/real-path/2026-10-10T05-41-07-797Z-keep-foreground/`（result.json 里有每个工具结果和每 100 毫秒的活动标签页采样，还有截图）。
- 反例：在点击里恢复“切到前台”、开新页恢复成活动页后复跑，a 的 3 项和 b 的“切回表单页后活动页不变”失败，活动标签页采样变成表单页和助手开的页。证据在 `out/acceptance/real-path/2026-10-10T05-33-24-182Z-keep-foreground/`。另一次只去掉交给用户时的切页，d 失败，证据在 `out/acceptance/real-path/2026-10-10T05-41-42-341Z-keep-foreground/`。两处都改回后复跑通过，才提交。
- 受影响的已有用例复跑全部通过：`send-confirm`、`pay-stop`、`handoff`、`sidebar-interaction`、`target-gone`、`pdf-download`。汇总在 `out/acceptance/real-path/summary-2026-10-10T05-38-07-159Z.json`。没有改已有用例的判据。

实现后发现、要用户决定的事：

- 点击打开的新页（target=_blank）。在 Chrome for Testing 里实测：Chrome 自己把新页设成活动页，所以用户的页仍被换走，这一步不是扩展切的。另外，新页记下的“打开者”是当时的活动页（用户的页），不是助手的工作页。扩展只跟随打开者是工作页的新页，所以现在跟不上这个新页：点击结果写“页面没有变化”，工作页还是原页。改前工作页在前台，打开者是工作页，扩展能跟上（见反例证据里 c 的点击结果）。修法要改“跟随新页”的判断，不在本任务范围，等用户决定。
