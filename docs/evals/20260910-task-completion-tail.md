## 用户可见变化

现在可能出现页面已经暂停/提交、所需内容已经读到，但助手继续观察、登记或生成，迟迟不交付。本轮要让完整结果及时显示，任务退出运行状态。登记和执行权限继续采用当前A方案。

## 单一指标

**六次固定任务全部正确完成的前提下，最长收尾等待时间不超过5.000秒。**

每次收尾等待 = T结束 − T结果齐备。

验收值 = 六次收尾等待的最大值。任一次真实任务失败、错误完成或遗漏要求，候选直接不达标；不以其余成功样本均值替代。最大值大于5.000秒也不达标。

采用最大值，保证六次中的任何一次都不能用其他快样本抵消长等待。本轮指标专门验收收尾，整体耗时、模型轮次、登记次数、token保留为诊断数据，不参与多维选型。

## 两个时刻如何独立确定

### T结果齐备

由测试程序在任务开始前定义每项要求的判据，并记录第一次全部满足的时刻，不使用模型自报的完成时间，也不取模型最后一次检查的时间。

- 页面操作：目标页面真实状态达到要求时的事件时间。例如指定视频实际暂停，指定表单由服务端确认提交。
- 读取信息：实际浏览器观察首次将全部必需信息返回应用的时间。例如前三条评论的随机值都在实际观察结果中。
- 多项任务：取上述各必要结果时刻的最大值。暂停视频后还要读评论，不能从单独暂停时刻就算整个任务结果齐备。
- 初始状态已经符合要求：取首次真实观察确认当前指定目标状态的返回时间，不取下达指令之前的历史时间。
- 目标、页面文档或当前要求变化后，旧结果不能算本次完成证据。

计时起点在场景脚本中预先固定，后续重复观察、更新登记或重复宣称完成都不能重置。测试用已知fixture自己的事件与内容核对，产品不能读取测试专用判定变量。

### T结束

下列条件第一次同时成立的时间：

1. 用户要求的完整正式结果已在面板显示，内容与测试页面事实一致。
2. 任务已退出运行状态；本次任务没有仍在生成的模型调用或仍在途的工具操作。
3. 所有要求均已完成，不能留下被忽略的未决结果。

只显示“完成”或切换UI状态不满足终点。第一字出现不等于完整结果交付。原有语音输出保持接通；长音频自然播放时长不计入本轮收尾时间，也不能通过取消应有正文/语音来缩短指标。

结束后额外观察10秒：不得再出现属于已结束任务的新网页操作或重复完成通知。自然结束的同一段语音播放不算重复通知。

时钟使用同一宿主时间基准；页面事件与宿主记录校准。原始毫秒数保留，展示可四舍五入，判定使用未舍入数值。

## 六次真实任务

沿用上轮三类任务，每类两次，使用新鲜独立页面和同一block的相同seed。当前A与修复候选各六次，交错执行，共12次。

| 场景 | 次数 | 正确结果 | T结果齐备 |
|---|---:|---|---|
| 暂停视频，读取前三条评论 | 2 | 真实暂停一次，正式回答含三条实际评论，顺序正确 | 暂停事件与首次获得全部评论内容两者较晚时间 |
| 两个同名控件，只操作指定对象 | 2 | 指定对象改变一次，另一对象未变，回答准确 | 指定对象实际改变时间；若任务还要求读取其他状态，则须等相应必要观察返回 |
| 按钮就绪后提交一次 | 2 | 就绪后实际提交一次，服务端/页面结果与回答一致 | 本次提交真实成功的事件时间，而不是按钮变可用时间 |

任务文案与输出要求提前冻结，不提示特定工具、登记机制或答案措辞。每个场景由机器读取真实状态、调用次数与随机内容判正确，不能以助手说“完成”当证据。

## 必须通过的边界检查

这些是正确完成的硬条件，不是另一套速度评分。模块检查与真实Chrome检查分别留证。

| 反例/边界 | 必须出现的行为 |
|---|---|
| 工具返回成功，但页面没有改变 | 不标记任务成功；不能提前进入完成出口 |
| 只完成多步骤中的第一步 | 继续剩余工作，不提前宣布整个任务完成 |
| 目标已经达成 | 确认后直接收尾，不再点击导致状态反转 |
| 登记的方法与实际成功方法不同 | 在现有权限允许并有正确目标证据的前提下，原意图能正确完成；不因旧方法名称留下假未决项 |
| 无关区域更新、别的对象成功、旧文档/旧任务证据 | 不算当前任务完成；当前完成入口拒绝这些证据 |
| 执行结果未知且没有可归属的结果证据 | 当前完成入口不能把unknown改成成功，不能为了结束任务自动重做 |
| 任务交付后继续观察10秒 | 无第二次页面副作用、无重复完成通知、无隐藏运行中的本任务模型/工具 |

已有R3恢复缺陷独立记录。本轮不新增unknown自动恢复途径，也不声称修复历史恢复缺陷；只要求新的完成出口不能绕过它应有的证据与状态检查。

## 如何保证验收独立

- Codex在实现前冻结场景、时钟、真值判据、5秒门槛与失败规则。
- DeepSeek先完善验收驱动，并在未修改的A上复现问题，再改候选。实现阶段不得修改测试断言让候选过关。
- 验收不导入产品自己的完成判断作为答案。真实页面事件/服务端计数是结果真值，产品运行时事件仅用于记录实际结束。
- 模型、推理档位、输出要求、fixture、起点一致。记录产品与验收脚本hash，运行中不得修改。
- 错误和慢样本逐条保留。基础设施故障另列，修复后按预先安排重跑；真实失败不删除、不刷到通过。
- 分别记录工具开始尝试、实际下发、网页结果、完整正文与真实运行结束，避免拿早期事件冒充结束。
