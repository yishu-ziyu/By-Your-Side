# 任务: 产品从用户自己的浏览里发现反复做的事，问一次，记住后当成做法

来源：2026-10-18 用户决定。以前习惯只来自助手做过的任务，用户自己反复做的事产品看不到。用户自用，效果优先、隐私其次：默认打开，网页标题、网址、点的按钮和链接、搜索词、填写的内容都记，交给快速模型归纳。先例调研（企业流程挖掘、Siri 建议、Atlas 浏览记忆、Recall）见对话记录；消费级没有完整先例。

## 规则

- R1 产品自己记：开关默认打开。用户在网页上打开页面、点击、填写、搜索后，侧栏「记忆」的「看到的操作」里能看到；助手做任务时的操作不算用户的。
  - 例子(正)：用户在测试页点「Docs」、在搜索框填「install」并回车，记录里有这几步 — 谁检查：`browsing-habits.mts`
  - 例子(反)：密码栏和卡号栏填的值出现在记录里；助手执行任务的点击被当成用户的 — 谁检查：`browsing-habits.mts`（密码栏），助手任务一项人工抽查
- R2 重复了才问：同一件事出现在 2 个不同日子里，侧栏出现「你好像每次都这样做：…。要我记住吗？」并带依据；只出现在 1 天的不问。点「记住」存成做法，点「这次就行」以后不再问。
  - 例子(正)：前一天和今天都在同一网站「看 README → 点 Docs → 搜 install」，侧栏问一次，记住后「做法」里有这条 — 谁检查：`browsing-habits.mts`
  - 例子(反)：只有今天做过就问；模型声称的日子在记录里没有也算数 — 谁检查：`browsing-habits.mts`
- R3 看得到、删得掉：「看到的操作」里每条能删，删了不再问；关掉开关后不再记；「全部删除」清空记录。
  - 例子(反)：删掉的那条之后又被问 — 谁检查：人工

## 技术前提

- 前提：内容脚本在所有 http/https 页面已注入（`content-ask.js`），能收到用户的点击和输入。小实验：用例里直接验证。结果：通过
- 前提：天数只按每次交给模型的那份记录算，宿主不另记天数，只记「问过」。这样用户删掉记录就真的不算，不用两边同步（两轮审查里删除后旧天数复活、进行中的归纳写回旧天数，都出在宿主另记了一份）。

## 边界与不做

- 记住后下次「准备」沿用[已确认习惯的准备入口](20261017-confirmed-habit-suggestions.md)，要打开「主动建议」才出现；本任务不改它。
- 风险：网页内容更多地进入模型。去掉批准卡后的提示注入风险（见 [STATUS](../STATUS.md)「仍需解决」）因此变大；用户自用接受，给别人用之前必须先处理。
- 不跨设备同步，不做可执行的站点脚本（AUV 式代码操作），等习惯证明有用再说。
