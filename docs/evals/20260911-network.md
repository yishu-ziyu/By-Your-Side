# 任务：`network` —— 被动看页面调了哪些接口

数据层第二步。用户 2026-09-11 批准顺序：`fetch` → `network` → 批量翻页/`download`。本文件是实施前冻结的标准。

**目标（用户可观察）**：Agent 不用改页面、不用猜，就能看到当前页最近真实发出过哪些请求（方法、地址、状态、类型、大小、耗时），据此找到站点自己的 JSON 接口，再用 `fetch` 取数据；而不是拿 DOM 硬刮。

## 完成标准

- [x] 1. 新只读工具 `network{urlContains?, types?, limit?, tabId?, clear?}`：默认只看 `xhr`/`fetch`，`types:"all"` 看全部；`urlContains` 按 URL 子串过滤（大小写不敏感）；`limit` 默认 40、上限 200，取最近 N 条；`clear:true` 清空缓冲并明确回执。 — 谁检查: npm test（`extension/test/network.test.ts` 21 项纯函数）
- [x] 2. 环形缓冲按标签页隔离（容量 300），跨导航保留、调试器分离后保留；溢出丢最旧并报 `dropped`；SW 重启后为空（内存态，明说）。 — 谁检查: npm test（同上）+ 代码评审
- [x] 3. 被动采集：扩展一旦 attach 调试器就开启 CDP `Network` 域（不额外 attach、不注入页面）；`navigate` 在改地址前先 attach，让加载期的接口调用也进缓冲。attach 失败（如 DevTools 占用）不影响导航本身。 — 谁检查: 代码评审 + 真实路径（navigate 采集到页面加载后的 101 条请求）
- [x] 4. 展示前隐去 URL 里的凭据：`user:pass@` 折叠成 `[redacted]@`；敏感查询参数（token/api_key/secret/password/session 等）只留键名、值替换为 `[redacted]`；业务 id（BV 号、订单号）不误伤。回执进上下文时仍过不可信边界。 — 谁检查: npm test + `agent/test/untrusted-page-content.test.ts`
- [x] 5. 不编造状态：未收到响应写 `pending`、失败写 CDP 的 `errorText` 并标 `canceled`；没有读数就不写数字。 — 谁检查: npm test
- [x] 6. 真实路径：在真实站点上，agent 走 `open_tab` → `navigate` → `snapshot` → `network`，能看到该页真实调用的接口；其中至少一个可由 `fetch` 直接取到数据（串起第一步）。 — 谁检查: 隔离 harness（真实站点、真实扩展构建），见下
- [x] 7. 不改写类工具语义、不动控制闸门；`network` 属读工具。全量测试、typecheck、build 通过。 — 谁检查: `npm run typecheck && npm test && npm run build`（150 文件 1315 项）

## 结果（2026-09-11）

真实路径：`node node_modules/tsx/dist/cli.mjs scripts/acceptance/network-realsite-run.mts`（isolated `isolated-extension.mts`：headless Chrome for Testing + 真实构建的扩展，去掉 manifest key），B 站视频页 `BV1GJ411x7h7`。全部 PASS，原始 JSON 见[运行结果](20260911-network-results.json)：

- `open_tab` → `navigate` → `snapshot` 后，`network` 看到 **101 条真实请求**（`types:"all"`，显示 60）；其中 **14 条**是页面自己调用的 `api.bilibili.com` 接口（view/cards、note、kv-frontend、gaia-gateway 等）。
- 从模型可见文本里取出一个真实调用过的 URL（`https://api.bilibili.com/x/note/is_forbid?aid=80433022&web_location=333.788`），直接用 `fetch` 取回 HTTP 200、`code:0` —— 被动发现接口 → fetch 取数据串通。
- 默认过滤只出 `xhr`/`fetch`；`urlContains:"api.bilibili.com"` 只出匹配；`clear:true` 回「101 requests dropped」，再读为 0。
- 记录行含方法/状态/类型/大小/耗时（如 `20. 200 GET https://api.bilibili.com/x/note/is_forbid?... — fetch application/json 762B 49ms`）。

真实运行暴露并修掉一个真缺陷：页面的 `data:image/png;base64,…` 伪请求也被 CDP 报成请求，首版把整段 base64 写进记录（其中一行上千字符进上下文）。已改为只记 `http(s)`（`isRecordableUrl`），展示 URL 截到 240 字符；重新跑，记录里无 `data:image`，最长行 288 字符。

## 未跑 / 未决

- 「调试器分离后缓冲保留」与「SW 重启即空」只有代码与单测级证据，没有真实验证。
- 用户开着 DevTools 导致 attach 失败时，`network` 只读已有缓冲；该分支未用真 DevTools 验证。
- `navigate`/`open_tab` 现在会提前 attach 调试器，真实浏览中页面顶部的「正在调试」黄条可能比之前更早出现；这条体验变化未人验（隔离浏览器看不到）。
- 未测 `Network.enable` 的额外开销（事件量、内存）；本机 101 条请求的样本看不出明显代价。

## 边界与不做

- 不记录请求/响应 body、headers、Cookie（v1 只做「调了哪些接口」；body 与回放留给后续）。
- 不记录 WebSocket/EventSource 帧；CDP `type` 原样展示。
- 不注入页面脚本、不 hook fetch/XHR；数据只来自 CDP Network 域。
- 缓冲不落盘、不跨 SW 重启。
- 不因 DevTools 占用而抢调试器：attach 失败时 `network` 明确说拿不到记录，不伪造。
- 采集窗口 = 扩展持有调试器期间（空闲 15 秒自动分离是既有的省电/省黄条设计，本轮不改）。
