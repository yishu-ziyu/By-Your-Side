## 阻断

1. 英文「not only … 应全局」未生效（假阳性，判成了 site）。`WIDENING_NEGATION_EN_RE` 被拿去匹配 `before`，而 `before` 是站点匹配起点之前的切片，永不包含 `this site` 本身，因此该守卫永远不触发（代码注释明确写着要挡 "not only this site"）。实测：

```
not only this site                         -> SITE（应为 all）
please remember, not only this site, ...   -> SITE（应为 all）
not limited to this site                   -> SITE（应为 all）
```

   直接验证根因：`WIDENING_NEGATION_EN_RE.test("not only this site") === true`，但 `...test("not only "（before）) === false`。实际影响是：本应全局的偏好被收窄并保存到当前标签页 hostname。对应路径 `clauseRestrictsToSite`（`agent/src/memory-runtime.ts:148`）。新增测试没有英文 "not only" 用例，所以测试全绿也不覆盖此项。

2. 回归：裸「本站」丢失识别 → 回退成 all。旧正则显式含 `本站`；新 `CURRENT_SITE_RE` 是 `(?:当前|这个|此|本)…(?:网站|站点|网页)`，`SITE_NOUN` 里没有「站」，所以「本站」不匹配任何分支。实测：

```
请记住，本条只用于本站   -> 新=all，旧=site
以后只用于本站           -> 新=all，旧=site
```

   「只用于本站」现在静默落成全局，正是本任务要消除的「回退成 all」失败类型，方向与目标相反。
