# 任务：让日常使用开始积累 EverOS 经历

用户明确要求现在启用，边使用边观察积累是否有效。此前“先证明生成技能才启用”的前提已被修订；本轮完成条件是日常入口持续积累，不是宣称学习收益。

## 完成标准

- [x] 1. 持久本地服务已运行，登录后可自动恢复，有明确关闭方式。— 谁检查：运行状态、health 与停启实测；未执行整机注销/重启，自动登录启动依据 LaunchAgent RunAtLoad
- [x] 2. 从启用后的新完成任务读取产品实际记录，经真实模型整理并落为可检查的文件。— 谁检查：真实产品记录链与 EverOS 回执/Markdown
- [x] 3. 不导入启用前的历史，不采集未交给助手的网页，不把任务结束当作成功，不覆盖个人事实或直接执行生成技能。— 谁检查：定点测试与接线检查
- [x] 4. 服务失败不阻塞当前浏览器任务；队列/断点保留，重启不重复导入已处理任务。— 谁检查：失败/恢复测试

## 实现边界

复用现有 ExperienceStore：原生 main 已对每个完成任务持久化受限长度、去除已知密钥的工具回执，无需重载正在使用的浏览器。独立服务仅扫描启用后的完成记录；不全盘读取聊天、截图或浏览历史。保留回执失败/未知状态和实际用户纠正，不补造缺失调用参数。

独立数据目录 ~/.sideagent/everos，与其他产品 ~/.everos 不混用。沿用 OpenCode Go/deepseek-flash，密钥启动时从现有 Pi 凭据读取，不写配置/日志。本地中文 embedding，512 维补零至上游 1024 维表结构，保持余弦相似度。关闭画像推断和预测；案例/技能整理可运行，结果不注入日常执行。

## 遇到并修正的问题

停用后的 launchd 条目可能尚未移除，立即开启会误踢即将删除的旧条目；关闭命令现等待条目移除。服务启动时后台接收器曾早于 HTTP 就绪发出请求，得到 ConnectError；现先核验 readiness，已确认未建立连接的失败可安全重试，其他不确定请求仍保留 needs_check。

上述启动问题影响了第一条验收记录；核实空 flush 和无 Markdown 后，只将该验收记录重新排队。最终实际记录已 extracted，保留 ingestion 中 repairNote；没有把接收不确定误报为已积累。

## 边界

现在启用的是积累与后台整理，生成内容不覆盖用户明确事实，也不直接改变浏览器操作。长期收益留待日常使用判断。接收时只用已有受限回执，不含截图/完整聊天；任意未标识秘密无法保证自动识别，敏感操作可关闭积累。未提交/发布代码；本机常驻服务已实际启用。
