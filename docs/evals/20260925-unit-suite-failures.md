## 待裁决：执行过通用脚本后，「执行账本覆盖全部变更」还算不算数

- 09-21 的测试（A）：成功执行过 `js` 后，`executionAuditComplete` 必须为否——脚本改了什么说不清，核对「不要保存」这类约束时不能拿账本当证据，只能重读页面。
- `ce4ecee` 同时加了两条相反的断言（B，`task-result-turn-economy`、`realtime-multiturn-repair`）：有副作用的 `js` 会自动记一条结果，所以账本仍算覆盖全部改动；结果未知的脚本靠「未知记录」拦住后续写入。
- [浏览器能力 v2 记录](20260922-browser-capability-integration-v2.md)当时写明这两条失败「未改其业务语义或删断言」，即没有做过决定。
- 按 A 修代码（`js`、`cdp` 执行过即审计不完整）后，A 通过，B 的两条失败；已撤回，保持现状。今天起页面脚本在所有模式下可用（[Sitegeist 对照](20260925-sitegeist-parity.md)），这条的影响面比以前大。

## 裁决与实现

用户选 A：日记（执行账本）里有「执行过一段脚本」这种看不出改了什么的一笔时，核对「没保存 / 没提交」必须回页面上看，不能只翻账本。

第一次实现直接让 `executionAuditComplete` 在执行 `js`/`cdp` 后置否，全量出现两条新失败：`conversation-manager` 用同一个标记当写入闸门（「每次改动都记了账」才放行写入），置否后执行过一次脚本，之后的写入永久被拦。已撤回。

最终实现把两个意思拆开：
- `executionAuditComplete` 不变：每次改动都记了账，写入闸门继续只看它；
- 新增快照字段 `opaqueEffectRan`：本 run 真正执行过 `js` 或 `cdp`（`executionFact` 不是 `not_executed`）就为真，随快照保存与恢复；
- 新增 `executionEffectsFullyKnown(snapshot)`（`shared/voice.ts`）：账本完整、没有未记账写入、没执行过看不出效果的工具才为真；`task_goals` 核验传给核对模型的 `executionAuditComplete` 改用它。

检查：
- 全量单元测试 3059/3059 通过；`task-goals` 那条改为断言 `executionEffectsFullyKnown`，删掉置位那一行时它失败（1 failed / 13 passed），恢复后通过。
- 真实路径（只装扩展，step-3.7-flash）：日常 `13-35-38` 复制不保存通过（39 秒，逐字、未保存）、翻译通过、圈画失败（只圈了「五小时用量」没带「32%」，本轮未用脚本，与本改动无关，上午同样 2/3）；Sitegeist `13-37-35` 5/5。所有回答都没有「没法确认」「仅交付部分结果」。
- 缺口：上述 8 条任务里模型一次 `js`/`cdp` 都没用，新规则在真实路径上没有被触发；只有单元测试覆盖。
