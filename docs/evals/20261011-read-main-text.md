# 任务: 问「这页讲了什么」时，第一轮就用读好的正文作答，不挂调试器（#255、#260）

## 规则
- R1 发送前读页给页面正文，不给 AX 树的前 12,000 字。正文没读完时，写明给了多少、一共多少，不写「truncated」。
  - 例子(正)：在 Wikipedia「Hayao Miyazaki」说「Summarize this page in 3 sentences」，模型一轮答完，不再调读页工具 — 谁检查：工程师用真实阶跃跑 6 次，看诊断记录的轮数
  - 例子(反)：改前同样跑，6 次里 2 次多读 1–3 轮 — 谁检查：同上（基线）
- R2 只读问题从发送到回答完，调试器一次也不挂（页面顶上不出「已开始调试此浏览器」） — 谁检查：工程师用测量脚本记 `chrome.debugger.attach` 次数
- R3 动作任务不因为读页没有元素编号而变慢或做错 — 谁检查：工程师用真实阶跃跑「搜索并打开」2 次，看轮数和第一步
- R4 隐私和读页相关的已有用例照常通过 — 谁检查：snapshot-privacy、readback-privacy、answer-straight、keep-foreground、welcome-context、sidebar-interaction、panel-tidy（脚本模型）

## 还没答上的问题
- 无。

## 技术前提
- 前提：在隔离环境里能取到页面正文，速度够快，正文占大头。小实验：Playwright 打开 3 个真实页面，执行同一个抽取函数。结果：通过。Wikipedia「Hayao Miyazaki」取到 `main#content`，全文 136,562 字，耗时 97 毫秒，前 12,000 字是信息框（约 800 字）加导语、早年经历和职业开端；Wikipedia 首页 7,024 字，22 毫秒；GitHub 组织页 2,963 字，4 毫秒。

## 边界与不做
- 核对目标那次读页仍取 AX 树，因为它要看表单里填了什么、勾没勾选，这些正文里没有。读页分层之后，只读问题多数一轮答完、不用工具，本来就不触发核对。
- 重启续做时的读页仍取 AX 树：续做的是动作任务，要元素编号。
- 调试器空闲 15 秒才断开（#260 的另一半）没改：只读问题现在不挂，动作任务的断开时机另做。
- 「圈出来」这类标注任务要元素编号，可能要先 snapshot 一轮；按文字圈的不需要。本次没测。
