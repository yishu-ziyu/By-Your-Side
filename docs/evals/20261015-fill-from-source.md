# 任务：把一页上已有的一段文字原样填进另一页时，文字由扩展直接搬，不经过模型重打

用户让助手把 A 页的一段长回答原样发到 B 页。以前模型会把全文读进来再重打一遍：每次约 30 秒；真实会话里重打还把中文引号改了，丢了 77 个字。PR #473 试过两版 browser_run 说明，模型时而照做、时而退回重打，所以这次改工具本身：fill 多了 `from`，模型只需指出文字在哪个元素。

## 规则
- R1 fill 给 `from: {target, tabId?}` 时，扩展读出那个元素的文字，按正常的 fill 流程写进目标栏。读法：输入框、下拉框读显示值；富文本编辑器读 editableText；快照里的 text 行（文字节点）读它自己的文字；其他元素读 innerText，也就是排版后的样子：段落之间、列表项之间有换行，隐藏的部分不读。首尾空白去掉。`value` 和 `from` 只能给一个。
  - 例子(正)：一段纯文字回答（中文引号、空行、列表），from 用 CSS 或快照里的 @ref 指向它，网站收到的文字与原文逐字相同 — 谁检查：`npx tsx scripts/acceptance/real-path/fill-from-source.mts --headless`
  - 例子(正)：由几个 `<p>` 和一个 `<ul><li>` 组成的回答，网站收到的文字段落和列表的换行都在，隐藏的段落不在 — 谁检查：同上
  - 例子(反)：value 和 from 一起给时报错，输入框一次都没被写过 — 谁检查：同上
- R2 来源是密码、验证码、卡号这类栏，或者来源元素自己没显示在页面上（display:none、在收起的面板里），就拒绝读取，记为“未执行”，目标栏不动。
  - 例子(反)：from 指向密码栏、隐藏的 div、收起的 `<details>` 里的字：都被拒；密码和隐藏的字没出现在给模型的任何内容里 — 谁检查：同上
- R3 搬运的文字不回给模型：回执只有字数和首尾各 20 个字，放在 `<page-content untrusted>` 里；fill 读回只留核对结论，不带读到的值；工具结果的 details 只记字数。语音直接操作时如果 fill 结果不明，回读只报“这一栏现在有 N 个字”，不交出全文。
  - 例子(正)：回执里有字数、“holds exactly this text”，没有正文中间的句子 — 谁检查：同上
- R4 读来源不改工作标签页：worker 读别的标签页上的来源后，写入仍落在原来要填的那一页。
  - 例子(正)：worker 路径没有自动用例，只做了代码审查；主助手路径见上面的用例（来源在另一个标签页，写入落在聊天页）。

## 技术前提
- 前提：快照里回答那一行常常是文字节点，visibleText 对文字节点读出来是空的。小实验：X19 第一轮里 MiniMax 两次用 from 都指向文字节点，报“没有可见文字”后退回重打。结果：已改成读文字节点自己的文字，用例覆盖。
- 前提：元素自己没显示时，innerText 退回 textContent，会带上隐藏的字和脚本。小实验：用例里的隐藏 div 带一段 `<script>`。结果：先查元素有没有显示，没显示就拒绝。

## 边界与不做
- 不强迫模型用 from：说明里只有一句话和一个示例，模型仍可以自己写 value。gpt-6-luna 至今没用过 from。
- 语音工具表跟着构建重新生成，语音也能用 from；语音“结果不明后回读”这条路径没有自动用例（要真实语音模型选中 from，还要在写入时断线）。
- 发送确认、付款、“填完回车”的规则都没变。
