# 任务: 修 10-06 日常一轮（关注播客）记录里看到的四个问题

来源：用户 2026-10-06 在日常扩展里让助手「关注这个播客」，中途插话问文字稿、要它记住邮箱，登录后接着做。诊断记录（扩展 `sideagent-diagnostics`）里看到下面几处，用户同意先修。

## 规则
- R1 任务进行中插话说「记住…」，记忆工具不再以「当前记忆操作已失效，未获授权」拒绝。
  - 例子(正)：任务跑着时插一句「记住我的邮箱是 …」，模型调用记忆修改，不报未获授权 — 谁检查：`scripts/probes/memory/steer-remember.mts`（撤掉修复时失败，报的正是这句）
- R2 插话只有在真纠正（「不对」「错了」…，沿用记忆模块的纠正规则）时才升思考档；补一个问题、补一条资料不升。
  - 例子(反)：插话「你有办法获取到这个播客的文字稿吗？」不再把 high 升到 xhigh — 谁检查：`agent/test/main-effort-session.test.ts`（一句纠正 + 一句补充，只升一档）
- R3 被插话作废、没执行的旧步骤，不算「改页面却没生效」；回答末尾不再补「页面没有变化：本轮 1 次改动页面的尝试都没有生效」。页面脚本被拦、一步没走的仍算。
  - 例子(正)：点「关注」那步被插话作废，回答不带这句 — 谁检查：`agent/test/page-unchanged-delivery.test.ts` 原有用例照过（规则只排除作废结果）
- R4 一步做完、下一步还没开始时，进行中那一行写「正在思考」，图标随之换成思考；不停在刚做完的动作上（记录里「正在读取页面结构」停了 83 秒）。发送前去掉文字里看不见的控制字符（记录里有一个退格符）。
  - 例子(正)：两步之间回到「正在思考」 — 谁检查：`scripts/probes/shell/process-line.mts`

## 技术前提
- 前提：原因都在记录里能对上。R1：插话时 `invalidateUserTurn("steer")` 只作废上一轮，没有开新的一轮，记忆工具找不到当前用户发言。R2：`steerCurrentTask` 无条件 `raise("user_correction")`。R3：作废的 browser_run 计入改页面尝试。小实验：`steer-remember.mts` 在旧代码上复现原报错。结果：通过

## 边界与不做
- 不改「目标核对说没做完就升档」（记录里升到 max）：要先看它在别的任务里的收益。
- 不改插话作废进行中动作的规则（记录里点「关注」被一句不相干的追问作废）：涉及执行安全，另议。
- 不改续做时把已完成的输入重新交给模型（记录里又去看了一遍文字稿）。
