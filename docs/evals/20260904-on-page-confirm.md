# 任务: 就地确认 —— 在被圈住的东西上点，而不是只在对话框里回「确认」

来源：2026-09-04 人评危险操作确认之后。用户指出有趣的不是侧栏再打一个「确认」，而是确认发生在页面上：圈住那条笔记的标注本身可以点（删除 / 取消只是例子，设计未定）。要通过点击感受「这一下是我做的」。

对应路线图：`docs/ROADMAP.md`「就地确认」。修订 2026-09-03「纯对话、不做就地 UI」。

```
Change:     Agent 提出删除（或同类不可逆动作）并圈住目标之后，用户能在页面上那块标注附近点一下完成确认或取消；点确认则动作发生，点取消则不发生。侧栏打「确认」仍然有效。
Not this:   只在侧栏多一句「请回复确认」；侧栏里的批准卡片；把整页做成不可点的遮罩；为每个网站做专用删除插件。
Evaluator:  人评。场景沿用 flomo：定位一条笔记 →「把这个笔记删掉」→ 不打字，点页面上的确认，笔记进回收站；另一次点取消，笔记还在。
Evidence:   真机路径 + 标注上控件的截图。观感由用户裁决。
```

画面：`docs/evals/20260904-on-page-confirm-done.html` 右边。左边是没做好。人已认右边。产品没长成右边，就还没好。

## 完成标准

完成标准由校验写于实现之前。实现不能改判定条件。对照以 HTML 为准，不以口头描述为准。

- [ ] 1. 要点「删除 / 清空 / 支付 / 发送」（及 Delete / Remove / Pay / Send）时，程序先不真点。目标旁画出框外「删除」「取消」。谁检查: `npm test`（`isDestructiveLabel` + click 在未放行时返回 held、不派发）+ 人评
- [ ] 2. 点页面「删除」，或侧栏打「确认 / 是 / 继续」，刚才那一下才发生。谁检查: `npm test`（放行后 click 返回 clicked）+ 人评（flomo 删笔记进回收站）
- [ ] 3. 点「取消」，或侧栏打「取消」，不执行，标注收起。谁检查: 人评
- [x] 4. 普通点击、填字不拦。谁检查: `npm test`（「分享」「编辑」「更多」不是危险词；2026-09-04：isDestructiveLabel 单测）
- [ ] 5. 控件跟目标走，不挡住笔记正文到无法辨认。谁检查: 人
- [x] 6. `npm run typecheck` / `npm test` / `npm run build` 全绿。谁检查: 机器（2026-09-04：201 tests）

## 人评 2026-09-04（未过）

场景：flomo「把除了置顶之外的第一条笔记删除」（MiroFish 项目）。侧栏已连接；伴随进程是当次会话拉起的，prompt 含 `mark.actions`。

- 页面上没有框外「删除 / 取消」。flomo 上只有 cursor overlay，没有 marks overlay。截图里看见的红「删除」是站点「更多」菜单的 `div.menu-item.danger`，不是我们的按钮。
- 这次 run 调了 14 次 `mark`，**全部没有 `actions`**。目标全是走查页标题，例如 `loc=css:h2:has-text("3. 点发送之后的第一帧")`、label `❌ 立案后空壳帧`（`file://…/show-me-walk/index.html`）。切到 flomo（第二次 `switch_tab` tabId=29950915）之后再没有 `mark`。
- 随后三次 click：「打开目标笔记查看删除入口」→「点击更多找删除按钮」→「试试点击详情面板无名按钮找删除」；第四次「关闭分享图对话框」失败。然后停在侧栏等打「确认」。
- Agent 文案写「已经在页面上把要删的那条笔记标红了」——与工具记录不符。

结论：扩展渲染链路这次没被走到。失败在模型没对目标笔记 `mark`+`actions`，还打开了站点自己的删除菜单。人评 1–4 不能勾。

## 边界与不做
- 视觉已定：框外双键（`docs/evals/20260904-on-page-confirm-compare.html` 第 1 案）。不做角上插件、不做整框即删除
- 不拦所有 click。只拦文案是删除 / 清空 / 支付 / 发送（及对应英文）的那一下
- 本轮不拦 `js` 里直接调删除接口
- 不做站点专用插件（flomo 只是用来走真实路径）
- 不做接管/交接
- 不改教学模式开关
