# 任务: 回答还在写时，用户往上滚一点就停在那里，不被拉回底部

以前对话区离底部不到 80px 都算“在底部”，滚轮往上一格（40–60px）之后，下一段字一到就把用户拉回底部。做法参考 Claude Desktop：对话区往上滚就离开底部，往下滚到离底部 40px 以内才重新跟上，用户刚动过滚轮、手指、滚动键或滚动条的一小段时间内不自动跟随。

## 规则
- R1 回答还在写时，用户往上滚，哪怕只滚一格或按一下 PageUp，画面停在滚到的地方，“回到底部”圆钮出来。在过程窗里滚，只滚过程窗，对话区照样跟着写。
  - 例子(正)：长回答写到一半，滚轮往上 40px，之后 1.5 秒画面不动，下面的字照常写 — 谁检查：`npx tsx scripts/acceptance/real-path/scroll-follow-hold.mts --headless`
  - 例子(反)：滚上去 40px，几十毫秒后又回到底部 — 谁检查：同上
- R2 用户滚回离底部 40px 以内、点“回到底部”、或发新消息，就重新跟着写，直到回答写完。
  - 例子(正)：滚轮滚回底部后，每次读数都离底部不超过 40px，直到回答写完 — 谁检查：同上
  - 例子(正)：上一个回答写完后往上翻了一点，再发新消息，画面回到底部 — 谁检查：同上
  - 例子(反)：滚回底部后，新写的字跑到可见区下面 — 谁检查：同上

- R3 停在底部时侧栏变窄、内容变高，画面仍贴着底部。
  - 例子(正)：一整段长回答写完，侧栏从 400px 拉到 300px，离底部 0px — 谁检查：同上
  - 例子(反)：拉窄后画面停在上面几百像素 — 谁检查：同上

## 技术前提
- 前提：浏览器按上一帧画出的内容滚到底，scroll 事件到达前常已插进一段新字，所以“滚回底部”按用户刚才看到的底部判断。小实验：本用例的滚回底部轮，旧判断下离底部 89px 后不再跟随。
- 前提：无头 Chrome 里滚轮一格立刻滚到位，PageUp 有平滑动画（约 170ms）；触控板的惯性滚动只能在有窗口的浏览器里看。
- 前提：过程块默认收着，点开后才是可滚的过程窗；过程跑完收起时内容变短，浏览器把画面夹回底部，会掩盖“在过程窗里滚让对话区停止跟随”这类错误，用例抓不到它。
- 前提：回答还在写时，输入框盖住“回到底部”圆钮的中心，点上去落在输入框上。用例只走“滚回底部”这条路；圆钮被盖住要另开任务修样式。

## 边界与不做
- 执行过程窗里的跟随只加了“滚轮往上就停止跟随”，阈值不变。
