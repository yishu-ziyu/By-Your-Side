# 任务：两个杠杆——当前页观察预注入 + 交付后运行时收尾（真实对照）

来源：用户 2026-09-11 在 claude 会话 `fc65696b-0778-4dcc-bc94-444a0ea40552` 追问"为什么改动之后总耗时反而增加了"，
接受"中位数基本不动"的更正后，要求把两个真正的杠杆改掉并做对照：
①把当前页观察预注入（少一轮观察）；②交付后由运行时判定收尾（少一次 1–3s 的模型调用）。
本文件是实现前冻结的标准，结果写在本文件「结果」一节。

**上一份标准的继承**：[20260911-fast-and-lean.md](20260911-fast-and-lean.md) 的 A1（单动作 ≤2 轮、
首个页面动作 ≤5s）本轮继续有效，本轮的标准是它的推进版。B/C 两组（模型面字符数、用户面单指示）不变。

**目标（用户可观察）**：页面已打开、目标明确的单动作任务里，模型只花 2 轮（动作 1 + 交付 1），
不再出现"先观察一轮"和"交付后再收尾一轮"；同 case 总耗时中位数明显低于改前（省下约两轮模型延迟）。
页面结果不变：真的暂停、恰好交付一次。

**范围**：`agent/src/session.ts`（发送用户消息前的预观察）、`agent/src/prompt.ts`（预置观察的使用规则）、
`agent/src/user-delivery.ts`（finding 交付的收尾信号）。扩展 RPC 名、控制闸门、账本语义、
危险确认、语音路径不动。

## 完成标准

### L1 观察预注入

- [ ] L1-1 用户消息发出前，运行时读一次用户当前页（`snapshot`，带 tabId），把观察文本按不可信页面内容包裹后
      附在消息尾部；读失败、超时、无 tabId、无扩展连接时静默降级为原文，消息照常发出，不阻塞。— 谁检查: npm test
- [ ] L1-2 真实路径：改造后首轮模型调用即动手（工具序列里第一个改变页面的动作之前没有模型自己的 snapshot 轮）。— 谁检查: 人（`scripts/acceptance/fast-turn-run.mts` + trace）
- [ ] L1-3 运行中插话（steer）路径不预注入，插话语义与延迟不变。— 谁检查: npm test

### L2 交付即收尾

- [ ] L2-1 `send_user_message(kind="finding")` 的工具结果带 `terminate: true`，run 在该轮后结束；
      `kind="ack"` 不带 `terminate`（开场应答不能掐断任务）；被拒绝的交付（异常）不带 `terminate`。— 谁检查: npm test
- [ ] L2-2 真实路径：交付轮之后不再出现新的 `turn_start`，交付仍恰好一次，页面结果正确。— 谁检查: 人（同上脚本）

### A 对照（同机同日、同模型、同 case，各 3 次）

- [ ] A1 轮数中位数 ≤2（改前 4–5）。— 谁检查: 人
- [ ] A2 总耗时中位数比改前低 ≥1.5s（≈两轮模型延迟）。— 谁检查: 人
- [ ] A3 改后 3 次全部：页面真的暂停、恰好交付一次、无错误。— 谁检查: 人

### R 回归

- [ ] R1 `npm run typecheck`、`npm test`、`npm run build` 通过；系统提示词仍 ≤15,000 字符。— 谁检查: npm test
- [ ] R2 合并工具真实扩展路径（`merged-tools-run`）、面板运行态（`run-status-ui`）重跑通过。— 谁检查: 机器脚本

## 边界与不做

- 不动扩展 RPC 名、`WRITE_TOOLS` 闸门、`PAGE_IDENTITY_TOOLS` 账本语义、危险确认与不可信内容边界。
- 不改语音、技能、记忆、多成员协作路径；steer 不预注入。
- 不为了凑轮数删掉模型的判断时间或改成固定动作序列。
- 真实观感（这一轮跑起来是否更顺）由用户裁决；机器只给轮数、耗时与结构事实。
- 本轮不提交、不推送、不重载用户扩展。

## 基线（改动前，当前工作区代码）

同一 case（页面已打开、视频在播，用户说"把视频暂停"），真模型 `minimax-cn/MiniMax-M3` + 隔离 headless Chrome。
改前实测（上一轮 + 本轮重跑）见「结果」一节；结构为「观察 1 + 动作 1 + 交付 1 + SDK 收尾 1」= 4–5 轮。

## 结果（2026-09-11）

### 对照（同机同日先后跑，真模型 `minimax-cn/MiniMax-M3` + 隔离 headless Chrome，同一 case「把视频暂停」）

| | 每次轮数 | 轮数中位 | 每次总耗时 (ms) | 总耗时中位 | 首个页面动作中位 | 恰好交付一次 | 页面真的暂停 |
|---|---|---:|---|---:|---:|---:|---:|
| 改前（3 次） | 4 / 4 / 5 | 4 | 15929 / 7693 / 13471 | 13471 | 7474 | 2/3 | 3/3 |
| 改后（5 次） | 3 / 2 / 2 / 2 / 2 | 2 | 10708 / 7459 / 5332 / 5043 / 4575 | 5332 | 2715 | 5/5 | 5/5 |

- A1 ✅ 轮数中位 4 → 2。A2 ✅ 总耗时中位 13.47s → 5.33s（−8.1s，远高于 ≥1.5s 的门槛）。A3 ✅ 改后 5 次全部页面真的暂停、恰好交付一次、无错误。
- 小样本说明：改前本身方差大（7.7–15.9s），单看某一次会得出相反结论；这里只按中位数与逐轮结构归因。

### 逐轮结构（run trace，`~/.sideagent/traces`）

| 运行 | 结构 |
|---|---|
| 改前（4 轮样例） | `tabs` → `snapshot`(20ms) → `click`(645ms) → 第 4 轮纯文本收尾（986ms） |
| 改前（5 轮样例） | `tabs` → `snapshot`(1294ms) → `click`(1067ms) → `send_user_message` → 第 5 轮收尾（1740ms） |
| 改后 run1 | `pre_observation`(31ms) → `tabs`(12ms) → `click`(590ms) → 交付 → **agent_end 紧跟该轮** |
| 改后 run2 | `pre_observation`(16ms) → `click`(579ms) → 交付 → **agent_end +1ms** |
| 改后 run3 | `pre_observation`(5ms) → `browser_run`(633ms，内含 click) → 交付 → **agent_end +1ms** |

- L1-2 ✅：改后 5/5 的模型第一轮直接动手（`preObserved=true`），改前那轮模型自己的 `snapshot` 消失，代之以运行时 5–31ms 的只读读取。
- L2-2 ✅：交付轮之后不再有新 `turn_start`，`agent_end` 与交付轮 `turn_end` 相差 1–4ms；改前那次纯文本收尾轮（986ms / 1740ms）整体消失。
- 改后 run1 多出的 `tabs` 轮是模型自己先确认工作标签页，不是架构开销。

### 机器检查

- L1-1 ✅ / L1-3 ✅ / L2-1 ✅：`agent/test/session-pre-observation.test.ts`（5 项：注入与包裹、读失败降级、无 tabId 不读、超长截断、插话不注入）+ `agent/test/user-delivery-runtime.test.ts` 新增 finding/ack 的 `terminate` 断言。
- R1 ✅ `npm run typecheck`、`npm test`（153 文件 1335 项）、`npm run build` 全过；系统提示词 14,993 → 14,973 字符（新增预观察规则，按"删重复不删规则"压回 15,000 以内）。
- R2 ✅ `merged-tools-run` 7/7（`{"ok":true}`）、`run-status-ui` 10/10（`{"ok":true}`）。
- 中途一次全量测试出现 2 个 QuickJS `interrupted` 失败（`browser-program-binding`、`harness-tool-access-evaluator`），单跑与复跑均通过，判定为并发负载下的既有抖动，与本次改动无关；同一次里真失败的是 `session-helpers` 的图片用例（`prompt` 现在晚一个微任务发出），已按新时序改写断言。

### 边界探针：多步任务（暂停 + 滚到底部，改后 3 次）

- 3 次里 2 次正常：两步都做完，最后一轮一次交付，`agent_end` 紧跟交付轮（结构符合预期）。
- 1 次在第 2 轮只输出了内部文本就结束，**没有向用户交付**。改前基线的单动作场景也出现过同样的 1/3 无交付（那次 `deliveryCount=0`），所以这是既有的模型行为缺口，不是这两个杠杆引入；但它值得单独查。

### 未跑 / 未验证

- 预注入的 token 成本：整页快照最多 12,000 字符进入每条新任务消息（快照真实大小因页而异），本轮只测了收益侧。
- 重页面（快照 24k 命中截断）与"用户消息其实不需要页面"的场景，预注入是否有净收益未测。
- 真实扩展里的人眼观感（是否更顺）、多步任务的交付缺口，均留给人裁决与后续任务。

### 结论

两个杠杆都真的起作用：结构上少掉「模型自己观察」和「交付后收尾」两轮，总耗时中位数降 60%，首次动作从 7.5s 提前到 2.7s；交付成功率没有变差（单动作 5/5）。代价是每条新任务多一次只读快照（5–31ms）与最多 12k 字符的上下文。

人裁决（2026-09-11）：用户看过本对照后确认提升有效，并要求提交推送；上面「未跑 / 未验证」里的真实观感与多步交付缺口仍留给后续。
