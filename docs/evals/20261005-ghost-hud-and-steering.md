# 任务：侧栏一点就直接操作页面；回答写到一半能当场改方向

[规范](../tasks/20261005-ghost-hud-and-steering-spec.md) · [使用说明](../guides/usage.md) · [协议](../protocol.md)

## 规则

- R1 页面有可控的媒体或长代码块时，侧栏顶部出现直连按钮；点了直接在页面执行，不调用模型。
  - 正：本机页有正在播放的媒体，点「暂停」后媒体暂停，侧栏显示耗时 ≤50 ms，脚本模型这段时间收到 0 次请求。机器检查：`accept:real-path` 的 ghost-hud-and-steering。
  - 反：页面没有媒体、没有长代码块时不出现按钮；页面没有「下一首」控件时不出现该按钮，不点别的「Next」链接。机器检查：同上。
- R2 执行后页面正中浮起深色毛玻璃提示，1.2 秒内淡出并删除，不留节点。
  - 正：点后 200 ms 内页面有提示且文字说明结果；1.5 秒后页面里没有提示节点。机器检查：同上。
  - 反：连点两次只留一个提示；减少动态效果时不播放缩放。机器检查：连点；减少动效由人看。
- R3 回答正在逐字写出时，输入区出现改方向的快捷按钮；点了或打字回车，不中断任务、不报错，正在写的回答当场换成新要求的样子。
  - 正：脚本模型慢速写长文，点「改成对比表格」后：第一段长文没写完就停，同一轮里模型收到原半截正文与改方向要求，回答位置换成表格，并显示「已改方向：对比表格」。机器检查：同上。
  - 反：侧栏不出现错误消息；原长文末句不出现在最终回答里；没在运行时不显示快捷按钮。机器检查：同上。
- R4 改方向不分裂会话：这一问一答只算一轮，历史里留下改方向那句话。
  - 正：整个过程只有一次任务开始与一次结束，会话数不变；重开侧栏后历史里有改方向那句话和表格回答。机器检查：同上。
  - 反：语音插话、模型正在调工具时不截断，照旧等这一步做完再读插话。机器检查：`agent/test/steer-reshape.test.ts`。

## 还没答上的问题

无。规范要求新增 `STEER_INFLIGHT_TASK`；现有 `task_action` 的 `steer` 已是同一件事，新增会让同一事实有两个入口。本轮复用 `steer`，快捷按钮只是预填好的插话。「下一首」只认 YouTube、Bilibili 播放器自带的按钮，不猜其他网站。

## 技术前提

- 前提：模型正在写正文时，把已写部分当成这一轮的完整回复交回，Pi 会在同一轮里读插话并开始下一次模型调用，不报错。小实验：`agent/test/steer-reshape.test.ts` 的第一个用例（脚本化真实 Pi 会话）。结果：见证据。
- 前提：侧栏可以直接给页面脚本发消息并拿到回复，不经后台。依据：Chrome `tabs.sendMessage` 对扩展页可用；由端到端验收的耗时项实测。

## 边界与不做

- 不给按钮接模型，不新增网页写权限之外的能力；只操作页面已有的媒体元素、播放器自带按钮和代码块高度。
- 不改语音插话行为；不改「运行中补充要求」的排队与销账规则。
- 不重载日常扩展、不提交。保留工作区里其他工作线的未提交改动。

## 证据

- 技术前提：`agent/test/steer-reshape.test.ts` 先红后绿。改动前插话后模型一直等长文写完（F1 超时）；改动后 3/3 通过。加严后，去掉「有工具调用不截断」的判断，F6 会失败。
- 端到端：`npx tsx scripts/acceptance/real-path/ghost-hud-and-steering.mts --headless --run=final`，20/20 通过。产物在 `out/acceptance/ghost-hud-and-steering/final/`：result.json、hud.png、ghost-bar.png、steer-before.png、steer-after.png。
  - R1：点暂停，页面内 1–2 ms 完成；按钮操作期间模型请求 0 次；页面上有普通「Next」链接时不出「下一个」，普通页不出按钮。
  - R2：提示文字为「已暂停」，1.4 秒后节点数为 0；连点只留一个提示。
  - R3：点「改成对比表格」后 35 ms 开始写新回答；模型收到 24/234 字的半截正文和改方向原话；侧栏无错误，长文末句没出现。
  - R4：主模型只调 2 次（被截断的一次 + 重写），只有一个最终回答；重开侧栏后改方向标记和表格仍在。
- 反例：临时关掉截断，「立刻按新要求写」变为 3478 ms，「半截正文」变为 234/234，两项都失败。「原长文末句没写出来」在不截断时也通过，因为旧段落会被收起，所以它不证明截断。
- 独立审查后修复：切会话时清掉待挂的标记；插话没发出或被拒绝时不挂标记；页面无回应的提示保留 4 秒；截断收下的消息做深拷贝；两条宽松的测试和两条验收判据改为可证伪。
- 工程检查：首次 `VITEST_MAX_WORKERS=1 npm run check` 退出码 0（253 文件、2392 测试）。修复后第一次复跑有 1 项失败：`side-judgment-session` 的 J3 用例多出一次后台判断调用，本次没有改这块代码，失败日志见 `check-rerun-flaky.log`。在独占条件下单独复跑这个文件 3 次，每次 8/8 通过。再次完整复跑退出码 0：253 个文件、2392 项测试，文档 0 错误 0 提醒，日志见 `check.log`。这项偶发失败没有修，也没有查明原因。
- 未跑：真实 YouTube/Bilibili 页面、供应商模型的改写质量、动效手感（需人看）。审查提到的已知小问题未修：播放在缓冲时没有超时；其他标签页刷新时，正在等的点按读数可能不显示；YouTube 悬停预览仍在播放时，按钮可能一直显示「暂停」。
- 此次未重载日常扩展、未提交。
