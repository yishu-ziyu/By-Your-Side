# 任务: 主模型挂起或出错时，用户十几秒内拿到快速模型的回答；重载扩展不再挤掉旧聊天

起因：10-01 日常记录，step-5-preview 挂起，「你好」等 170 s（30 s 报 Connection error → 重试 3 次，最后一次 63 s）；另一任务 429 + 流提前结束，丢约 480 s。备用模型写死为 `zai-coding-cn/glm-5.3-flash`，且要原模型重试用尽才换。另：每次重载扩展，每个会话多出约 7 条相同的 idle 状态，1024 条的会话丢了最早 4 条真实消息。

## 规则

- F1 主模型 15 s 内没有第一个事件就取消；有快速模型时立刻换它，不再问挂起的模型。
  - 例子(正)：主模型连上后不出字，那么约 15 s 后快速模型回答，主模型只被问一次。 — 谁检查：`agent/test/model-failover.test.ts` F1；`scripts/acceptance/real-path/model-failover.mts --headless`
- F2 连接错误、429、5xx、流提前结束第一次出现就换快速模型。 — 谁检查：同测试 F2（429、early-end 两例）
  - 例子(反)：快速模型就是主模型、或没设快速模型时，不换。 — 谁检查：同测试 F3
- F3 没有备用模型：原模型最多再试 2 次（等 0.5 s、1 s），挂起最坏约 46.5 s 报错，错误写明哪个模型。 — 谁检查：同测试 F3；`extension/test/models.test.ts`
- F4 切换时侧栏显示「已由 A 切换到 B」（沿用已有提示，不加新界面）。 — 谁检查：真实路径截图
- H1 紧跟同一状态的重复状态不追加进侧栏历史，不挤掉真实消息。 — 谁检查：`extension/test/panel-history.test.ts`

## 还没答上的问题

- 无。备用模型取舍（本任务决定）：不另设，用设置里的快速模型；去掉写死的 GLM 备用。

## 技术前提

- 前提：pi-ai 的 OpenAI 兼容流在收到响应头后才发 `start`，正文/思考/工具/结束才算第一个事件。小实验：读 `pi-ai/dist/api/openai-completions.js`（`start` 在 `withResponse()` 之后）；真实路径里只回响应头的服务被判挂起。结果：通过。
- 前提：侧栏回放跳过 seq 不大于已应用的条目，不追加的重复状态不会改变侧栏。小实验：读 `sidepanel/main.ts` `applyHistory`。结果：通过。

## 边界与不做

- 不改本机 AgentSession 的重试（本机模式已退役）；切换后本会话继续用快速模型，不自动切回。
- 回答中途卡住（已出字后不再出）不在本次范围。
