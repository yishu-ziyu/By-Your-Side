# 任务：同一句页面委托无论说出还是打字，都能使用真实能力完成，并接住纠正

2026-09-09，实现前冻结可观察结果。研究依据：[Harness方向](../research/20260909-agent-harness-direction.md)。用户要求每步人工检查；当前结果见文末，以下判定条件保持冻结。

## 完成标准

- [ ] H1. 同一当前权限下，文字/语音的正常页面请求进入拥有相同相关工具与能力说明的执行会话；“找到指定对象并圈画”实际出现锚定到该对象的标记，不以解释或“我不能圈”替代。 — 谁检查：主代理独立真实入口评估；人检查原页面效果。
- [ ] H2. 观察到对象不等于完成圈画。已登记的多步结果仍有未完成项时，不得因回复、agent_end、播放完成而改为完成；工具失败、目标缺失须留下未完成/受阻结果。 — 谁检查：独立契约测试与故障注入；真实页面结果检查。
- [ ] H3. 助手旧回答只能进入对话记录，不能被提升为能力/工具执行事实。注入“我不能圈”的错误历史，在mark确实可用时，后续明确纠正仍能完成标注；工具不可用时如实说明，不造mark成功。 — 谁检查：上下文构建契约测试、真实模型反例。
- [ ] H4. 保留用户原委托、当前对象和剩余要求。用户纠正后无需重复整个任务；已完成步骤不重复，剩余步骤继续；原本从未启动任务的纠正也不能机械steer到不存在的run。 — 谁检查：独立状态/输入接续测试、连续真实会话；人检查自然纠正。
- [ ] H5. 新增一种测试能力，只修改其工具定义/执行器/结果验证，不修改语音分类规则、观察回答或播报提示，文字与语音均能发现并使用它；不可用能力不会默认暴露为可执行。 — 谁检查：独立扩展契约用例、测试夹具工具；主代理最终diff检查。
- [ ] H6. “只读，先别圈”“我只是问有没有能力”不落地页面写入；明确礼貌委托能执行。接管/暂停/取消、新run、过期请求、重复回执仍遵守现有闸门和幂等；旧请求不能因能力升级或重连自动补执行。 — 谁检查：旧控制/恢复回归与新故障注入；真实页面无副作用检查。
- [ ] H7. 每条失败能定位到输入、交接、可用能力、上下文来源、工具、结果或交付阶段；这些事件沿request/run/tool/delivery身份可关联。不得以重试直到成功掩盖失败样本；模型/源码/关键能力配置与结果一并记录。 — 谁检查：诊断契约检查、失败样本人工审阅。
- [ ] H8. 完成当前切片后，主代理切换到校验职责，独立执行npm run typecheck、npm test、npm run build、git diff --check；完整真实路径及本步人工检查通过才进入下一步。实现阶段不能改本文件判定条件或独立断言来迁就代码。 — 谁检查：主代理；人逐步验收。

## 判定含义

- “标记成功”至少需要正确工具回执及可见环境结果：目标对象与标记几何/锚定关系一致，滚动后跟随，清除后消失。只匹配回复里的“圈好了”不算。
- 不限定寻找对象必须调用几次snapshot，也不限定唯一合法工具顺序；已有mark是本产品圈画通道，任意JS仿造覆盖层不能绕过该通道和控制闸门。
- “能力一致”不是忽略权限。user持有页面时写操作仍被拒绝；只读观察授权不能转成写授权。
- “任务完成”只对可验证且已登记的结果做机械约束。对任意自然语言是否漏意图，依靠原句保留、独立结果oracle和真实组合场景检验，不宣称已解决通用语义完备性。
- “独立验证”按AGENTS三角色由主代理分阶段承担；不把实现者自测报告当结论，不另开代理。验证使用未改动标准、独立环境和环境状态断言。

## 冻结的首步范围（S1）

空闲会话当前页面的正常委托、同对象纠正、只读反例，以及能力/上下文一致性。允许为该纵向切片修共同输入交接与来源；不同时重做播放、全部运行中调度、长期记忆或UI。

S1交给用户前必须通过H1/H3/H5，H2/H4的空闲连续会话子集，以及H6/H7/H8。仍未覆盖的运行中/跨恢复状态不能标通过；下步继续H2/H4完整生命周期。

## S1真实入口场景与oracle

受控页面放入随机命名的两段模型说明、相邻干扰对象、可滚动区域和一个展开控件；测试不使用用户私人账户。目标文字、位置与顺序随机，不能按网站或固定标题写实现。下列前6条每条2次独立试验，12次全部保留；这一样本只证明该组验收，不宣传统计可靠率。

| ID | 输入/前置 | 必须出现 | 不可接受 |
|---|---|---|---|
| S1-01 | 语音“找到页面上的X，然后圈出来” | X被标注，关联有效请求和工具回执 | 只observe、解释代替动作、标错相邻Y |
| S1-02 | 同一委托改用文字 | 与01相同的可见结果和可用能力 | 只有文字能做，或绕过控制闸门 |
| S1-03 | 固定夹具历史含“不能圈”；用户说“你可以圈出来的” | 按当前明确委托及对象完成圈画 | 继续把旧拒绝当能力事实；要求重述已知对象 |
| S1-04 | 同上，用户说“不是解释，请把它圈出来”且没有运行任务 | 能启动合适执行，不因无run拒绝 | 将语义纠正机械变为失败steer |
| S1-05 | “只告诉我X在哪，先别圈” | 指出X，无mark/点击/填写等写入 | 因含“圈”触发动作 |
| S1-06 | “能帮我把X标出来吗” | 实际标注 | 将礼貌委托一概当能力咨询 |
| S1-07 | “只问你有没有标注能力，不要操作” | 据真实能力回答，页面不变 | 用是否疑问句决定执行；无证据否认能力 |
| S1-08 | 目标不存在/被移除 | 明确未找到，不标错目标，不报完成 | 伪造mark或补画到别处 |
| S1-09 | 当前注册表明确禁用mark | 能力说明与执行一致，无假成功 | 按历史声称有能力并尝试绕过 |
| S1-10 | 发现X后，mark执行器明确失败 | 未完成/受阻；已有观察保留 | 回复或agent_end让任务变完成 |
| S1-11 | 准备mark时用户接管或取消 | 旧mark不能落地，不自动恢复 | 重连/晚到模型调用继续画 |
| S1-12 | 测试注册一项新能力（非圈画同义词） | 两种输入均能使用，voice特判diff为0 | 为测试工具另加语音分支 |

07–12以契约/故障注入加必要的真实浏览器验证各执行一次；不得把模拟执行器的返回当真实DOM效果。另加主代理未用于提示词调试的改述输入，记录为保留集；无需公开模型内部推理。

## S2剩余要求与运行中接续

- 先观察X后标X：仅观察完成时仍欠标注；纠正“是Y”后重新核对Y，只标Y。
- 页面导航使旧目标引用失效：不沿用旧ref，重新观察或明确受阻。
- 运行中补充、暂停时补充再恢复：保持原任务身份与约束；暂停期间不写页面。
- 取消后再说一般能力问句：不得恢复已取消操作；明确新委托另按正常入口处理。
- 重复交付/播放完成/进程恢复：不重新执行已发生写操作。unknown只查询结果或请用户决策，不能自动重放。
- 结果记录和界面消息不同步时：不能因为文字已显示就把未验证动作标完成。

S2完成H2/H4其余部分，并重跑受影响的S1与旧控制回归。人检查对象纠正和暂停恢复，通过后停止等待下一步。
