# 自然表达覆盖：本地规则与Jev

## 运行前协议

- 比较对象：新写的本地完整句法匹配规则（不是声称项目已有同等路由）与上一轮冻结的Jev三问题router。两者都不执行网页操作。
- 支持范围：已有译文的宋体、原字体、双语、仅译文及其组合。其他任务、含额外要求、缺上下文和无译文必须回退。
- 原生子Agent在不读两种实现的前提下编写48条合成留出表达；主代理在看留出之前写完规则。语料不是用户真实流量。
- 主标签比较精确action/参数。可执行句的null是回退损失；应回退句的非null是错误放行；参数多改/少改都算错。明确区分请求式“能帮我…”与只问能力。
- Jev继续使用jev-1.13.0、eligible Noul>=0.8、参数选择概率>=0.8。冻结后不调整阈值或提示词追分。本地规则整句消费，避免只抓到“宋体”就忽略额外任务。
- 最多48次Jev请求，每句一次、单次5秒、不重试、并发2。记录原始概率与耗时。本地规则重复100次取平均，以免单次测量噪声。
- 分开报告：正确直达/可直达正例、错误放行、错误参数、回退、类别覆盖、延迟与调用成本。不能只比较整体准确率（全回退也能避错）。混合策略在同一冻结结果上组合，不再调用模型。
- 本轮证明的是这两个具体实现的差异，不是所有正则或所有Jev方案的极限。不得据此声称生产收益。

## 第一轮与公平性修订

第一轮48条独立自然表达，Jev正例13/28正确直达、本地规则0/28，双方负例错误放行0/20。首版本地规则六条标准开发控制全部通过，但完整句法匹配对这组释义过窄；不能拿这一个差基线推出Jev普遍优于本地规则。原[结果](../../out/experiments/typesafe-natural-1789703528224/summary.json)保留。

因此增加一个明确分开的开发/留出轮：将前48条降为开发集，编写更宽的关键词/语义短语规则及否定、未来、局部范围、额外任务保护；在新留出揭示前重新哈希冻结。本地V2在旧开发集表现仅用于检查，不当作泛化成绩。Jev保持原始问题与0.8阈值不变。独立Agent另出24条新句（14正/10负），增加24次以内Jev请求预算；不用原48题反复调到高分再自测。

第二轮运行前标注裁决：v2-012“中文书本正文的字体”不足以唯一指定宋体（不同书籍也可能用其他字体）。主代理将其列为回退，保留originalProposedExpected及理由，未看模型答案。最终13条可执行、11条回退。双方实现不因看题修改。

### 语义候选与可执行覆盖要分开

逐题检查font/mode的最高概率候选，第二轮13个正例全部与期望参数一致。当前执行策略仅放行2个：7条只被eligible概率挡住，2条只被字体概率挡住，1条只被保持模式的概率挡住，另1条同时有多项不确定性（各类计数按诊断文件逐条为准，不将闸门数当案例数）。这些是观察性诊断，不是新的执行策略，也不能声称实际覆盖13/13。

若直接丢掉eligible与参数阈值，会对4条负例产生候选：局部标题宋体、仅显示译文后导出PDF、只否定双语、未明确字体的书本风格。参数提取正确不等于整个请求可直接执行。

典型差异：

- “宋体，只看翻译。”规则只提取宋体，漏了仅译文；Jev两项都正确。
- “不是只要译文，两个版本都放着。”规则误选仅译文；Jev模式候选为双语，但eligible较低，最终回退。
- “只显示译文，然后帮我导出一份PDF。”规则擅自只做前半句；Jev拒绝直达。
- “宋体在长篇阅读里通常挺耐看的。”规则把陈述当操作；Jev拒绝。

## 主代理判断

**Jev在这组未见表达的参数理解与拒绝非任务上显示了优势；当前路由方案还没有把优势转化为足够的正确直达覆盖。** 不能根据首轮窄规则0/28宣称优于所有规则，也不能根据最高概率候选13/13宣称可直接接入。

建议保留严格、完整匹配的本地快捷命令；不要把本轮V2宽匹配规则放进产品。Jev值得继续，但下一版先拆开“是否直接委托”“是否包含额外任务”“是否要求局部范围”等独立问题，并明确工具只能整页改变。按各分支的意义决定需要哪些概率，避免把一个笼统eligible分数当万能闸门。旧两批题转为开发回归，下一版仍需新留出验证错误放行与实际回退成本。

这轮是两个具体实现的工程比较：本地V2看过首轮开发数据，Jev问题保持此前冻结版本，优化预算不同；不是同训练条件的模型能力评测。语料由独立Agent合成，尚不能估算真实用户命中率、线上总体提速或罕见误操作率。生产代码和日常扩展未改。
