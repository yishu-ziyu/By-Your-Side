# 任务: 让 SideAgent 能锁定用户当前页面

用户问"这页面是关于什么"时，agent 列出 16 个标签页反问"指哪一个"。根因：`user_message` 只携带纯文本，没有"用户正在看哪个页面"的信号；工具集中也没有查询当前活动标签的能力。

## 验收标准

- [ ] 1. 协议 `user_message` 支持携带当前活动标签上下文（tabId/title/url），字段可选、向后兼容 — evaluator: 针对 `shared/protocol.ts` 的契约测试（npm test）
- [ ] 2. 面板发送用户消息时自动附带当前活动标签的 title/url — evaluator: 人评（扩展里问"这页面是关于什么"，agent 直接读当前页而非反问）
- [ ] 3. agent 新增 `get_active_tab` 工具，返回当前活动标签（含没有活动标签时的明确空结果）— evaluator: npm test + 人评
- [ ] 4. agent 收到带页面上下文的消息时，上下文被注入会话，"这页面"类指代可直接解析 — evaluator: 人评
- [ ] 5. 全量机器检查通过 — evaluator: `npm run typecheck` / `npm test` / `npm run build`

## 边界与不做

- 不改模型选择按钮的可发现性问题（hover 才显可点），另行处理
- 不做多窗口活动页的复杂推理：取 `lastFocusedWindow` 的活动标签
- 取不到活动标签时上下文缺省，agent 回退到现有 `list_tabs` 行为，不报错
- 不改 teach 模式下 `page_event` 的既有消费逻辑
