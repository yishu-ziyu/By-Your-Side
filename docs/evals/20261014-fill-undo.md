# 任务: 助手把表填错了，用户在侧栏点一下「还原填写」，网页里它填过的格子回到动手前的样子

用户 10-14 看过原型后同意。现在用户只能一格一格自己改回去。后台怎样记、怎样写回、隐私怎样守，见 PR #373 的描述，这里只写用户在网页和侧栏两边看到的规则。

## 规则

- R1 只还原助手这一轮填过、还没提交的格子，按它动手前的值写回；用户后来自己改过的格子不动。
  - 例子(正)：助手把电话填进姓名栏、人数填成 4 人，用户随后在姓名后面打了字；点还原后手机号回到空、人数回到 2 人，姓名留着用户打的字 — 谁检查：`scripts/acceptance/real-path/fill-undo.mts`、`fill-undo-button.mts`
  - 例子(反)：仿 React 受控输入的格子还原后过一会儿也不回弹；编辑器里的文字、原来有内容的密码这类栏不还原，结果行写明；只改了编辑器文字时不出还原按钮，回答下只写“编辑器里的文字没还原。” — 谁检查：`fill-undo.mts`、`fill-undo-button.mts`
- R2 回答下的主按钮是「还原填写（N 处）」；点了以后按钮灰掉写「已还原」，下面一行写“还原了 N 处。「X」你后来改过，没动。”，上面那段回答变淡。只能点按钮，空输入框按回车不还原。
  - 例子(正)：还原后结果行和变淡都在；下一轮开始、或重开侧栏后，这条回答仍是“已还原”，更早的回答不变淡 — 谁检查：`fill-undo-button.mts`
  - 例子(反)：没点过还原就开始下一轮，那条回答的按钮换回「复制」 — 谁检查：同上
- R3 收不回时说清为什么：网页真的提交了表单（只认网页发出的提交，不按“点了提交按钮”推断），按钮灰掉写「已提交，收不回」；页面跳走、刷新或扩展重启过，写「页面变了，收不回」。带这些状态的回答，文末一排一直显示。
  - 例子(正)：用户点了网页的「提交预约」，按钮变成「已提交，收不回」，下面写“表单已经交给网站，扩展撤不回” — 谁检查：`fill-undo-button.mts`
  - 例子(反)：任务还在跑时请求还原，网页不动，侧栏提示“助手还在做事，做完后再点还原” — 谁检查：`fill-undo.mts`（后台回 busy）
- R4 格子的值不离开网页：动手前的值不进工具回执、存储、日志和诊断导出，侧栏只显示栏名。
  - 例子(正)：练习页里带记号的原值不出现在模型收到的回执和导出里 — 谁检查：`fill-undo.mts`

## 技术前提

- 前提：网页用 React 这类受控输入时，按原生 setter 写值再派发冒泡的 input/change，框架会认这次改动。小实验：`fill-undo.mts` 里的手机号格子仿 react-dom 的值跟踪。结果：通过（去掉事件后手机号回弹，用例失败）
- 前提：真实模型常按快照里的 @N 引用填写（走 CDP、在页面主环境里执行），这条路线也记得住。小实验：`fill-undo.mts` 把手机号、人数、儿童座椅改成 @N 引用。结果：通过

## 边界与不做

- 提交以后不撤回：资料已经发给网站，扩展做不到，只说清楚。
- 网站自己画的勾选框和下拉框、上传的文件、编辑器里的文字不还原。
- 经 fetch / XHR 提交、不走表单的，判断不了“已提交”，只能等跳页或刷新时变成“页面变了”。
- 只还原这一轮；新一轮任务开始就清空，旧回答上已经定下来的状态留着。
