# 任务: 加固记忆底座——同一件事只会有一个生效值，读坏不覆盖，忙时没记住的事后补上，面板不再报版本冲突

依据：[记忆模型](../memory-model.md)「10-01 架构与交互调研后的决定」，[调研页](../previews/20261001-memory-design.html)。用户 2026-10-01 选择先加固再做纠正询问。用户界面几乎不变。

## 用户能看到的变化

1. 连续换几次邮箱、撤销、删除，任何时候「记忆」面板里同一件事只有一个生效值。
2. 过往任务的数据就算读不懂或有损坏，也不会被新的写入整个覆盖掉。
3. 助手正忙、判断「要不要记」失败时，这一轮结束后会补判；同一句话不会因为补判记两次。
4. 「记忆」面板开着时，助手新记了一条，面板自动更新；接着修改这条不会报「版本冲突」。
5. 设置页导出的诊断记录里，记忆判断只留编号与结论，不留你的原话。

## 场景

| # | 情境 | 期望 |
|---|---|---|
| H1 | 预置一份看不懂（未来格式）或损坏的过往任务数据，再完成一个会留过往任务的任务 | 原数据一字不差仍在；任务照常完成；不出现空列表覆盖 |
| H2 | 邮箱 a→b→c，撤销、删除历史中间一条、再撤销、聊天里说「忘掉我的邮箱」，每一步后检查库 | 任何时刻同一件事生效值 ≤1；忘掉后整件事全部消失 |
| H3 | 判断「要不要记」的模型请求第一次失败（返回服务错误），用户说「我坐飞机都要靠过道」 | 诊断记录有一条失败记录；这一轮结束后补判成功，记下 1 条且只有 1 条；补判再触发一次也不重复 |
| H4 | 「记忆」面板开着，用户在对话里说「我的邮箱是 c@example.com」 | 面板自动出现这条；随即在面板里修改它，成功，不报版本冲突 |
| H5 | 说过 H3 那句后导出诊断记录 | 记忆判断记录里没有「靠过道」原话，只有编号、种类与结论 |
| H6 | 预置格式 2 的真实样本（资料、被替换链、过往任务） | 升级到格式 3 后全部可读可用，替换链关系不变，同一件事共用一个编号 |

## 边界与不做

- 不做纠正询问、「用了几条记忆」、「这里别用」（后续块）。
- 不上同步引擎、操作日志为唯一数据源、拆分存储。
- 补判队列只在本机保存，判完即删原话。
