## 规则

- R1 已识别的列表、招聘或文章页给 2–3 个起点；概括放在最后。
  - 正例：供应商列表给整理、对比、概括；招聘页给整理职位、比较要求、概括。检查者：`welcome-context.mts`，对照用户认可的预览。
  - 反例：有一组可比较的供应商，仍只有概括。检查者：同上。
- R2 点击只填草稿，不发送、不执行。已有草稿不覆盖。
  - 正例：点整理供应商后输入出现请求，没有用户消息、没有任务或页面写入。检查者：同上，侧栏、模型请求、服务器计数。
- R3 换网页和活动标签页后更新建议，草稿保留。拿不到结构或超过预算时只显示概括，不等待模型。
  - 正例：切到招聘页后起点变化，但之前草稿不变；受限页面只保留概括。检查者：同上。
- R4 不改模型、语音或主任务路径。建议来自可见页面结构和标题，不读取表单值。
  - 反例：为了生成按钮调用模型或发送页面内容。检查者：同上，生成前后模型请求数相同。
