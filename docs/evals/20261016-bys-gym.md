# 任务：执行之后，独立检查网页是否真的按要求变化

## 规则

- R1 只用 BYS 原有侧栏、Agent 和浏览器工具执行；A 保留现有目标核对，B 只增加最多两次错误类别反馈。不得泄漏答案、位置或选择器。
  - 正例：少填一栏时反馈 FIELD_VALUE，Agent 重新观察后纠正。反例：告知具体缺什么值不算合规。检查者：真实模型轨迹和独立审查。
- R2 只以独立状态约束判成功；自述、工具 ACK、页面观察分别记录。未知不能计失败或成功。
  - 正例：两条待办的文本、完成状态、刷新后持久化都正确。反例：工具称成功但真实页面未改变。检查者：隔离观察世界和 Node 私有评估器。
- R3 三任务各三个固定种子，每轮重置浏览器、扩展及网站；两组使用相同模型、任务和预算。不删失败样本。
  - 正例：表单三个值正确、没提交、旁边字段未变。反例：脚本直接改数据冒充浏览器输入。检查者：状态与输入审计。
- R4 现有确认与结果未知防护不变。等待用户或已发生意外提交时，不自动反馈续做。
  - 正例：未知动作先重新观察。反例：新增操作未确认结果就重复执行。检查者：真实浏览器异常路径和轨迹。

## 技术前提

复用现有隔离扩展驱动和 ChatGPT 登录，不建平行 Agent。源码确认 `session.ts` 已用快模型和页面快照做目标核对；它不是应用状态 oracle。独立评估器在 Node 进程，网页只提供应用逻辑，没有评分接口。观察在独立 JavaScript 世界，防止网页覆盖查询函数。选项控件沿用 BYS 的合成 DOM 事件适配。文本输入接受可信事件，或与目标字段、值和时间绑定的原生填写适配器调用；仍独立核对真实值。直接存储写入判违规，无法证明来源的页面脚本判未知，不信模型自称只读。导航仅限本轮 fixture 源，不能打开私有评估器文件。

正式18轮已运行：两组各9/9独立状态成功，均无误报成功；B没有触发额外纠正，不能证明新增机制有效。九对初始状态、初始任务和模型参数核对一致。完整逐轮数据、录像与汇总在工作树 `out/gym/matrix-2/`。Token取真实响应usage，含后台判断；123次请求中7次缺少最终用量，总量至少867,647，订阅现金费用未知。

## 研究依据与迁移边界

[Player-1 论文 §3.3、附录 C/D](https://arxiv.org/html/2610.20584v1) 用环境真实状态的分数增量提供奖励，特权状态不交给策略，并扰动外观、场景与控制响应。可迁移的是可重复初始化、私有状态判据、相同语义的扰动；持续按键、游戏控制空间和 PPO 训练不适用于本期。论文的跨游戏训练提升不是 BYS 可靠性的证据。

[官方发布清单](https://github.com/TencentARC/Player-1#-release-plan) 在本次查阅时尚未发布环境、模型和训练代码；本实验借鉴机制，不声称复现该训练系统。

[BrowserGym 任务接口](https://github.com/ServiceNow/BrowserGym/blob/main/browsergym/core/src/browsergym/core/task.py) 分开 setup、validate、teardown，validate 返回 reward、done、反馈和 info。[环境实现](https://github.com/ServiceNow/BrowserGym/blob/main/browsergym/core/src/browsergym/core/env.py) 在操作后验证，并保留截图、DOM、AX 等观察。本期借鉴职责分离，不引入 Python Gym 或替换 BYS 执行器。

软件测试上，把要求写成文本相等、集合相等、持久化和禁止副作用约束；控制上，比较“观察—操作—页面自检”与额外真实状态反馈闭环。这里仅做同任务执行修正，不做跨任务经验迁移，更没有更新模型权重。

## 边界与不做

本机练习页和真模型只证明这组任务，不等于真实第三方网站验收。固定种子是未给 Agent 预先示范的布局，不是统计意义的分布外测试集。18 次只能探索方向，不能宣布显著性。两组保留相同的现有动态思考策略，记录实际参数与缓存；供应商采样和缓存仍有波动。预算计浏览器命令，不以工具返回“成功”代替页面效果。

反馈走真实侧栏继续消息，不是生产功能开关。是否允许自动纠正由任务授权约定控制；等待用户、出现确认卡或接管时不发反馈，不用模型的“已完成”代替用户批准。证据保留在工作树 `out/gym/`，不更新日常扩展、不自动合并、不训练模型、不做后台。

## 还没答上的问题

是否在更困难的独立任务集上改善成功率、收益能否覆盖成本，尚未证明。没有精确账单，也没有第三方真实网站泛化证据。

## 实验发现与验收边界

- 正常矩阵来自冻结产品基线 `ce9792b0`，运行器版本 `296b10f9`。后续判定器修正对这18轮重新评分，结论不变；不改原始JSON。分支随后同步最新主干，完整矩阵没有被冒充为新主干重测。
- 备注延后丢失的配对异常：A靠原有核对补齐，B收到一次独立 FIELD_VALUE 反馈后补齐。证明闭环真实运行，不证明B优于A。
- 已发出的回车丢失确认：记录unknown，下一次输入前重新取得AX树，最终没有重复待办。控件替换：真实出现IDENTITY_CHANGED，重新snapshot后完成。等待用户：首次控制器多催两次但模型未越权；补上任务授权后反馈为零，备注始终未填。
- 新增无效的真实样本里，模型直接修改localStorage并重建页面。旧判定器误计成功；现保留原记录，另写adjudication改判执行违规。不能只看最后画面。脚本模型通过真实Agent和浏览器故意重复新增、自述成功及直接写存储，均被独立判定拒绝；这些负例不计入18轮真模型质量数据。
- 另一次误判来自把原生填写工具的兼容DOM写入拒绝为非法输入；已按字段绑定来源，并通过真实Agent兼容路径检查。首轮采集语法错误、负载中断的两轮、修正前异常样本都保留，未混入正常矩阵。
- 隔离观察抗MAIN查询篡改、伪造输入拒绝、提交副作用优先于unknown、预算拦截及私有文件导航拒绝均有真实Chrome探针。旧的结果未知后重读再试用例通过。没有跑全量测试，没有更新日常扩展。

原始数据与修正记录由 `out/gym/FINAL_REPORT.md` 汇总。CLI、报告、只读轨迹回放的参数见对应脚本文件头；回放不重新执行浏览器动作。下一步优先考虑更难的保留任务集、等预算的“只重读”对照组、更多确认/不可逆操作故障；不扩展为训练系统。
