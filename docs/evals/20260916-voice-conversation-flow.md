# 任务：沿现有阶跃链路实现连续对话与后台任务协作

## 完成标准

- [ ] 用户说话时后台结果不抢播；多条结果等待后按顺序交付，不丢、不重。— 谁检查：生产会话受控回归、真人听感。
- [ ] “别说了”被判定为停播后，不因待播结果再次开口；停止播报不取消网页任务。— 谁检查：生产路由与会话回归、真人。
- [ ] 被打断的回答不把未播完全文标为用户已听见；后续对话保留可核验的播放边界。— 谁检查：播放回执、会话上下文回归。
- [ ] 纠正、停顿、附和有明确处理：纠正接原任务，未说完不执行，附和不机械重派任务。— 谁检查：真实模型与受控网页路径、人。
- [ ] 后台任务期间仍能对话并接收补充；过期结果不覆盖新要求。— 谁检查：运行中真实网页路径。
- [ ] 日常Mac内置麦克风一次正常音量插话有效，安静/扬声器回声不误停。— 谁检查：人，参考收音专项。

## 范围

用户明确授权整套修改，由主代理直接执行；沿现有阶跃服务，不引入不可购买的GPT-Live/Gemini Live。先复现具体缺口，再改最小路径。各层证据分开，不把单测通过当整体完成。

## 执行记录

收音阈值候选已加载日常侧栏，真人结果另见[收音专项](20260916-voice-input-diagnosis.md)。本轮接续检查对话编排、队列、上下文和轮次处理。

### 已复现与修复

1. `VoicePlayback.takeQueued` 原先一次清空队列，调用方启动第一条语音即返回，剩余结果丢失。改逐条取走，播放完成再取下一条；失败回归先复现丢第二条，再修复通过。
2. `silent` 原先继续flush待播结果，“别说了”后又开口。明确停播增加quiet语义，与过期结果静默丢弃分开；保持安静直到新的有效输入，空白噪声不解除静音，网页任务不取消。
3. 实时回答文字在音频播完前就进入本地对话历史，打断后仍带上未听到的全文。现等播放完成回执再写入；缓存播报向上游注入的“已播报”记录同样后移。当前没有字级对齐，打断的部分不猜测文字范围，尚未实现精确从断句处续播。
4. 新增语义listen分支，仅针对尚未说完的表达；不执行、不出声追问，保留20秒未完成文本供后句合并。噪声不消耗片段，过期片段不混入后来问题；等待期间后台结果入队。
5. 纯附和在已有语音回答或实际播放被打断的上下文中不再调用模型或派发任务。现有待确认控制优先；“继续”“确认”及带修订的整句不走附和捷径。当前仍会先停播，尚未做到短附和后原句无缝续播。
6. 明确且仅停播的短句复用统一判定直接返回quiet，不等待分类模型；任务控制、引用、复合要求保留原路径。

### 真人失败推动的修订

用户在新会话中说“我想。”→“你给我介绍一下。”→“这个YouTube的视频。”，最后仍显示“你继续说，我在听”。用户确认整句已经说完。原始事件保留在[真人分段失败](20260916-voice-conversation-flow/human-split-before.log)。

确认两层缺陷：listen判定在manager等待后续轮次决策，返回太晚，前文没有及时接入；并且首次新提示词会被“我想”的开头误导，合并全文也错误listen。前者让无副作用的listen先返回；后者明确按全文最终完整性判断，不凭开头判未完成。生产回归覆盖上一轮listen晚于下一轮开口、早于下一轮转写的顺序及连续三段合并。

真实模型重放原三段：原始[合并后仍失败](20260916-voice-conversation-flow/joined-intent-before.json)保留；修订后[listen→listen→observe](20260916-voice-conversation-flow/joined-intent-after.json)通过。它证明分类，不证明页面读取或真人听感。

### 第二次真人失败：新问题被旧闲聊任务抢占

用户改用“还不错，我现在在看这部剧，就这个YouTube的这部剧。”接“你可以告诉我说这部剧的内容是什么吗？”，仍体验到等待/要求继续说。日志显示这次第二句已判observe，不是listen；读页后返回silent。会话任务归档证实启动的是前一句闲聊的任务，而非新问题。见[当轮时间线](20260916-voice-conversation-flow/human-overlap-before.log)。

根因：空闲chat虽然语义只读，但willStart把它标成可跨轮保留的动作。用户的新observe解除等待后，旧chat仍启动任务并改变runId，当前观察结果因身份变化被丢弃。修复按语义动作判断跨轮保留：chat/observe等只读问答允许被新问题取代，显式start/steer/pause等仍保留动作保护。

生产manager交错回归先用旧条件实测失败（旧闲聊startTask被调用一次），再恢复修复条件验证通过（旧任务不启动，新读页返回答案）。这不是修改成功标准。35个语音测试文件358项、两端类型通过。额外6种真实模型表达（文章问答、套餐比较、实际剧集问题、纠正、完整总结任务、确实未完成的预算句）全部按既定语义分类，见[多表达结果](20260916-voice-conversation-flow/varied-intents.json)。分类证据不代替真人整链路。

当前未完成：修复后的真人确认；此前的逐字续播、声学指标和极快片段组合边界依旧保留。不再要求用户只复述提示词中的固定句子。
