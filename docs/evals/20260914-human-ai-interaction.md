## 证据与结果

- 当前生产前端基线与改后分别由本地 /before/、/after/ 提供，原生日常宿主截图缩略图未用于视觉结论；内置浏览器已捕获同源前端对照。
- 已检查鼠标选“概括当前页”和键盘选“帮我填写表单”：只填草稿、焦点到输入框、消息区仍空，改写后Enter才发送并出现明确标识的模拟回答；有消息后引导消失。
- 预览计数最初只匹配user_message，遗漏生产实际task_action；已修正并重跑，以修正后0→1的计数及实际UI为准，旧计数不能证明没有发送。
- 诊断展开后“记录本轮问题”与用途说明可见；点击不会新增任务请求，语音区域仍未启动，提示“语音未开启，标记未发送”。
- 独立复核静态检查未见发送绕过、诊断生命周期变化；指出历史首帧与读屏播报需要运行验证。其“草稿恢复竞态已排除”结论被主代理反例推翻：5s延迟的原有草稿恢复期间，点击起点会把storage里原草稿写成建议。问题是旧草稿被覆盖，不是新建议被restore覆盖。已返回执行者一轮修正，保留原失败依据。
- UI Skills目录失败、执行者尝试headless Chrome被沙箱SIGABRT的结果均不算视觉验证；最终视觉证据由主代理的Codex内置浏览器提供。
- 一轮修正已完成：起点需当前草稿真正恢复、历史回放完成才出现；点击处理器也有同样检查，移除用“新会话”标题猜测是否空白的条件。切会话清空ready，旧restore早退不能把新会话标ready。
- 主代理复跑5s慢草稿：加载期间实际DOM的引导不可见，恢复后“不要覆盖这份原有草稿。”原样出现；storage没有写入覆盖，任务请求为0。此结果取代独立复核最初对竞态的错误判断。
- 主代理真实前端切换：在会话A写“保留这份草稿，不发送。”，新建命名会话B可见空态起点、输入为空；切回A原文字完整、任务请求仍为0。恢复引用+测试PNG后点起点，引用文字与1张附件仍在，只有输入新增建议，没有发送。
- 未送达：生产前端收到失败回执显示原文和“重试”；用户点重试才从1次请求增加至2次，第二次仍失败时如实显示未送达，无模拟成功输出。重试逻辑没有被此次改动。
- 键盘：Enter可选择起点；输入框仍能编辑并用Enter发送；summary可用Enter展开/收起诊断。诊断点击仅增加明确提示，不新增任务或启动语音。
- 新增VoiceUI状态回归沿用既有DOM夹具，仅替换麦克风启动：驱动真实UI注册的connecting/listening/thinking/speaking/error回调，活动区域与结束/重试按钮均可见，诊断保持折叠，idle才收起。该测试验证UI接线，不代表真实麦克风/读屏器验收。
