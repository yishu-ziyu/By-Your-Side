# 任务：写入结果不明时不自动重复执行

## 冻结依据与角色

用户要求先完成问题定义、修复前复现、独立验收标准与工程任务书，再交其他 Coding Agent 实现，由原主代理验收。本文在产品修复前建立。实现者可增加检查，不可修改本文判据或固定检查来迁就实现。接口适配由验收者复核，不得替代行为断言；用户修订需求时保留修订原因。

## 问题定义

请求已发出、页面已产生副作用，但成功回执在途中丢失。此时超时或断连只证明调用方不知道结果，不证明页面未执行。若系统允许重新登记并重放，可能重复新增、发送或提交。

目标是结果不明期间禁止自动重复写入，并允许只读核查及安全接续；不承诺任意网站的 exactly-once。宿主不能从一次快照未出现记录推断从未写入，也不能取消已经发生的外部副作用。

## 完成标准（冻结 v1）

- [ ] A1 正常对照：隔离页新增一条记录，工具正常返回；页面与服务端计数均为1。— 谁检查：固定浏览器验收脚本。
- [ ] A2 成功后丢回执：分别注入 RPC 超时和断连。注入必须发生在服务端已记录第一次写入之后。系统保留结果不明，不把它当作确定未执行。— 谁检查：固定浏览器验收脚本与结果状态证据。
- [ ] A3 A2之后重新登记同一要求，再次调用同一写工具时执行层拒绝；实际写入总数仍为1。不能只靠提示词，也不能用测试桥代替产品阻止重放。— 谁检查：固定浏览器验收脚本。
- [ ] A4 重新 snapshot/read_element 可执行。能核查第一次操作唯一关联的记录时，据环境证据解决不确定性并接续剩余独立步骤；总写入数仍为1。关联证据必须来自真实工具回执、当前页面/任务，模型仅自述已核查不能解除限制。— 谁检查：验收者的恢复集成检查、生产运行时加隔离浏览器路径。
- [ ] A5 查不到充分证据时仍保留未知；回复明确“结果无法确认，未重复执行”，不能声称“没有执行”或“已成功”。不要求固定措辞。— 谁检查：验收者的生产运行时/侧栏检查，机器核对状态与计数，人检查表达是否可理解。
- [ ] A6 发送前明确拒绝，或执行器在动作前明确拒绝：写入数为0；修正可恢复的前置条件后，在原授权下允许成功一次。用户取消/接管不属于可恢复定位失败。— 谁检查：故障边界契约测试与隔离浏览器。
- [ ] A7 晚到/重复回执只关联原操作；旧任务、其他会话的回执不能解除新任务限制或触发写入。相同调用重复到达执行器不得重复产生副作用。— 谁检查：协议及运行时集成测试。
- [ ] A8 未知状态在现有持久会话恢复中保留；不能通过修改结果id、CSS/@ref别名、换用browser_run或通用js绕过同一未决写入。至少检查同工具换id/别名、browser_run内click、js三种入口；其他会话独立页可正常工作。对无法判定等价性的通用写入口允许在受影响范围内保守阻止。— 谁检查：执行与持久化契约测试，隔离浏览器反例。
- [ ] A9 真实模型经生产任务运行时、生产工具和侧栏在隔离浏览器完成正常路径及超时/断连路径；保留模型调用、工具身份、故障时刻、页面最终状态、正式答复。固定驱动不能冒充模型端到端通过，CDP桥不能冒充native messaging通过。— 谁检查：原主代理独立复验；人工浏览器及麦克风不是本任务前置门槛。
- [ ] A10 定点通过后一次 npm run typecheck、npm test、npm run build、git diff --check。所有未跑项明确标记，不以增加超时、取消故障或全禁用写入让测试通过。— 谁检查：实现者自测，原主代理核对并做必要复验。

## 固定入口与证据要求

第一层固定入口：`npx tsx scripts/acceptance/write-receipt-loss-run.mts`。
该入口覆盖A1—A3及只读仍可调用、晚到回执观察；不是A4—A10全套验收器。退出码0仅代表它覆盖的断言通过，1代表产品行为失败，2代表测试基础设施异常。

A4—A9在修复后由原验收者沿本文场景扩展集成驱动，接口可以适配，以上输入、外部计数与禁止条件不变。实现者须提供生产入口及调用示例，不能仅交新增纯函数测试。

脚本创建独立临时Chrome配置和仅监听127.0.0.1的页面；使用生产click、snapshot、ControlGate、ToolRpc、BrowserAgentSession事件转发/执行检查、TaskProgress和浏览器工具定义。模型和SDK调度由固定事件驱动替代，native messaging由CDP桥替代，不等同于完整生产入口。服务器计数是测试外部裁判，产品不得直接读取测试报告作为成功证据。

保存每种故障的第一次写入时间、故障时间、首次错误、重试是否派发、最后服务端记录和DOM计数、运行前源码hash；失败不覆盖成通过。验收者复验前校验冻结文件hash。

## 边界与不做

- 不修通用业务成功判定，不进入TTS、模型更换、视觉改版或架构重写。
- 不模拟对真实外部账号发送或付款；只使用隔离本地页面。
- 不扩大私人日志采集，不写原始音频、凭据或私人网页。
- 用户对未知写入的再次授权交互暂不新增；无法核查时保留未知即可。
- 不因未知禁止所有会话、所有只读操作；允许保守锁住受影响页面的写入。
- 实现阶段不修改本任务固定验收文件；需要适配先提交说明由验收者处理。

## 修复前基线

2026-09-09主代理运行上述固定命令，退出码1：15条检查中9条通过、6条按预期暴露缺陷；没有基础设施失败。

| 场景 | 第一次页面写入 | 首次回执后状态 | 再次请求后页面/服务端计数 | 结论 |
|---|---|---|---|---|
| 正常 | 1 | satisfied | 1 / 1 | 对照通过 |
| 写入后丢回执，等待默认30秒超时 | 1 | blocked | 2 / 2 | 未知未保留，重复请求到达页面 |
| 写入后断开RPC发送连接 | 1 | blocked | 2 / 2 | 未知未保留，恢复连接后重复请求到达页面 |

两种故障的只读重新观察均成功；测试随后刻意要求重复操作，以检验宿主是否真正阻止。生产任务检查没有拦住，第二次真实click造成第二条服务端记录。故障发生在服务端记账之后；不依赖模型是否碰巧选择重试。

完整证据：[修复前JSON](20260909-write-receipt-loss-baseline.json)，含操作事件、服务端时间、源码hash、首次错误与晚到回执记录。临时构建及profile位置见JSON的out，归档JSON不依赖临时目录仍然存在。环境错误与产品断言失败使用不同退出码。
