# 任务：助手要点「发送」时，侧栏里出一张确认卡，写清发到哪、发什么，用户在侧栏里就能答

## 规则
- R1 助手点名字以「发送 / Send」开头的按钮前，侧栏出一张卡：网站、按钮名、按钮附近的草稿（读不到就不写这一行），两个按钮「发送」「先不发」。网页上的确认框照旧在，两边答的是同一个等待；答了哪一边，两边都收起。
  - 例子(正)：用户在侧栏点「发送」，网站恰好收到一条，网页确认框收起；在网页上点「发送」，侧栏的卡也收起 — 谁检查：`npx tsx scripts/acceptance/real-path/panel-send-confirm.mts --headless`（p1、p3）
  - 例子(反)：用户点「先不发」，网站收到 0 条，草稿还在 — 谁检查：同上（p2）
- R2 只有用户真实的鼠标点击能放行：脚本合成的点击、键盘按下「发送」都不算；「发送」刚露出来的一小会儿（网页上和侧栏里都是）点了也不算，免得本来就在路上的一下点击落在刚冒出来的按钮上，浏览器的权限弹窗也这样做。原有的保护不变（连点拒绝、网页脚本程序里不等、2 分钟超时、停下、接管、离开网页都不发）。
  - 例子(反)：侧栏里用脚本点卡上的「发送」、聚焦它按回车或空格、它露出来 300 毫秒内就点，网站都收到 0 条，卡还在 — 谁检查：同上（p1、p5）
  - 例子(反)：网页确认框的「发送」露出来 300 毫秒内就点，0 条；1 秒后再点同一处，1 条 — 谁检查：同上（p6）
- R3 卡上的按钮只在后台确实还在等时出现。重开侧栏回放历史时，还在等的卡照样能点；答过、过期的卡只剩一行结果（「你没让发，草稿还在」「没发：…」）。「已发送」只在按钮真的点下去以后写：用户确认了、还没点下去时写「你确认了发送」；没点到写「你确认了，但没点到发送键，草稿还在」。开着几个侧栏时，在一个里答了，其余的卡一起收起。
  - 例子(正)：等确认时重开侧栏，卡还能点，点了就发 — 谁检查：同上（p4）
  - 例子(反)：再重开侧栏，答过的卡没有按钮；二号窗口的侧栏在一号里答完后也没有按钮 — 谁检查：同上（p1、p3、p4）

## 还没答上的问题
无。

## 技术前提
- 前提：侧栏页连后台的端口带着 `sender.url`，网页和内容脚本冒充不了侧栏；后台先记下等待、再发事件，所以侧栏连上时拿到的状态里没有的卡，后台已经不等了。小实验：不另写，`panel-send-confirm.mts` 的 p1、p4 直接覆盖。结果：见 PR。

## 边界与不做
- 不加「这个网站以后不问」：用户决定不要。
- 不读收件人、主题：程序现在只读得到网站、按钮名和按钮附近的草稿，不编别的。
- 原来的缺口不变（按回车发送、iframe 里的按钮、读不到名字的按钮），见[网页操作不再逐次确认](../browser-confirmation.md)。

## 踩过的坑与没跑的
卡上的草稿预览随开始等的那条事件存进侧栏历史（本机 chrome.storage.local），存一次；结局和点击结果那两条不带草稿。诊断记录（run-trace）记的是助手循环的事件，不记这几条。扩展后台重启时等待丢失，卡收成「这次确认已经结束」，没有自动用例；「没点到发送键」那一行也没有自动用例。真实网站、真模型没跑。
