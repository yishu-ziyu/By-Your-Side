# 任务: 对话超出模型的上下文窗口时，这条消息照常答完，不报错

来源：[论文对照](../research/20261011-harness-paper-review.md)第 2 项（已收窄），用户 10-11 说「都做」。论文里不管理上下文的做法在窗口满时直接失败，管理以后这类失败为 0。#276（#271）起每轮的运行上下文也留在历史里，所以长对话比以前涨得快。

## 规则

- R1 模型回「超出上下文窗口」时，程序把这一轮之前的大段旧内容（读页结果、页面快照、运行上下文）各换成一行占位，再请求一次；侧栏显示回答，不显示错误。
  - 例子(正)：同一会话在三个长页面上各问一句；脚本模型在请求同时带着三页正文时回超窗口错误；第三问照样答完 — 谁检查：`overflow-retry.mts`
  - 例子(反)：去掉重试，第三问侧栏显示错误 — 谁检查：同一用例，改代码后跑
- R2 这一轮自己的内容不删：重试的请求里还有第三页的正文，前两页只剩占位。
  - 例子(正)：重试请求里有第三页的标记词、没有前两页的标记词 — 谁检查：`overflow-retry.mts`
- R3 没超窗口时历史不改，所以 #276 的缓存前缀不受影响。
  - 例子(正)：第二问的请求、第三问第一次请求都带着前面各页的全文 — 谁检查：`overflow-retry.mts`

## 还没答上的问题

- 无。

## 技术前提

- 前提：OpenAI 兼容接口回 400「maximum context length is N tokens」时，pi-ai 判为超窗口。小实验：读 pi-ai 的超窗口规则表，有 `/maximum context length is \d+ tokens/i`。结果：通过，用例里第三问第一次请求收到 400 后程序删除重试（下面的证据）。

## 边界与不做

- 只在超窗口报错后删一次；平时不按阈值删，因为删会改历史前缀、丢掉缓存。
- 删的只在内存里：会话记录里还是全文，扩展重启后读回全文，下次超窗口时再删一次。
- 不用模型总结，不做「删掉的内容再取回」（论文测出模型几乎不用）。
- 删完仍超窗口时，照旧显示错误。
- 只在模型报错时删：pi-ai 把「回答成功、但输入超过配置的窗口」也算超窗口，那条回答已经给了用户，不能删掉重问（reviewer 读代码发现；用例没覆盖这种情况）。

## 结果（2026-10-11，脚本模型，隔离无头 Chrome）

- R1、R2、R3 通过：`overflow-retry.mts` 三项通过。重试的请求只剩页 C 的正文；第二问和第三问第一次请求都带着前面各页全文。
- 反例：去掉删除重试后，第三问侧栏显示「模型这次没有给出回答」的错误卡，a、b 失败。改前用户点卡上的「重试」，推断也会再次超窗口（没测）。
