# 任务: 发出问题后侧栏立刻显示在做（#18）

## 规则
- R1 发送后 0.2 秒内出现停止键和过程行，读页慢时也一样。
  - 例子(正)：少数派长文，开工前读页用了 3–4 秒，停止键和「正在思考」仍在约 0.05 秒内出现 — 谁检查：一次性计时脚本（见证据）
  - 例子(反)：模型没开始就出错，停止键一直亮着 — 谁检查：`process-line.mts`、`answer-receipt.mts`、`takeover-handback.mts` 回归
- R2 切回一个正在跑的会话时，不凭空多出一行过程行 — 谁检查：条件只在「最后一轮是刚发出的用户消息」时建行；人看
- R3 观感 — 谁检查：人

## 技术前提
- 前提：侧栏的停止键与过程行只跟「运行中」状态走，而 agent 原来在读页之后、模型开始时才报。小实验：发送前挂 MutationObserver 记时间，导出诊断记录对齐 `run_start`/`pre_observation`/`agent_start`。结果：读页 2.7–3.0 秒时，停止键晚到 2.9–3.0 秒，与读页时长吻合。

## 边界与不做
- 不改读页本身的速度；冷启动读页超时另见下文。
- 「正在思考」进行中的墨色加扫光是过程行设计本身（`styles.css` 注释），不改。

## 证据
- 现版本（main，只装扩展，gpt-6-luna，`summary-real-sspai` 用例）首字 4.3–14.1 秒、整轮 4.8–14.7 秒；9-30 的 115 秒（本机模式）不再复现。
- 改前冷启动 3 次停止键 0.17 / 2.9 / 3.0 秒；改后 4 次 0.03–0.05 秒，过程行与停止键同一毫秒出现（25、43 毫秒），早于模型开始（约 80 毫秒）。
- 回归：`process-line.mts`、`answer-receipt.mts` 全过，`memory-used-line.mts` 16/16，`takeover-handback.mts` 0 失败。
- 首轮临时脚本有两次「消息没发出」：脚本切前台后侧栏没拿到焦点，不是产品吞字。
- 新发现：冷启动时开工前读页 4 秒超时放弃，模型没拿到页面，自己再读一次，多一整轮（一次 34 秒，3 次模型请求）。未处理。
