# 任务：比较主流程状态与控制的呈现位置

- [x] 可点击走通发起、逐步执行、修改、接管、交还、断连恢复、完成与停止。— 谁检查：主代理真实浏览器操作，回执由原型模拟

- [ ] 选定后接入真实侧栏与后台并重验原路径。— 谁检查：主代理

## 本轮边界

隔离原型位于 `prototypes/task-flow/index.html`，没有修改生产代码。模拟文章、段落进度和回执，不调用模型、不改变用户网页，不代表真实 Agent 的执行验收。顶部按现有视觉简化显示，本轮不比较会话管理和设置。

## 两个方向

- 固定状态：控制始终位于侧栏顶部；优势是易于找到，代价是长期占用消息区域高度。
- 随任务呈现：状态和控制位于消息流中；优势是任务与进度相邻，代价是翻看历史时需要回到当前任务。

## 观察记录

- 固定版：发送 → 翻译一段 → 发送仅译文修改 → 接管 → 交还 → 断连 → 恢复核对 → 完成；最终示例网页只有中文，显示 3/3 完成。
- 随任务版：发送 → 接管 → 保存修改 → 断连 → 恢复仍为用户控制 → 交还生效 → 翻译一段 → 停止；已有一段译文保留，未完成部分未显示为成功。
- 随任务版另完成三段双语结果路径；固定版展开过程查看接收、读取和逐段完成记录。
- 状态文字变更 180ms 轻量过渡，按钮按压 120ms，支持减少动态设置；没有持续装饰运动。减少动态分支已实现，本轮未切换真实系统偏好验收。
- 为避免演示切换器遮挡输入，切换器放在页面上方；并排场景在较窄窗口改为纵向。

## 后续全栈接入条件

复用既有 task action / receipt / runId / controlVersion，而不是将原型计时器移入产品。停止、接管和恢复状态必须由真实控制回执驱动；断连不能显示为已暂停。仅在用户选择后把呈现层接入，真实翻译段落结果、插话生效与恢复均需重新验证。
