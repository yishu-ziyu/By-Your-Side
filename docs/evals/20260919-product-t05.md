## 用户可见变化

改前：host 重启或连接断开后，任务只剩一句「任务因……中断」，没有目标、已完成、剩余、卡住原因的集中视图，也没有可点的接续入口；要恢复只能自己记得在输入框里打「继续」。写操作的「允许一次」确认卡因为消息缺 `conversationId` 被后台整条丢弃，用户永远看不到卡片，只能等到 60 秒后收到「确认已过期」——这是 A04 挂起与本轮 P0 `confirm_blocked_write` 全部超时后停写的直接原因。

改后：

- 侧栏在运行、中断、阻塞、未知、停止各状态显示接续摘要：目标原文（含修订数）、已完成项、剩余项及状态（未完成／执行受阻／结果未知）、卡住原因、合法下一步、具体缺口；摘要只在有真实状态时出现，空闲且无剩余项时不占位置。
- 只有真实可恢复时（中断且留有恢复输入，或已结束但只交付了部分结果且恢复输入仍在）才出现「继续原任务」按钮；按钮点击期间禁用去重，拿不到当前页面或连接不可用时不发送并如实说明。
- 面板重开、重连、切回会话时补取一次权威视图（`task_view_query`），摘要不靠旧缓存；会话切换时清空旧摘要。
- 写操作确认卡恢复可见：用户能看到「允许一次」，选择真正生效。

## 根因定位与修复（本票范围）

1. **A04「检查点恢复触发、页面重读后 turn 挂起到超时」根因：扩展上行连接的旧重连定时器拆掉了刚建立的新连接。**
   证据链：T01 baseline（`docs/evals/20260919-product-t01.md`，A04 4/4 超时）与 `eval/runs/journeys-baseline-2026-09-19T06-50-24-889Z/A04-plain-0-resume/events.json`：恢复后 `agent_start` 约 800ms 出现 `checkpoint: interrupted` 的 `conversation_updated`（即 `manager.disconnect()`），随后终态事件被中断过滤吞掉，运行器等不到 `agent_end`。
   隔离连接层复现（真扩展 + 真 host 重启序列，不调模型）：旧代码 `host2` 连接后 ~835ms 又关闭并重连；修复后 6 秒观察窗内保持稳定。证据 `out/acceptance/20260919-183457-t05/connect-stability/before-fix/`、`after-fix/`（脚本 `scripts/acceptance/t05-connect-repro.mts`）。
   修复：`extension/src/background/uplink.ts` —— 重连定时器到点时若已有活传输则不再 `teardown()`；`retry()` 主动重连前清除旧定时器；`connectNative/connectWs` 在已有活传输时直接返回。
   真实 A04（T01 运行器、MiniMax-M3、真实无头扩展）：material 0 由 420s 超时变为 **PASS，10.1s**；material 1 仍 FAIL（190s，原因见「仍有问题」）。
2. **写操作确认卡不可达根因：`WriteConfirmBroker` 发出的 `consent_request` 缺 envelope `conversationId`。**
   `parseServerMessage` 要求 `request.conversationId === msg.conversationId`，后台收到后整条静默丢弃，真实面板从未渲染过卡片；有界恢复只能等确认超时。修复：`agent/src/write-confirm.ts` 补 `conversationId`；回归测试断言该消息能被 `parseServerMessage` 接受（`agent/test/task-confirmed-recovery.test.ts`）。

## 恢复状态表与按钮调用关系

| 视图状态 / 等待原因 | 摘要头条 | 「继续原任务」按钮 | 点击实际调用 |
|---|---|---|---|
| `running` | 正在执行 | 无（摘要显示剩余项） | — |
| `interrupted` + `restart_checkpoint`，有恢复输入与 runId | 已中断 · 可继续 | 有 | `task_action/resume`：`{requestId, conversationId, source:'text', action:'resume', expectedRunId, expectedControlVersion, text:'继续原任务', context:当前活动页}` → 现有 `ConversationManager.dispatchTaskAction` resume 分支 → `session.resumeInterruptedTask`（先重读当前页面、核对页面身份、带持久检查点提示词续跑）；不携带任何旧工具参数 |
| `idle`/`error` 且 `nextStep.delivery==='partial'`，恢复输入仍在 | 任务已结束 · 仍有未完成项 | 有 | 同上（宿主先 `interrupt('manual_continuation')` 再走同一 resume） |
| `paused`（页面归用户） | 已暂停 · 页面归你 | 无（说明「在页面上点交还」） | 交还仍走既有页面按钮 → handback → `continueAfterHandback` |
| 未知写入（`unknown_*`） | 任务已结束/中断 · 结果未知 | 有（点击前摘要已说明不会重复提交） | 同上；未知写入闸门保留，`confirm_blocked_write` 是唯一受支持的一次性重设路径 |
| `aborted` | 已停止 | 无 | —（历史保留，不自动复活） |
| 检查点不可用 | 原任务检查点无法恢复 | 无 | —（原记录未被覆盖，其他任务可另开会话） |
| 超时/失败回执 | — | 解除等待、按原样显示失败原因、可重试 | 同一 resume 动作（新 requestId；宿主按 `checkpointResumes` 去重） |

其它按钮：接管仍是既有 `control/takeover`；页面「交还」仍是既有 handback；本票未新增自动执行旧工具参数的入口。
