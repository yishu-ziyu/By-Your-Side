# 任务: 助手点完、填完一步，就知道页面上新出现了什么，不用再读一次页

用户 10-14 同意方向。用户一周的记录里，一次来回中位 6.7 秒，87% 在等模型；一件“记进 flomo”的事 14 次来回，有 8 次只是为了再看一眼页面。原因是点击、填写之后，工具只说“页面有反应”，不说多了什么。

## 规则

- R1 点击、双击、回车、填写、选择之后，同一页上新出现的按钮、输入框和文字，跟着结果交给模型，带可以直接用的编号；只给新出现的，最多约 2000 字，绝不给整页。
  - 例子(正)：点「新建笔记」弹出对话框，结果里有标题框和「保存」的编号；模型照编号填写、保存，整轮只读一次页 — 谁检查：`scripts/acceptance/real-path/action-page-changes.mts`
  - 例子(反)：3000 段正文的长页上，结果里不出现正文段落 — 谁检查：同上
- R2 换了页、开了新标签页的，沿用换页后的回执，不再加这一段；页面一大块都变了的，只说一句让模型自己读。
- R3 旧值和敏感栏的值不交给模型：还原填写记下的旧值从摘要里去掉；密码、验证码、卡号这类栏只说填了。
  - 例子(正)：填标题后页面显示“原标题「草稿-…」已替换”，结果里旧标题换成占位；口令框、autocomplete=one-time-code 的框的值都不出现 — 谁检查：同上
- R4 为此多花的时间，中位数不超过约 300 毫秒，不然只是把等模型换成等页面。
  - 例子(正)：练习页上点开对话框、回车、选择、填写，每一步多花几十到一百多毫秒；备注框的自动保存请求 1.5 秒才回来，填写不等它 — 谁检查：同上（读扩展后台记下的毫秒数）
  - 例子(反)：在有跳动时钟的页面上点一个没反应的按钮，结果照旧警告“没有可归因的变化”，不把时钟当成新内容 — 谁检查：同上
- R5 列表里每项都有同样的按钮时，新出现或变了的按钮行尾写明它在哪一项。快照是平的，看不出按钮属于哪条；10-14 Memos 置顶 6 次里 3 次第一下点到了上一条的“更多”，基线点完读整页能改回来，只给新内容时就改不回来了，还说成功。
  - 例子(正)：点第二张卡片的「More」，结果里展开的按钮带着“读书笔记…”；置顶后新出现的「Unpin」也带着“读书笔记…” — 谁检查：同上

## 技术前提

- 前提：只读变过的那几处，比读整页快得多。小实验：维基百科长条目（3.4 万个无障碍节点）读整页一次 1.0–1.5 秒，其中树本身 13 MB；只读新加的一个对话框，树热了以后 1–12 毫秒，第一次 223 毫秒。结果：通过，所以改成页面里记下变过的地方、只读那几处
- 前提：页面重画后编号会全换。只按编号比，重画的地方会全部算成新的；所以只比动作期间变过的几处，不比整页。

## 边界与不做

- 比的是“模型上次读到的这一页”，不是动作前另读一次（那要多花一次读页时间）。所以摘要说“自上次读页以来新出现的”，不断言都是这一步引起的。
- 只说新出现的，不说消失的：消失的多半是旧值、旧提示。挪了位置的旧行（置顶后整条移到最上面）也不说，结果里写明这一点。
- 按键只有回车带这一段（方向键、Tab 连按时每下多等不值得）。
- 填写、选择之后：页面还在改 DOM 就等它安静下来，最多 200 毫秒；不等网络（会自动保存的编辑器每填一次都发请求）。所以要等网站回话或靠计时器延后才出现的（自动补全）这一步看不到。还没读过这一页时不等，摘要也没有。
- 动作前就在一直跳字的地方（时钟、倒计时）不算新出现的，也不算“页面还没安静”；刚开始记的头一两秒还认不出它在跳。
- “这一步没引起变化、别盲目重复”的警告只看效果判断，不看摘要；摘要不是这一步带来的时候写明“不一定是这一步带来的”。
- 一个字的旧值、下拉框的旧选项、已经关掉的还原记录（提交、还原、换页后值已丢掉）不去掉：那时页面上的字和读页看到的一样。
- 页面里的影子 DOM、零尺寸元素不单独处理：变化记录看不到影子 DOM 里面；零尺寸过滤要读全页布局，这里不做。
- “在哪一项”宁可不说，不说错：同组几项的字一样（同一作者的推文头一行、两条都是“谢谢”）又分不出时，不写在哪一项。还认不出的：这一项自己没有文字（只有图片、表情）会说成旁边条目的字；名字不同的同类按钮（“赞 3”和“赞 4”）、没有名字的图标按钮，不写。
- browser_run 程序里的点击、填写也会挪动“上次读到的”基准，程序没交回的新内容，之后的摘要不会再说。
