# 任务: 语音说“终止任务”就真的终止，不读回、不抢先宣称；回答不再以客套反问收尾

方向依据见[语音交互原则](../voice-interaction.md)。本任务是其中“底线”一步的前半部分。

## 完成标准

- [x] 1. 任务在等点选时说“终止任务”：原 run 收到 `source=voice` 的 abort，`applied`，点选层消失 — 谁检查: `inproc-voice --case=stop-task`
- [x] 2. 过程中没有“你是说……对吗”读回 — 谁检查: 同上 `noReadback`
- [x] 3. 终止回执之前，侧栏和语音里都不出现“已终止/停了” — 谁检查: 同上 `noClaimBeforeReceipt`；原始帧时间线核对模型抢答被扣住、未下发
- [x] 4. 可控任务期间的普通对话照常回答；停声只停播报，任务不动 — 谁检查: 同上 `chatPassesGate`、`muteKeepsOriginalTask`
- [x] 5. 迟到的旧要求不能复活已终止的任务 — 谁检查: 同上 `lateRequestCannotRevive`
- [x] 6. 语音问答、圈画不回归，用时不变慢 — 谁检查: `inproc-voice --case=question`、`--case=mark`
- [ ] 7. 结尾客套反问在多轮真实使用中明显减少 — 谁检查: 人（单次样本不足）
- [ ] 8. 日常 Chrome 真人试用 — 谁检查: 人（未加载日常）

## 修订依据

原标准（[core-into-extension](20260924-core-into-extension.md) 第 10 行）要求“读回→确认‘对’→终止”。2026-09-24 用户决定明确终止直接执行，标准随之改为本页第 1–3 条。原红例保留。修订前实测还发现 StepFun 会把单字“对。”判成附和（未公开事件 `speech_backchannel`），清掉音频且不给转写，3/3 次复现，与是否中途停声无关。

## 边界与不做

- 只有明确的“终止/取消/停止…任务”句由宿主直接处理；“停一下”这类含糊说法仍交模型判断。
- 问候回答仍带“有什么想聊的……吗”，圈画仍复述可见结果：提示词只能引导，需后续实测再定。
- 人设与自适应习惯不在本任务内。
