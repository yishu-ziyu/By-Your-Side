# 任务: 回答写完后，用户拖动回答下面的把手，把回答收成要点或一句话，再拖回来是原样全文

用户 10-14 看过原型后同意。三层都从这份回答里截出来，不再问模型，所以立刻变，字和全文一字不差；代价是截法只看结构（段落、列表、卡片推荐项），不懂语义。

## 规则

- R1 三层从同一份回答截出：全文原样；要点留第一段、列表和表格、下面有列表的小标题、卡片里的推荐项；一句只留第一段的第一句。
  - 例子(正)：比价回答往上拖一格，只剩结论段、推荐的那一家和“值不值得等”的两条要点；再拖一格只剩“拼多多百亿补贴到手最便宜，¥1529（含运费）。” — 谁检查：`scripts/acceptance/real-path/answer-shorten.mts`
  - 例子(反)：任何一层都不出现全文里没有的字；回到全文时和收短前一字不差 — 谁检查：同上
- R2 把手好找、好用：点一下短一层，最短再点回全文；键盘上下键同样；旁边写着现在是哪一层、约几秒读完；长回答时把手贴着侧栏底部。
  - 例子(正)：焦点在把手上按上键，层名从“全文”变成“要点” — 谁检查：同上
  - 例子(反)：一句话能说完的回答（不到三行）不出把手 — 谁检查：同上
- R5 拖的时候跟手：回答高度跟着手指走，两层之间被拖过的块从下往上逐个收起；松手按手指速度弹到最近的一层，轻甩也能换层。用户 10-15 嫌按 36px 一档整层切换“太跳”，在本机预览里试过后同意。
  - 例子(正)：从全文慢慢往上拖，把手一直在手指下面，“细节”段先淡出收起，对话区不被弹回顶部 — 谁检查：`answer-shorten.mts`
  - 例子(反)：回弹没停时再抓住拖，回答不留下半截：开头段、卡片推荐项都在 — 谁检查：同上
- R3 复制按看到的那一层：收短后点“复制”或“复制为 Markdown”，拿到的是当前层，因为收短多半是为了转给别人。
  - 例子(正)：一句层点“复制”，拿到的就是第一句 — 谁检查：同上
- R4 第一句就是结论：侧栏主回答和阅读卡用同一条写法规则，一句层才有意义。
  - 例子(正)：gpt-6-luna 回答比价题，第一句直接说哪家最便宜 — 谁检查：`answer-shorten.mts --live`，人看截图
  - 例子(反)：第一句不是复述问题，也不是“好的，我来比较一下” — 谁检查：同上

## 技术前提

- 前提：收起过程由脚本每帧按手指位置写高度，CSS 只负责最后收起的块不渲染。放弃了 CSS 高度过渡：它只能在两层之间自己播完，跟不了手。
- 坑：往短拖时对话区变矮，浏览器会把滚动位置往回夹，整页跳一下；拖的时候在对话区底部临时补空白，停稳后再收掉。

## 边界与不做

- 不再请模型重写短版本：会慢、会改说法，也会花钱。
- 层级只活在这一页：历史回放默认全文，不跨会话保存。
- 回答比侧栏高、用户往上滚着读开头时，先收的是视口下面看不见的块：拖的前一段画面不动，松手照样换层。没做，因为要先决定这时该收看得见的块还是先滚到末尾。
- 表格里非推荐的行收起时整行一下消失，不逐渐变矮：表格行不接受高度。
- 第一段不是段落（以卡片、列表或小标题开头）时不出把手。第一段只有一句时，一句层就是整个第一段。
