# 任务: 出错→恢复收成一行：回执留在出错的位置，没做成那行写原因，再出错不抖

来源：设计地图「出错→恢复收成一行」（F24/F25，#286），PR #321 在 10-13 主线上重做。用户要知道哪坏了、能做什么；修好之后看见它「从出错处接着做了」。前置：[失败原因人话](20261012-issue-304.md)（#304，主线 #338）。

## 规则

- R1 恢复成功后错误卡在原地收成一行回执，答案跟在它下面
  - 例子(正)：断网出错、点「重试」恢复 → 原卡位置变成「出过错 · 已重试，已从出错处继续」，续写的答案在它下面，错误卡不再可见 — 谁检查：`npx tsx scripts/acceptance/real-path/error-recovery-show.mts --headless`（一）、`error-recovery.mts`
  - 例子(反)：错误卡消失、回执追加到答案后面 — 谁检查：同上
- R2 「继续原任务」卡上那行写失败的人话原因，不写步骤名；回答原文不带宿主补的一句（宿主那句在过程行上，主线 #337）
  - 例子(正)：点不可用的「提交」、模型说做完了、核对没结论 → 卡上一行「没做成：目标现在不可用」；后台重启后、以及 10-04 以前按计划列目标的旧会话恢复后，仍是这一行 — 谁检查：`error-recovery-show.mts`（二、三、四）
  - 例子(反)：重启后变成「没做成：点击页面上的一项」，或旧会话里变成「还没确认完成：提交退货申请」 — 谁检查：同上（故意去掉对应修复各失败一次）
- R3 重试又失败时同一张卡原地换内容，只淡一下；不抖、不重新进场
  - 例子(正)：断网点「重试」仍不通 → 仍是 1 张卡 — 谁检查：`error-recovery-show.mts`（一）
  - 例子(反)：卡片被替换并抖 5px — 谁检查：人
- R4 prefers-reduced-motion 下进场、收行、淡化全停，信息不依赖动效
  - 例子(正)：减少动效时恢复照常收行、文案一致，入场、收行、抖动都不播 — 谁检查：代码审查

## 技术前提

- 前提：错误卡排在后到的答案前面，答案自然落在它下面。小实验：`error-recovery.mts` 断言回执在答案之前。结果：通过。
- 前提：失败原因随 `tool_end.reason` 进执行账本和检查点，侧栏从任务视图读到。模型看到的账本副本（`record_task_results`、语音 `task_status`）去掉原因，和改前一样。小实验：`error-recovery-show.mts` 三。结果：通过。

## 边界与不做

- 过程行仍写「有 N 步没做成」（#337 的设计）；原因只写在卡上那一行和展开过程里的那一步。
- 目标核对或模型自己交代的「还差」原文照旧优先于步骤原因；核对判做完时卡不出现（#334）。
- 不改错误卡的文案、动作与换 key、换模型、倒计时路径。
- 失败原因只给侧栏看，不进模型的任务快照：它可能取自网页原文（挡住按钮的元素名、页面脚本的报错）。
