# 任务: 出错→恢复收成一行：回执留在出错的位置，没做成只说一次，再出错不抖

来源：设计地图「出错→恢复收成一行」（F24/F25，#286）。用户要知道哪坏了、能做什么；修好之后看见它「从出错处接着做了」。前置：[出错状态实现](20261006-error-states.md)（#74）、[失败原因人话](20261012-issue-304.md)（#304）。

## 规则

- R1 恢复成功后错误卡在原地收成一行回执，不再在答案后面另出第二条元素
  - 例子(正)：错误卡曾是第 N 条消息，恢复后第 N 条位置是「出过错 · 已重试，已从出错处继续」（或 已换密钥 / 已换成 X），续写的答案跟在它下面；`.error-receipt` 类保留在这行上，`.error-card` 不再可见 — 谁检查：`npx tsx scripts/acceptance/real-path/error-recovery.mts --headless`（断言回执在答案之前、error-card 不可见）
  - 例子(反)：错误卡消失、回执追加到答案末尾，两行说同一件事 — 谁检查：同一命令
- R2 「没做成」只说一次：答案不再带「（有一步没做成…）」括号注，由「没做成：… + 继续原任务」卡说；行内优先写失败的人话原因（如「目标现在不可用」），没有原因才写步骤名
  - 例子(正)：点击步骤失败、模型说做完了 → 答案原文不带括号注；侧栏一行「没做成：目标现在不可用」+「继续原任务」 — 谁检查：人（真实路径目测）
  - 例子(反)：答案末尾有「（还有没做完或没核对的部分。）」同时下面又出「没做成」卡 — 谁检查：人
- R3 重试又失败时同一张卡原地换内容，只淡一下；不抖、不红闪、不重新 6px 进场
  - 例子(正)：断网点「重试」仍不通 → 同一元素更新文案与动作，仍是 1 张卡 — 谁检查：`error-recovery.mts` 断网段（卡数 === 1）
  - 例子(反)：卡片被替换并抖 5px — 谁检查：人
- R4 卡的进场保留 rise 6px 200ms；prefers-reduced-motion 下进场、morph、淡化全停，信息不依赖动效
  - 例子(正)：reduced motion 下恢复照常收行、文案一致 — 谁检查：代码审查（WAAPI 三处都判 `reducedMotion()`）

## 技术前提

- 前提：错误卡挂到接续锚点（`#resume-entry-root`）之前，后到的答案自然落在它下面，「原地收成一行」就在出错的位置。小实验：读 `main.ts` `appendToMessages` 的锚点与 `ensureRun` 的尾部追加。结果：成立。
- 前提：失败原因可从 `tool_end.reason`（#304）随账本进 `TaskViewResultItem`，不需要另造通道。小实验：`noteEnd` 在 `tool_end` 事件同帧拿到 `e.reason`。结果：成立。

## 边界与不做

- 不改错误卡的文案、动作与换 key/换模型/倒计时路径。
- 目标核对/模型自己交代的「还差」原文照旧优先于步骤原因。
- 语音念交付的路径不动：`spokenDeliveryText` 对部分交付本来就说宿主自己的话。
- 「仍然重试」卡在没有动作回执时不留回执行，与原来一致。
