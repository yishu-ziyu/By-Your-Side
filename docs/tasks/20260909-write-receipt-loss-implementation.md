## 3. 问题与因果链

三个时刻：请求发出 → 页面产生副作用 → 成功回执返回。第二步和第三步之间断开，会留下“已执行但调用方未知”。

当前关键路径：

`createBrowserTools → ToolRpc → 扩展执行器 → tool_result → Pi工具结束事件 → BrowserAgentSession → TaskProgress → TaskResultBook → 下一次执行检查`。

源码定位：

- `agent/src/rpc.ts`：timeout删除pending并reject，断连rejectAll；晚到回执在pending不存在时被忽略。连接断开前是否已发送必须分清。
- `shared/protocol.ts`：工具失败主要是 `ok:false/error:string`，不能完整表达是否已产生副作用。
- `extension/src/background/index.ts`：执行器抛错被统一转成字符串；动作前拒绝与动作后不确定可能汇入同一出口。
- `agent/src/conversation-runtime.ts`：tool_result转交RPC，新增元数据不能在此丢失。
- `agent/src/session.ts`：工具事件投影主要保留isError和文本；执行检查已能拒绝unknown，但依赖上游准确登记。
- `agent/src/task-progress.ts`：将isError作为failed交给结果账本。
- `agent/src/task-results.ts`：failed进入blocked，重新登记可回pending；unknown已有保留逻辑。
- `agent/src/browser-program.ts`、`agent/src/tools.ts`：组合工具的内部调用、通用JS也必须服从同一未决写入约束。

修复前实测：正常新增1条；写入成功后超时和断连均被记为blocked，重新登记并调用后实际新增2条。15条检查中9条通过，6条暴露缺陷，退出码1。完整事件与源码hash见[基线JSON](../evals/20260909-write-receipt-loss-baseline.json)。基线使用真实Chrome页面和产品click/RPC/执行检查，但固定驱动替代模型调度，CDP桥替代完整扩展分发及native messaging。不能把它称作真人或完整Agent端到端失败。

## 4. 工程建议：先修结果语义，再接恢复

### 切片一：在调用链中保留“是否执行”的区别

建议区分三类事实；具体类型名称由实现者决定：

| 事实 | 可依据的证据 | 后续行为 |
|---|---|---|
| 确定未执行 | 未发送；或执行器确认在副作用之前拒绝 | 可恢复的前置失败允许修正后继续；接管/取消仍受原控制约束 |
| 执行结果不明 | 已发送后超时/断连；可能部分执行后异常；旧协议无法证明未执行 | 保留未决操作，拒绝自动重放，允许只读核查 |
| 已收到执行结果 | 与原操作身份匹配的回执或充分核查证据 | 按回执处理；不能从事件派发推导任意业务成功 |

禁止从错误文案正则或`isError`猜测副作用状态。旧协议缺少信息时，已经发出的写入保守归未知；读取错误不因此锁死写入。

优先扩展既有RPC/工具结果协议与账本，不再建立竞争性的任务真相。核对Pi锁定版本实际如何把工具异常转成工具结果：把类型加在Error对象上不代表SDK事件会保留它。需要沿生产回路验证元数据到达最终执行闸门。

### 切片二：把未决操作绑在宿主身份上

沿现有conversationId、runId、成员、toolCallId/传输id、控制轮次建立对应关系。重试生成新工具调用id，不代表是新的用户授权。

未知状态不能通过重新登记、新结果id或selector别名被洗掉。通用JS难以判断意图等价时，可先在受影响页/任务上保守限制写操作；必须仍可读页，不能阻塞其他会话独立页。

扩展重复收到同一操作身份时，应返回已有状态或结果，不再次执行。复用现有持久化边界保留未决信息，恢复时不能把未知变回普通pending。不要承诺浏览器或站点没有幂等接口时的全局exactly-once；执行器进程中断、记录淘汰等不能靠猜测恢复成功。

### 切片三：让核查解决未知，而不是让模型宣布解决

先实现窄的恢复闭环：读当前页面，取得能关联到该次操作的唯一记录/结果，引用真实观察回执。宿主校验身份和证据来源，模型不得直接写status或伪造证据。

当前页面没有记录可能只是延迟、翻页或视图变化，不是确定未执行。证据不足就维持未知。可以通过现有正式回复告诉用户情况，不新增确认弹窗或改侧栏布局。

充分的晚到成功回执可用于解决原操作；不能解除另一个run或另一页的限制。晚到失败也必须按是否可能已执行分类，不能把未知降回可重试。

### 切片四：覆盖所有现有写入口

检查普通工具、browser_run内部步骤、js、lead/worker调用与会话恢复。尤其防止某个入口只检查prompt层，或browser_run捕获异常后继续写入。取消/接管的现有权限优先于恢复，不被“有回执了”覆盖。
