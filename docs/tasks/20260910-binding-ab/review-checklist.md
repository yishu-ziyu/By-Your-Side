# 主代理评审清单

不代写候选、不代跑测试。以下仅细化冻结标准的证据检查，不改变判定条件。

1. A/B/C来源同一WIP，差异只在登记/绑定机制；比较时模型、reasoning、任务文案、fixture数据和时间起点一致。
2. B的“唯一”按当前run+成员+工具+pending+未绑定筛选；不能仅按数组第一个或只看工具名。显式已绑定目标不被另一次调用静默改写。
3. C的resultId从实际动作一直传到绑定边界，再剥离为内部元数据；browser_run子步骤和普通工具一致，不遗落在上层schema或传入网页。
4. 先有合法绑定及其执行身份，再发RPC；拒绝路径不产生副作用。在途/unknown/satisfied不能被注册覆盖；重启恢复不能把未完成派发恢复成可重试pending。
5. 原生页面身份、ref有效性、成员权限、禁用工具、epoch/接管仍在原执行层生效。减少一次登记不能等于减少这些检查。
6. 工具回执满足和用户结果正确分别测；必须检查实际DOM/状态/副作用次数与用户要求的具体对象。
7. 18次原始数据中包含全部失败和慢样本。比较按场景配对，不把不同任务的平均值混成提速结论；额外登记与失败重试计入成本。
8. 查看失败样本，辨别错目标、false success、拒绝了合法操作、provider故障、驱动错误。若修过执行器或测试环境，受影响的A/B/C组一起重跑。
9. 修订旧断言仅限已明确改变的登记语义，替代反例保持安全目的；不改R3既有反例，也不把历史失败宣称本轮解决。
10. 选型后由DeepSeek将限定差异回接当前工作区，保留root中后续用户修改；执行最终检查并提供线上构建证据，主代理才可报告正式结果。
