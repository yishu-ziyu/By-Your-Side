# 评测中的站点不可用

[验收入口](acceptance.md) · [测量规则](../../eval/README.md)

评测把站点不可用的题单独列出。判定条件见 [`environment.mjs`](../../eval/harness/environment.mjs)。

## 怎样算不可用

- 只有浏览器证据能把一题判为站点不可用。不按助手的解释判断。
- 以下情况单独出现时，不能作为排除依据：网页普通正文提到断网、限流或验证码；模型自称断网；任务超时；HTTP 404；操作失败。
- 任务开始时站点已不可用，评测就不调用模型，只保存实际页面截图和证据。
- 结束时只按最新页面判定。早先断连、后来已恢复的，不排除。
- 重定向或子资源报错，不能借用原页面的状态。
- 旧记录没有采集证据的，不推定为站点不可用。

## 怎样计分

- 每题先按原成功规则判分。已完成的结果不因后续页面不可用而排除。
- 普通答案错误不因同页有站点问题而排除。只有当失败确实由浏览器证据支持的不可用造成时，这题才单列。
- 评测程序不把站点不可用的题判为成功，也不判为产品失败。报表、复核页和看板单独显示这些题的数量，并把它们排除出通过率分母。
- 产品任务的平均 token、调用次数、耗时与成本也排除这些题，因为零调用的受阻题会稀释平均数。
- 普通失败和无法确定的题仍计入分母。共同题比较只采用所有配置都有正常判分的题。

## 调度

同一主机名的任务串行，不同主机的任务可以并发。主机串行只是评测调度，不改变产品的网络行为，也不写全局设置。

验收命令：`npx tsx scripts/acceptance/eval-environment.mts`。结果见[验收](../evals/20261002-eval-environment.md)。
