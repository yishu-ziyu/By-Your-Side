# 验收脚本入口

[文档导航](../README.md) · [开发检查](../development/checks.md)

本页只写怎样选入口时代码里看不出的边界和坑。

## 先用这个入口

`npm run lab` 是开发统一入口，踩过的坑写在它的文件头里，由它挡住，不靠记。

## 怎样选入口

- **真实网站护栏**：训练集与独立测试集网站不重叠，分析者只看训练集过程记录；改前改后两份预构建扩展须在同一时段并排跑。
- **CI**：E2E 工作流还没在 Linux 上跑通过。

## 每日核心验收

当前自用 Mac 每天 03:00 跑核心集，只用隔离扩展、无头 Chrome、本机练习页和脚本模型。非核心用例、真实模型与日常 Chrome 的任务不自动跑。

- 每轮从本机主目录的 HEAD 生成独立快照，不改工作目录，不自动拉取远端。并发上限为 2，默认不录屏。
- 入口是 `~/.config/devin/jobs/bys-core-nightly.py`，定时配置在同目录的 `com.yishuziyu.bys-core-nightly.plist`。配置不常驻重跑。
- 历史保存在 `~/.config/devin/jobs/bys-core-history/`，包括源码标识、逐项结果、日志和截图。`latest.json` 指向完整核心运行，过滤试跑另记到 `latest-smoke.json`。失败或缺结果都不会记成通过。
- 安装时核心 51/51 通过，系统调度试跑也通过。交还与超时误报修复已装日常，后台和侧栏代码已核对；真模型、真网站未跑。旧版备份在主目录 `out/daily-dist-backup-20261029-before-core-acceptance`。

## 录屏与慢放

单跑一个真实路径用例时，网页和侧栏会被自动并排录下来。关浏览器后在 `out/recordings/<用例>-<时间>/` 出三样东西：真实速度、0.25 倍慢放、带时间戳的逐帧总览。查闪烁、跳动、先后顺序这类问题时，用 `npm run frames -- <目录> <起秒> <止秒>` 把这段时间里的帧拼成图，一帧一帧看。用法见 [`recording.mts`](../../scripts/acceptance/real-path/recording.mts) 文件头。

- 全量验收（`run-all`）和 gym 评测默认不录：几十个用例的原始帧会占几个 GB，合成也会拖慢整轮。要录就加 `SIDEAGENT_RECORD=1`，不要录就加 `SIDEAGENT_RECORD=0`。
- 后台标签页加载时也会出帧。录屏按每帧当时这页可不可见来取舍，所以「网页」那一路只留用户眼前那一页。
- 原始帧只留三天，视频和总览一直留着。所以超过三天的录屏不能再逐帧放大。

## Ego 任务空间清理

用 Ego 跑对比测试时，Ego 的 `finish()` 只把任务空间交还给用户，不会关闭空间；关掉最后一页后它还会自动补一个空白页。测试结束必须用 `Target.closeTarget` 逐个关掉自己开的任务空间里的每一页（脚本建空间时名字一律以 `bys` 开头，只关自己开的）。

## 评测中的站点不可用

评测把站点不可用的题单独列出（判定见 [`environment.mjs`](../../eval/harness/environment.mjs)）：

- **怎样算不可用**：只有浏览器证据能把一题判为站点不可用，不按助手解释判断。网页正文提到断网或验证码、模型自称断网、任务超时、HTTP 404 或操作失败单独出现时都不排除；结束时只按最新页面判定。
- **怎样计分**：已完成的结果不因后续页面不可用而排除；站点不可用的题单独显示数量，从通过率分母以及平均 token、调用次数、耗时与成本中排除；普通失败和无法确定的题仍计入分母。

## 脚本模型与真实模型

- 多数用例用本机脚本模型。脚本模型只验证交互呈现，所以通过不代表供应商模型的质量，也不代表真人语音验收。
- 接真实模型要本机凭据和用户授权。缺凭据时如实写「没跑」。
- Kimi 订阅登录的访问令牌只活约 15 分钟，刷新令牌用一次就作废，只能由一处续期：`npm run kimi:keep` 装的后台任务每 6 小时续一次，验收脚本取令牌时也在 Pi 的锁里续，交给测试扩展时不带刷新令牌。系统通知说登录失效时，运行 `npm run kimi:login` 在网页上确认一次。
- `answer-selfcheck` 不加 `--live` 也要本机 GLM 凭据，因为目标核对默认用真实 GLM 快速模型。
- `gpt-live-voice` 会用掉用户 ChatGPT 套餐的语音额度；声音来自合成语音，不代替真人试听。

## 容易误判的地方

- **试用包不等于当前源码**：验试用包时，用 `SIDEAGENT_ACCEPTANCE_DIST` 指向试用包。当前源码通过，不代表试用包通过。
- **日常 Chrome**：`everyday-baseline --daily` 连到用户已开的日常 Chrome。只在用户同意后运行。
- **只能有窗口跑**：`background-tab-input --headed` 会弹出测试窗口，不进整轮。从没显示过的后台标签页不渲染、输入会丢，无头 Chrome 复现不了。运行时别点那个窗口，点了会让新页到前台，这次不算数。
- **圈画判据**：页面圈住目标、没有点击、侧栏交付无错误，三项都要满足。只看到圈画、但目标账本报未完成，仍算失败。
- **固定页面不等于完整评测**：`answer-selfcheck` 的固定页面检查不代替完整产品评测。
- **快捷键**：`sidebar-interaction` 只检查快捷键消息，不等于操作系统真的按下 ⌘J。
- **夹具数据**：`killer-interactions` 的翻译批次由夹具写入，不代表供应商翻译质量。`ghost-hud-and-steering` 不覆盖真实视频网站，也不覆盖供应商模型的改写质量。
- **读回与核对发现**：`claim-after-check` 的目标核对结论是脚本写的，只验证侧栏怎样显示，不代表快速模型核对得准不准。
- **站点提示**：`site-hint` 要能上网打开真实网站。断网时它会失败，这不代表产品坏了。
- **结果未知后重试**：`retry-after-unknown` 只覆盖量不到元素位置这一种成因，不覆盖超时和断连。
- **发送前确认与教学**：`send-confirm` 和 `guided-teaching` 都没有覆盖“用户一直不理就超时”，因为产品没有缩短等待的开关，也不为测试加开关。`guided-teaching` 也没有覆盖 iframe 里的目标。

## 设置页检查中的反馈

设置页用例在点击前检查控件是否可见；失败时同时留下当前页面、用户可见的错误原因和截图。已有密钥的失败原因可能出现在表单状态区，不能只等密钥输入框下方的提示。

## 当前缺口

- `page-readouts --live` 尚待适配。
- `inproc-voice --case=stop-task`（语音确认中止原任务）当前有失败记录：原任务靠真实文字模型调起「等用户点选」，模型常直接用文字反问，任务没进入等待，用例在搭场景时就超时。`--case=ask-status` 因此用本机脚本模型拖住原任务。
- 产品没有专用的只读脚本工具，因为求值标记盖不住返回对象序列化时的副作用。

## 脚本留在主线的条件

任务专用脚本至少满足一条，才留在主线：

1. 是 `scripts/acceptance/real-path/` 下的用例。一个用例跑不通又没人修，就删掉，因为测试按抓到过什么问题评价；
2. 被 `package.json`、`docs/` 下的现行文档或另一个活跃脚本引用；
3. 是多个任务共用的驱动、夹具或独立判定程序。

一次性探针在任务完成后合入共用驱动，或从 HEAD 删除。
