# 验收脚本入口

[文档导航](../README.md) · [开发检查](../development/checks.md)

本页说明怎样选验收入口，以及代码里看不出的边界。脚本的参数和前提写在各脚本的文件头，本页不复述。

## 先用这个入口

`npm run lab` 是开发统一入口：查环境、跑用例、跑评测、读使用记录、管本机测试网站、清理残留。用法见 [`scripts/maintenance/lab.mjs`](../../scripts/maintenance/lab.mjs) 的文件头，不带参数运行也会打印。

踩过的坑由它挡住，不靠记：负载超过 20 时 `case` 和 `eval` 不开跑；用例和评测默认用按当前代码冻结的一份扩展；清理只关确定没人在用的测试浏览器；Ego 任务空间只关名字以 `bys` 开头的，所以脚本建任务空间时名字一律以 `bys` 开头。开始测之前先跑 `npm run lab -- env`。

下面是它底层调用的命令，要单独用或排查时再看。

## 怎样选入口

- **合并前**：`npm run check` 和这次改到的用例。
- **用户发现问题或要求时**：`npm test`。`npm test` 只跑核心用例：只装扩展、用脚本模型，不要凭据。
  用户在等结果时，用 [进度页](../../scripts/acceptance/real-path/progress.html) 让用户看到每项测什么、测到哪。新加核心用例时，在进度页里补一句它测什么。
- **全部真实路径用例**：`npm run accept:real-path`。加 `--only=` 是过滤轮：没选的用例记为未跑，过滤轮永远不算整轮通过。
- **浏览器主链**：`npm run accept:browser`。
- **单项**：在 [`scripts/acceptance/real-path/`](../../scripts/acceptance/real-path/) 找到对应脚本，先读文件头，再加 `--headless` 运行。
- **技术前提**：`scripts/probes/` 下的[前提小实验](../development/checks.md#前提小实验)只证明前提，不代替功能验收。
- **评测环境分类**：见[站点不可用](eval-environment.md)。
- **CI**：E2E 工作流跑 `npm test`，目前只能手动触发，还没在 Linux 上跑通过。

## 脚本模型与真实模型

- 多数用例用本机脚本模型。脚本模型只验证交互呈现，所以通过不代表供应商模型的质量，也不代表真人语音验收。
- 接真实模型要本机凭据和用户授权。缺凭据时如实写「没跑」。
- Kimi 订阅登录的访问令牌只活约 15 分钟，刷新令牌用一次就作废，只能由一处续期：`npm run kimi:keep` 装的后台任务每 6 小时续一次，验收脚本取令牌时也在 Pi 的锁里续，交给测试扩展时不带刷新令牌。系统通知说登录失效时，运行 `npm run kimi:login` 在网页上确认一次。
- `answer-selfcheck` 不加 `--live` 也要本机 GLM 凭据，因为目标核对默认用真实 GLM 快速模型。
- `gpt-live-voice` 会用掉用户 ChatGPT 套餐的语音额度；声音来自合成语音，不代替真人试听。

## 容易误判的地方

- **试用包不等于当前源码**：验试用包时，用 `SIDEAGENT_ACCEPTANCE_DIST` 指向试用包。当前源码通过，不代表试用包通过。
- **日常 Chrome**：`everyday-baseline --daily` 连到用户已开的日常 Chrome。只在用户同意后运行。
- **只能有窗口跑**：`background-tab-input --headed` 会弹出测试窗口，不进整轮。从没显示过的后台标签页不渲染、输入会丢，无头 Chrome 复现不了。运行时别点那个窗口，点了会让新页到前台，这次不算数。
- **圈画判据**：页面圈住目标、没有点击、侧栏交付无错误，三项都要满足。只看到圈画、但目标账本报未完成，仍算失败。
- **固定页面不等于完整评测**：`answer-selfcheck` 的固定页面检查不代替完整产品评测。
- **快捷键**：`sidebar-interaction` 只检查快捷键消息，不等于操作系统真的按下 ⌘J。
- **夹具数据**：`killer-interactions` 的翻译批次由夹具写入，不代表供应商翻译质量。`ghost-hud-and-steering` 不覆盖真实视频网站，也不覆盖供应商模型的改写质量。
- **读回与核对发现**：`claim-after-check` 的目标核对结论是脚本写的，只验证侧栏怎样显示，不代表快速模型核对得准不准。
- **站点提示**：`site-hint` 要能上网打开真实网站。断网时它会失败，这不代表产品坏了。
- **结果未知后重试**：`retry-after-unknown` 只覆盖量不到元素位置这一种成因，不覆盖超时和断连。
- **发送前确认与教学**：`send-confirm` 和 `guided-teaching` 都没有覆盖“用户一直不理就超时”，因为产品没有缩短等待的开关，也不为测试加开关。`guided-teaching` 也没有覆盖 iframe 里的目标。

## 当前缺口

- `page-readouts --live` 尚待适配。
- `inproc-voice --case=stop-task`（语音确认中止原任务）当前有失败记录。
- 产品没有专用的只读脚本工具，因为求值标记盖不住返回对象序列化时的副作用。

## 脚本留在主线的条件

任务专用脚本至少满足一条，才留在主线：

1. 是 `scripts/acceptance/real-path/` 下的用例。一个用例跑不通又没人修，就删掉，因为测试按抓到过什么问题评价；
2. 被 `package.json`、`docs/` 下的现行文档或另一个活跃脚本引用；
3. 是多个任务共用的驱动、夹具或独立判定程序。

一次性探针在任务完成后合入共用驱动，或从 HEAD 删除。
